# AHC074：中立探索の追加近傍と、一般窓を使う掘り出し省略

## 位置づけ

**研究報告用。NOT FOR MERGE。2秒制約を満たす提出版ではありません。**

PR #114 の「2→2中立リライト＋再短縮」を掘り下げました。紙の設計は変えていません。今回の結果は二つに分ける必要があります。

- **広い探索版（permutation）**：移動先の変更対象を広げ、既存2操作のオペランド交換を加え、改善が続く間だけ最大3ラウンド反復しました。40ケースで前回版から214手、平均0.005224609375手/注文の追加削減です。ただし時間は大幅に増え、追加20ケースだけでは差は標準誤差の2倍に届きません。
- **一般窓アクセス専用版（portal）**：比較器の移動先を要求紙より下へ変えることで、ハンドル以外から要求紙を見えるようにして掘り出しを省きます。合法な12→11手の具体例を検証できました。しかし40ケースの総差は前回版から4手しかなく、平均改善は確認できませんでした。

「新しい短縮機構が成立した」ことと、「総手数を安定して下げる解法ができた」ことを混同しないため、結果を別々に記録します。

同梱資料：[ケース別手数](case-results.csv)、[実験条件と集計](manifest.json)、[独立検証結果](verification.json)、[12→11手の全状態](visibility_swap.json)、[広い探索の差分](permutation-core.patch)、[一般窓アクセス専用の差分](portal-core.patch)。

## 2. 広い探索版で変えたこと

### 2.1 一度だけ動く紙も、移動先変更の候補にする

元の後処理は主に「前の注文から列外にある紙」や「同じ手順で複数回動かす紙」を対象に挿入先を変えていました。中立候補を集める段階に限って、この対象をその注文で動く全ての紙へ広げました。

挿入先候補そのものは、元の列境界・所属列内・比較器周辺の規則を使っています。192通りの全挿入位置を総当たりしたわけではありません。特に、比較器に対して任意の商品紙をanchorとして与える候補は、この変更だけでは十分に生成されません。

### 2.2 既存2操作のオペランドを同時に交換する

操作は数値の深さではなく、`(k,a)` =「紙kを紙aの直下へ置く」と表します。a = −1は最上部です。

2操作 `(k_i,a_i), (k_j,a_j)` に対して、以下を試します。

1. **挿入先だけ交換**：`(k_i,a_j), (k_j,a_i)`。
2. **動かす紙だけ交換**：`(k_j,a_i), (k_i,a_j)`。
3. **操作順を交換**：二つの操作そのものを入れ替える。

長さmに対して最大 `3 * C(m,2)` 候補です。自分自身の直下へ置く指定は除外します。残る候補は実際の順序で再生し、不可視操作・表示不一致・キャップの不変条件違反・列外紙の回収不能を除外します。no-opは出力しません。

これは「積層中の2枚を直接交換できる」という新しい操作を導入するものではありません。**合法な1枚移動のプログラムを別のプログラムへ書き換える探索**です。紙の選択、挿入先、実行時点の依存関係を同時に変えられるため、単独の挿入先変更では現れない候補が出ます。

### 2.3 新しい手順からもう一度近傍を作る

1ラウンドは、全移動紙の挿入先変更、2操作交換、前回の2→2共同修復、候補の再短縮です。終了状態込みの評価Fが改善した場合だけ次のラウンドへ進み、最大3回で止めます。

```
既存の通常処理と後処理
  ↓
最大3ラウンド:
  同手数候補を生成（挿入先変更、2操作交換、2枚共同修復）
  正表示・合法な候補を最大4本保持
  各候補へ既存の短縮を再適用
  Fが改善しなければ終了
```

評価は前回と同じ `F = 操作数 + filler_charge + adaptive_next_cost`。候補幅4、同手数候補の許容幅F+0.75、再短縮深さ2も同じです。実際の次の注文は使用しません。

反復が止まっても、大域最適や全近傍の局所最適を証明したわけではありません。保持幅と生成する挿入位置に制限があります。

### 2.4 同一の後処理を正確に再利用する

注文ごとにキャッシュを空にし、中立候補を収集していない後処理だけを再利用します。入力操作列、開始時の終了積層、top_d、fillersの順序付き内容、通常処理/2→1処理の種別をキーにします。ハッシュ一致だけでなく、実データも一致させます。

キャッシュヒット時には終了状態と出力操作列を復元し、後続の分岐に使われる `mid_accepts` の差分も再現します。この差分を落とすと、同じ手順でも再短縮の起動条件が変わってしまいます。`post_saved`の差分も反映します。試行数など、実際の仕事量を表す全カウンタを水増しするものではありません。

キャッシュは注文内でのみ有効で、固定された同じ初期状態・要求・設定を前提とします。注文をまたいでキーをそのまま使える一般的なキャッシュではありません。

## 3. 新しい具体例：比較器の移動先を利用して12→11手

入力0001、第73注文（0始まり72）、商品104です。**要求紙は紙8**。以下はすべて実出力の0始まりの紙・窓番号です。

元の12手には次の部分がありました。

|操作|元のanchor表現|変更後|
|---|---|---|
|比較器1を並べ替える|1 → 6|同じ|
|比較器2を並べ替える|2 → 1|**2 → 8**|
|比較器4を並べ替える|4 → 2|同じanchor指定|
|紙7をどかして紙8を取り出す|7 → 8|**削除**|
|要求紙を持ち上げる|8 → 最上部|同じ|

2操作交換では、紙2と紙7の挿入先を交換します。紙2は紙8の下へ、紙7は紙1の下へという指定になります。すると紙7は既に紙1の直下にいるため、その移動がno-opとなり、1手消えます。

特に重要なのは、**紙4への既存操作が「紙2の直下」を参照していること**です。紙2を下へ移すと、続く紙4への操作も下へ向かいます。2枚を1回で動かしているのではなく、もともと必要だった2回の比較器移動の着地点が連動しています。

### なぜ紙7をどかさずに要求紙8を動かせるのか

次の2窓を見ます。

|紙|窓35|窓42|
|---|---|---|
|比較器2|0|1|
|比較器4|1|0|
|上に残る商品紙7|穴|穴|
|要求紙8|1|0|
|要求色|1|0|

比較器2と4を要求紙8より下へ移すと、**紙7の穴を通り、一般窓35・42で紙8が見える**ようになります。専用ハンドルを掘らなくても、紙8の持ち上げが合法になります。

独立検証の結果は以下の通りです。

|変更|手数|可視性と表示|
|---|---:|---|
|元の手順|12|合法・正表示|
|紙7への操作だけ削除|11|**紙8の移動時に不可視**|
|紙2の移動先だけ変更|12|合法・正表示、まだ短くない|
|**紙2の移動先変更＋紙7の操作削除**|**11**|**合法・正表示**|

片方ずつの変更が両方とも不正になる例ではありません。紙2の変更だけなら同じ12手で合法ですが、その変更が紙7の削除を可能にします。ここにも「同手数の別手順を経由する」意味があります。

また、操作を削ると数値深さは変わります。検証器もanchorで手順を編集し、挿入深さを再計算しています。紙2と紙4の数値深さはともに6から8へ変わりますが、紙4のanchor指定は元と同じです。

開始積層・全192枚・前後の全操作を `visibility_swap.json`（バンドルでは `witnesses/visibility_swap.json`）に収録しています。`verify.py --witness-only` で上の4通りと実際のanchor交換を再生できます。

## 4. この仕組みだけを狙う専用版

大きな探索を毎回回さず、次の候補だけを前回版の最後に追加しました。

1. 要求紙を持ち上げる前に動かす比較器から、最大2操作を選ぶ。
2. 選んだ比較器を要求紙の下へ向ける。選んだ比較器同士の最終順は、元の候補の順に合わせる。
3. 要求紙と同じ列にある、持ち上げ前の非要求紙への操作を一部削除する。
4. 全操作を再生し、正表示・可視性・後続注文に必要な不変条件とF改善を確認する。

比較器操作が6個以下、削除候補が10個以下の場合に限り、比較器部分集合（サイズ1または2）と非空の削除部分集合を列挙します。上限を超える場合はこの追加近傍を使いません。前回版の主処理自体を別解法へ切り替えるものではありません。

40ケースで追加候補は208264件（約5.08候補/注文）、24注文で直接1手ずつ短縮しました。しかし、その後の積層も変わるため、総手数差は−4手に留まります。**局所で24手削れても、全注文で24手得をするわけではありません。**

適用範囲も狭いです。比較器を下げても、さらに上の商品紙が一般窓を不透明にしていれば要求紙は見えません。深い列ほどこの障害が増えます。また、比較器より上に商品紙を残すと、次の注文での回収費用も発生します。専用版については、機構の成立は確認しましたが、単独採用を推奨する平均改善は得られていません。

## 5. 切り分けと、採らなかった案

### 追加近傍の切り分け

|方式|ケース|前回版からの総手数差|
|---|---:|---:|
|全移動紙の挿入先変更＋前回の2→2、1ラウンド|0–2|−18|
|上記を最大3ラウンド|0–19|−98|
|**さらに2操作交換＋キャッシュ（広い探索版）**|**0–19**|**−154**|

終了積層が変わるため、これらを同じ注文における独立の寄与として足し算することはできません。最後の差56手も、「各注文の交換だけで必ず56手削った」という意味ではありません。

### 他の方向

- **不可視になった操作を連鎖的に削除してから修復**：最初の3ケースでは前回版から8手減りましたが、1勝1分1敗。大きな利益はなく、全40ケースの候補には選びませんでした。
- **候補をbeamに入れる前に短縮して正規化**：2ケースで5手の削減。候補ごとに後処理を繰り返す費用が増え、採用根拠としては弱い結果です。
- **3操作のanchor・紙・順序の巡回置換**：3ケースで広い探索版より4手減りましたが、ローカル時間は約1秒増加。小標本の結果にすぎず、採用していません。
- **正表示を保つ紙を1枚追加してから不要操作を削る**：3ケースで、追加しない最大3ラウンド版と出力が同一でした。試した範囲では追加の利益を得られませんでした。
- **注文途中への2枚共同修復**：初回の1ケースでは最大3ラウンド版から手数が減らず、時間は約5.1秒から約10.4秒へ増えました。構造一般を否定する実験ではありませんが、この実装は継続採用しませんでした。
- **前回版を先に完成させ、追加探索で即時手数も減った場合だけ採用**：3ケースで前回版から7手減少。時間増に見合う明確な改善は得られませんでした。

これらは探索段階の少数ケースです。非採用は「その近傍に利益が存在しない」という証明ではありません。

## 結論

今回の上積みは、40ケースで前回版から214手、平均約0.0052手/注文でした。追加ケースでも差の向きは改善ですが、その20ケースだけの優位性は未確定で、時間の増加は大きいです。

一方で、**比較器の既存移動を一般窓のアクセス確保にも兼用する**という、新しい具体的な短縮機構を記録できました。専用化すると候補数は小さくなりますが、現状の平均改善はほぼゼロです。

次に検討するなら、単純にbeamや操作数を大きくするより、各窓で要求紙を隠している紙の集合から「既に予定されている移動の着地点を変えるだけでアクセスが開くか」を先に判定し、意味のある交換だけを生成する方向が候補です。これは今回の実測結果ではなく、具体例から導く次の仮説です。

**10.0手以下、2–3%改善、2秒制限への適合は、今回も達成していません。**
