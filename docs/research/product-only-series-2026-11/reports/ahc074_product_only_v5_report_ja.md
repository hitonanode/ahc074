# AHC074 商品紙のみ研究 v5 — 担当の一意性を外す案と、保持する案

評価日: 2026-11-06（日本時間）

## 1. 要約

**0.1手以上の削減を確認できた。ただし、その案は「各商品の担当紙を一意にする」という従来の設計を緩める。** 担当のない紙を6枚追加したわけではなく、既存の背景兼務6枚について、同じ商品を普通の商品紙でも担当するようにした。

100ケース平均は、v4強化版の **10.44931640625手**から、担当重複を許す強化版の **10.286123046875手**へ改善した。削減は **0.163193359375手/注文、1.561761%**。90勝10敗、表示誤り0、不正操作0だった。

同じ構造の軽量版も **10.33841796875手**で、v4強化版から **0.1108984375手**減った。直列4ケースの平均時間は、v4強化版5.895秒、今回軽量版3.338秒だった。

一方、**担当を一意に保つ版では10.40177734375手、改善は0.0475390625手に留まった**。元の一意担当路線で0.1手の削減を達成したとは報告しない。

また、重複担当の背景6枚がその注文の主紙として採用されたのは、対象商品の2356注文中30注文だけだった。印刷色の制約と合法な主紙手順は保持しているが、機能的には汎用補完寄りである。今回の拡張案を「汎用紙不要」の厳密な実証と混同しないこと。

元の6汎用紙版の保存済み参照値10.09322265625手には、まだ0.192900390625手届いていない。10.0手以下・9.5手以下も未達。

### 配布ソース

- `src/ng_product_v5_overlap.cpp`: 担当重複を許す強化版。
- `src/ng_product_v5_overlap_fast.cpp`: 同じ構造の軽量版。
- `src/ng_product_v5_unique.cpp`: 担当の一意性を保持する版。
- `src/base_v4.cpp`: 比較用v4強化版のソース。
- `src/validate.cpp`: ソルバから独立したC++再生検証器。

生成済みの各C++ソースは、別のソースをインクルードせず単独コンパイルできる。コンパイル例と再現方法は `README.md` を参照。

## 3. 最も有望な案の詳細

### 3.1 変更する制約は「担当の一意性」

v4では、背景兼務6枚それぞれに専用の商品があり、その商品には普通の主紙がなかった。疎な6枚が自分の商品を作れるようにするため、普通の商品紙を穿孔して補完役にしていた。

v5拡張案では、背景6枚の担当は残すが、同じ6商品にも普通の主紙を用意する。紙は追加せず、普通の専用紙の一部を共有紙へ変える。

|区分|v4|v5重複担当|
|---|---:|---:|
|キャップ|1|1|
|背景を兼務する専用紙|6|6|
|普通の専用紙|120|114|
|普通の共有紙|65|71|
|物理的な紙の合計|192|192|
|普通の紙だけで担当する商品数|250|256|
|全体の担当関係数|256|262|

専用紙数をs、共有紙数をq、重複担当数をdとすると、

    s + q = 191
    s + 2q = 256 + d
    q = 65 + d,  s = 126 - d

である。今回のd=6では、120専用紙＋71共有紙になる。262個の異なる商品を作るわけではなく、256商品中6商品だけが二つの担当紙を持つ。

背景6枚の各不透明窓は、引き続き実際の担当商品の色に一致させる。任意の色を印刷した6枚を、後から名前だけ商品紙に変えているわけではない。ただし主紙としての採用率は低く、この形式上の所有制約と実際の機能は分けて考える必要がある。

### 3.2 「他の商品紙に穴を増やして救う」必要をなくす

普通の256商品について、単独紙なら通常窓を印刷し、共有紙なら不一致窓を6枚の比較器で作れるペアを選ぶ。したがって、普通の主紙を使う全256商品に対して、追加穿孔なしの通常窓の完成手順を持てる。

今回の100ケースの実測:

|方式|表現可能性を確保するための追加穿孔数/ケース|
|---|---:|
|v4|86.75窓|
|v5一意担当・通常窓37|90.41窓|
|v5重複担当・強化|**0窓**|

ここで0窓とは、共有紙の不一致窓や階段アクセスの穴をなくしたという意味ではない。それらの基本的な穴に加えて、他の商品を補完するために削る印刷部分が0、という意味である。

今回の変更は、「補完役6商品の注文だけを短くする」以上の影響を持つ。これらを救うために普通の商品紙の印刷を犠牲にすることも不要になるからである。一方、共有紙は65枚から71枚へ増えるので、それによるコスト増もある。実測では利益側が上回った。

改善の因果効果をこの二項へ厳密に分解したわけではない。担当・ペア・列配置を一緒に作り直しているため、0.163193手の全てを穿孔削減だけに帰属させることはできない。

### 3.3 比較器の専用ハンドルは不要

6枚の比較器では、全15種類の紙の組に少なくとも一つの比較窓を割り当てている。その窓は、その2枚だけが不透明であり、色は反対である。

比較器を連続したブロックとして操作できる局面では、一番下以外の紙kについて、その下の紙lを一枚選べる。kとlの比較窓では、他の比較紙は穴なのでkが見える。従って一番下以外は専用ハンドルなしに取り出せる。最短手順の状態グラフも、一番下の紙の直接移動を許さない。

この性質を使い、背景列の物理ハンドルをなくした。強化拡張案では通常窓36を維持し、空いた窓を普通の列のハンドルへ回す。普通の列は26列から27列へ増える。

一意担当版では通常窓36/37/38を比較し、20ケースで良かった通常窓37を100ケース評価へ進めた。従って、その版は通常窓37＋普通の列26＋キャップ窓1である。

実装内部では、既存の列用データ構造に合わせるため、背景列のハンドル番号にキャップ窓63を仮の値として使う。ただし、これは物理的なアクセス窓として使わない。通常窓の条件、ハンドル修復、穴の需要から除外する。実際の操作の合法性は、常に192枚・64窓の本物の可視性で検査する。

### 3.4 注文処理と重複担当の意味

通常の商品には、v4と同じ一枚/二枚の共同補完と比較器への差込みを使う。重複対象の6商品については、普通の主紙を使う案と、元の背景紙を主紙として使う案を比較する。既存の列内再配置、列の状態価値、合法な操作列の短縮を継承している。

100ケースでは、対象2356注文に対し、元の背景紙を主紙として選んだのは30注文、約1.27%だった。その場の操作数の差を足したカウンタは合計4手。最初の8ケースでは選択機能を無効にしても結果は同じだった。

従って、今回の成果を「二つの主紙候補を毎回賢く選ぶだけで0.16手減った」と説明するのは不適切である。普通の紙だけでも全商品を担当できるようにした設計変更の効果が大きいと考えられる。将来の状態への影響もあるため、4手という局所カウンタを厳密な反実仮想の総効果とはしない。

背景紙を主紙にする合法な手順は、強制検査でも確認した。しかし、利用の大半は補完なので、「各紙が自分の商品を日常的に担当する」ことを要件とするなら、この拡張案を採用結果にしてはいけない。

## 4. 捨てた案・保留した案と理由

### 4.1 背景6商品の通常窓を、比較器だけで直接表現する

6商品それぞれに、その商品紙が先頭となる表示順を一つずつ用意し、各比較窓が全6商品の要求を同時に満たす割当だけを許した。

4ケース全てで表現可能性のための追加穿孔0を実現し、表示誤り・不正操作0だった。ただし平均10.505859手で、0.1手の改善にはならなかった。同じ4ケースの「ハンドル削減のみ」より悪化した。

制約を4商品だけに緩めた案も、20ケースで10.441992手に留まった。背景商品の自己表現を保証する代償として、普通の65共有ペアを作りやすい窓割当を失う。証明用の表示順と窓割当を同時に変えるマクロ近傍も試したが、今回の実装では改善しなかった。

### 4.2 1窓に3枚以上を印刷する背景

各比較窓に2枚しか印刷しない制約を外し、別の商品紙にも自分の担当色を追加印刷する。既存の共有ペアを固定すると、ほとんど編集を受理できなかったため、ペアも選び直す版を実装した。

しかし、印刷を増やすと、一方の目標を作れる並べ順が増えても、その共有相手を作れる並べ順が失われる。自己表現への重み8の8ケースは10.451172手、重み24は10.462402手で、ハンドル削減のみの10.411011手を上回れなかった。

### 4.3 5枚・120状態の比較器

従来コードで未対応だった5枚の場合について、120順列と合法移動距離から部分順序の正確な平均費用を計算するキャッシュを実装し、1枚/2枚の差込み手順も一般化した。

通常窓34の8ケースは10.478027手。通常窓36は6/8ケースで新構造の構築に失敗して既存の相互補完構造へ切り替わり、平均11.138306手だった。

背景担当の商品は1個減るが、共有ペアを安く作る表現能力も落ちた。比較器の枚数を減らすだけでは、今回の0.1手削減にはならなかった。

### 4.4 補完価値を設計へ直接入れる

現在の列先頭の商品紙一枚・二枚で通常窓とハンドルを共同補完できる価値を近似評価し、Hungarian法による担当再割当へ追加した。

8ケースで10.407959手だったが、出発点のハンドル削減版10.411011手との差は約0.003手。今回のモデルでは、0.1手級の改善を確認できなかった。

模擬注文から補完紙の需要・ハンドル修復需要を学習して列の状態価値を作り直す案も実装したが、最大でも小規模比較で約0.019手の改善に留まった。主結果には含めていない。

### 4.5 6商品専用の補完関係を、浅い3列へ作る

背景6商品のそれぞれに、別の実商品紙一枚を補完役として割り当て、その6枚を浅い二枚列3本へ置く案も実装した。全商品の主担当は一意のままである。

構築できた4ケースでは、一枚の補完で完成する証明を持ち、必要な穿孔も減らせた。しかし8ケース中4ケースでこの配置の構築が失敗し、切替込みで10.865723手だった。少数の補完役を浅い列へ固定することの制約が強く、今回は採用していない。

### 4.6 採否のまとめ

一意担当のまま0.1手以上の削減を達成した案は、今回見つかっていない。小さな改善を大きな成功に見せるために、多数の設定を足し合わせたり、実注文の結果でケースごとに最良方式を選んだりはしていない。

0.1手以上が再現したのは、**「担当を一意にする制約」と「背景列にも専用ハンドルを持たせる制約」を同時に外した拡張案**だった。背景商品の救済費用を、普通の商品紙の多数の穿孔で払うのではなく、6組分の追加共有で払う、という設計上の交換が今回の有力な結果である。
