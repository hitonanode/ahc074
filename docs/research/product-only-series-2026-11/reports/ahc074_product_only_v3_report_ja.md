# AHC074 商品紙のみ v3：担当商品を持つ6枚で、720通りの補完背景を作る

作成日：2026年11月5日。評価は配布ツールに含まれる seed 0〜99 の100ケース。手数は小さいほど良い。

## 1. 要約

**汎用専用紙0枚・階段列構造を維持したまま、平均11.355986手から10.637275手へ改善した。** 同じ102,400注文で73,596手、1注文あたり0.718711手、6.3289%の削減。100ケースすべてで前回v2を上回り、表示誤り・不正操作は0だった。

前回の「3列×2枚、8通りの常設背景」を、「1列×6枚、並べ順による720通りの常設背景」へ置き換えた。6枚は全て実際の担当商品を持つ専用紙で、印刷する通常窓の色も担当商品の色に一致させる。担当のない汎用紙は生成しない。

ただし、**目標の10.0手以下と、元の6汎用紙版10.093223手にはまだ届いていない。** また、強化版は本環境の直列実行で平均5.09秒。探索を軽くした版は10.703770手・平均2.38秒で前回v2より速かったが、こちらも2秒制限への適合を保証できない。現状は手数改善を確認する研究実装である。

### 配布する実装

- `src/ng_product_v3.cpp`：手数優先版。単独でコンパイルできる。
- `src/ng_product_v3_fast.cpp`：同じ構造・注文処理で設計探索の反復回数を減らした軽量版。単独でコンパイルできる。
- `src/validate.cpp`：ソルバをインクルードしない独立した出力再生器。
- `scripts/`：バッチ比較、オンライン対話検査、構造監査、厳しい注文列、集計・再検証のスクリプト。

実行例：

```sh
make all
./product_v3 < inputs/0000.txt > answer.txt
./validate inputs/0000.txt answer.txt
```

## 3. 最も有望な案の詳細

### 3.1 構造：6枚の並べ順を背景として再利用する

通常窓36、ハンドル27、キャップ窓1に分ける。最初の列に6枚の専用紙を置き、残り26列に120枚の専用紙と65枚の共有紙を置く。つまり、全体は次の構成である。

- キャップ1枚。
- 専用紙126枚。このうち6枚が常設の補完背景を兼務。
- 共有紙65枚。担当目標は130個。

合計192枚、担当目標は126+130=256個。キャップ以外に、担当のない紙はない。

補完役6商品の番号を \(t_0,\ldots,t_5\) とする。通常窓 \(j\) ごとに、\(A_{t_a,j}\ne A_{t_b,j}\) となる2商品 \(a,b\) を選ぶ。その窓は紙 \(a,b\) にそれぞれ自分の商品の色を印刷し、他の4枚は穴にする。

この窓は、6枚のうち \(a,b\) のどちらが上にあるかで色が決まる。15種類の紙の組を少なくとも1窓ずつに割り当てるので、6枚の並べ順 \(6!=720\) 通りが、区別できる通常窓背景を作る。

前回の3本の2枚列は各列の先頭を選ぶだけなので、背景は \(2^3=8\) 通りだった。背景の数が90倍になったという表現力の比較であり、手数が90分の1になるという意味ではない。

**比較器自体は元の `esw-clean.cpp` の発想を再利用している。** 今回の変更点は、その6枚を無所属の汎用紙ではなく、担当商品と自然な印刷色を持つ商品紙として1列に組み込み、担当商品も含めて設計することである。

### 3.2 汎用的な機能は残るが、汎用専用紙は0枚

この区別は重要である。6枚には多くの注文に使われる補完機能を集中させており、「全商品紙が同じ役割」という対称な構造ではない。

それでも、6枚は各々実際の担当商品を持つ。通常窓で印刷する色を自由に選べるわけではなく、担当商品の色と一致する窓だけを印刷する。担当商品が要求されたら、当該紙を主紙として取り出し、他の商品紙で不足分を補う。この費用を評価に含める。

したがって実証したのは、**補完専用の無所属紙を使わず、商品紙に補完機能を兼務させる方針が、前回より大きく伸びること**である。汎用機能そのものが不要だという主張ではない。

### 3.3 共有ペアの表現可能性

共有紙が目標 \(u,v\) を担当するとき、不一致部分 \(D=A_u\oplus A_v\) が穴になる。

通常窓の穴で目標 \(u\) の色を表示するために、各窓の比較紙のうち正しい色を持つ方が他方より上、という向き付き制約を加える。この6頂点のグラフが非巡回なら、通常窓だけについては条件を満たす並べ順が存在する。目標 \(v\) の条件は全ての向きが逆になる。

ただし今回は補完列にもハンドル \(h_0\) があり、共有紙がそこを穴にする場合には、列先頭の紙の色も要求に一致しなければならない。そのため、非巡回性だけでは足りず、\(u\) 側のグラフで所望のハンドル色を持つ入次数0の頂点があること、\(v\) 側でも同じ条件が成り立つことを検査する。

設計目的は、65組の互いに重ならないペアを確保した上で、概ね「ハンドル差分＋比較器の平均移動費用＋全窓差分」を下げるもの。比較器の平均移動費用には既存の部分順序クラス表を再利用した。ハンドル色を指定することによる追加移動費用までは設計目的で厳密評価しておらず、ここには改善余地がある。

### 3.4 6商品の選択と窓の割当を同時に変える

補完役6商品を最初に固定すると、ある窓で比較できる紙の組が限定され、良い共有ペアを選べなくなる。

そこで、窓の入替や比較辺の変更に加えて、補完役の商品を交換する操作を入れた。ある紙が現在印刷している窓で色の近い商品を候補にし、交換で両端が同色になってしまった比較窓だけを別の辺へつなぎ直す。全15辺を残し、ハンドルの両色を維持し、65ペアの目的値を再評価する。

この変更は、補完役の6商品自身が使える印刷形状と、他の250商品を共有紙にできる条件を同時に変える。単に同じ設計を複数回作って良いものを選ぶ方法ではない。

設計後は、補完役6商品のように通常窓の穴が多い目標を含め、全256目標に対する補完手順を探索する。必要なら他の商品紙の印刷を削り、全目標の補完可能性を再検査する。強化版100ケースの追加穿孔は平均86.75窓、最小61・最大115窓だった。これは当該設計の補完可能性を成立させる編集であり、後段の任意の追加穿孔最適化とは区別する。

### 3.5 普通の商品紙を6枚の間へ挿入する

通常の注文では、補完列を適切な順番へ変更し、主紙を上へ出し、残るハンドルを修復する。

しかし6枚の比較器だけで通常窓の穴を全て補う必要はない。別の商品紙 \(X\) を比較器の途中へ差し込むと、上側の比較紙で隠されている場所では \(X\) の色は問われず、露出する場所だけ一致すればよい。この \(X\) が、主紙のハンドル穴も同時に埋めることがある。

実装では各目標・候補紙について、「比較器の並べ順」と「差込み深さ」の有効な組を事前計算する。注文時には現在の順番からの移動距離、候補紙の取り出し深さ、残るハンドル修復を見積もり、上位候補を実際のスタックで検証する。

強化版100ケースでは、1ケース平均911.74回の追加候補評価があり、既存候補を改善する採用更新が平均75.72回あった。この値は最終的な採用注文数そのものではなく、探索中の最良候補更新回数である。同じ8ケースでは、この追加によって10.752075手から10.670166手へ改善した。

### 3.6 取り出し順と背景確定の順番

補完役の商品自身を主紙や補完紙として使う場合、比較器から1枚以上を取り出す。この取り出しのために列を掘ると、残った比較紙の順番が変わる。

初期試作では、背景を先に確定してから商品紙を掘ったため、背景が変わって不正な表示になる候補があった。最終版は、**選択した補完列の紙を先に取り出し、その後で残る補完列の背景を確定し、普通の商品紙の取り出しへ進む**。

6枚がそろっている通常時には、15比較を全て含むことにより、列の最下段以外の各紙は、少なくとも最下段との比較窓で見える。比較器の経路表は、この可視性を満たす移動を使う。一部を取り出した場合や商品紙を挟んだ場合も、実行候補を紙全体の可視性で再生検査する。

主紙・補完紙の回収については、前回からの合法な全回収候補を残す。無害な紙を置いたままにする候補や局所短縮も試すが、最終表示、操作ごとの可視性、回収可能性を確認した候補だけを使う。

## 4. 捨てた案と理由

### 4.1 1列の先頭を3〜4種類から選ぶだけの背景

3列×4枚、通常窓28の4ケース比較は11.743652手だった。2ケースでは新構造を作れず、普通の商品紙相互補完へ切り替えている。2列×4枚も11.666260手で良くなかった。

先頭の候補を増やすと表現力は増えるが、狙う紙を先頭へ出すための掘りも増える。下にある紙を表示に使わない構造では、追加の枚数を十分に生かせなかった。

### 4.2 小さい比較器を複数列に分ける

2列×4枚・通常窓36は、4ケース全件で構築・検証でき、平均11.230957手だった。これは初期の有望案だが、1列×6枚の方を優先した。

小さい列を独立に操作できる利点はあるが、複数のハンドルを消費し、補完役の商品数が増える。各窓で使える比較紙が同じ小列に制限されることも、共有ペアの選択を狭める。

### 4.3 ハンドルへの追加穿孔と背景の先読み

6枚1列の初期版で8ケースを比較したところ、基準10.834717に対し、追加穿孔10.834961、背景先読み10.835327、両方10.835693だった。この範囲では改善を確認できず、最終既定値では無効にした。

これは設計時の補完可能性を成立させるための穿孔を無効にした、という意味ではない。追加の費用最適化だけを不採用にした。

### 4.4 通常窓を38に増やす

担当商品の交換も入れた8ケース比較では10.946777手で、36窓案より悪かった。1ケースは構築に失敗し、代替設計へ切り替えている。

通常窓を増やすとハンドル穴を減らせる一方、共有ペアに課す比較制約が増え、列数が減って掘る費用も増える。今回の実装・探索設定では36窓が良かったが、38窓一般が悪いという結論ではない。

### 結論

今回の確かな成果は、**「担当のある6枚を、列に置いたまま動かせる比較器にする」ことで、商品紙のみの方針を平均10.637275手まで進められたこと**である。前回から6.33%改善し、100ケース全てで改善した。

一方、目標の10手以下や元の6汎用紙版を超えるところまでは未達で、強化版の実行時間も長い。新構造を既存最良に勝つ提出版としてではなく、次の設計改善を行うための、実測で改善を確認した土台として提供する。

強化版の既定値は `NG_G=36`, `PC_COLS=1`, `PC_SIZE=6`, `NG_CONTROL_MAP=50000`, `NG_CONTROL_ANNEAL=14900000`, `PC_CLIMB=154000`, `PC_REMATCH=4`, `PC_OWNERS=1`, `PC_HELPERS=1`。軽量版は `NG_CONTROL_MAP=20000`, `NG_CONTROL_ANNEAL=4000000`, `PC_CLIMB=30000` だけが異なる。追加穿孔最適化と背景先読みは `PC_PERF=0`, `PC_LOOK=0`。
