## 1. 比較の前提

### 問題と元解法の構造

64窓、192枚、256商品、1024注文。誤り1注文は384操作分なので、研究の狙いは誤りを許して操作数を稼ぐことではなく、正しい表示を維持した手数削減である。注文は逐次与えられ、実注文の先読みはできない。

元解法の主構造は次の通り。

- 汎用比較器6枚。38個の汎用窓は比較器2枚の前後関係を表示し、全15比較対を含む。比較器順序は720通り。
- 固定黒cap1枚が1窓を担当。商品紙をcapの上へ置くか直下へ置くかで、その窓を切り替える。
- アクセス用ハンドル25窓。商品紙185枚は71組の共有ペアと114枚の単独商品紙からなる。
- 商品紙を列から取り出し、比較器順序とハンドルの穴を修復する。他の商品紙を補助紙・フィラーとして再利用する。
- 戻す紙の深さは将来費用で評価し、複数の計画を比較。最後に操作削除・挿入先変更・2操作削除＋1操作修復などの後処理を行う。

一つの操作が取り出し、複数ハンドルの修復、比較器補助、次注文の準備を兼ねる。そのため、各項を独立に足す評価式と実際の総手数にはずれが生じうる。

### 手数の比較から時間依存の簡易化を除く

第2回以降の主比較では次を使った。

```text
FIXED_WORK=1
MAP_ITERS=262144
GOPT_STEPS=65536
ANNEAL_ITERS=12582912
CLIMB_ITERS=32768
```

研究用の `FIXED_WORK` は計測関数に0を返させ、主要探索を固定反復回数で終える。その後の再割当て・穿孔・補助表構築も時間切れで省略しない。壁時計時間は別に測る。**固定時計を使うときは、全ての時間依存ループが有限の反復数で終了する設定を同時に与える必要がある。**

基準は元の強い注文処理を1024注文すべてに実行する版で、単純な弱い基準へ置き換えたものではない。注文処理の比較では紙模様の一致も確認した。二窓capや設計選択の比較は、設計そのものを変更するため別扱いにする。

過去のコンパイル条件は主に `g++ -std=c++20 -O2 -march=native`。現在のリポジトリのC++23・`LOCAL_BENCH`・`CLOCK_SCALE`・保存設計の運用へ移植して再評価する場合とは区別する。

### 入力と統計の読み方

第2回の開発32ケースは独自C++生成器seed 41000000〜41000031、追加64ケースは51000100〜51000163。後者のファイルIDは0100〜0163。生成規則は問題文と同じだが、公式Rust生成器の同番号seedと同じ入力ではない。

## 2. 最も再現性のある手数改善：列の部分列MDP

### なぜ逐次の重み付き深さだけでは足りないか

元の `adaptive_insert` は、紙の担当商品数と補助用途による重み付き深さ、各色の最初の紙までの深さを使う。軽量だが、取り出しを何度も繰り返したときの列状態の遷移を直接評価していない。

各列の紙を「1商品担当・白」「1商品担当・黒」「2商品担当・白」「2商品担当・黒」の4種類に集約する。同じ種類を区別しなければ、列長n、各種類枚数n0〜n3に対する完全状態数は `n! / (n0! n1! n2! n3!)`。192枚全体を探索せず、列ごとの小さい状態空間を扱える。

### 鍵は、動かさない末尾が部分列として残ること

列が `a,b,x,c,d` でxを取り出すとする。a,bをどかし、xを取り出して後に戻すとき、動かしていないc,dの相対順序は保たれる。抽象モデルで必要なのは、その末尾を部分列として残す最良の次状態である。

価値関数Vに対し、次を用意する。

```text
F(s) = min V(π)  subject to s being a subsequence of π
H(s) = min V(π)  subject to s being a subsequence of π,
                         and π[0] having the same type as s[0]
```

商品紙を取り出すときはFを使う。ハンドルの色を直すために最初の正しい色の紙まで掘る場合は、その紙を先頭に残すのでHを使う。

全状態から1文字ずつ削除するDAGを作り、Fは任意位置の削除、Hは先頭以外の削除へ最小値を伝播する。これにより、毎回全ての再挿入順を列挙せずに部分列条件付きの最良値を得る。

### 平均費用の価値反復

位置iの紙の担当商品数をw_i、色bの修正要求の重みをλ_b、最初の色bの位置をd_b、要求重みの総和をWとする。抽象モデルのBellman更新は概略、

```text
g + V(π) = { Σ_i w_i [i + F(π[i+1:])]
             + Σ_b λ_b [d_b + H(π[d_b:])] } / W
```

各反復で最小値を引く相対価値反復を8回行う。従来の列評価の一部を、混合係数0.25でこの長期価値へ置き換える。元の補助用途などの評価を全て捨てるわけではない。紙が列外に出ている場合は、残った列を部分列として評価する。

状態爆発を避ける上限は列長14、完全状態40000、部分列状態250000。上限外の列では元の評価を使う。この評価関数の代替と、時間不足で注文処理全体を簡易化するfallbackは別のもの。

### 厳密な部分と近似の部分

F/Hの最小値伝播は、構築した有限状態上では厳密。しかし、実問題全体の最適MDPではない。紙ID固有の模様、他列、補助紙の重なり、直前商品を除く需要分布などを集約し、価値反復も8回で打ち切る。列外の紙も近似的に扱う。

最後の操作列は通常の可視性・表示・後続処理の条件で検査する。MDPの近似値が良いだけでは不正な計画を採用しない。

### 実測と期待される効果

最初の固定設計32ケースでは334250→333855手、0.118175%削減、24勝1分7敗。追加64ケースでは667917→667249手、0.100012%削減、48勝1分15敗。後者のlog比は **−0.099661% ± 0.022956% SE**。

期待できるのは、必ず必要な取り出し・返却の後に、より良い列状態を残す小幅改善。単純な反復回数増加より、重要な補助紙の用途を少数の追加クラスにすることや、列外の紙の状態を区別する方が有望という仮説がある。ただし追加状態・初期化時間に見合うかは未検証。

## 3. 必ず動かす前方紙を一括で戻すDP

### 逐次挿入で落ちる自由度

同じく `a,b,x,c,d` からxを取り出すとき、a,bはどちらも動かす。元実装はaの戻し先を決めてからbの戻し先を決めるが、両方を必ず動かすなら、2枚を動かした後の並びをまとめて選べる。変えられないのはc,dの相対順序だけ。

必ず動かす紙をハンドル色で白・黒に分け、同色内では `adaptive_weights` 降順に並べる。同色同士を交換しても「最初の色の位置」は変わらないため、重い紙を浅くした方が重み付き深さは良くなる。

残る問題は「可動白紙」「可動黒紙」「不動末尾」の3列マージである。各列から使った枚数を(i,j,k)とし、次の位置r=i+j+kへ紙pを置くコストを `weight[p] × r / 256` とする。その色がまだ現れず、列外にも利用可能でない場合には、最初の色の深さに応じた修復需要コストも足す。取り出す商品紙の色は列外で利用可能と扱う。

白w枚・黒b枚・不動s枚なら状態数は `(w+1)(b+1)(s+1)`、各状態は最大3遷移。

### 同じ取り出し操作数で実現する

前方紙を元の上から順に動かす。目標並びで直前に位置する配置済み紙の下へ挿入し、それがなければxの直下へ置く。xを障壁として残すので、未処理の前方紙を再び隠さない。前方紙は各1回ずつ動かす点を変えず、取り出し後の状態を改善できる。

実装は商品紙・補助紙・フィラーを実際に取り出す場面に限定し、単なるハンドル色合わせの掘り全てには適用していない。局所の操作数は増やさないが、後続の計画選択・次注文の状態が変わるため、総手数の単調改善保証ではない。

### 実測と併用の注意

`batch-prefix.cpp` 単独は追加64ケースで667917→667728手、189手、0.028297%削減、40勝2分22敗。log比は **−0.028182% ± 0.013242% SE**。平均削減2.9531手/ケースの過去の95% t区間は[0.1946,5.7116]で下端が0に近い。

列MDPと素朴に併用した開発8ケースではMDP単独より悪化した。評価目的が異なるため改善率を足せない。次に試すなら、マージDPの目的とMDPの終端価値を整合させることだが、まだ実証していない。

## 4. 前の商品紙を7枚目の比較器補助紙として使う

元の補助紙探索は、前の商品紙やフィラーを列へ戻した状態から、新しい補助紙を取り出す。そのため「すでに列外にある前の商品紙を、そのまま比較器層で使う」という候補を取りこぼしうる。

現在の商品紙のハンドル穴に誤色を出す場合や、取り出し対象のアクセスを塞ぐ場合は除外する。汎用窓の表示が合う並びを見つけたら対象商品紙を取り出し、既存のハンドル修復へつなぐ。比較器がcapを越えないことと、具体的操作の可視性も確認する。

## 6. 補助紙の重複利益を除いたHungarian再割当て

別々の補助紙が同じ窓を直す場合、それぞれの利益を独立に足すと二重計上になる。`ahc074-research.cpp` の `OverlapReassign` は、商品ごと・仮想の列先頭状態ごとに、実際に両立する非重複区間のDPを解き、紙の変更の限界利益を評価する。

ある列cの補助候補を変更するとき、前向きDP F、後ろ向きDP B、cを使わない最良値avoid[c]を保存する。新しい区間[l,c]の利益をe[l,c]とすると、更新後の値は概念的に、

```text
max(avoid[c], max_l { F[l] + e[l,c] + B[c+1] })
```

から求められる。これを再割当てのコストに入れ、Hungarian法の巡回置換を実際の代理目的でも再評価して採否を決める。単一変更の限界利益を複数変更へそのまま足すと相互作用を落とすため、再評価が重要。

最初の8ケースで0.183%改善したが、独立32ケースでは0.0500%に縮小し、推定区間は0を含んだ。8サンプル・1反復が初期試験では良かったものの、初期計算も増える。保留であり、確定した提出改善ではない。

## 7. 二窓cap：紙や持ち上げ回数を増やさず表現を広げる

### 仕組み

1枚のcapが担当する窓を1つから2つへ増やす。商品紙をcapの上に置けば商品紙の色、下に置けばcapの色になる。もともと必要な持ち上げの行き先だけで2窓をまとめて切り替える。

既定の構成は汎用37窓＋ハンドル25窓＋cap2窓、比較器6枚＋cap1枚＋商品紙185枚。紙枚数は増えず、比較器の担当窓が1つ減る。ただし**2ビットを独立に切り替えられるわけではない**。上/下の二択なので、2ビットパターンを一括切替する。

今回の商品紙はcap窓で不透明。共有2商品のcapパターンをa,b、cap自身のパターンをCとすると、適合条件は、

```text
a == b || a == C || b == C
```

となる。例えばC=00なら00と10は共有できるが、10と01はこの構成では共有できない。比較器の負担減と、共有ペアの条件が厳しくなる損を同時に評価しなければならない。

### 実装と結果

capの窓と色を入力から選ぶ。近い商品ペアの割当て費用による選択と、頻出パターンによる選択を試した。

| 構造・開発32ケース | 総手数 | 元構造比 |
|---|---:|---:|
| 1窓cap、汎用38窓 | 334250 | — |
| 2窓cap、汎用37窓、ペア費用で窓選択 | 334596 | 0.103515%悪化 |

## 9. 補助紙を設計の適合条件に含めるsoft-pair案

### 設計と注文処理の能力差

比較器のみで表示できる共有ペアでは、穴の各窓が要求する前後関係がDAGでなければならない。例えば `C0<C1, C1<C2, C2<C0` は循環なので不可能。

しかし、実際の注文処理は比較器の間へ既存商品紙を補助紙として挿入できる。循環の一部を補助紙が正色で覆えば、比較器に残る要求はDAGになりうる。**比較器だけでは不可能であることは、現在の全紙集合で不可能であることを意味しない。**

これは補助紙を新たに増やす案ではない。既存紙の補助能力を、商品ペアを選ぶ設計制約に戻す案である。

### 厳密な表示判定

比較器順序πの表示をV、挿入深さdより上の比較器が覆う窓集合をQ、補助紙の不透明窓をO、黒窓をBとすると、補助紙を挿入した表示は、

```text
V' = (V & (Q | ~O)) | (B & ~Q)
```

となる。商品紙の汎用穴Dと目標A[u]について、

```text
((V' ^ A[u]) & D) == 0
```

を検査する。補助紙が商品紙のハンドル穴へ誤色を出さないことも別途必要。

6枚なら720順序×7挿入位置。補助紙候補を192ビットの集合で表し、窓ごとに「誤色を出さない紙」「正色を不透明に印刷している紙」の積集合で絞れば、具体的な補助紙・順序・深さを証人として返せる。ペアの両商品について検査し、必要なら別々の補助紙を許す。

過去に説明した監査範囲は、`pair(a,b)+single(c)` を `pair(a,c)+single(b)` へ変更し、紙枚数・共有ペア数・担当列のハンドル色を維持する近傍。商品間距離26以下、比較器のみの最良表示が1窓違い程度の候補へ限定する。全ての補助紙付き設計を網羅する探索ではない。

### 完成図の存在と低手数を分ける

完成図が正しくても、そこへ合法操作で到達できることは別に確認する必要がある。ただし、各紙に1つ以上不透明窓がある場合には、任意の現在順から任意の目標順へ最大K回で移せる。

未処理部分を前方、処理済み部分を後方に保つ。未処理の先頭紙はスタック全体の先頭なので必ず可視。それを処理済み末尾の中の目標順位へ挿入する。毎回未処理が1枚減り、K=192枚を処理すれば目標順になる。操作しない同位置挿入も数えるとして最大192回であり、注文上限384以下。

全て穴の紙は問題上許されるが、この証明では除外している。また、完成順列へ到達できることは、元の通常処理が要求する列・cap・フィラーの不変条件を保って10手程度で遷移できることとは違う。監査で全64窓一致を確認しても、低手数ソルバーの改善実証にはならない。

### オンライン実装へ進める際の注意

単に `compatible()` のDAGチェックを緩めればよいわけではない。既存コードは通常の比較器単独計画があることを仮定し、補助紙を使わない費用で候補を刈る箇所がある。DAG不適合を許すなら、補助必須商品の計画生成、候補の取得可能性、深さ制限、補助表の再構築、失敗時の正しい表示、次注文への復帰条件を一緒に設計する必要がある。

紙を再ペア化すると、その紙自身の補助用途も変わる。変更前の補助紙表の証人を、変更後にも使えるとは限らない。

### 期待と現状

期待するのは取り出しやすいペア選択の自由度を増やし、既存のハンドル修復に使う補助紙へ汎用窓の修復も兼ねさせること。一方、補助紙の取り出し・挿入・返却が増えると負ける。評価すべきは独立な追加費用ではなく、商品取得から表示完成までの総操作列である。

この会話系列では改善スコアは未確認。監査器ソースも今回確認できず、再実行済みの証明器としては収録していない。

### 既存研究との関係

PR作成時にリポジトリを確認すると、[PR #57](https://github.com/hitonanode/ahc074/pull/57) には補助紙で非整合ペアを救済する実装と否定的評価が既にある。同PRは固定された同一1枚の補助紙を両方向へ使うことの限界も報告している。[PR #74](https://github.com/hitonanode/ahc074/pull/74) は商品紙自体を比較器間へ挟むだけではDAG条件を超えないことを扱っている。

従って本案の一般的な新規性は主張しない。現在の強い補助紙処理を前提に、別々の補助紙の証人と取得費用を含めて再検討する位置付けである。既存の否定結果を無視せず、どの条件を変えたため再検討するのかを明示する必要がある。

## 10. 実行予算制御は別枠の工学的改善

初回は、元実装が計測時刻1.80秒以降に簡易処理へ切り替わる環境だった。高価なejectionを前半で使い切るより、通常処理の時間を全注文分残す方が有利だった。

各注文の処理時間からejection時間を引いて通常処理の平均tを更新し、残り注文数rについて、

```text
reserve = (r - 1) * t * 1.12 + 0.008
```

を予約する。`elapsed + reserve < 1.94` のときだけejectionを行う。紙設計・補助紙・通常計画比較は保ち、最後の安全策として1.94秒で簡易処理へ移る。

独立16ケースでは10.590759→10.202881手、3.662423%削減、16勝0敗。簡易処理件数は平均371.875→4.250件/ケース。MDPを加えた別32ケースでは2.707922%削減したが、集合が異なるため候補同士の優劣には使わない。

同じ開発8件では、元10.497803、打切り時刻のみ1.94秒にした版10.217896、予算予約版10.166016だった。また固定設計でejectionを完全に外すと悪化は約0.130%だが、注文処理時間は観測上約0.58→0.36秒だった。

この数%差は**紙構造の改善ではない**。ユーザーの環境で全注文が通常処理なら同じ効果を期待する根拠はない。1.94秒には小さい余裕しかなく、本番TLEを保証なく否定できない。fallbackなし研究の結論へ合算しない。過去集計は [results/phase1-summary.csv](results/phase1-summary.csv)。
