1. 全体像

1.1 一言でいうと

256 個のバーコードのほぼ全部に「専用の紙」を用意し（2 個で 1 枚を共有する「対」を含む）、注文が来たらその紙を掘り出して山の一番上へ持ち上げる。紙の穴からのぞく窓だけを、ほかの紙を動かして目標の色に合わせる。

窓 64 個は 2 種類に分かれる（コードでは H = 34、G = N − H = 30。59 行）。

  • 汎用窓 G（30 個）: 山の上の方にある汎用層（土台 1 枚 + 反転紙 5 枚）が常に覆う。専用紙が対で、2 つの目標の色が違う窓は専用紙の穴になり、そこは汎用層の向き（ブロックごとに Y か ~Y）で合わせる。
  • ハンドル窓 h0…h33（34 個）: 専用紙は 34 本の列に分かれていて、列 l の紙は h0…hl で不透明、hl+1 以深で穴（三角形）。列 0, 1, … の順に汎用層の下へ積むと、列 l の一番上の紙は hl でだけ見えるので、そこを掴んで掘る（一番上の紙を列の一番下へ回す）ことができる。

注文 u の専用紙 D が列 l にあれば、列 l を掘って D を列の一番上にし、D を山の一番上へ持ち上げる（lift()）。D は hl+1 以深で穴なので、そこには各列の一番上の紙の色が見える。違っていればその列を掘るか（fix_handles()）、深い列の紙をまとめて差し込んで覆う（穴埋め紙）。どの手順をとるかは、注文ごとに最大 28 通りの計画を実際に走らせて最も安いものを選ぶ（process()）。誤り E は全 500 件で 0。

main.cpp の冒頭 42 行のコメントに、この全体像と主要な関数の役割が英語でまとまっている。audit4-flip の冒頭にあった各版の変更履歴（約 190 行）は clean-base では削られ、経緯は trial_log.md だけにある。

1.3 重ね順の構造と模型

山の上から順に、[持ち上げた専用紙 D] → [据え置きの紙（あれば）] → 汎用層（6 枚） → [穴埋め紙（あれば）] → 列 0 → 列 1 → … → 列 33。待機中（注文の間）は、前の注文の D と穴埋め紙が列の外に出たまま残っている。

2.2 窓・ブロック・Y の山登り（choose_blocks）

最初に、どの 30 窓を汎用窓にするか、それを 6 窓ずつの 5 ブロックにどう分けるか、各ブロックの色 Yb を決める（choose_blocks() 317〜387 行。ブロック数は (G + 3) / 6 = 5）。

  • 対 (u, v) がブロック b と整合する ⇔ ブロック上の相対模様 x = A ⊕ Yb が入れ子（xu ⊆ xv か逆）。ラムダ best_y は、ブロックの局所模様ごとの目標数から部分和変換（zeta 変換）で入れ子の目標対を数え、整合する対の割合が最大の Yb を 26 通りから選ぶ。
  • 目的は Σb log（ブロック b と整合する目標対の割合）。対は触れる全ブロックで整合する必要があるので、使える対の割合はほぼその積になる。
  • 近傍は、2 ブロックの窓の交換と、汎用窓とハンドル窓の交換（30%）。3000 回。2 ブロックの交換の前に乱数を 1 回だけ空読みしている（使われなくなった近傍の名残。元と同じ乱数列を保つために残した）。目的値は audit4-flip で平均 −4.06（当時の stderr block_log_consistency。clean-base は出さない）。

(S, H) = (6 窓/ブロック, 34 列) は何度も測り直されて最良のまま（5.2 節）。clean-base ではどちらも定数で、H は 59 行、ブロックの窓数はこの関数の (G + 3) / 6 に埋め込まれている。

2.3 対と列の初期化

  • 列の大きさ（design() 231〜243 行）: 列 l の大きさ ∝ 1 + l を偶数に丸める。焼きなましの近傍は大きさを 2 ずつしか変えない（奇数だと色の交互が崩れて直しが増える。hub5 の節）。
  • 対の数: 186 枚で 256 目標を覆うので、対はちょうど 256 − 186 = 70 組。
  • 対の初期化（244〜271 行）: 全目標対を（整合しないブロック数 × 1000 + ハミング距離）の昇順に貪欲にマッチング。残りは焼きなましが組み替える。
  • 列への割り当て（272〜306 行）: 対は自分の列のハンドル hl で 2 目標が同じ色でなければならない（color_at() が −1 なら置けない）。各列に両方の色を最低 1 つずつ入れる。

2.5 山登り（filler_climb の proxy）

焼きなましの後、1.15 秒まで（828 行の t_end。CLIMB_ITERS > 0 なら回数固定）、同じ種類（対どうし・単独どうし）で両方のハンドルで色が同じ 2 単位の列を入れ替える（列の釣り合いと掘りは変わらない）。目的は「ハンドルの穴の正確な持続費用 − 0.3 × Σu proxy(u)」（kW 0.3、kH 0.51）。

  • proxy(u) = u より深い各列 c について、c の単位 y の紙を段付き（u との最も深い不一致の次の段）で置いたときに覆える u の三角形の穴の重み g から max(0, g − 3) を作り（filler_gain() の kT = 3）、列内で平均して足したもの。穴の重みは持続モデルで省ける直しの期待値 2(1 − pm(Au[m]))。
  • 注文ごとの回帰で proxy 1 単位は約 0.7 手（pool-climb の節）。入れ替えで変わるのは 2 列だけなので差分で評価する。終わったら、計画探索が使う多数派の色 bias_c と利得 bias_g を数え直す（967〜972 行）。
  • clean-base では、CLIMB_ITERS が 0 以下なら時間制になる（audit4-flip の「負なら山登りなし」の切り替えはない）。

2.6 予備の分割と紙の生成

3. 注文処理

3.1 1 注文の手順

1 つの計画は run_plan()（2114〜2204 行）が次の順で実行する（同時計画 fret_mode = 5 だけは run_joint() に任せる）。

  1. 後片付け: 前の D と前の穴埋め紙を、計画の選択肢に従って列へ戻す・新しい段へ移す・その場に残す（return_paper, refill_or_return）。前の D を据え置く計画（ret_mode 4）や、前の D を新しい D の穴埋め紙にする計画（ret_mode 3。level_for で段を決めて move_to_level）もある。
  2. 汎用層: D の汎用窓の穴が要求するブロックの向きに合わせる（set_blocks(wanted_blocks(u, holes))）。
  3. 持ち上げ前の穴埋め紙: 区間 DP で選んだ紙のうち、D の列の上端を隠さないものを置く（choose_fillers_prelift, place_filler）。
  4. 掘りと持ち上げ: D の列を D が上端になるまで回し（dig、平均 2.91 手）、D を位置 0 へ（lift がこの 2 つをまとめて行う）。
  5. 持ち上げ後の穴埋め紙: 区間が D の列のハンドルに届く紙（FillerPick::post）を置く。
  6. 直し: まだ色が違うハンドルの穴ごとに、その列を掘る（fix_handles → set_handle）。

D が前の注文の穴埋め紙として列の外にいるときは、掘りも戻しもせずそこから直接持ち上げる（run_joint の中。audit4-flip で 1 ケース約 5 回）。対の相方が続いて同じ紙が既に一番上なら、そのまま使う（keep。このときの穴埋め紙は choose_fillers_dp で選び、列の外の穴埋め紙が kMaxFillers = 8 枚に達したらそれ以上置かない）。

3.4 汎用層の先読み

汎用層の 6 枚の順序は 720 通り。build_abstract()（1182 行。焼きなましの冒頭で一度だけ呼ぶ）が、見えている紙の合法な手だけで状態のグラフを作り、全点対の最短路（blk_dist, blk_nxt）、各状態の向き（blk_disp）、向きの符号ごとの充足状態（blk_sat）とそこまでの距離（blk_dsat）を作る。want_costs()（焼きなましの費用表）も build_block_tables()（1325 行、紙の生成の後）もこの表を使う。後者は各状態から「設計の対の目標全部」へ行く手数の平均 blk_v を作る。set_blocks()（1360 行）は、要求の向きを満たす状態のうち最短のもの、同点なら blk_v が最小のものへ進む（1 段先読み。厳密な MDP と比べても差なし: audit3-mdp +0.002 ± 0.010%）。汎用層の上に紙が残っているとき（据え置き）は、その紙が覆う窓を除いた BFS（set_blocks_blocked, 1403 行）。予備の分割をしたケースは set_blocks_plain（1476 行）。1 注文の汎用層の手は run 010139 で 0.997 手（generic_moves / 1024。audit4-flip の計測では対の注文で約 1.8 手）。

3.5 穴埋め紙の区間 DP

ハンドルの添字 0…33 の上の区間 [lv, c] を候補（Cand）にした重み付き区間スケジューリング。DP 本体は best_intervals()（1737 行）にまとめられ、次の 3 か所が候補の作り方だけを変えて呼ぶ。

  • choose_fillers_prelift()（1798 行）: D を持ち上げる前に選ぶ（すべての列の上端が見えている）。候補は、D の列以外の各列 c の深さ p ≤ 3（kFillerDepth）の紙を、覆える穴がある各段 lv で置くもの（狭い段も含む）。利得 = 省ける掘り − 1 − p で、利得が 1（kFillerCost）以上のものだけ採る。さらに同じ段に 2 枚を重ねる候補（Stack）。区間が D の列のハンドルに届くものは持ち上げの後に置く（post）。
  • choose_fillers_dp()（1765 行）: D がすでに一番上の計画（keep）用。
  • run_joint()（1992 行、fret_mode 5）: 前の D と古い穴埋め紙（置き直しの利得 = 省く掘り − 0.5（kRelevel）、その場に残す利得 = 省く掘り + 1 − 0.8（kStay））と新しい穴埋め紙を 1 つの DP で選ぶ。
  • refill_or_return()（1930 行。DP ではない）: 古い穴埋め紙を新しい段へ（level_for、1907 行）。省く掘りが 2 以上なら移す。gen_harm()（1921 行）は、土台より上に残った紙が新しい D の汎用窓の穴で違う色を見せるなら残さない。

穴埋め紙を戻すときは前任のすぐ下へ戻して巡回順を保つ（上端・下端へ雑に戻すと +0.5〜8.6% 悪化した記録がある）。audit4-flip の free_return は return_paper に吸収された。その中の「前任が列の底のときの分岐」は、canonicalize が前任を −1 にするので発火せず（run 20261031-235016 の 500 件で 0 回）、clean-base では削られている。

3.6 二重の手の併合と記録の作り直し

  • merge_double_moves()（2246 行）: 計画の中で同じ紙を 2 回動かしていたら、1 回目で 2 回目の行き先へ直接動かすか 1 回目を省く。全手が合法で最終の重なりが同じものだけ採る（1 ケース約 20 手の節約、audit4-flip の計測）。
  • canonicalize()（2349 行）: 注文の後、列の外の紙の記録（持ち上げた紙、穴埋め紙の段と前任）を、紙の順序と巡回順 cyc（init_cycles()、2335 行）だけから作り直す。各列の在位の紙は初期順の回転なので一意に決まる。記録の取りこぼしで捨てていた計画を拾えるようになった（audit4-）。clean-base では常に呼ぶ（切り替えはない）。
