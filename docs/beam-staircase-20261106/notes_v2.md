# AHC074：階段完成型ビームの挙動分析と連動改善

## 結果

前回の構築が固定していた列容量・共有紙の占有位置・ハンドル順序を、完成後も同じ探索の中で変更するハイブリッドです。ビームで実行可能解を作り、既存 `esw-clean.cpp` の焼きなましを初期化し直して続け、補助紙の価値に基づく列交換、目標のハンガリアン再割当を行います。純粋なビーム探索だけの改善ではありません。

| 解法 | 添付100ケースの平均 | 総操作数 | 独立チェッカーの誤り／不正操作 |
|---|---:|---:|---:|
| 前回ビーム | 10.263828125 | 1,051,016 | 0 / 0 |
| 今回・品質優先 | 10.09685546875 | 1,033,918 | 0 / 0 |
| 今回・軽量 | 10.1197265625 | 1,036,260 | 0 / 0 |
| 既存 esw-clean.cpp | 10.09322265625 | 1,033,546 | 0 / 0 |

品質優先版は前回比0.16697265625手、1.6268%改善。91勝9敗です。既存解法には49勝51敗、平均で0.0036328125手負けています。既存最良を安定して更新したという結論にはなりません。

調整では主にseed 0〜4を使いましたが、構造・操作の観察には100ケース全体も使っています。したがって、seed 5〜99を完全に未使用のホールドアウトとは呼びません。

| 今回・軽量 | 10.137825520833333 | 311,434 |
| 既存 esw-clean.cpp | 10.123860677083334 | 311,005 |

いずれも誤り0・不正操作0。品質優先は前回に27勝3敗、既存に19勝11敗です。既存との差のケース単位正規近似95%区間は約[-0.0077,+0.0917]手（正なら改善）で、0を含みます。追加30ケースだけを根拠に明確な優位を主張しないでください。

## 観察から分かったこと

前回ビームは全ケースで列容量が
`2,2,2,3,3,3,4,4,5,5,6,6,7,7,8,8,9,9,10,10,11,11,12,12,13,13`
に固定されていました。後ろの約4分の1の列を使う注文の掘り出しは平均4.3854手。既存解法では同じ相対位置で3.9780手でした。末尾列の単独紙の初期深さも前回7.5258、既存6.6439で、後ろに寄せすぎていました。

単に印刷するbit数を増やすと、後ろの列へ紙が集まり、取り出しが高くなります。今回の品質優先版は、最上位の商品紙の可視担当bit数が45.6430から45.0787に減っていますが、手数は改善しました。「濃い紙を作るほど良い」わけではありません。

100ケースの操作ラベル（生成時の由来を後処理にも引き継いだ分類）：

| 分類 | 前回 | 今回・品質優先 |
|---|---:|---:|
| 主紙掘り出し dig | 3.0660742 | 2.7917090 |
| ハンドルの色合わせ fix | 1.7563086 | 1.7562109 |
| 共通紙の移動 gen | 1.2228223 | 1.2061328 |
| その他 | 4.2186230 | 4.3428027 |

掘り出しを0.2744手減らせた一方、返却・後処理などが一部を相殺しています。これは厳密な因果分解ではなく、操作生成時のラベルです。元のラベル付き出力を `results/diagnostic_*` に保存しています。

## 採用した探索

窓の配分は前回と同じく、共通37・ハンドル26・キャップ1。紙は共通6・キャップ1・主紙185（71ペア＋114単独）です。

1. 上から階段順序を選ぶ完成割当ビームで実行可能な全体解を作る。
2. ビームの紙を `Design` に取り込み、容量、列位置、目標ペア、ハンドル順序を同じ焼きなましの状態として動かす。ペア＋単独2枚を別のペア＋単独2枚に置き換える近傍も再利用する。
3. 補助紙として使える列先頭を改善する列交換を行う。
4. 既存のハンガリアン再割当を4回行う。
5. ハンドル順序の変更を物理的な紙の模様と solver の `handle` に反映し、列ごとに白黒の先頭と使用頻度を考慮して並べ直す。
6. 注文処理は既存の検索設定F3_MODE=2を既定にする。

主要設定：

| 設定 | 品質優先 | 軽量 |
|---|---:|---:|
| 初期ビーム幅 | 2 | 1 |
| 段ごとの候補数 | 5 | 3 |
| 連動焼きなまし回数指定 | 14,900,000 | 4,000,000 |
| 補助紙の列交換回数指定 | 154,000 | 154,000 |
| 目標再割当 | 4 | 4 |
| 注文探索設定 | F3_MODE=2 | F3_MODE=2 |

軽量版の幅1は、完成案評価を伴う逐次選択です。多数状態を維持するビームではありません。既存の焼きなまし・注文処理・比較器を再利用しており、それらを新しい発明として主張するものではありません。

## 不採用案と限界

容量の自由化だけ、共有先を全アンカーへ再割当する探索、列先頭の単独紙をより重視する評価、穴のまとめ開けビーム、掘り出し紙の即時再利用、深いハンドルを高く評価する重み、共通紙の第三色紙追加などを試しました。今回の小規模比較では、採用構成を明確に上回る安定した改善にはなりませんでした。3目標共有も確認しましたが、seed 0の固定した共通層には実現可能な三つ組がありませんでした。一般に3目標共有が不可能という意味ではありません。

76設定・370ケース実行の探索ログ集計を `tuning_summary.csv` と `tuning_configs.json` に保存しています。これは主に3〜5ケースの探索的比較です。探索段階すべてに独立チェッカーを適用したわけではなく、誤り0・不正操作0の主張は最終ベンチマークのケース集合についてです。研究コードは `research/` に保存しています。最終ソースは不採用の構築関数を除いています。

純ビームの初期構築が、既存解法の初期構築より強いと実証できたわけではありません。今回の確実な成果は、前回の固定容量に由来する弱点を取り除き、前回比0.14〜0.17手の改善を再現したことです。

## 実行時間

同時実験・コンパイルを止め、診断なしビルドを一括入力で単独実行した6ケース（0,1,2,3,4,99）です。

| プロファイル | 平均実測壁時計時間 | 最大 |
|---|---:|---:|
| 品質優先 | 2.8368 秒 | 2.9276 秒 |
| 軽量 | 1.8065 秒 | 1.8901 秒 |

品質優先版は2秒制限を超えます。軽量版はこの6ケースでは2秒未満でしたが、本番環境・全ケースでの時間制限順守を保証しません。時間超過を防ぐ打ち切りは未実装です。対話検証の壁時計時間にはPythonチェッカー待ちも含まれるため、上の計測とは分けています。

## 検証

Pythonチェッカーは全操作の可視性、添字、操作数、紙の文字列、全64bitの最終表示、余分な出力を確認します。公式Rustテスタはこの環境では実行していません。

診断付き最終ソースは品質・軽量とも、調整版と100ケース全出力が一致しました。診断なしビルドも別に全130ケースを独立検証しています。上表は通常ビルドの数値です。追加30ケースの17番だけ、品質優先版の通常ビルドは診断付きより1手多い結果でした（10,276対10,275）。ビルド条件により同手数の別操作列が選ばれることがあるため、全ビルドで操作列が一致するとは主張しません。結果は `release_verification.json` を参照してください。

seed 0,50,99は、注文を一つずつ送る対話方式でも両プロファイルを検証しました。構築時に未来の注文を渡していません。実際のC++コードも、紙を出力・flushした後で注文を読み込みます。

## コンパイルと再現

品質優先：
```sh
g++ -O3 -std=c++20 -march=native staircase_beam_v2.cpp -o solver
```
軽量：
```sh
g++ -O3 -std=c++20 -march=native -DBEAM_FAST=1 staircase_beam_v2.cpp -o solver_fast
```
診断付きビルドには `-DLOCAL_BENCH` を追加します。環境変数による試験設定を残していないシェルで実行してください。

```sh
bash reproduce.sh quality official
bash reproduce.sh fast official
bash reproduce.sh quality extra
bash reproduce.sh fast extra
```
`WORKERS=3` は並列評価、`DIAGNOSTICS=1` は紙と操作のラベル出力を追加します。並列評価の時間は速度評価に使わないでください。

対話方式：
```sh
python3 benchmark.py --solver ./solver_fast --inputs inputs_official --results interactive_rerun --seeds 0,50,99 --workers 1 --interactive --save-output --timeout 90
```

全ケース比較は `comparison100.csv` と `comparison_extra30.csv`、操作の内訳・区間推定・留保は `evidence_summary.json`、独立検証結果と出力は `results/` にあります。
