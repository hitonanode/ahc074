## 2. 着眼点A: 最終状態の補助紙は「全部が同時に可視」でなくてもよい

`fillers_reachable()` の旧不変条件は「最上段の専用紙を除いたとき、全補助紙がそれぞれ見えている」。だが必要なのは、戻す**瞬間**に可視であること。別の補助紙を先に外せば見えるようになる紙は残して構わない。

- 現在の最上段専用紙は次注文の処理で最初に戻せる前提とする。
- 補助紙集合をpendingとし、上から全紙を走査。pendingのうち現時点で可視の紙を選択し、取り除いたものとして次走査でスキップする。
- 全部取り除けるなら合法な返却順が存在する。各moveの可視性チェックは別途行う。
- 返す時も、その時点で見えている補助紙を選んで順次 `adaptive_insert` する。適応的な戻し先はこの列構造を破壊しない位置に制限する。

この制約緩和は `solutions/gpt6pro-10-01-filler-chain` と `solutions/imp10-hidden` などの既存工夫と重複する。独立した新発明として扱わない。

## 3. 着眼点B: 最短手数の「汎用終状態」に対する一段先の期待距離

汎用6枚は (6!=720) 通りの順序がある。generic窓は2紙の大小で色が決まる比較器なので、商品uの共有紙が穴の窓で要求する大小関係はDAGとして表せる。合法な終状態はこれを満たす720順列の部分集合 (mathcal{G}_u)。

最下段紙は、汎用層を連続に保持しているとき比較器の構造上見えないため、任意順列への移動にLCS距離を使うのは誤り。最下段以外の可視紙だけを1回動かす有向グラフ上の最短距離 (d(s,t)) をBFSで前計算する。

各順序sに対して

[
V(s)=rac{1}{256}sum_{u=0}^{255}min_{tinmathcal{G}_u}d(s,t)
]

を計算し、**今の注文への最短操作数を維持する範囲で** (V) の小さい目標順序に遷移する。全商品に対する逆向き多点BFSを720状態で実行すれば計算が安い。現在の商品を次の商品から除いても、(d(s,mathcal G_u)=0) なので順位に影響しない。

`Comparator::plan()` の先頭で有向合法距離の候補を列挙し、同率の終状態を `future_value` で選ぶ。これは将来の**generic層のみ**を見積もる1-step tie-break。専用紙・取っ手・補助紙に関する将来費用は評価していない。

## 4. 着眼点C: 既存2手を除き、別の見えている紙の1手で修復

操作列は固定した終順序そのものを実現する必要はなく、**表示だけ**が合えばよい。元の `post_optimize` はアンカー（紙kを紙aの直後へ）表現により一手削除、二手削除、アンカーの付替え、二手削除後に一手修復する`eject`を持つ（`solutions/imp-post`で既に実装済み）。

再構成では `eject`の候補挿入位置の探索幅を広げ、可視紙kを一度抜いた際の表示と要求との差を64bit maskで判定する。紙を抜いた後の表示を `B_0` として、誤り集合 `bad = B_0 XOR A_u` が紙kのopaque窓に含まれ、しかも紙kがそこで正しい色を出せなければ候補を棄却する。今の正しい表示をkが壊す窓は、抜いた残りの紙より**下**に入れる必要があり、`bad` を修正する窓は対応する紙より**上**に入れる必要がある。これで挿入位置の合法区間 `[lo,hi]` を求める。

各候補では操作列を開始時のorderから再生し、可視性・表示・汎用層の連続性・補助紙の回収可能性を検証する。基準の評価

[
C=m+Phi,quad Phi=0.6cdot(	ext{補助紙数})+1.0cdot(	ext{次注文の推定コスト})
]

のほか、ejectにはより厳しい `m+2 Φ` の判定を設ける。今の一手削減で次の注文が大幅に悪化する候補を回避する意図。これは厳密なvalue functionでなくヒューリスティック。

重要: 今回再構成したコードは `imp-post` の候補生成を拡張しているが、前回説明したprefix/suffixで全挿入位置をO(1)に判定する最適化まで**同一コードだと確認していない**。実装・時間を確認するまで、同等の速度を主張しない。
