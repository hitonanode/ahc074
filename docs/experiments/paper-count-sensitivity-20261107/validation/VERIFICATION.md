# 検証記録と限界

このディレクトリの数値は、会話に添付された実験アーカイブに保存された1,300ランの結果から作成しました。原実験の全生stdout/stderrはGit管理外で、約45MiBの添付ZIPに保存されています。

- 同じ100ケース（seed 0..99）、各1,024注文、全13水準、全1,331,200注文・13,491,597操作を独立C++再生検証し、誤表示・不可視紙の操作・範囲外挿入・2K上限違反・余剰出力いずれも0。
- K=192の可変枚数ソースは提供された元コードと、10ケースの模様・全注文操作列において標準出力がバイト一致。
- 各Kでseed0の一括実行と、次の注文を出力後に供給するreactive実行が一致。
- `tools/in/0000.txt`, `0001.txt`, `0009.txt`, `0099.txt` のGit blob SHAが原実験の入力と一致。残るseedの同一性はリポジトリの同じ公式生成器によることに基づき、GitHub上で全100のblobを個別ハッシュ照合したわけではない。
- 全水準で比較窓G=38に成功し、窓割当の再試行・非常用設計は未使用。
- 公式Rustテスタを走らせたのではなく、同梱のC++独立実装で再生した。実行時間は4並列・AMD EPYC 9V74・フル固定反復。公式2秒制限内の完了は保証しない。
- Kを公式の192以外に変更しているため、この研究でK>192の優位性は提出可能な実績ではない。汎用紙6枚を固定しておりM=5/7の直接比較でもない。
