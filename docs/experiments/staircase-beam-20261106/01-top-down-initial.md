# 第1段階：全目標の残余bitを上の紙から覆う初版

**史料の範囲**: この段階の数値・設計は2026-11-06の会話中の報告に基づく。初版ソース・生出力・CSVは今回アクセスできる添付物に含まれていないため、この節の数値は再実行・再集計したものではない。後続2段階と同じ検証条件だとは主張しない。

## 要求された構築仮説

- 紙を上側から順にビームサーチで決める。
- 各目標 `t` について、まだ塗り切れていないbitの集合 `R[t]` を追跡する。
- 新しい紙の不透明マスク `M`、黒マスク `C`、目標模様 `A[t]` に対し、未充足位置での誤色を許さない: `((C XOR A[t]) AND M AND R[t]) = 0`。
- その紙の寄与は `popcount(M AND R[t])`。寄与下限より小さい目標をその紙の受益者に数えない。下限は構築後半ほど上げる。
- 採用目標について `R[t] = R[t] AND NOT M` とする。上の紙で隠れた位置に対する下の紙の色は自由。
- 初期の紙は少数のbitを疎に覆い、後半は残った目標に密に対応していくことを期待した。外側に紙列候補を保持するビームも試した。

## 観察・結果（当時の報告値）

最初の素朴な方式は192枚を使っても126目標が未完成。隠れる位置の自由度を生かすと全256目標を完成できたが、目標あたりの使用紙は平均8.43枚。被覆数を強く追った別設定では、使用21.95枚／31.66手まで悪化。

初期の収納方式はseed 0で約49手、構築順と収納段を分離して約19.77手、さらに構築・操作を調整して約15.99手に改善した（この系列は単一ケースの調整中の値）。

固定設定の報告:
|設定|ケース|平均操作数/注文|表示誤り/不正操作|
|---|---:|---:|---|
|品質寄り|100|16.01297|0 / 0|
|高速|100|16.13713|0 / 0|
|外側ビーム幅2|20|15.96831|0 / 0|

外側ビームの比較は同一20ケースで16.02993→15.96831（-0.06162手）だった。上記100ケースと20ケースの数値は直接比較しない。高速設定の内部実行時間は100ケース平均1.20秒・最大1.38秒（当時の実行環境での測定）。

## 反証された仮説

**被覆総量の最大化は実手数の良い代理指標ではない**。目標あたりの紙枚数と、その掘り出し・戻し・他窓修復が支配的だった。下限だけ強くすると少数の残余bitを持つ目標が完成しづらい。
