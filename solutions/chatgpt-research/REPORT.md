# [ChatGPT] 均衡先着ゲート・冗長専用紙の検証報告

2026-11-02 JST。マージを目的としない研究用報告。

## 結論

**今回、`imp-gla` を圧倒する解法は得られていない。** 新しい表現を実際に使う C++ 解法を二系統実装し、同じ生成ケースで比較した。探索を続けるなら優先するのは、汎用層を「2枚比較の集まり」から**入力に合わせて選ぶ均衡先着ゲートの符号ブック**へ広げ、ゲートと商品対のマッチングを同時に最適化する方向である。

根拠は単なる候補数の増加ではない。4枚・2白2黒のゲートは、2枚比較では表せない相補パターン対を実際に表せる。ただし、その表現力をスコアへ変える設計器はまだ弱い。後付けで単独紙を穴の多い共有紙へ変える冗長化は、今回の実装では不採用とする。

以下では、実測、構成的な証明、未実装の次案を区別する。新しい窓が一つも採用されなかった対照実験や、実行時間の配分だけで良くなった対照を、新原理の改善として扱わない。

## 2. 主提案: 均衡した多者先着ゲート

### 2.1 何を変えるのか

現解法の汎用窓は、黒の紙aと白の紙bの先後、すなわち `a < b` で色が決まる。ある商品対の違う窓を共通専用紙の穴にすると、その商品の表示条件は有向グラフの辺の集合になる。閉路があれば、その商品対は同じ紙を共有できない。

新しい窓は、黒の集合Bと白の集合Wのうち、一番上の紙の色で決める。特に `|B|=|W|=2` を使う。

```text
黒が出る条件: min(rank(B)) < min(rank(W))
```

黒にしたいときに勝つ紙を二つから選べ、白にしたいときも別の二つから選べる。一つの比較関係に固定されない。この違いにより、従来の比較器では互換でない商品対を互換にできる。

6枚の紙では、向き付きの2枚比較は30種類しかない。4枚・2白2黒は `C(6,4) C(4,2)=90` 種類、6枚・3白3黒は20種類あり、比較器も含む均衡した特徴関数は140種類になる。一様な順序での出力は、どれも白黒1/2である。

### 2.2 表現が本当に増える構成例

3窓をそれぞれ `a<b`, `b<c`, `c<a` とする。左の紙が黒、右が白である。このとき111も000も閉路になり表示できない。

第1窓だけを黒 `{a,d}`、白 `{b,e}` に変えると、

- `d,b,c,a,e` で111を表示できる。
- `e,a,c,b,d` で000を表示できる。

両パターンを1枚の共通紙の穴から表示できるようになった。独立プログラム [`gate_witness.cpp`](gate_witness.cpp) で6枚の全720順序を列挙した結果、2枚比較では両方0状態、4枚ゲートでは各24状態が得られた（[`gate_witness.json`](gate_witness.json)）。

3枚目を1枚だけ加える方式は性質が異なる。追加紙と逆の色を要求する側には元の比較制約が残るため、他の窓が2枚比較のままなら、1窓変更だけで元から不可能だった相補対を可能にはできない。実際、この例でも3枚ゲートは片側だけ30状態、反対側は0状態だった。4枚を本命にする理由は、この両方向の自由度である。

### 2.3 実装した解法

[`chatgpt-structure/main.cpp`](../chatgpt-structure/main.cpp) は `imp-gla` を基にするが、専用紙の商品対を決める**前**に汎用層を変える。

1. 15組の紙対について、従来の比較窓を1個ずつ保存する。どの順序でも、最下段以外の5枚は少なくとも1窓で見える。このため合法移動のグラフと最短距離は厳密に保たれる。
2. 残り21窓から3窓を選び、均衡4枚ゲートに変更する。正式評価設定は `GATE_ARITY=4 GATE_COUNT=3 GATE_FULL=1` で、各窓の90候補を全て比較する。
3. 候補ごとに全720順序の表示を計算する。距離26以下の商品対について、両側に充足順序があるかと充足順序数を調べ、ハンドル差を加えた費用で70組を貪欲に選ぶ。
4. ゲートを決めた後、専用紙の対と列を改めて設計する。この段階の互換性と汎用移動費用は、実表示と合法距離から正確に計算する。注文時の最短路・補助紙・先読みも実表示を使う。

この試作は表現を実際に変える実験なので、代理目的が悪くても指定の3窓を変更する。既存比較器へ戻して成績を隠す構成にはしていない。逆に、3窓の位置は固定の選び方であり、全21窓、窓の割り当て、商品対、列配置を一体の探索にはしていない。

多者の模様そのものは、既存 `trial_log.md` の `bold-probe` でもランダム割り当てとして調べられている。今回の差分は、**入力依存の均衡特徴選択、可視性を守る15窓、商品対の選び直し、実表示による正確な評価**を実動ソルバーにした点にある。

## 4. 別案: 同じ商品への複数の専用紙

[`chatgpt-novel/main.cpp`](../chatgpt-novel/main.cpp) は、元の単独商品aの紙に商品vの担当を加え、共通部分だけを印刷する。vは元の紙と追加紙を選べる。二候補がある注文は、同じ現在状態から両方の合法な操作列を実際に計画し、手数と次注文の費用で選ぶ。

## 5. 次に育てるなら何をするか

### 5.1 ゲートとマッチングを一緒に動かす

次の実装候補は、現比較器を初期点とし、2枚・4枚・6枚の均衡ゲート全140特徴、窓の対応、商品対を同時に探索するもの。

- ゲート1窓の変更で壊れる対を取り除き、増大路や交互路でマッチングを修復する。全商品の可解性を守ったまま新しいペアへ移る。
- 充足順序数だけで評価せず、最寄り充足順序への合法手数と、ハンドルの穴・列からの取り出しを評価する。現在の代理目的には、貪欲マッチングの不足1組につき1000の罰があり、実際の後段設計と評価の食い違いが大きい。
- 変更窓の位置を固定せず、変更する窓と新特徴を同時に選ぶ。今回の3窓強制変更より大きい自由度を正しい目的で使う。
- 各特徴の720状態での出力を12個の64bitワードで保持する。商品対が各窓に課す条件もbitsetなので、窓ごとの積のprefix/suffixや木を持てば、変更した1窓を除いた充足集合を高速に得られる。全720状態を毎回一から走査する必要はない。この更新器は今回の解法には未実装。

この拡張の探索空間は現解法を含み、構成例では真に広い。しかし有限の探索時間で良い解を発見できるか、ランダムな本番入力で実益が出るかは未確認である。次の採用条件は、反復数を揃えた未使用ケースで差が負になり、通常設定でもその効果が残ること。今回はそこに到達していないので、現在の最強解法を置き換える提案ではない。

### 5.2 7〜8枚へ拡張するときの距離表を圧縮する

ここでは確実に使える計算上の結果が得られた。最下段だけが不可視な汎用層では、紙番号の付け替えは合法移動グラフの同型写像になる。順序を位置から紙番号への置換p、qとすると、

```text
dist(p, q) = dist(id, p^{-1} ∘ q)
```

である。恒等順序からのBFSを1回行い、相対順列で距離表を引けばよい。親と操作も保存し、経路の紙番号iをp[i]へ戻すと、任意の始点からの最短路を復元できる。距離は有向であり、対称性を仮定していない。

| 汎用紙枚数 | 状態数 | 単一BFSの辺数 | 距離配列だけ | 全状態対の距離配列を持つ場合 |
|---:|---:|---:|---:|---:|
| 6 | 720 | 18,000 | 720 B | 518,400 B |
| 7 | 5,040 | 181,440 | 5,040 B | 25,401,600 B |
| 8 | 40,320 | 1,975,680 | 40,320 B | 1,625,702,400 B |

親・操作・順列一覧等の記憶は別途必要だが、これらも状態数に比例する。[独立検証](../chatgpt-structure/permutation_metric_probe.json)では、2〜6枚の**全533,416状態対**について既存全始点BFSとの距離一致・各操作の合法性・終点一致を確認した。7枚と8枚も全状態への恒等順序からの経路を確認した。

これは表の計算と記憶の問題を解消する結果であり、枚数を増やせば点数が上がるという結果ではない。既存のtrial_logでは2枚比較の7枚構成は悪化している。多者特徴との組み合わせ、設計時の多数の部分目標に対する平均距離の計算、注文時の候補探索は別の研究課題として残る。

## 6. 捨てた仮説: 6枚で任意8商品の完全符号化

`3^6 > 2^8` という模様の個数だけを根拠に、6枚の順序で任意8商品を表せるとは言えない。紙枚数m、順序πでの紙iの順位rについて `x[π,i]=3^(-r)` と置く。窓の紙iが黒・穴・白なら、それぞれ `w_i=+1,0,-1` とする。先頭の非穴の項が後続の項の絶対値の和より大きいため、

```text
黒が表示される ⇔ Σ_i w_i x[π,i] > 0
```

である。従って窓で実現できる色関数は、m次元の同次線形分類器の部分族であり、任意に色分けできる状態の数は高々mである。

直接には、m+1個の状態ベクトルに正負両方の係数を持つ線形従属関係を取る。正係数の状態を黒、負係数の状態を白と指定すると、wとの内積を取った従属関係が正になり、0であることに矛盾する。よって6枚で8状態の全256ラベルを表現する万能な構成は不可能。

入力の64窓で実際に現れる高々64種類のラベルだけを表せる可能性は否定していない。ただし、それだけで64窓を十分に表せるという見積りもまだない。この仮説は今回の提出用解法にはしていない。

Rustの公式テスターを使える環境では、同じwrapperへ `--official-tester` を追加する。元の `scripts/pahcer_run.py` の `ensure_tester` がRust版をビルドし、生成ケースの番号範囲とログ保存はそのまま使用できる。今回の環境ではRust版そのものの実行はしていない。公式0〜7については通常の `scripts/pahcer_run.py --compare ... --seeds 0-8` でもよい。

```sh
GATE_ARITY=4 GATE_COUNT=3 GATE_FULL=1 \
python3 solutions/chatgpt-eval/run_compare.py --official-tester --threads 2 \
  --compare solutions/imp-gla solutions/chatgpt-structure \
  --seeds 100000-100064 --no-record -c 'balanced gates; official Rust tester'
```

固定反復の初期run `20261101-072636` と `20261101-072955` は、終了時の正常スコアに対して保存されたstdout/stderrが途中で切れる不整合があり、正式結果から除外した。原因の詳細は未特定である。wrapperを「終了までメモリへcaptureし、完成したログをatomic replaceで保存」へ変えて再実行したところ解消し、再実行のスコアは一致した。正式結果には、保存済み全出力を再生できたrunだけを使っている。
