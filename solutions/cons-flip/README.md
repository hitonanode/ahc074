# cons-flip

改良元: solutions/cons-stack

汎用層の反転紙の模様を変え、オンとオフが混ざった向きの注文を安くした。対の整合（どの対を作れるか）は変わらない。あわせて、焼きなましの汎用層の費用を、新しい形での方策の模擬から求めるようにした。

## 紙の形の変更

- これまでの反転紙 F_b は、自分のブロック b だけで不透明（色 ~Y_b）だった。cons-flip では、ブロック b の反転紙が、番号の小さいブロック c < b でも、土台と同じ色 Y_c で不透明になる。
- ブロック c は、c を覆う紙のうち一番上が自分の反転紙ならオン（~Y_c）、そうでなければオフ（Y_c）を見せる。反転紙 b を上へ動かすと、b がオンになると同時に、b より下の番号のブロックが 1 手でオフになる。
- オンにしたいブロックの反転紙を番号の大きい順に土台の上へ積めば、32 通りの向きをすべて出せるので、対の整合は変わらない。方策の模擬（solutions/cons-probe/flipsim.cpp）では、向きのそろった注文は少し高く（1.0 → 1.4〜1.5 手）、混ざった注文は安く（2.0〜2.8 → 1.9〜2.15 手）なり、対の注文の平均は 1.92 → 1.79 手になる。
- ブロックを分割して 6 個以上になったケース（まれ）は、元の形（反転紙は自分のブロックだけ）に戻す。

## 注文処理の変更

- audit2-blk の先読みの表（汎用層の紙の順の間の最短路と、次の対の目標の期待手数）を、新しい形の一般的な規則で作る: 紙は、自分が覆うブロックのどれかが上の紙に覆われていなければ動かせる。ブロックは自分を覆う一番上の紙の値を見せる。
- 専用紙が汎用層の上にあるとき（前の専用紙を残す計画など）は、元の手順の代わりに、その専用紙が覆う窓を除いた BFS で向きを合わせる（set_blocks_blocked。最短の中で次の対の期待手数が最も小さいものを選ぶ）。合わせられなければ、その計画を捨てる。

## 焼きなましの変更

- 費用がどのブロックをオンにするかに依存するので、cons-tab の表（触れた数 × オンの数）の代わりに、向きの符号（ブロックごとにオン / オフ / 触れない、3^5 通り）ごとの手数 wcost を使い、対は 2 目標の符号の費用の和にする。
- wcost は、焼きなましの前に、先読みの方策を合成の注文で模擬して求める（約 30 ms）。合成の注文は cons-tab で測った構成（対が触れるブロック数と向きの割合、単独の割合）に合わせ、8 組を作って平均する（1 組だとブロック間の偏りが出るため）。同点の終わりの状態は無作為に選ぶ。
- 焼きなましの 1/3 と 2/3 の時点で、そのときの対の向きを使って wcost を模擬し直す。

## パラメータと指標

- 環境変数 `FLIP_RESET`（既定 1）: 0 で元の形の反転紙。`WANT_SIM`（既定 1）: 0 で wcost を使わず cons-tab の表で見積もる。`WANT_SETS`（既定 8）: 合成の注文の組の数。`WANT_RESIM`（既定 2）: 焼きなまし中に模擬し直す回数。`WANT_RANDTIE`（既定 1）: 模擬の同点を無作為に選ぶ。
- stderr の `wcost_t<t>_on<k>`: 最初の模擬で求めた wcost を、触れたブロック t 個・オン k 個の符号ごとに平均した値（cons-tab の表 kBlkTab[t][k] に当たる）。
- 調査用: `WCOST_PROBE=1` で、ブロックに触れる注文（対の注文）について、選んだ計画の汎用層の実際の手数（`wp_mv_t<t>_on<k>`）、それと最後に模擬した wcost との差（`wp_res_t<t>_on<k>`）、注文の数（`wp_cnt_t<t>_on<k>`）を出す。`WCOST_DUMP=1` は 5 ブロックのうち 1 つだけオン / 1 つだけオフの符号の費用を並べて出す。
- それ以外の stderr の指標は cons-stack と同じ。
