# hub5

改良元: solutions/hub4

対の組み方と、単位（単独の目標か対の紙）を置く列を、手数の見積りを最小にする焼きなまし（anneal_units）で決めるようにした。hub4 の貪欲な割り当ては焼きなましの初期解になる。

## 変更点

- 見積り（全目標が同じ頻度で来るとして、1 目標あたりの手数）:
  - ハンドル窓の穴 1 個 0.51 手。列 l の単位は、より深い H−1−l 個のハンドルが穴（三角形）。対ならさらに、浅いハンドル h_0..h_{l−1} で 2 目標の色が違う窓も穴。
  - G の穴（対の 2 目標が違う G の窓）1 個 0.45 手。
  - 掘り: 列の大きさ n に対して平均 (n−1)/2 手。
  - 対は 2 目標分を数える。列の中でハンドル窓の白と黒の数の差が 2 以上なら 1 につき 50 の罰（色が交互にならない）、片方の色がない列は禁止。対は自分の列のハンドル窓で色が一致していなければならない。
- 近傍（既定）: 2 単位の列の入れ替えと、2 単位の間で目標を 1 つ交換する対の組み替え（列は保つ）。単位を別の列へ移す近傍も実装してあるが、既定では使わない（列の大きさが奇数になると色の交互が崩れ、見積りは下がっても実測が悪化するため）。
- 反復は 300 万回で、温度は 3.0 から 0.05 へ指数的に下げる（乱数の seed は 777）。
- 列の大きさの傾き `HUB_SLOPE` の既定を 0.3 → 1.0 にした（深い列をより大きく）。

## パラメータと指標

- 環境変数（hub4 のものに加えて）: `HUB_ANNEAL`（反復回数、既定 3000000）、`HUB_MOVES`（使う近傍のビットマスク。1 = 単位の移動、2 = 列の入れ替え、4 = 組み替え。既定 6）、`HUB_IMB`（色の偏りの罰、既定 50）。
- stderr に足したもの: `model_cost_before` / `model_cost_after`（焼きなまし前後の見積り。1 注文あたりの手数）、`model_dig` / `model_handle_holes` / `model_g_holes`（焼きなまし後の見積りの内訳: 掘りの手数、ハンドル窓の穴の数、G の穴の数。いずれも 1 注文あたり）。
