# 汎用紙の間に共有紙を挟む構造の検査

改良元: なし（`solutions/imp-combo` の出力を読む解析用プログラム）。

`probe.cpp` は提出用解法ではなく、設計済みの 6 枚の汎用紙について、
「2 商品が異なる窓も共有紙に印刷し、必要なら共有紙の上に汎用紙を置く」
という拡張が、新しい共有可能な商品対をどれだけ増やすかを厳密に数える。
対象は汎用窓上の静的な表現可能性であり、ハンドル窓の表示や、紙を操作する途中の
合法性・手数は評価しない。

通常の共有紙は、2 商品が異なる汎用窓をすべて穴にする。
このとき共有可能性は、その差分に対応する比較器の有向グラフが DAG かどうかで決まる。
拡張案では、共有紙の穴・白・黒を自由に選び、各商品について汎用紙の順列と
共有紙を挟む位置も自由に選ぶ。6! 通りの順列、7 通りの位置を列挙するので、
固定された汎用紙に対する静的な表現可能性の検査は厳密である。

順列による汎用表示を B、共有紙より上の汎用紙が覆う窓を C とする。
商品 A の表示には `(B xor A) & C == 0` が必要。
商品 u, v の構成 `(B_u,C_u)`, `(B_v,C_v)` が同じ共有紙を使える条件は、
差分 Δ = A_u xor A_v に対して
`(B_u xor A_u) & Δ & ~C_v == 0` と
`(B_v xor A_v) & Δ & ~C_u == 0`。
この条件から共有紙も構成し、両方の商品を表示できることを検査する。

片方の C が空なら、もう片方の汎用順序は Δ の全窓でその商品の色を出す必要がある。
比較器の順序を逆にすれば相方の差分も出せるため、その対は通常の DAG 条件でも共有できる。
したがって、**新しい対が増えるには両商品とも共有紙より上に汎用紙を置けることが必要**。
その一番上の汎用紙は、不透明な汎用窓の全部で商品と一致しなければならない。
この必要条件で検査する対を絞り込み、最後は上の条件で厳密に判定する。
さらに、この拡張でも新しい対は増えないことを有向閉路から証明できる。
証明と検査結果は `REPORT.md`、各ケースの数値は `results.csv` に記す。

実行例:

```sh
g++ -std=c++23 -O2 solutions/chatgpt-layer-probe/probe.cpp -o /tmp/layer-probe
/tmp/layer-probe tools/in/0000.txt runs/RUN_ID/out/0000.txt
```

`input` と `output` は必ず同じ生成ケースの組を渡す。
第 3 引数で汎用紙の枚数も指定できる（既定 6、上限 8）。
出力は CSV 1 行。近い対は既存解法と同じハミング距離 26 以下で数える。
新しい共有対が存在しても、そのまま手数改善を意味しない点に注意する。

今回の列挙値を再現するため、`designs/0000.txt`〜`0007.txt` に対象runの先頭6枚を保存した。
解析器が読むのはこの6枚だけなので、たとえば次でcase 0の数値を再現できる。

```sh
/tmp/layer-probe tools/in/0000.txt solutions/chatgpt-layer-probe/designs/0000.txt
```

入力は `solutions/chatgpt-study/generate.py` のseed offset 20261102版を使う。
