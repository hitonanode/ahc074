# audit4-fix

改良元: solutions/audit3-stack

列の外にある紙の記録（どの紙が列の外か、穴埋め紙の段、列へ戻すときの巡回順の前の紙）の取りこぼしを直した。紙の設計と計画の種類は audit3-stack と同じ。

4 回目の監査（solutions/audit4-tools）では、選んだ計画の途中の各時点で重なりから状態を作り直し、合法な 1 手を足して計画探索をやり直した。良い計画が見つかった注文の最大の種類は、計画ではなく記録の誤りによるものだった。

## 変更点

- 汎用窓の害（gen_harm）: 前の専用紙を残す計画（ret_mode 4）で土台より上に残った紙は、次の注文の専用紙の汎用窓の穴に自分の色を見せる。これまでは、この紙を段 0 へ置き直す候補が「もう列 0 より上にある」として動かさず、害のない据え置きの判定も汎用窓を見ていなかったので、残す計画がすべて表示の不一致で捨てられ、紙は列へ戻されていた。今は、汎用窓で目標と色が違うときは、置き直しで汎用層の下へ動かし、その場に残す候補には入れない。
- 両端への戻し（free_return）: 列の外の紙は、列の色の交互を保つため、巡回順の前の紙のすぐ下へ戻していた。その後の掘りで前の紙が列の下端になっていれば、この紙は巡回順で下端と上端の間にあるので、上端へ戻しても順は保たれる。このときは計画の戻し方（上端 / 下端 / hub7 の規則）に従って戻す（掘りを 1 手省ける場合がある）。
- 記録の作り直し（canonicalize）: 毎注文の後に、列の外の紙の記録を重なりの順だけから作り直す。どの計画も各列の巡回順を保つので、順から「どの紙が列にあるか」「穴埋め紙の段（すぐ下にある列の紙の列）」「巡回順の前の紙」が一意に決まる。計画が残した記録との違いは次のとおり。
  - 前の紙が下端なら、両端へ戻せる紙として記録する（上の free_return）。
  - すぐ前の紙が列の外にあれば、列にある最も近い前の紙の下へ戻す。
  - 自分の列の上端に巡回順どおりに乗っている紙は、列の外でなく列にあるとみなす。
  - 順が巡回順として解釈できなければ、記録はそのままにする。

## パラメータと指標

- 環境変数 `GEN_FIX` / `PRED_BOTTOM` / `CANON`（既定 1 / 1 / 1）: 0 でそれぞれ gen_harm / free_return / canonicalize を使わない。
- stderr の `canon_fail`: 記録を作り直せなかった注文の数。`canon_change`: 作り直しで記録が変わった注文の数。`pb_try` / `pb_top`: 前の紙が下端だったので両端のどちらかへ戻した回数 / そのうち上端へ戻した回数。`gh_try`: 汎用窓の害があると判定した回数。この 3 つは計画探索で試した計画（選ばれなかったものを含む）での回数。`req_sec`: 注文の計画にかかった時間の合計（注文の入力待ちを除く）。`end_sec`: 終了時刻。
