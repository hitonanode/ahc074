# 注文処理の整理

改良元: `solutions/time-alloc`。設計固定元: `20261105-141234_time-alloc`。

**結果:** 担当領域4,590→4,199行。通常2000件は+0.000789 ± 0.000977%、固定2000×2は+0.001234 ± 0.000690%で両方の許容条件を満たす。req_secは通常4.03%、固定3.57%短縮。全てWA・self_wrong・op_label_errors=0。

## 範囲と検証方法

注文処理の指定された段だけを編集する。ヘッダ目次、Common、Comparator、PosetSums、Interleave、設計、DesignState / make_solverは変更しない。段の名前は維持し、`check_regions.py` で非担当段のバイト一致を検査する。初期の担当領域は4,590行、全体9,455行。

全テストは `scripts/pahcer_run.py` を経由。通常比較は記録し、固定設計比較は仕様により非登録。基準にも届く環境変数は比較時に設定しない。各ablationの既定値を別の `clean-req-*` に固定した。
差は候補/基準の平均log比（%、負が改善）、±はseed間の標準誤差。注文列2本はseed内平均してからSEを求める。時間は同じ比較の平均req_sec。

eject・中立候補の再編集は、古いプロファイルの呼出しごとの目的値改善より、最終スコアへの寄与が大きかった。削除しない。チェーンと同時フィラー選択も残す。全腕WA・self_wrong・op_label_errors=0、評価外負荷は平均0.17・最大0.40コア。

追加計画プールは、現在の通常後処理計画数3本と既定追加候補数3本が同じため、既処理候補の除外で探索に進まない。既定で同点でも、予算を増やした場合の価値までゼロとはいえない。過去のMODE=2比較で寄与があるため、その予算経路の削除は慎重に扱う。


固定2000×2へ同じrunを延長（元の200件に残り1800件を追加）:

全腕WA・self_wrong・op_label_errors=0、追加評価の外部負荷は平均0.17・最大0.64コア。現在の予算でのクエリ記憶の寄与は小さく、削除による+0.001248%は指定された+0.003%以内。前の商品紙をそのまま残す候補も効果を確認できず、候補生成と専用分岐を削除した。フィラーの再利用価値stay_tableは別機能であり維持した。両者の組み合わせも、後述の通常2000件と固定2000×2で確認済み。

## 挙動を保つ整理

- 操作深さから直前紙アンカーへの変換を共通化。整理だけの段階では後処理と過去手順再生が同じ変換を使い、ラベルを保持する。最終版では過去手順再生を削除した。
- 計画開始時の積層復元・操作列初期化を共通化。
- 紙の配列移動と、リンク列の移動をそれぞれ共通化。可視性検査・エラー処理は呼出し元の順序を維持。
- 通常計画・別計画・追加計画のeject→再編集反復を共通化。F3_PROFILEの段・周回番号を変えない。
- 補助紙1枚/2枚の汎用順変更と掘り出し・挿入を共通化。商品紙を持ち上げる順序と失敗時の処理順序を維持。
- SearchConfigの型・環境変数名・既定値を同じ宣言にまとめ、重複した項目一覧を削除。初期化の順序と全スイッチを維持。
- 後処理の初期積層をint配列とbyte配列で二重に保存していた部分をbyte配列に統一。
- 操作列の共通型をSolver内のMovesにまとめ、崩れたネストのインデントを修正。
- 長い導入説明を短くし、合法性・積層・列挙順・浮動小数点の不変条件を残す。途切れたコメントを修正。

| canon | 区間一括正規化 CANON=1 | +0.000000 ± 0.000000 | 0.455112→0.459487 | 1.009613 |

整理版は400/400のstdoutと非時間stderrが一致した（`refactor-fixed-equality.json`）。実験用キャッシュ3種は全て同点で、この200件では速度改善を確認できない。下記の2000×2へ延長して判断した。QM_MODE=2にも優位性がなく、クエリ記憶全体の削除に含める。全腕WA・self_wrong・op_label_errors=0、外部負荷は平均0.18・最大0.37コア。

## 一致検証とビルド

| 比較 | run接頭辞 / 候補 | 検査 | 結果 |
|---|---|---|---|
| 共通化だけ、固定200×2 | 20261105-143010 / clean-req-refactor | stdout・非時間stderr | 400/400一致 |
| 共通化＋既定無効経路削除、通常200 | 20261105-144704 / clean-req-exact | stdout・非時間stderr | 200/200一致 |
| 同、固定200×2 | 20261105-145719 / clean-req-exact | stdout・非時間stderr | 400/400一致 |
| 同、プロファイラ有効、固定8×2 | 20261105-145903 / clean-req-prof-refactor | stdout・非時間stderr（計測値以外） | 16/16一致 |

`verify_saved.py` は保存されたファイルだけを読み、`*_sec`の行を除いたstderr全行を順序込みで比較する。最終候補の通常200件でも、指標名の一覧と順序、@paper属性は全件一致（`normal-log-schema.json`）。最終候補は機能削除を含むため操作列とカウンタ値の一致は要求せず、スコア・合法性を別に確認する。

通常200の最終候補は、差−0.000522 ± 0.002653%、80/27/93、req_sec 0.437312→0.420885秒、比0.962436。全腕WA・self_wrong・op_label_errors=0。外部負荷は平均0.14・最大0.38コア。このrunの基準と最終候補を2000件へ延長した。

プロファイラ照合は `COLFAST_PROFILE=1` / `F3_PROFILE=1` の両腕に、F3_MODE=2、F3_NS_ALTERNATE=1、F3_REFINE_BEST=1、F3_HEAVY_TRACE=1、F3_HEAVY_PREDICT=1を同じ設定で渡した。ここでは設定の寄与ではなく挙動の一致を確認するため、意図して共通の環境変数を使った。cfprof_*の呼出回数、#f3post/#f3opの非時間項、#heavy/#heavycand等が一致。時刻だけ（*_sec、cfprof_*_inc/_exc、#f3post/#f3opの最後の時間値）を除外した。詳細は `profile-equality.json`。

GCC / Clangそれぞれで `-std=c++23 -O2 -Wall -Wextra`、LOCAL_BENCHなし／あり／全計測有効の計6構成が警告0で成功。最後はCOLFAST_PROFILE、F3_PROFILE、AF_PROFILE、DESIGN_PROFILE=3、AS_PROFILE、POSET_VERIFY、SIM_HARNESSも同時に有効化したコンパイル確認で、バイナリを直接実行していない。コンパイルは共有評価ロック下で実施し、ログは `build-check.log`。

run-id: `20261105-144704_time-alloc` / `20261105-144704_clean-req`。200件から同じバイナリで残り1800件を延長し、通常runとして登録済み。

## 採用した整理と受け渡し

| 段階 | ファイル全体の行数 | 担当領域の行数 |
|---|---:|---:|
| time-alloc | 9455 | 4590 |
| 共通化・コメント等の整理 | 9364 | 4499 |
| 上記＋既定で無効の実験経路3種の削除 | 9232 | 4367 |
| 最終版：さらにクエリ記憶・ret_mode=4を削除 | **9064** | **4199** |

担当領域を391行（8.52%）、全体を4.14%削減した。単なる圧縮や改行の除去ではなく、重複処理の共通化と寄与を測定した経路の削除によるもの。スコア改善ではなく、指定の許容範囲内でスコアをほぼ保ち、注文時間とコード量を減らす変更である。

廃止したスイッチは **QM_MODE、F3_CANON、F3_SHARED_VIS、F3_CROSS_MEMO**。ret_mode=4は内部の計画候補で外部スイッチではない。F3_*の探索予算・残した近傍、NEUTRAL、COLMDP_*、全てのプロファイラ、ログの名前と形式を維持する。廃止機能のログ名も残す（qm_requestsは実注文数、それ以外のqm_*とf2_canon_*・f2_visibility_*は0）。

**段の追加・統合・改名・削除はない。ヘッダ目次は変更していない。** `Solver: previous-query plans` の段は廃止した機能の互換指標を置く短い段として残した。担当外の変更は不要で、非担当段は `check_regions.py` により基準と完全一致。Comparator、PosetSums、Interleave、DesignState / make_solver、設計から呼ばれるSolverのインターフェースは維持した。

最終main.cppは通常2000・固定2000×2の両runの保存ソースとバイト一致。コミットはしていない。共有スクリプト・他解法・trial_logを編集していない。pahcerへの記録は評価スクリプトによる通常runの登録だけで、手編集していない。

再現コマンド（最終ソース）:

```sh
python3 scripts/pahcer_run.py --compare solutions/time-alloc solutions/clean-req --seeds 0-2000 -c "clean-req: normal confirmation"
python3 scripts/pahcer_run.py --compare solutions/time-alloc solutions/clean-req --design-from 20261105-141234_time-alloc --seeds 0-2000 --orders 2 -c "clean-req: fixed confirmation"
```

`analyze.py` は保存済み結果とログだけを集計する。`verify_saved.py` は出力一致、`check_regions.py` は編集範囲を検査する。`refactor.py` と `remove_features.py --memory --stay --canon --shared-vis --cross-memo` は変更の再現用。評価用の各兄弟ディレクトリにも日本語READMEを置いた。
