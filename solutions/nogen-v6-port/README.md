改良元: solutions/ng-product-v6-fast

v6の潜在所有者による背景窓設計を維持し、nogen-map9k の注文計画と安全策を移植した。
- 背景ヘルパーの未加工計画を通常計画の候補集合へ渡し、後処理・排出・中立変更・キャッシュを共有する。ペア候補深さ3、予備候補16、実計画4、単独候補3。
- DesignStore v2へ更新し、M=0、背景列数、重複所有者も保存する。
- 窓0–62は全所有者との色一致を監査。窓63は同色所有者ならその色、異色の2所有者なら白印刷＋黒キャップという承認済み規約を監査する。異色ペアの禁止は設けない。
- 古い背景目的関数の辺整列を安定radix sortへ変更。v6の主探索は元から差分評価・radix sortを使用する。
- 窓探索は300,000反復＋60,000 climb、列探索2,000,000、フィラーclimb 30,000、再割当4回。背景窓G=36。
- scaled clockで窓探索0.85秒、通常列の焼きなまし1.15秒、climb 1.20秒を上限にする。所有者推定に失敗した場合だけ、同じ商品紙設計の初期状態から従来の窓探索を最大6,000回（1.00秒まで）行う。別の解法へ切り替えない。
- 注文は1.70秒から軽量計画を使用し、LOCAL_BENCHでは切り替えを無効にする。

`inverse_map_sec/iters` と `inverse_climb_iters` は潜在所有者の窓探索時間・反復数。`audit_owner_violations` は窓0–62の色違反、`audit_cap_violations` はキャップ規約違反、`audit_cap_exception_papers` は異色ペアを白印刷した枚数。違反はLOCAL_BENCHでassertする。
`ng_helper_sec` はヘルパー生成だけ、`ng_base_sec` は共通後処理を含む残りの注文時間。`joint_helper_wins/product_helper_wins` は未加工費用で暫定最良となった回数。操作ラベルとその他の監査を維持する。

背景紙を別の主紙として追加評価する V5_ALTERNATE は、nogen-map9k と同じ0。元v6の単独6・ペア計画6より完成候補は少なく、予備ペア候補16・深さ3は多い。
