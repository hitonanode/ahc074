# 汎用表示層の符号と局所順列の検証

改良元: なし。研究用の全列挙プログラムで、提出用の reactive 解法ではない。

- `enumerate_three.cpp`: 3 枚の紙の `0/1/.` の全 27 列と全 6 順列を列挙する。4 商品に 4 順列を割り当てたとき表せる 4 bit の列パターン数を厳密に数える。既存の「1 商品に主紙 1 枚」という制約から離れ、4 商品を 3 枚の順序で符号化する案の必要条件を調べる。
- `kernel_probe.cpp`: 6 枚の通常の比較器、通常の比較器と 4 枚中 2 枚黒・2 枚白の窓の混合、3 対または 4 対の紙による「符号付き優先順位」を比較する。各紙対を同時に交換すると全窓が白黒反転するため、後者は 3 枚以上不透明でも商品対の補色対称性を保つ。
- 入力の事前公開部分（64 窓の 256 商品）だけを読む。注文列は読まない。固定回数の焼きなましで、70 または 72 個の互いに素な商品対を作れるか、ハンドル側の違い、満たす状態数を調べる。
- 選んだ商品対については全 `6!` / `8!` 物理順列と**実際に見えている紙だけ**を動かす有向グラフを作り、逆 BFS で目標集合までの距離を厳密に求める。平均は全物理順列の一様平均であり、対話で生じる定常分布ではない。
- 初期の焼きなまし目的は `0.65 × ハンドルの違い + 2 × sqrt(状態情報量) + 0.04 × 全窓の違い` の貪欲なマッチング。`sqrt(状態情報量)` は探索を安くするための代理指標で、手数ではない。最終行の `exact_mean_moves` だけが上記の正確な距離。
- 全ての 2 枚比較の組（または各白黒ペア）の単独比較窓を最低 1 つ保ち、可視性と到達性を確保する。混合型には通常の比較器だけの設計も含まれる。別解法を実行中に切り替えるものではない。

再現例:

```sh
g++ -std=c++23 -O2 solutions/astranova-kernel/enumerate_three.cpp -o /tmp/enumerate_three
/tmp/enumerate_three
g++ -std=c++23 -O2 solutions/astranova-kernel/kernel_probe.cpp -o /tmp/kernel_probe
/tmp/kernel_probe tools/in 0 8 2000
```

引数は入力ディレクトリ、開始 seed、終了 seed（含まない）、設計の反復数。出力は CSV。
本プログラムの指標は AHC074 のスコアではなく、紙の設計の必要条件・局所的な表示層の評価である。対話解法全体の優劣は別途 `scripts/pahcer_run.py --compare` で測る必要がある。
