# 自由3列の終状態価値：小模型で確認できた改善

**提出可能な構成への移植では、現在のところ改善を確認できていない。**
下記の小模型の正の結果を受けて実装した `chatgpt-free-joint` は、
紙の設計をそろえた4ケースの比較で対照版 `chatgpt-free-lex` より悪化した。
模型内で得た利得と、実際の操作の評価結果を分けて読む必要がある。

## 確認できたこと

1ケースの実際の紙の設計から抽出した9個の6枚模型では、
**「各窓を個別に直す費用の和」を「3窓を同時に直す最少手数の期待値」に置き換えると、
終状態の選択が改善した。学習係数は不要だった。**

9群の修正費用の合計は、従来型の窓別近似を使う方策の4.949492手から、
同時修正の一段先評価を使う方策の4.727425手へ下がった。
最少手数の中で終状態を選び直すだけで同じ値になり、将来のために今1手多く払う必要はなかった。

これは下に定義する**6枚の修正模型**の結果である。
実際の長い列での掘り・持ち上げ・返却・穴埋め込みのコンテストスコアではない。
新しいC++解法 `solutions/chatgpt-free-joint` は、この知見を実際の操作で検証するための実装である。

## 模型と入力

元の紙の設計は `runs/20261101-160656_imp-combo/out/100000.txt`、
商品集合は `tools/in/100000.txt` である。
28ハンドルを元の列順に並べ、先頭27列を3列ずつ9群に分けた。
残る最後の1列は含めていない。

各元列の初期の紙の順から、その列のハンドルが白になる紙・黒になる紙を1枚ずつ取る。
3列の計6枚の、実際の3窓の印刷を使う。仮想的な色や穴を追加することはしない。
各商品の専用紙は、全不透明セルが商品と一致する紙がただ1枚であることを確認して特定した。
各商品でその専用紙の穴となる窓と要求色から、27通りの部分要求の度数を数えた。

この部分要求を経験分布から独立に抽選する。公式の「直前と同じ商品は注文されない」
条件は含めていない。専用紙の掘り出し・持ち上げ・返却、残りの紙、汎用層、
ほかの群からの穴埋めも含めていない。

紙の状態は6枚の全720順列である。
要求されない窓は上の専用紙で隠されているので、その窓を可視性の証拠として使わない。
必要窓に見える紙を1枚選び、他の5枚のどの隙間へ挿入してもよい。
この規則により、必要窓マスク7種類ごとに異なる合法な遷移グラフができる。

全6枚の印刷と要求度数は `models-seed100000.json` と `models-seed100000.txt` に保存した。
TXTは `probe --models` で直接再生でき、元のrunは再現に必要ない。

## 有限MDPの数値解法

状態sから部分要求qを満たす状態tへの合法な最少手数をd_q(s,t)とする。
終状態の相対価値hを与えたとき、各要求について

```
B_q(h)(s) = min_{tがqを満たす} [ d_q(s,t) + h(t) ]
```

を計算する。qを満たす全状態を始点とし、その初期費用をh(t)とする
逆辺の多始点Dijkstraで求められる。
要求確率で平均したBellman作用素を使い、基準状態の値を引く相対価値反復を行った。
周期を抑えるため新旧の値を半分ずつ混ぜる。

Bellman残差T(h)(s)−h(s)の全状態での最小値と最大値は、最適平均費用の上下界になる。
作用素は非空要求に条件付けた確率で計算し、その上下界に各群の要求発生確率を掛けて、
元の1注文あたりの単位へ戻す。
反復の上限は400。最後の3群はこの上限で止まり、上下界の幅をそのまま記録した。
9群の合計の数値的Bellman上下界は、表示桁を外向きに丸めて
**[4.644871, 4.645710]** である（元の計算値は4.644871641、4.645709252）。
これは倍精度計算による値であり、区間演算で浮動小数点誤差を保証したものではない。

比較方策の定常費用は、同じ初期列順からの確率分布を反復して求めた数値である。
分布のL1変化が10^-13未満で終了し、上限は10000反復。
独立列方策の費用は、各窓の白・黒要求確率をa,bとした2ab/(a+b)の和で解析的に計算した。

独立した3組の白黒ペアに全3窓一様要求を与えたとき、全720状態で
Bellman作用素の値が厳密に1.5手になることを `--self-test` で確認した。

## 比較結果

すべて同じ9群・同じ要求分布の数値。単位は元の1注文あたりの模型内修正手数である。
各群の非空要求あたりの定常費用に、その群の要求発生確率を掛けてから合計した。

| 終状態の選択方法 | 9群の合計 |
|---|---:|
| 元の3列に分け、各窓を独立に操作 | 5.093541357 |
| 最少手数、その中で窓別費用Fが小さい状態 | 4.949492069 |
| 手数＋F | 4.949492069 |
| 手数＋4F | 4.978049683 |
| 手数＋F/要求発生頻度 | 4.949492069 |
| **手数＋同時修正の一段先期待値F_joint** | **4.727425248** |
| **最少手数、その中でF_jointが小さい状態** | **4.727425248** |
| 26距離特徴から回帰したh | 4.727642219 |
| 8集約特徴、未知の群への回帰 | 4.729590769 |
| 価値反復で求めた近似hを使う方策 | 4.644873169 |
| 最少手数、その中で近似hが小さい状態 | 4.644873169 |

F_jointは、必要窓だけを使う合法グラフにおける、各部分要求までの最少距離d_q(s)の平均である。
要求が空でない注文に条件付けて平均した。学習した数値や、次の注文の実現値は使わない。
独立列から近似hを使う方策までの利得の約81.6%を、この一段先評価で得られた。

窓ごとの初出深さは、必要窓が1つだけの要求までの最少距離と等しい。
したがって従来のFは26距離特徴のうち単窓の6種類だけを使った近似であり、
F_jointは2窓・3窓の相互作用を追加するものと解釈できる。

## 回帰による確認

各群の720状態のうち576状態から、価値反復で求めた近似hを26個のd_qで線形回帰し、
残る144状態で調べた。小さなridge項10^-7を入れた。
holdoutのR²は0.916〜0.994、RMSEは0.071〜0.148手だった。
6個の色の初出深さと可視枚数を追加してもほとんど変わらなかった。
色の初出深さはもともと単窓距離に含まれているので、実質的な追加情報は可視枚数だけである。

これは未知の状態に対する検証であり、未知の印刷型・入力への検証ではない。
そこで、各窓集合7種類について要求の周辺分布で距離を平均した7特徴とF_jointを使い、
9群のうち8群から学習して残る1群へ適用する検証も行った。
R²は0.739〜0.968、RMSEは0.151〜0.325手、方策費用は4.729591手。
**回帰を使わないF_jointより良くはなかった。**
よって、今回の試作には学習係数を埋め込まず、F_jointそのものを使う。

## 長い列へ移すための具体案と限界

実際の3列の現在順序から、各元列の白黒を1枚ずつ代表として抜き、その6枚へ射影する。
第1列の2枚は自分の1窓だけ、第2列の2枚は前の1窓に3通り、第3列の2枚は前の2窓に
3通りずつを持つので、代表の印刷型は3^(2+4)=729通りに収まる。
その相対順序は720通りである。型・順序・群ごとにF_jointをキャッシュできる。

`chatgpt-free-joint` では各必要マスクからの前向きBFSを行い、要求色がすべて見つかると止める。
終状態評価は、実際の全紙に対する平均掘り費用に、6代表のf_g F_jointを加える。
ここでf_gはその群の要求が空でない確率であり、条件付きのF_jointを元の1注文あたりの
無条件期待値へ戻している。両項の単位をそろえ、掘りと修正の相対的な重みを保つ。
同じ手数のGOALだけを比較し、途中のbeam・greedy・戻しの選択は対照版を保つ。

この射影は同色の紙が深く連なる状況を過小評価しうる。
また、修正MDPには掘り・取り出した紙の返却が入っていない。
全720状態の中の選択を、幅8・深さ4の探索で再現できるとも限らない。
従って小模型の0.222手という利得を、そのままコンテストの手数改善として報告してはならない。

## 再現と記録

```sh
g++ -std=c++23 -O2 solutions/chatgpt-block-mdp/probe.cpp -o block_mdp
./block_mdp --self-test
MDP_REGRESSION=1 ./block_mdp --models solutions/chatgpt-block-mdp/models-seed100000.txt 400
./block_mdp --cross-models solutions/chatgpt-block-mdp/models-seed100000.txt 400
```

- `results-seed100000.csv`: 群ごとの基本比較と数値的Bellman上下界。
- `regression-seed100000.log`: 26/33特徴のholdout回帰と近似hを使う方策。ログ中の`exact_h`は価値反復で求めたこの近似hを指す。
- `cross-fit-seed100000.log`: F_joint方策と8特徴の群単位holdout。
- `summary-seed100000.json`: 9群の集計。
- `regression-runtime.json`, `cross-fit-runtime.json`: 実行時間など。

9群のMDP・回帰の計算は子CPU5.71秒、別実行の9群のMDP・群単位holdoutは4.98秒だった。
このMDPを毎ケースそのまま提出プログラムで計算する時間はない。
実験版は価値反復を行わず、6代表の短いBFSとキャッシュだけを使う。

## 実際の操作での最初の比較

`20261101-162732` の同時比較（新規生成seed100000〜100003、4ケース）で、
紙の設計のSHA-256がケースごとに3解法で同一であることを確認した。
これは設計探索回数を固定した方策の比較であり、通常の時間制での最終スコア比較ではない。

| 解法 | 平均絶対スコア | 平均手数/注文 |
|---|---:|---:|
| imp-combo | 10,834.25 | 10.580322 |
| chatgpt-free-lex | 12,016.50 | 11.734863 |
| chatgpt-free-joint | 12,205.25 | 11.919189 |

全解法E=0、WA=0、保存出力の可視性付き再生が一致した。
free-jointはfree-lexに対し約0.1843手/注文悪化した。
ケースごとのlogスコア比は **+1.556 ± 0.183%（平均 ± 標準誤差）**、0勝0分4敗だった。
ケースごとの値と共通の紙設計hashは `../chatgpt-free-joint/pilot-scores.csv` にある。
seed100000では新規BFS1150回、キャッシュ参照31624回、計算時間0.00989秒、予算切れ0回だった。
したがって、少なくともこのケースの悪化は新評価が計算できなかったためではない。

4ケース平均の内訳は、掘り2893.0→2995.5手、修正5714.25→5800.5手、
汎用層1362.25→1362.25手だった。初期上界からビーム探索が減らした手数は
221.25→401.25手と増えているが、最終的には掘りも修正も増えている。
計算予算切れは全4ケースで0、平均BFS計算時間は0.009478秒だった。
また、提出側の前向きBFSと研究側の独立した逆向きDijkstraを9模型の全6480状態で照合し、
最大差4.44×10^-16、キャッシュ再参照6480件も一致した
（`../chatgpt-free-joint/projection-check.json`）。

考えられる相違は、6代表が長い列の重複紙の深さを落とすこと、
修正だけの模型が掘り・返却の状態価値を含まないこと、
実装の限られたGOAL候補が模型の全720状態とは異なることにある。
これらの寄与はまだ切り分けていないため、原因を特定したとは述べない。
現時点でこの移植版の採用は勧めず、模型と本番の価値のずれを調べる研究材料とする。
