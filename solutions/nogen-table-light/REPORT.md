# 不要な距離表の省略と時間配分

`Feas` は背景の表示色列挙だけを使い、穿孔用Solverは背景列数だけを使う。この2か所のControlTable::initを距離表なしにし、実注文処理用の表は残した。穿孔後・再割当後の証明検査と最終印刷の独立監査は継続する。

通常500件 `20261106-115053`（先頭SOTA、perf-reuse、table-light）のperf-reuse/table-lightは平均10403.3で、全stdoutが完全一致。table-lightのjudge平均1.631338、p99 1.816765、最大1.845167、2秒超0。外部負荷平均0.06/最大0.31コア。設計・候補・乱数を変えない速度改善と確認した。

固定設計500件×注文列2本（保存設計113548）の使途比較:

|版|run-idの日時|table-light比 log ± SE (%)|勝/分/敗|req_sec|
|---|---|---|---|---|
|table-light|20261106-115054|0|0/500/0|0.510070|
|spend-three|20261106-115102|−0.050820 ± 0.003145|388/0/112|0.551194|
|spend-rounds|20261106-115115|−0.094763 ± 0.004012|429/0/71|0.602371|
|spend-wide|20261106-115127|−0.106097 ± 0.004046|435/0/65|0.744287|

threeは通常後処理候補2→3、roundsはさらに中立書換1→2巡、wideは拡張候補3→5と追加候補1→3。wideの時間当たり利得は低く、候補から外す。列予算11Mを9Mへ減らしてroundsを使う版も通常比較へ進めた。固定設計のreq時間は通常評価より長くなるため、最終時間判定には使わない。

通常比較と後続高速化の最終結果は、採用版のREPORTにまとめる。途中の小差を確定結果とはしない。
