# マイルストーン1: 商品所有の紙だけで時間内に動く基準版

統合対象は `solutions/nogen-owned-g34`。SOTA超えは未達。
元のv5よりスコアは悪いが、64窓すべての所有色制約を満たし、時間内で次の設計を比べるための基準になる。
キャップ以外の191枚はすべて商品紙で、背景6枚も実商品の色だけを印刷する。

## 変更

- ペアの所有者は窓63も同色の商品に限る。元のv5はここを監査から除外し、異色のペアにも白を印刷していた。
- 入力の元バーコードと実際の印刷位置を、全所有者・全64窓で照合する監査を追加。違反時はLOCAL_BENCHでassert。
- 背景窓は34。割り当て探索は6,000反復、候補ペアの距離上限は28。商品・列の焼きなましは4,000,000反復。
- 補助紙1枚・2枚の操作生成と後処理は各2案。2枚の組は6組を予選。実益が小さい別主紙の追加探索を止める。
- 短いペアだけの近似マッチングが足りなくても、その後の全互換ペアによる実マッチングへ進む。
- DesignStore版2に背景列数・背景紙の所有者を保存し、M=0・仮想ハンドルを含む設計を再読込できるようにする。
- 窓割り当ては有効な組が揃った後、経過1.00秒で打ち切る。商品・列の焼きなましは1.15秒まで。
- ジャッジでは1.70秒から同じ計画器の最初の有効な計画を使う。LOCAL_BENCHでは通常探索を完遂する。
- CLOCK_SCALE、操作ラベル・紙属性、段の目印と目次を維持。既存解法・scripts・trial_log・STATEは編集していない。

## 現在の問題と次の書き換え

G34の操作集計は `20261106-092916_nogen-owned-g34` の2000件。
単独商品9.497、ペア商品11.468操作/注文。旧v5に比べ単独商品は軽くなり、ペア商品が重くなった。
SOTAとの差0.516操作/注文の内訳は、fix +0.490、help +0.125、hdig +0.051、fret +0.091、
repair +0.075、dig −0.250。genの差は+0.009。
設計模型も、ハンドル費用4.590（SOTA 3.925）、列費用2.695（SOTA 2.956）で同じ方向を示す。

次は `design_controls` の窓割り当てとマッチングの目的関数をまとめて書き換える。
現在は「71組を貪欲に選ぶ平坦なハンドル差の和」で窓を固定してから列を決めるため、
実際にどの深さのハンドル修正が発生するかを窓の選択に戻せない。

1. キャップに使う物理窓も選択変数にし、商品ペア・背景所有者・背景窓・列を同じ候補状態で評価する。
   キャップを変えても、全所有者の一致色だけを印刷する制約と64窓監査は保つ。
2. 互換グラフの組数だけでなく、拡張路を含むマッチングと、列に置いた後の `colcost`・`hcost`・フィラー価値を使う。
   G34で得たマッチングの余裕を、単なる成立率でなく穴修正の少ないペアへ振り向ける。
3. 商品紙のハンドル穿孔と穿孔後の再割り当てを組み込む。穴を追加する操作は所有色の制約を壊さない。
   背景の仮想ハンドルは穿孔対象から外す。背景紙の印刷色を自由にする操作は導入しない。
4. 注文側では背景補助紙案を共同区間DPと統合し、完成後の列価値と既存フィラーの再利用まで評価する。
   候補ごとの同じ後処理のやり直しを減らし、設計へ時間を戻す。

削減量の目安は、旧v5を超えるには0.239、SOTAを超えるには0.516操作/注文。
現在のfixと補助紙の余分な操作だけで0.666操作/注文あるため、この部分を主な測定対象にする。
これは改善の保証ではない。最初はG34・保存設計を基準に個別変更を測り、設計変更は通常比較で判定する。
時間配分は設計0.90秒・注文0.55秒・その他0.02秒なら、指定の模型で約1.70秒。
候補を制限した現在の設計0.80秒・注文0.61秒から、補助紙候補の共通処理を減らすことを狙う。
