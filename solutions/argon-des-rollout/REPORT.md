# D5：最終候補の1手先rollout

助言01-3「最終候補に対する1ステップ・モンテカルロロールアウト」をPR146で検証する。
BASE.mdの07:00新方針（0.03%以上・時間条件、改訂1回まで）を適用。

`Request processing (process)`では複数の候補に既に後処理している。
その操作列と終了状態を保存し、最終勝者＋元の費用が近い異なる終了順序の上位2候補を比較する。
次の目標は一様分布から現在の目標を除く255種類。将来の実際の注文を使わず、全種類を列挙する。
各候補・次目標に対して、前商品を戻す通常案、前商品をフィラーに使う案、jointフィラー案の
3通りを試し、「操作数＋既存の終状態価値」が最小の値を平均する。
現在の操作数とこの期待値を足して選ぶ。これは軽いplannerに対する厳密な期待値であり、
完全な最終plannerや最適な将来政策の数学的oracleではない。

計算用のSolverを1個コピーして再利用し、実際の状態や操作列を壊さない。
選ばれる操作列は既に本体が合法性を確認したもの。
既存のprofile/traceを残し、d5_*で終了状態の多様性、選択変更、予測と即時費用、
標本間の分散、費用差による候補制限の予測利益を測る。

smoke run `20261106-073015_argon-des-perf-latew105` / `20261106-073015_argon-des-rollout` は
固定2×2、WAなし、候補実時間約9.5秒/ケース。時間超過の計測であり記録しない。
その後、保存候補の更新時にも再ソートする修正を加え、選択無効の出力対照10×2と本計測100×2を行った。

## 予備結果と改訂

選択無効の対照runは `20261106-073224_argon-des-perf-latew105` /
`20261106-073224_argon-des-rollout`。10×2で全件同点。
候補保存時の費用の再参照によりcf_value_hitsだけが増えるため、
追加のd5_*とこの説明できる参照回数を除いた非時刻stderr、およびstdoutは20/20実行で完全一致した。
根拠は`control-identity20.json`。最初の`control-identity10.json`はcf_value_hitsの差を検出した
途中の照合記録であり、最終照合とは区別する。

初回100×2は `20261106-073225_argon-des-perf-latew105` /
`20261106-073225_argon-des-rollout`、−0.019067±0.011471%、51/0/49。
ただし外部負荷0.72/4.09コアの警告があり、決定比較には使わず再実行した。

予備診断では701.58/1024注文が異なる終了状態を持ち、200.765注文で選択を変えた。
予測改善0.019947手/注文に対して実測は約0.00191手/注文と小さい。
即時操作は+0.011177、次の軽い計画の操作予測は−0.038966、終状態価値予測は+0.007842手/注文。
つまり候補の不足ではなく、軽い次注文plannerの予測が、実際の強い後処理を含む政策の
改善にそのまま対応しない。費用差が完全同点の候補だけに絞ると、予測改善自体が
0.0002167手/注文（スコア約0.0022%）まで減る。

採用候補間の次目標ごとの費用差の標準偏差は平均0.526、
有限母集団で符号を95%判別する正規近似の必要標本数は平均126。
全列挙の段は約13秒/ケース。そこで費用への改訂を1回だけ行い、
助言にある16標本へ減らした `argon-des-rollout-s16` を同じ比較に加えた。
乱数は固定で候補間に共通、実際の未来の注文は読まない。

固定100設計×2注文列、外部負荷は平均0.17・最大2.00コアで警告なし。

## 予測と実測のずれ

全列挙では701.58/1024注文（68.5%）に異なる終了状態が残り、
200.765注文（19.6%）で選択を変更した。保存候補が元の静的費用でも現勝者より安い件数は0。
候補の取りこぼしや選択保存のバグで改善を作っているわけではない。

| 指標（手/注文、件数以外） | 全列挙 | 16標本 |
|---|---:|---:|
| 選択変更件数/1024注文 | 200.765 | 228.335 |
| 現注文の操作増 | +0.011177 | +0.011309 |
| 次注文の操作数の予測改善 | +0.038966 | +0.053223 |
| 次注文後の状態価値の予測改善 | −0.007842 | −0.007779 |
| 合計予測改善 | +0.019947 | +0.034136 |
| 実現した操作数の改善 | +0.001914 | −0.005132 |

全列挙でも実現する改善は予測の約1/10。軽いplannerには本体の後処理・中立書換えがなく、
その将来費用の差が本体の政策で残るとは限らない。
16標本では予測利益と選択変更数が増えたのに実測は悪化する。
少数標本から最良候補を選ぶ偏りが加わったという診断と整合する。
全列挙時の候補差の標準偏差0.526に対し、平均約126標本を必要とする符号判定の近似からも、
10〜20標本で微小な候補差を安定して判定する設計は支持されない。
この標本数は正規近似による診断値であり、必要数の厳密な下限ではない。

`observe-final.log`は同じ再測定runの第1注文列100件を`observe.py --vs`と
`@ops`で調べた記録である。16標本版のラベル別差（操作/注文）は
fix +0.119629、fill +0.029688、dig +0.007617、fdig +0.007275、
fret −0.061162、gen −0.046201、repair −0.049238。
これは操作を作った場所の分類であり、動かした汎用紙の枚数とは一致しない。
例えばseed 80の注文47はfixが6→9、注文205はfretが1→2、fixが2→4で、
どちらも3操作増。seed 49の注文119でもfixが3操作増える。
これらは既に違う状態へ分岐した後の比較なので、その注文の選択だけの因果効果とはしない。
全体では、戻しや汎用操作のラベルが減っても、フィラーと修正の増加で利益が消えることを確認した。

## 結論

助言の「異なる終了状態を先読みで比較できる」という点は成立する。
ただし全列挙でも0.03%かつ2SEを満たさず、時間は自由予算を大幅に超える。
費用を減らすための16標本という改訂は有意に悪化し、なお時間超過。
完全同点だけなら予測利益自体が約0.0022%で、対象を絞るだけで0.03%を狙う根拠もない。
従ってBASE.mdの失敗案は改訂1回までという新方針に従い、D5は未採用で終了する。
通常2000件の採用比較は行わない。全ての将来政策への数学的な上限を示したわけではなく、
本体同等の強いplannerをさらに高速化して先読む方向は今回の測定の外に残る。

両候補ともGCC/Clang・C++23 O2 Wall/Wextra・LOCAL_BENCH有無の4構成で
警告・エラーなし。各ディレクトリの`build-results.json`と`build-*.log`に記録。
既存の指標・スイッチ・段を保持し、追加したrolloutの段を目次にも記載。
ビルドは一時ディレクトリで行い、実行バイナリは削除した。
