# chatgpt-multiroute

改良元: `solutions/imp-910`

各商品を1枚の代表紙に固定する制約を緩め、同じ商品を別の列からも取り出せる重複した辞書を作る。
元の紙設計の焼きなましを終えた後、単独商品 a の紙を a と b の共有紙に変更して、b の既存の代表紙を残す。
紙の数・列・取っ手の色を変えず、両商品の違う窓だけを穴にする。汎用層で両方を表示でき、取っ手の色が一致する組だけを使う。

候補の評価では、a の汎用層の費用増と取っ手の穴の費用増を支払い、b が2つの列のうち安い方を使う利益を引く。
利益は2列の一様な深さの全組合せを列挙して見積もる。単独紙の元の商品と第2経路を得る商品は重複させず、見積利益の上位から最大8組を採用する。
研究用の既定設定では負の見積利益でも採用し、多重経路の効果と費用を実際に測る。予測で不利な構成を含むため、既存解法への改善を期待して提出する設定ではない。
これは多重経路の効果を小さく切り出すための初期実装であり、共有紙・列配置・利用確率の同時最適化は行わない。

注文ごとに両方の代表紙について同じ開始状態から計画を作り、操作数・列外の紙・次の注文の推定費用の和が小さい方を採る。
汎用層への穴埋め紙の挿入表は代表紙ごとに別に構築する。将来費用の紙の利用重みと取っ手の穴の重みは、設計時に見積もった経路選択率で分配する。
時計倍率 `CLOCK_SCALE`、合法性確認、入力の flush、時間が少ないときの軽い計画は改良元と同じ。

## パラメータと診断値

- `MULTIROUTE_LIMIT` 環境変数: 追加経路の上限。既定8、0以上を指定可能。
- `MULTIROUTE_MIN_GAIN` 環境変数: 1組あたりの見積改善の下限。既定−100手（上位候補を実証するため）。0.05を指定すれば正の見積利益だけを採る保守的な選別を再現できる。
- 取っ手の穴1個の静的費用: 0.4手。汎用層の費用: 既存の正確な順列距離表の両方向平均。
- `route_design_count`: 追加した経路数。
- `route_proxy_gain`: 見積改善の合計を256商品で割った値（手/注文）。
- `route_requests`: 2経路を評価した注文数。
- `route_selected`: 第2経路を選んだ注文数。
- `route_selected_move_gain`: 第2経路選択時の「第1経路の操作数−第2経路の操作数」の累計。終状態費用も含めて選ぶので負の場合もある。
- `route_alt_helper_papers`: 第2経路用に構築した穴埋め候補の件数。
- 改良元の計画回数関連の診断値は、採用されなかった経路を含む探索全体を数える。

評価結果は `trial_log.md` と[検証レポート](../../docs/chatgpt-multiroute-rescue-study.md)を参照。
