# Task 5 の記述用メモ

## 新しい変更の理由

従来のHungarian再割当ては、ペア紙の片方をanchorとして固定し、残りの目標を各紙のslotへ割り当て直していた。その際、単独紙にも「元のslotと同じハンドル色」という制約を掛けていた。この制約はペアの両目標を同時に表示するためには必要だが、単独紙では必須ではない。

穴あけ後の再割当てで単独紙の色固定を解除する。ペアの互換性とanchorは従来通り。巡回全体を適用した後で、各列に両色の紙が残ることを検査し、従来の正確な仕上げ目的 `model_cost − weight × head_filler_value` が改善した巡回だけ採る。Vは完成候補の選択にだけ使う。8候補、各段の探索回数、焼きなまし、窓割当ては同じ。

前半の再割当てにも広げる、元4枝を除いて追加候補だけに使う、単独紙のうち代表紙以外に絞る、といった対照実験を行う。採用範囲は学習seed 0–499の8列replayで選ぶ。

列MDPは紙を4種類に量子化している。元の「色×専用目標数1/2」はfillerとして使われる頻度の差を潰していた。同色の紙を実際のfiller込み需要で整列し、群内二乗誤差が最小になる2群へ分ける。従来と同じ4種類のMDP、同じ反復数・状態数上限で解く。1注文先の正確な紙別の値はそのまま使う。

汎用紙の順序の末端評価には、既存の1注文先の平均最小操作数×0.5を加える。将来の注文そのものは使わない。これは設計を変えない注文処理のみの変更である。

## 出力を保つ高速化

窓割当てのradix sortで、histogramの累積和を8項ずつAVX2整数演算で計算する。全64bitキー、同値の順序、greedy matchingの列挙順は同じ。Vの積分点からの色マスク生成も、30bit整数の大小比較8個をAVX2でまとめる。いずれも浮動小数点の式と加算順を変えない。

採用した高速化は親とのstdoutバイト一致をGCC/Clangそれぞれ250ケースで検査する。時間は24並列の同時比較で測る。プロファイラを有効にした200ケースは律速箇所の診断専用で、その絶対時間を高速化の根拠には使わない。

## 測定の区別

全設定の選択はseed 0–499。品質はケースごとに対象列の操作数を平均し、その比のlog×100を集計。SEもケース単位。基準replayは `20261107-130357_deval-ordered8`。新規列1–7を主判定、列0と全8列も併記する。

最終候補のsourceを固定してから、old/nofb/ordered8/candidateの通常2000ケースを記録付きで同時比較する。保存した候補の設計を未使用seed 500–999の8列で再生し、`20261107-134239_deval-ordered8` と比較する。時間は通常比較から `1.04×helper_end_sec + 1.35×req_sec + (end_sec−helper_end_sec−req_sec)` で計算する。replayの時間は採用判定に使わない。

全試行のrun-id・成績・段階時間・出力一致は `TABLES.md` から報告へ取り込む。ビルドと重い集計は共通flock下、解法の実行は常に標準pahcerスクリプトを通す。共有ファイル・trial_logは編集しない。
