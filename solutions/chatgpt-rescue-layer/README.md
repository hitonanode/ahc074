# chatgpt-rescue-layer

改良元: `solutions/imp-910`。汎用紙の表現を変更し、専用紙の列・紙の再挿入・穴埋め紙の計画は引き継ぐ。

## 6枚の比較紙と2枚の救済紙

既存の6枚の比較紙に、互いに補色の2枚の救済紙を加える。汎用窓36個のうち35個を比較窓にする。救済紙はその一部（既定8窓）だけに色を持ち、残る1個は救済紙だけが色を持つ専用の窓にする。救済の対象外の比較窓は穴なので、救済紙の下にある比較紙の順序も表示に寄与する。
比較紙だけでは、共有紙の穴の要求が比較関係の閉路になったり、同じ比較器を使う窓が矛盾したりすると表示できない。
救済紙を比較紙の途中に入れると、上側の比較紙が担当しきれない窓をその紙の模様で補い、表現できる部分模様を増やせる。
救済紙専用の窓があるので、上側の救済紙は汎用層を露出させた際に必ず動かせる。

救済紙2枚のうち下側を汎用層の一番下に置く。上側の救済紙は6枚の比較紙の前・間・後の7通りの位置に置く。
比較紙の順列720通り、挿入位置7通り、救済紙の表裏2通りからなる10080状態を列挙する。
見えている紙1枚の移動でこの形を保てる遷移を、実際の不透明マスクを使って厳密に作る。
上側の救済紙を最下段に送る遷移では、救済紙の色が切り替わる。

各商品の要求する穴に合う全状態から逆向きBFSを行い、その状態集合までの最短手順をキャッシュする。
注文処理中の操作列の後処理で汎用紙が別の並びになった場合は、必要に応じて上側救済紙を最下段へ送る1手で列挙した形へ戻す。
紙の可視性・最短距離が厳密なのはこの10080状態と遷移の範囲であり、8枚の全40320順列に対する最短性は主張しない。

## 紙の設計と費用の近似

最初に既存の窓割り当て探索を比較紙6枚・比較窓35個で実行し、その後は救済紙を含む8枚の構成だけで設計・注文処理を行う。
元の割り当て探索の目的関数は6枚の比較紙用なので、新しい表現力を完全には評価していない。
汎用紙が2枚増えるため、専用紙は184枚、共有する商品対は72対になる。取っ手窓は28個のまま。

共有可能性は、10080状態の表示をビット集合で絞り込み、両商品の要求を満たす状態が存在するかで厳密に判断する。
設計の汎用層費用は、満たす状態数を q として `0.35 * log2(10080 / q)` と見積もり、対の両方向を平均する。
これは各共有候補でBFSを行う費用を避けるための近似であり、実際の平均最短距離ではない。
注文処理では前述のBFSによる実際の最短手順を使う。

6枚専用の Interleave（汎用紙の間への穴埋め紙の挿入）は無効。通常の取っ手の穴埋め・複数紙の組の探索は維持する。
新しい設計が初期化できなかった場合は `hybrid_design_failure` を出し、そのケースを失敗として計測する。旧6枚方式への切り替えは行わない。

## パラメータと診断値

- `CLOCK_SCALE`: 改良元と同じ。すべての時計を倍率で補正する。
- 窓割り当て0.35秒、窓割り当ての登山0.40秒、設計の焼きなまし1.28秒、穴埋め用の登山1.34秒まで。1.80秒以後は軽い注文計画。
- `MAP_ITERS`、`GOPT_STEPS`、`ANNEAL_ITERS`、`CLIMB_ITERS`: 改良元と同じ固定探索回数の実験用設定。
- `RESCUE_Y`: 救済紙6の35窓の黒模様を整数で指定する実験用設定。既定は `0x365f993b3`。紙7はその補色。専用窓は紙6が0、紙7が1。
- `RESCUE_SUPPORT`: 救済紙が色を持つ比較窓の集合を整数で指定。既定は `0x418c01120`（8窓）。専用窓35は指定にかかわらず不透明。
- `rescue_y`、`rescue_support`: 実際に使った模様と窓の集合。
- `hybrid_states`、`hybrid_edges`: 列挙した状態数と合法遷移数。
- `hybrid_cache_builds`、`hybrid_bfs_edges`: 作成した目標集合のBFS表の数と、BFSで調べた逆辺の累計。
- `hybrid_plan_calls`、`hybrid_normalization_moves`: 汎用層の計画を呼んだ回数と、列挙した状態へ戻す操作を作った回数。採用されなかった計画も含む。
- `hybrid_build_sec`: 窓割り当てと汎用状態グラフの構築終了時刻。
- `hybrid_design_failure`: 初期化失敗なら1、専用紙の割り当て不整合なら2。

評価結果・時間制限上の適否は `trial_log.md` と[検証レポート](../../docs/chatgpt-multiroute-rescue-study.md)を参照。

## 汎用層の独立検査

`verify.cpp` は提出用の `main.cpp` 自体を読み込む検査プログラム。全不透明・部分不透明・専用窓のみ・既定の5構成を検査する。
各構成について12個の穴の条件で状態数の総当たりとbitsetのgoal数を照合し、1800個の任意8順序からの手順を1操作ずつ再生して可視性と最終表示を確認する。
これは汎用層の正当性検査であり、1024注文を通したスコア評価の代わりではない。

```sh
g++ -std=c++23 -O2 solutions/chatgpt-rescue-layer/verify.cpp -o /tmp/rescue-verify
/tmp/rescue-verify
```
