# chatgpt-edge-rewire

改良元: `solutions/chatgpt-multiroute`（元の紙設計・注文処理は `solutions/imp-910`）。

重複する商品表現を増やすとき、既存の単独紙だけを共有化する代わりに、2枚の紙を同時に書き換える。
単独商品 a の紙と、商品 b,c の共有紙を選び、前者を (a,c)、後者を (a,b) の共有紙へ変更する。
これにより a は2列の代表紙を選べ、b,c はそれぞれ1枚で表示できる。b,c を交換した割り当ても評価する。

紙の列は変えず、両紙の自列の取っ手の色も変えない。各共有紙はその列の接頭辞から作り直し、共有する2商品の異なる窓を穴にする。
旧 (b,c) で穴だった窓も、新 (a,b) の色が一致するなら不透明へ戻す。
汎用層で新しい両対を表示できることを確認する。この変更には互換グラフの三角形が必要なため、候補不足そのものも計測する。

設計時の費用は、汎用層の平均手数、取っ手の穴1個につき0.4手、列内の深さの和。
2列の一様な深さの全組合せに対し、変更前の3商品の費用と、変更後の「両葉の費用＋中心の安い方の経路の費用」を比較する。
汎用層の平均手数には対の両方向の平均を用いるので、中心 a の片方向の費用もこの平均で代用している。
深さの一様性・固定された取っ手費用を含め、設計用の近似であって実測の改善を意味しない。

見積利益の大きい順に、商品が重複しない最大8組を採る。方式の挙動を検証するため、既定では予測利益が負でも採用する。
経路ごとの helper table、同じ状態からの2経路の実計画、経路利用確率による将来費用の重み分配は改良元と同じ。
既存の代表紙の対応を b,c,a すべてについて更新してから helper table と将来費用を構築する。

## パラメータと診断値

- `REWIRE_LIMIT`: 採用上限。既定8。
- `REWIRE_MIN_GAIN`: 3商品の合計での見積利益の下限。既定-100。0にすると正の見積利益だけに限定できる。
- `rewire_tested`: 異なる列の単独紙・共有紙について試した割り当ての数。b,c の交換を別々に数える。
- `rewire_candidates`: 汎用層の整合性と取っ手の色の条件をすべて満たした割り当て数。
- `rewire_positive_candidates`: そのうち見積利益が正の数。
- `rewire_best_gain`: 最良候補の見積利益（3商品の合計手数）。候補0件なら0。
- `route_design_count`: 実際に採用した3商品の組数。
- `route_proxy_gain`: 採用した組の見積利益を256商品で割った値（手/注文）。
- `route_requests`、`route_selected`、`route_selected_move_gain`、`route_alt_helper_papers`: 改良元と同じ。
- 計画回数関連の診断値は、最終的に採用されなかった経路の模擬も含む。

評価結果は `trial_log.md` と[検証レポート](../../docs/chatgpt-multiroute-rescue-study.md)を参照。
