# R2 継続: 既存の計画を後処理候補から落とした損失

改良元 `solutions/argon-des-perf-latew105`。追加DPの第2解は候補の押し出しを防ぐと改善するが、生成と後処理の費用が大きい。そこで追加DPを作らず、既に生成済みの計画のうち通常の編集対象に入らなかったものを再利用する。

## 実装と仮説

既存の `collect_future` と同じ積層・移動紙列の同族判定で、通常計画・共同DP・チェーン・ヘルパーの候補を保存する。通常の候補一覧は変更しない。探索の最後に、未編集・別積層・raw評価値差1以内の候補を削除だけの安い編集へ回す。編集後に現在の勝者以下の評価値なら、既存の追加ejectで仕上げる。目的関数は不変で、将来注文を読まない。

## DP第1解だけを再利用した分離試験

PR #145基準 `20261106-062839_*`、200×2。rawscreen-v2（抽出直後DPのみ）は−0.000485±0.000394%、16/173/11、req 0.449314→0.453287秒。rawscreen-both-v2（修正後DPも対象）は−0.000172±0.000557%、28/145/27、req 0.452555秒。明確な改善はなく、DPだけではほぼ既存探索に吸収されている。

## 全種類への拡張

旧基準の小範囲確認 `20261106-064046_*`（PR #145、24×2）は−0.012%だったが、この範囲だけでは採用を判断しない。

PR #146基準 `20261106-064603_*`、保存設計 `20261106-062412_argon-des-perf-latew105`、24×2から200×2へ拡張。**−0.001681±0.001249%**、81/44/75。req **0.451509→0.461587秒**、固定設計のジャッジ平均増分+0.013611秒。外部負荷平均0.20・最大0.39コア、WA / self_wrong / op_label_errors = 0。

1ケースあたり約80.94計画を削除編集し、約1.50計画だけ追加ejectへ進む。追加分を含めたvalue_seed_gainは0.71606→1.11044、value_seed_savedは1.03→1.80だが、実現改善は約0.17手/ケースにとどまる。小範囲の効果は拡張すると縮んだ。

## 次の原因分離

安い編集後の評価差0という条件が厳しすぎる可能性を検証する。`planscreen-probe` はすべての未編集計画を独立にeject・中立探索まで仕上げ、同じ注文の複数候補の利得を二重加算しない最大利得も測る。出力と積層は基準へ戻す。結果により、候補を広げる価値と必要時間を判定する。

## 足切りを緩めた実測と判断

`20261106-065737_*`、24×2→200×2。全件WA / self_wrong / op_label_errors = 0。外部負荷平均0.33・最大1.19コア。

| 候補 | raw上限 / 削除後上限 | 平均log比 ± SE (%) | 勝/分/敗 | req_sec | 固定設計のジャッジ平均差 |
|---|---:|---:|---:|---:|---:|
| 基準 | — | 0 | 0/200/0 | 0.456069 | 0 |
| planscreen-gap2 | 2 / 0 | −0.005853 ± 0.001691 | 110/13/77 | 0.472014 | +0.022143s |
| planscreen-all | 無制限 / 0 | −0.007878 ± 0.001797 | 114/7/79 | 0.481109 | +0.034353s |
| planscreen-eject | 2 / 0.5 | −0.010104 ± 0.002032 | 125/2/73 | 0.478094 | +0.030144s |

追加ejectを許すと効果は伸びるが、約0.34%/ジャッジ秒で費用基準0.6%/秒を下回る。raw上限撤廃の追加利得は約0.002%に対し約12ms増で、さらに効率が悪い。候補収集の完全同一共通化も別途400出力で検証したが速度改善はなかった（`argon-req-collectonce/REPORT.md`）。通常2000件の採用比較へ進める候補はない。

単に最初の案が悪かったという結論ではない。候補押し出し、処理済み候補との重複、値差の足切り、全仕上げ時の潜在利得、削除のみとeject・中立探索の費用を分離した。候補を広げれば改善は残るが、それを取り出す費用が既存探索予算の価値を下回るため、この拡張は不採用とする。ヘルパー計画そのものを直接良くするR4は別項目として残す。
