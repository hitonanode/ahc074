背景ヘルパー計画を注文処理 `process` の候補集合へ統合する。従来の「通常計画を最終処理した後、各ヘルパーを個別に後処理する」二段階を廃止し、通常・ヘルパーの未加工計画を同じ費用で選ぶ。後処理、排出、中立変更、計画キャッシュを共有する。

ヘルパー生成と残りのハンドルの区間DPは従来のまま。共通候補幅は従来設定（通常2、拡張3）。紙の設計とDesignStoreは変更しない。軽量処理ではヘルパーを省略する。
`ng_helper_sec` はヘルパーの未加工計画生成のみ、`ng_base_sec` は共通後処理を含むそれ以外の時間。`joint_helper_wins` と `product_helper_wins` は未加工費用で暫定最良になった回数へ意味が変わる。他の指標、64窓の所有権監査、操作ラベルは継承する。
