# AHC074：自由な紙順、同時修正の価値関数、順列符号の検証

2026-11-02。基準は `imp-combo`、取得時の上流コミットは
`dee23c8fce0eba04e513478629402f20b843e9f0`。

## 結論

**今回の実装で imp-combo を上回る解法は得られなかった。提出版の置換は勧めない。**
既存の紙設計を利用しつつ、注文ごとに残す紙順を大きく変える独立した方策を実装したが、完成版のフィラー・補助紙・返却・先読みの強さに届かなかった。

研究として残す価値があるのは、次の三点である。

1. **複数窓の同時修正距離を終状態の価値に入れる。** 6枚の厳密な小模型では、窓別の費用を足す評価より明確によく、最適方策との差の大部分を学習係数なしで埋めた。ただし、192枚への単純な代表紙射影は実測で悪化した。小模型の利得を実際の改善として扱わない。
2. **注文境界の全紙順を固定した操作短縮の余地は小さい。** 調べた8,192注文の各開始時・終了時の全192枚の順序を保存する後処理では、可視性を考慮した下界から、短縮量の上限は316/8192手、約0.03857手/注文となる。数手の改善を狙う研究対象は、紙順を変える方策または紙設計そのものになる。
3. **単純な「4商品を3枚の順列で表す」案は棄却できる。** 2入力について全174,792,640組ずつを調べ、成立する4商品群はゼロだった。順列の情報容量だけでは印刷の整合制約を満たせない。

このPRは研究記録であり、優勝級の性能や現在の順位を更新したという主張はしない。

## 1. 何を変えたか

### 1.1 隣接3列を自由に混ぜる

元の列構造は、列の先頭を各ハンドルから独立に取り出せるため強い。一方、列の順を固定すると、各ハンドルの不一致を別々に直す操作が多くなる。

`chatgpt-free-triples` は隣接3列を一つのブロックとし、その中の全紙を自由な順序で持つ。ブロック間の順序は保つ。紙設計は imp-combo と共通だが、注文処理は新しい方策に置き換える。

- 要求紙Dを掘り出すとき、Dの不透明窓ごとに上にある遮蔽紙を数え、最少の窓から掘る。
- 遮蔽紙の挿入先と前の要求紙の返却先は、将来の掘り・色修正の見積りで選ぶ。
- Dを上げた後、実際に穴になっている1〜3窓だけを使い、見えている紙の移動を幅8・深さ4のビームで探索する。
- 探索の上界は、残る必要窓で色が合う最初の紙を固定し、その前の不一致紙を後ろへ送る有限な貪欲手順とする。移動先はその紙より下の最良位置を選び、ブロック末尾には固定しない。

重要な点は、Dが覆う窓を「その下の紙が見える根拠」として使わないこと。探索の各状態で、必要窓に本当に見えている紙だけを動かす。

現在の順序からDを見えるようにする厳密な最少手数は

\[
\min_{j:\,D\text{ が不透明}} b(D,j)
\]

である。ただし固定した前方ブロックや汎用層で覆われる窓は除く。ここでb(D,j)はDより上の不透明紙の枚数。最後にDが見える窓では、その遮蔽紙をすべて移動する必要がある。一方、その窓の最上位紙を順にDより下へ送れば、同じ枚数で合法に到達できる。

したがって自由順序版の掘りが高いとき、その状態に対する掘り探索を強化しても改善しない。前の注文でどの順序を残すかを改善する必要がある。詳細は `../chatgpt-free-triples/THEORY.md`。

### 1.2 対照と派生実装

| 実装 | 共通方策からの差分 | 調べる仮説 |
|---|---|---|
| fixed-columns | ブロック幅1 | 元の高度な注文処理を外した影響と、列自由化の効果を分離 |
| free-triples | ブロック幅3、手数＋4×将来費用 | 同時穴修正が取り出しに不利な順序を残す損失を上回るか |
| free-context | 将来費用をブロック使用確率で正規化 | 使用されない注文の自己遷移が評価を薄めていないか |
| free-lex | まず手数最少、その中で将来費用最小 | 将来のために余分な手を払わず、同点の終状態だけ選べばよいか |
| free-fill | 深いブロックからのフィラー、据え置き、直接要求を追加 | 列自由化と複数ブロックの穴埋めを共存させられるか |
| free-joint | free-lexの同点評価に同時部分要求距離 | 窓別評価の見落とす相互作用を小模型から持ち込めるか |
| local-macro | imp-comboの計画末尾だけ3列同時再探索 | 既存機能を全部残して局所的な自由化を導入できるか |

free-fillは重ならないブロック区間を最大3枚のフィラーで覆い、次のDの取り出しを邪魔せず要求色も合えばフィラーを残す。利益は同じ自由順序修正で省ける手数から移動・返却の見積り1.7手を引く。これは調整を詰めた値ではない。

free系では、元の複数の返却・据え置き計画の比較、細かい区間への連鎖フィラー、汎用紙の間への補助紙、汎用層の先読み、元の操作列短縮を省いている。free-fillも限られたブロック単位の機能を戻した段階である。従ってimp-comboとの差全体を列自由化の効果とみなしてはいけない。その切り分けのため、同じ簡略化方策の幅1対照を設けた。

local-macroは元のフィラーや補助紙を含む計画を作った後、最後のハンドル修正の区間だけを幅8・深さ3で再探索する。3窓以外の表示を変えないこと、紙の再分類とフィラーの合法な返却を検査し、元と同じ終状態評価で全体を採否する。追加探索は倍率付き経過1.77秒で打ち切る。`macro_saved` は局所候補を選んだ段階の値であり、最終スコア差ではない。

## 4. 同時修正距離という価値関数

### 4.1 小模型では何が分かったか

1ケースの実際の紙から、隣接3列ごとに白・黒を1枚ずつ取り、6枚・720順列の模型を作った。28ハンドル中27個に対応する9群。256商品の専用紙の穴から27種類の部分要求の分布を作り、必要窓だけで可視な紙を動かす合法グラフを使う。

各要求qについて、状態sから要求を満たす状態tへの最短距離をd_q(s,t)とすると、相対価値hに対するBellman作用は

\[
(Th)(s)=\mathbb E_q\min_{t\models q}\{d_q(s,t)+h(t)\}
\]

になる。逆グラフ上の多始点Dijkstraと相対価値反復で計算した。状態遷移は厳密だが、有限回の価値反復には残差があるため、最適平均費用の上下界を併記する。

| 方策 | 9群合計の模型内修正費用 |
|---|---:|
| 各列を独立に操作 | 5.093541 |
| 最少手数、その中で窓別Fが小さい状態 | 4.949492 |
| 最少手数、その中で同時修正距離F_jointが小さい状態 | 4.727425 |
| 真の相対価値の近似解hを使う方策 | 4.644873 |
| 最適平均費用の数値的Bellman上下界（外向きに表示丸め） | [4.644871, 4.645710] |

ここでF_joint(s)は「将来の部分要求を合法に同時修正する最短手数」の期待値。空でない要求に条件付けた値で、学習係数は使わない。表の費用は、各群の非空要求あたりの定常費用に要求発生確率を掛け、9群について合計した、元の1注文あたりの値である。Bellman上下界は倍精度の残差から求めた数値で、浮動小数点誤差を区間演算で保証したものではない。独立列から最適方策までの模型内利得の約81.6%を一段先の距離で得た。26距離特徴の回帰や群をまたぐ回帰は、単純なF_jointを上回らなかった。

この模型には、長い列の重複紙、Dの掘り・持ち上げ・返却、汎用層、群間フィラーがない。また要求をi.i.d.とし、公式の直前商品除外を省いた。**5.093541−4.644873をimp-comboの手数から引くことはできない。** 詳細と再現用の模型は `../chatgpt-block-mdp/`。

### 4.2 192枚への移植は失敗した

free-jointは各列の最初の白紙・黒紙を取り出して6代表へ射影し、その印刷型と順序でF_jointをキャッシュする。実装では、要求が空でない確率をf_gとしてf_g F_jointを使う。これは元の1注文あたりの無条件期待値であり、同じ単位で計算した全紙の掘り距離の項に加える。窓別の色深さの項を置き換え、二重加算はしない。GOALの同点選択以外はfree-lexと共通。

|---|---:|---:|
| imp-combo | 10834.25 | 10.580322 |
| free-lex | 12016.50 | 11.734863 |
| free-joint | 12205.25 | 11.919189 |

free-jointのfree-lex比は **+1.556 ± 0.183% log差、0勝0分4敗**。E=0、WA=0。全紙設計は同一で、BFS計算予算の打ち切りは全4件でゼロ。

1ケース当たりの内訳では、掘りが102.5手、穴修正が86.25手増え、汎用層の操作数は一致した。局所ビームの短縮量は増えても、以後の状態が悪くなった。6代表が落とす長い同色列の深さ、修正と掘り・返却の結合、有限幅探索のGOAL集合の違いが候補だが、寄与は切り分けていない。

## 5. 最終紙順を固定した後処理の限界

同じ新規生成4ケースをimp-comboで2回実行した計8,192注文を解析した。独立8ケースではない。runは `20261101-160151_imp-combo` と `..._imp-combo-2`。

操作前後で一度も動かさない紙の集合Uは共通部分列をなすので、単純な下界はK−LCS。しかし可視性を無視している。

動かす紙xの初回移動を考える。初期順でxより前にあるUの紙は、その時点でも必ずxより前にある。それらがxの不透明部分を全て覆うなら、xを初めて動かすこと自体ができない。従ってUには

\[
\forall x\notin U:\quad
\mathrm{opaque}(x)\setminus
\bigcup_{u\in U,\ u\prec_{before} x}\mathrm{opaque}(u)\ne\varnothing
\]

という必要条件がある。この条件を満たす最長の共通部分列をL_visibleとすれば、合法な操作数はK−L_visible以上。同じ紙を何度動かす計画でも成立する。

| 注文当たり | 1回目 | 2回目 |
|---|---:|---:|
| 実際の操作 | 10.59888 | 10.60425 |
| K−LCS | 8.43335 | 8.43970 |
| 見かけの短縮余地 | 2.16553 | 2.16455 |
| 強化下界を考慮した短縮余地の上限 | 0.04028 | 0.03687 |
| 合法な1紙1移動合成で実際に削減 | 0.00415 | 0.00317 |

全対象で下界探索が完了し、下界の打ち切りはゼロ。操作合成側には34件の打ち切りがあるが、316/8192 = 0.03857421875手/注文という上限には影響しない。小さい300例では下界計算を全部分集合の列挙と照合した。

これは測定した前後の紙順に対する保証であり、すべての解法や未知入力に対する下界ではない。特にlocal-macroや自由順序版は終状態を変えるので、この0.03857に制約されない。詳細は `../chatgpt-eval/relocation-notes.md`。

## 6. 順列符号による紙の節約

q商品の表示をm枚の紙の異なる順列で表す案も検討した。順列が多くても、1窓の最上位不透明紙の色を全商品で矛盾なく印刷できるとは限らない。

固定した商品ごとの順列に対して、1窓の実現可能性は厳密に判定できる。白を要求する商品の先頭と、黒を要求する商品の先頭に同じ紙が現れたら、その紙は必ず穴。これを取り除いて繰り返し、矛盾なしで止まれば印刷を構成できる。全部消える場合は不可能。

3枚の6順列から4商品へ割り当てる6P4=360通りを全列挙すると、1窓で表せる4bitの色パターンは最大10種類。公式ケース0と新規ケース100000では、全C(256,4)=174,792,640群を各々調べ、現れる64窓の色パターンが10種類以下となる群自体がゼロだった。

これはその2入力の全商品選択を尽くした否定結果。全将来入力について不可能という証明ではない。6枚/7商品では成立する小例を得たが、256/192の必要な圧縮比に届かない。6枚/8商品、8枚/11商品の探索では完全な符号を得ておらず、合法なアクセスも実装していない。現時点で有望な提出方針とは扱わない。詳細は `../chatgpt-permutation-code/REPORT.md`。

## 7. 次に研究するなら

優先するのは、**長い実ブロックの取り出しと修正を同じ価値関数で評価すること**。今回の自由化で生じた費用の付け替えを解決する必要がある。

1. 6代表への射影をやめ、3窓での各不透明型・同色連続長・要求紙の分布を保った状態圧縮を作る。現在の正確な掘り距離を一段先の項として足すだけでは、悪い順序が何注文も残る損失を評価し切れていない。
2. 小模型の要求に「ある紙IDを取り出す」「前のDを戻す」イベントを加え、修正専用のMDPと何が変わるか確認する。まずオフラインでモデル誤差を測り、2秒で使える評価へ落とす。小模型の良い結果から直接組み込まない。
3. imp-comboのフィラー・補助紙を含む状態を保って、異なる終状態の候補を比較する。今回のlocal-macroは末尾だけ、幅8・深さ3の小さい近傍なので、改善できないことは自由順序全般の否定にはならない。ただし現状の計算量増を正当化する利得はない。
4. その方策の定常費用が改善してから、紙設計の目的関数へ同時修正の価値を入れる。現在の紙設計は固定列向けのままなので、自由化に有利な印刷や群分けを探索した証拠はまだない。

研究価値は「小模型で相互作用を入れた価値が効く」という限定的な根拠にある。192枚でbaselineを上回る見通しが立った、あるいは育てれば必ず勝てるとは言えない。限られた残り時間でこの枝に大きく投資する前に、2の模型を拡張した時点で利得が残るかを確認するのがよい。

## 8. 評価の条件と再現

- g++ 13.3、C++23、`-O2 -DCLOCK_SCALE=1.1`。1並列で、同じケースの各解法を続けて実行し、実行順はケースごとに交代する。
- Rust/Cargoのない環境のため、公式ソースから対話と採点を移したC++テスターを使用。公式Rustバイナリそのものではない。既存 `scripts/pahcer_run.py` の比較・記録機構を使用し、共通ファイルは変更していない。
- テスターは次の注文を1つずつ送る。新解法が将来の注文列を読むことはない。可視性、操作範囲、余分な出力、異常終了など23件のテストを行い、各本番比較も別実装の可視性付き再生で全手を検証する。
- ケースID100000〜100063は、Pythonの乱数seed74020261102〜74020261165から新規生成。重み32の64bit商品を256種類、注文は直前と異なる商品の一様抽選。Python乱数なので公式ChaCha20と同じseedの同じ入力にはならない。ケースIDは公式seedと区別する。生成器と全入力hashは `../chatgpt-eval/generated-inputs-manifest.json`。
- 開発16ケースは100000〜100015。最終の未使用32ケースは100032〜100063。最終比較の前にソースを凍結し、そのケースを使った係数調整は行っていない。
- 比較対象ソースの上流SHAは冒頭のコミット。ローカル記録のgit SHAは部分取得した作業用スナップショットなので、上流SHAとは異なる。結果CSVに実際にコンパイルしたmain.cppのSHA-256を保存する。
- 通常の時間打ち切りでは同じ固定乱数でも探索回数が変わる。固定設計比較では紙設計hashの一致で方策差を確認し、通常時間比較は別表として扱う。
- このマシンとAtCoderのCPU・コンパイラは異なる。実時間は参考値で、AtCoder上のTLE適合性の証明ではない。

### 保存出力の不整合と除外した比較

初期の `20261101-161140_*` と `20261101-161818_*` では、実行直後に読めた得点に対し、保存stdout/stderrが後で途中までしか残らない不整合を検出した。原因を確定したとは主張せず、この2バッチは比較結果から除外した。

その後、全出力をPIPEで親メモリに捕捉し、そのbytesから採点・独立再生を行い、集計前に入力と全出力を単一gzipへatomic保存してhashを再読検証する方式に変更した。通常のout/errも親から保存する。本文の成績表はこの方式で検証できたバッチだけを使う。保持した出力からのファイル復元を行う場合も解法は再実行せず、その事実を記録する。詳細は `../chatgpt-eval/infrastructure-incident.json`。

下界解析の旧8実行はPIPE方式以前のものだが、保存済み入力・出力を全件再生し、得点と解析中の実手数が一致することを事後検証した。証拠は `evidence/legacy-lcs-baseline.json.gz`。PIPE方式の実行時捕捉とは区別する。
