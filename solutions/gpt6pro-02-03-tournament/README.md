# gpt6pro-02-03-tournament

改良元: solutions/gpt6pro-02-02-adaptive

## 改良元との差分

- 下位 28 窓を「8 枚の総当たり」で表示する: 基礎紙 C_0〜C_7 の組 (u, v)（u<v）ごとに窓を 1 つ割り当て（8C2 = 28 窓）、その窓は C_u が 0、C_v が 1、他の 6 枚は穴。窓 (u, v) の表示は C_u と C_v のどちらが上かで決まる。注文が要求する 28 bit は基礎紙の順序制約の有向グラフになり、基礎紙だけで表示できる必要十分条件はそのグラフが非巡回であること。前景の紙でその窓を覆えば、対応する辺を消せる（循環を壊す被覆）。基礎紙は上位 36 窓がすべて穴。
- 基礎紙の最短の並べ替え: 最下段以外の基礎紙は必ず見えている（自分より下の紙との比較窓を持つため）。「動かさずに残す紙の集合」F（2^8 通り）を全部調べ、F の中で現在の相対順と矛盾する必須経路がなく、最下段の条件（最下段は見えないので、sink でなければ sink を 1 枚動かして最下段へ）を満たす最大の F を取ると、最小の合法な手数 8 − |F| と手順が求まる。
- 紙の配分: 基礎紙 8 枚 + 白背景の補助紙 1 枚、上位 36 窓（内部の窓 28〜63）に三角形の群（窓 28〜47 は 2 枚ずつ、48〜63 は 8〜9 枚ずつ）で計 183 枚。前景の紙は基礎紙の前にも途中にも差し込む（未確定の窓をすべて正しく出せる基礎紙は先に確定でき、その窓は後の紙に一致を要求しない＝グラフの source を取り除く）。
- 学習を「巡」に分ける: 上位の群の候補を、まず各群 4 枚ずつ全群で作り、巡の最後に商品ごとに最良の 1 枚を選ぶ（作った直後には確定しない）。残差を更新して各群に 4 枚追加する第 2 巡、その後に残りの候補と下位の群で全 256 商品の作り方を完成させる。後半の紙にも上位窓を塗る余地を残すのが目的。
- 注文時: 前の前景紙を取り出し窓の高い順に戻す → 基礎紙を上の最短手順で並べ替え → 群内で必要な共有紙を露出 → 新しい前景紙を取り出し窓の低い順に差し込む。幅は最大 128 のビーム探索で、残り CPU 時間と残り注文数から幅を調整する（最小 32、時間切れで 0）。探索がうまくいかない注文は設計時に保存した作り方を使う（teacher fallback）。設計で全商品の作り方を検証できなければ、1 bit ずつの汎用の設計に切り替える。
- 時間: CPU 全体 1.80 秒（探索は 1.76 秒まで、学習は 1.17 秒まで）。

## パラメータ

- 基礎紙 8 枚（PAL=8）、下位窓 28（setup(28)）、HEAVY_START=48、POWER=1.7、学習の試行（starts=128, probes=24, λ=6）、巡ごとの候補数 4 / 4（環境変数 FIRST_SLOTS / SECOND_SLOTS、未設定なら 4）、最大ビーム幅 128、CPU 上限 1.80 秒。学習の乱数は入力の商品のハッシュで初期化する。
- stderr: `design_cpu`、`total_cpu`、`universal`（1 なら汎用設計に切り替えた）、`teacher_fallback_queries`（保存した作り方を使った注文数）、`mean_beam`（注文あたりの平均ビーム幅）。

## 移植について

出所: main checkout の other_agents/gpt6pro-02.md と gpt6pro-02-layered_barcode_graph_bundle.zip（layered_barcode_tournament.cpp。zip の README が提出版と明記）。元から reactive 形式で、引数なしで提出用の設定が動く。未来の注文は読まない。環境変数（FIRST_SLOTS, SECOND_SLOTS, NO_ADAPT, FORCE_FALLBACK, TRACE_PATH, PROFILE）は未設定のときが提出用の既定。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた。
- 最後に上記の統計を `名前 = 数値` の形で stderr に出すようにした。アルゴリズムは不変。自己テスト・入力生成用のコードは残してある。
- 報告された成績（独自生成ケース、公式 seed とは対応しない）: 改良元と同じ 5 ケースで 13.678 → 13.395 手/注文（全ケースで改善）、別の 3 ケースを合わせた 8 ケースで平均 13.384 手、最大 28 手、誤り 0、CPU 約 1.75〜1.76 秒/ケース。

同じ zip の対象外のファイル: graph_research.cpp（研究用のシミュレータで reactive ではない。報告 13.346 手）、baseline_matched_driver.cpp（改良元の自己テスト生成器だけを変えた比較用）、native_oracle_verifier.cpp（基礎紙の最短手数を全状態の逆向き BFS と照合する検証器。6 枚・8 枚で計 3,139,200 組が一致と報告）、validate_protocol.py・replay_trace.py（独自の検証器）、math_notes_ja.txt（構成の説明）。
