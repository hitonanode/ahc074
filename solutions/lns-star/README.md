改良元: solutions/deval-helper-wide

Task 7 phase 1 の研究版。注文処理は改良元と同一。

通常の8完成候補を作った後、比較紙1枚に接続する比較組の窓と選んだ取っ手窓を解放する。領域内の窓割当・極性を破壊し、旧ペア喪失数の足切りをせず窓を焼きなます。新しい互換グラフで壊れたペアと隣接する単独商品を再マッチングする。領域外の有効ペアと列を初期配置に保持し、短い列焼きなましと通常の仕上げを行い、完成後の V で採用する。

LNS_MODE=1 はこの近傍、2 は通常の追加 anneal branches、3 は通常の追加 refinishes。LNS_STEPS が追加回数。LNS_MAP_ITERS / LNS_ANNEAL_ITERS / LNS_HANDLES / LNS_GROUPS が修復予算と領域。全て固定回数で、時間による切替はない。既定の LNS_STEPS=0 は改良元と同じ設計を返す。

研究版は --no-record で実行する。@lns_step / @lns_candidate に各修復の変化と V を記録する。通常の計測・注釈・DesignStore も維持する。

追加の研究スイッチ: LNS_KICK=-1 は領域全体のシャッフル、0 は親の窓配置から足切りなしで修復、正値はその回数の kick。LNS_FIRST_SEG は列焼きなましの開始区間。LNS_RELEASE_MODE=1 は初期破壊で壊した全ペアを修復中も解放し、2 は領域の窓で色が異なる全ペアを解放する。LNS_KEEP_COLUMNS=1 は組が変わらず取っ手も変わらない紙の列を修復の初期配置に保つ。Mode 4 は全パイプラインの独立再実行、mode 5 は窓を変えず完成済み最良割当から再焼きなましする対照。

LNS_DUMP_DIR と LNS_DUMP_IDS（カンマ区切り）で、標準評価中に生成した完成候補を DesignStore 形式で研究ディレクトリへ保存できる。ID 1000 は追加探索前、1001+j は j 回目終了時の最良状態、2000+j はその回の局所候補の最良状態。再生は必ず標準 pahcer_run.py を使う。領域外の窓が不変、全商品が一度だけ割り当てられ71ペアであることを assert する。

追加の切り分け: LNS_PREFERRED_PAIRS は先に指定した新ペアの互換化を促す。LNS_SOFT_PENALTY は窓修復の途中だけ不適合ペアを有限の罰則で扱う（完成設計は厳密に合法）。LNS_MIN_WINDOWS は親と指定数以上の物理窓が異なる修復結果を選ぶ。LNS_TRANSFER_HOLES は親の追加穿孔を合法な部分だけ新設計へ引き継ぐ追加仕上げ。@lns_prefix は各固定反復数を終えた累積時刻と最良V。
