# gsel

改良元: solutions/clean-base

汎用窓・ブロック・Y_b の選び方（choose_blocks）を 4 回走らせ、そのうち「整合する対の貪欲マッチングでのハンドル窓の違い」が最も小さいものを採る。

- 動機（trial_log の ceil-）: 注文を乱数で模擬して設計の期待手数を測ると、choose_blocks の乱数だけを変えた設計の間で、焼きなましの後の期待手数が sd 約 0.4% ばらつき、それは焼きなましの乱数を変えても持続する（G の選び方そのものの差）。choose_blocks の目的関数（ブロックごとの整合する対の割合の対数和）はこの差をほとんど予測しない。
- 選択の指標 greedy_pair_obj: 選んだブロックと Y_b で整合する目標の対だけを候補に、ハンドル窓で違う窓の数が少ない順に貪欲にマッチングし、必要な対の数（P − 専用紙の枚数 = 70 組）の平均の違いを返す（足りなければ 1 組 10 の罰）。焼きなましの後の期待手数との相関はケース内で 0.54。
- 候補 0 は従来どおり設計の乱数 rng で作り（その後の初期割り当ての乱数も rng のまま）、候補 1〜3 は別の seed（12345 + 1000 i）。
- choose_blocks の best_y を速くした（出力は同じ）: Y_b とその補色は整合する対の数が同じで、最初に見つかる最良の Y_b は最上位ビットが 0 なので、その半分だけを試す。数え上げを int の固定長配列にした。1 回 65 → 15 ms ほどで、4 回走らせても焼きなましの開始は clean-base とほぼ同じ時刻（約 0.09 秒）。
- 主な定数: kGselK = 4（候補の数）。stderr: `gsel_obj`（採った候補の指標）、`gsel_pick`（採った候補の番号）。
