# astra-gproxy

改良元: `solutions/as6-imb0gb`。

窓の割り当ての目的だけを変更する。対の貪欲選択のキーは元のままにし、選んだ 71 対全体に対して、元の目的から次の二項を引く。

- 0.001 × ハンドル窓の色の偏りの二乗平均。各窓の 256 目標中の黒の数を n として、25 ハンドルの (n−128)² を平均する。穴の要求を偏らせやすい窓をハンドルに残す。
- 0.07 × ハンドル別の対の違いの標準偏差。選んだ対のうち、各ハンドルで違う対の数を数える。違いを一部のハンドルに集めることで、違いの少ないハンドルを浅く配置する余地を増やす。

前者は窓ごとに前計算し、8 回の表引きで求める。後者は 71 対のビットマスクを 7 段のカウンタに集計し、ビット数から和と二乗和を求める。

探索時間は元と同じで、割り当て 0.50 秒、山登り 0.61 秒、設計の焼きなまし 1.305 秒、穴埋めの山登り 1.36 秒まで（CLOCK_SCALE 込み）。設計の後段と注文処理は元のまま。新しいフォールバックは追加しない。

stderr の gproxy_before / gproxy_after は、割り当ての山登り前後の補正済み目的。model_cost とその内訳、end_sec、fast_requests などは元と同じ意味。

研究結果と検証は REPORT.md。build_probe.py / build_variants.py は固定回数の調査用コードを作る。run_experiments.py は最大 12 子プロセスで模擬を実行し、run_tester.py は最大 6 組（テスターと解法で 12 プロセス）の公式テスターを実行する。研究用の MAP_SEED は提出用 main.cpp には入れない。
