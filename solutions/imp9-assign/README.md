# imp9-assign

改良元: solutions/imp-lean

窓の割り当て（assign_windows）の評価を、solutions/gpt6pro-09-01-legal-dist と同じ「実際に紙を共有する 70 対」の費用に替えた。

- 元の評価: 焼きなまし（0.50 秒まで）は「各目標の互換で近い相手の重みの和（次数）の (次数 + 0.2)^0.7 を全目標で足したもの」を大きくし、山登り（0.61 秒まで）は互換な近い対の貪欲マッチング（ハンドルの違い + 閉包の関係の数）を、次数の和が 5% 以上下がらない範囲で小さくしていた。紙を共有するのは 70 対（140 目標）だけなので、次数の和は「どの対が実際に組まれるか」を見ていない。
- 新しい評価: 互換で近い対（距離 26 以下）を費用の小さい順に並べ、頂点が重ならない 70 本を貪欲に選び、その費用の平均（70 本取れなければ 1 本あたり 10 を加える）を小さくする。対の費用は Design::initialize の対の選び方と同じ形で、0.65 × ハンドルでの違い + 汎用層の期待手数（対の 2 目標それぞれの平均の和）+ 0.04 × 全窓での違い。費用は 3600 倍した整数で、基数ソート（9 ビット 2 回、安定）で並べる。焼きなましの手・温度（0.2 → 0.005）・時間の区切りは元のまま。山登りも同じ評価で、次数の下限の制約は外した（09 と同じ）。
- 汎用層の期待手数は、最下段の紙を動かさない合法な距離での 720 通りの順序からの平均（Comparator::mean_moves と同じ値）。焼きなましの中で毎回引けるように、6 要素の半順序 318 種類の値の表（kPosetClasses。09 の表を、imp-lean の mean_moves と全件一致することを確かめて埋め込んだ）を、起動時にラベル付きの 130,023 通りのハッシュ表（PosetSums）に展開する。
- 速さ: 09 は手ごとに全部の互換な対の閉包と表を引き直していたが、ここでは対ごとに表の値（WindowPairs::rel）を持ち、evaluate_move が関係の変わった対だけ引き直す。次数の計算（pow）がなくなった分、割り当ての反復は imp-lean とほぼ同じか少し多い。

設計の対の費用（Design の gcost）は imp-lean のまま（片側の 2 倍）。

stderr: `gobj_before` / `gobj_after` は山登りの前後の上の評価（70 対の平均費用。imp-lean の gobj とは別の量）、`map_iters` は割り当ての焼きなましの反復数、`gopt_steps` は山登りの反復数。
