# astra-cap-joint

改良元: `solutions/astra-cap`。

キャップに任せる1窓を、専用紙の実際の列・共有対・穴の費用を見て選び直す。比較器6枚・汎用窓36・ハンドル27窓・専用紙185枚の構成は変えない。

設計SAの4区間の間、計3回、現在のcap座標と各ハンドル座標を交換する27候補を調べる。専用紙の共有対、所属列、ハンドルの順番はその候補評価中は固定する。新しいハンドルを受け持つ列で、全ての共有対が同色であり、白黒両方の紙が残る場合だけ許す。既存の `Design::cur`（列の取り出し費用、穴の修復費用、汎用操作費用）を全体から厳密に再計算し、最も改善する交換を1つ採用する。その後、残りのSA区間で列と共有対を再調整する。内側のAVXによるSAは変更しない。

内部表現ではcapを常にbit63に置く。採用時は全目標のbit63と対象ハンドルのbitを交換し、出力時の物理座標対応表も同じ2座標で交換する。汎用36窓の座標・模様は変わらないため、既存の汎用互換表と距離表をそのまま使える。オンライン操作と最初のcap移動1手も改良元と同じである。

時間配分は改良元と同じ。区間間の座標評価時間も設計SAの時間枠に含める。追加の診断値は `cap_joint_tried`（評価した座標数）、`cap_joint_valid`（列の成立条件を満たす候補数）、`cap_joint_accepted`（採用交換数）、`cap_joint_gain`（各採用時のモデル費用減少の合計を256目標で割った値）。`cap_window` は最後にcapが受け持つ物理座標を示す。
