改良元: `solutions/esw-colmdp`。

固定設計で標準出力を保つ注文処理の高速化。探索候補・列挙順・浮動小数点加算順を保つ。設計・CLOCK_SCALE・LOCAL_BENCH・紙属性・操作ラベル・設計の保存と読み込みを継承する。

- 正規化では列外の紙だけを集めて二度目の全紙走査を省く。
- 補助紙の回収可能性は上から一度走査して判定する。
- 1→1 修復のアンカーが端点だけで揃った場合は後続のアンカーを作らない。
- 2→2 修復では第3所有者まで確定した後の窓計算を省く。
- 列 MDP の部分列を種類ごと2ビットと長さの目印で表し、列ごと16個の値を保存する。列挙した種類の列を完全に照合するので値は近似せず、元と同じ F 値を元の順序で加算する。
- 同じ積層での補助紙の列内深さを一度に求める。filler の各開始レベルの節約手数は整数の差分で求める。

`COLFAST_PROFILE=1`（ソースのマクロ）で包含時間・排他時間・呼び出し回数を stderr の `cfprof_*` に出す。CLOCK_SCALE 適用済み。既定では計測コードをコンパイルから除く。詳細は [REPORT.md](REPORT.md)。

積層とその保存状態を192バイトの固定配列で持ち、動的確保と整数配列のコピーを減らす。紙の位置は memchr で探す。設計保存形式は変えない。

次状態価値は列内の紙順と generic 層より下の補助紙の紙・レベルを完全一致で照合して256個まで保存する。元の加算順で計算した double 自体を再利用する。`cf_value_hits/misses` が一致・不一致の件数。

上端ペナルティが0のため同じ計画になる返却モード1・2は、モード1のシミュレーション結果をモード2でも使う。全候補の採点と登録は元の順序で実行する。

次状態価値の計算ではキャッシュ照合用に作った列内の紙列を再利用する。紙・深さごとの `adaptive_weights[k] * depth / P` を元と同じ式で前計算し、積層順の加算は変えない。
