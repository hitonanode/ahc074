D1の測定用。Hungarian後のペア・列・ハンドル順を固定し、汎用層の事後再最適化の余地を調べる。
既定では測定結果を設計へ反映せず、通常の設計と注文処理を続ける。時間制限を超える予算は `--no-record` で測定する。

- 汎用窓1個または2個のシート対・極性を全列挙する。6枚の全15比較辺が残り、全ペアが整合するものだけを採点する。
- 汎用窓とハンドル窓の交換について、全30通りのシート対・極性を調べる。列の自分のハンドルでペアの色が一致すること、列の両色の存在も検査する。
- `ARGON_D1_EXTENDED=1` では、上の窓交換に別の汎用窓のラベル変更を加えた全列挙も実行する。
- `ARGON_D1_BLOCK=3`〜`5` では、指定個数までの汎用窓のラベル同時変更を全列挙する。
- `ARGON_D1_APPLY=1` の測定では、列・穴・汎用層の総モデル費用が最小の候補を設計へ反映する。
  `d1_oracle_delta` が探索全体の最良差、`d1_applied` が変更したケースの印。
- `ARGON_D1_GROUP_ITERS=N` は、同じ比較辺を使う全窓をひとまとめにして、辺群1〜3個の向き・割当を同時変更する焼きなまし。
  4種類の初期温度で各N回、不整合を罰点として一時的に許し、全ペアが整合する候補だけを保存する。
  `d1_group_*` は試行・受理・整合候補・改善候補数と最良差。
- `ARGON_D1_STEADY=1` は、見つけた全整合候補を、現行set_genericの720状態の定常費用で選び直す。
  単独紙の注文では汎用層の状態を保つモデル。紙の名前の一斉置換は重複として除く。
  ハンドル交換の列・穴費用も加え、均一順序モデルで悪化する候補も調べる。
  `d1_steady_*` は候補数・改善数・基準値・最良差・一様順序費用との差・定常分布の残差と反復数・時間。
  このモードの `d1_oracle_delta` とAPPLYの基準は定常費用であり、通常のmodel_costとは異なる。
  連続する同一目標がないことは費用の256/255倍で反映する（定常分布は同じ）。
  `d1_steady_dominated` は全ペアの関係を強めるだけで列・穴費用も下がらない候補数。
  `d1_steady_dominated_better` / `d1_steady_selected_dominated` は、その中で方針の定常費用が下がった数と選ばれた印。
- `d1_*_candidates` / `d1_*_feasible` / `d1_*_improved` は候補数・全制約成立数・元の費用から改善した数。
  `d1_*_best_delta` は元の設計からの最小費用差（1注文あたり）。負が改善。
  `d1_*_blocks` は調べた窓集合の数。candidatesは循環による部分棄却を通過した候補数。
  `d1_baseline_gc` はPosetSumsで再計算した汎用層費用、`d1_sec` は測定時間。

既存のログ・ラベル・プロファイラ・予算スイッチ・CLOCK_SCALE・LOCAL_BENCH・DesignStoreを維持する。
追加の段の目印と目次を入れる。評価とコンパイルの重複を防ぐため `bin/g++` は評価と同じロックを使う。
