# 設計の反復回数の固定（esw-fixiter）

改良元: solutions/esw-pace

改良元の設計は、各段を締め切りの時刻（時計の読み）で打ち切っていた。この解法では、設計の段の反復回数を定数として埋め込み、設計の結果が経過時間（マシンの速さ・負荷）に依存しないようにした。回数は、ジャッジ（Clang）で設計がおよそ 1.3 秒で終わる量にした。

## 変えたこと

- **窓の割り当て・その山登り・焼きなまし・filler climb を固定回数にした**（main.cpp の「Design iteration counts」）。
  - 窓の割り当ての焼きなまし: kMapIters = 450000 回。G を減らしたやり直しでは kMapRetryIters = 160000 回（改良元では 0.162 秒）。
  - 割り当ての貪欲マッチングの山登り: kGoptSteps = 133000 手。
  - 設計の焼きなまし: kAnnealIters = 14900000 回。改良元と同じく 4 区間に等分する。温度は回数の進み具合で下げる。
  - filler climb: kClimbIters = 38500 回。
- **時間で打ち切っていた残りの段は、最後まで行う。**
  - 再割り当て（Hungarian）は常に 4 回（改良元は最大 4 回で、平均 3.2 回）。
  - 穴あけは候補を 1 巡する。
  - 補助紙の表は常に最後まで作る（改良元は 1.305 秒で諦めていた）。
  - 初期化の期限もなくした（改良元でも期限に近づいたことはない）。
- 設計の段は、時計を判断に使わない。stderr に出す `*_sec` は記録だけ。
- 注文処理のペース配分（Pacer）は改良元のまま残した。終わりの見込みが 1.85 秒を超えそうなときだけ後処理を省く、TLE の保険。LOCAL_BENCH では改良元と同じく常に手間 0。
- 実験用の環境変数 MAP_ITERS / GOPT_STEPS / ANNEAL_ITERS / CLIMB_ITERS は、回数の上書きとして残した。0 か未設定なら上の定数。GOPT_STEPS / CLIMB_ITERS = −1 で山登りなし。
- 改良元の kDesignScale（PACE_DESIGN_SCALE）は使わなくなった。代わりに、マクロ ITER_SCALE（既定 1.0）で 4 つの回数をまとめて何倍かにできる（計測用のコピー向け）。

## 回数の決め方（calibrate.py）

- 改良元の手元の評価（20261104-153439・160615・162633・163016 の esw-pace）で、各段がケースごとに何回反復したかを集計した（iter_stats.py）。
  - 窓の割り当てと山登りは、1 回の重さがケースで大きく違う。同じ seed の 2 回の run での回数の相関は 0.66 / 0.97、map の回数は 231k〜17M。
  - 焼きなましと filler climb の回数のぶれは、ほぼマシンのぶれ（相関 0.12 / 0.07）。
- ジャッジの速さは、AtCoder のコードテスト（esw-pace、seed 0）での回数から求めた。
  - Clang: map 355k、焼きなまし 16.1M。
  - GCC: climb 34.6k。Clang ではこれの 1.13 倍と仮定した。
  - 山登り（gopt）は、map と同じ評価を使うので map と同じ比とした。
  - これを手元の seed 0 の回数で割った比を、全ケースに当てはめた。
- 各段の平均の時間が改良元のジャッジでの時間の 1.02 倍になるように、回数を決めた。式は、比 × 全ケースの調和平均 × 1.02。
- 見積りでは、ジャッジ（Clang）での設計の終わりは、平均 1.30 秒、99% 点 1.44 秒、最大 1.62 秒。ここに注文処理の約 0.26 秒が加わる。
  - seed 0 は窓の割り当てが重いケースで、約 1.37 秒の見込み。これは、空いた手元の Clang での時間とジャッジとの比から見積もっても同じ。
  - GCC ではおよそ 1.13 倍かかる（設計の平均約 1.47 秒）。
- 回数を固定したので、手元の評価でもジャッジと同じ回数を探索する。手元での時間は、評価の実時間と `*_sec` で別に確かめる。同じビルドなら何度実行しても同じ出力になる。ただし GCC と Clang、-march=native の有無で浮動小数点の計算が変わり、設計も変わる。

## stderr の指標

- 改良元と同じ。map_iters・gopt_steps・anneal_iters・climb_iters・match_iterations は、上の固定の回数になる。anneal_iters は、区間ごとに 256 の倍数へ切り上げた値。
