# gen-relax

改良元: solutions/search-bf2

ブロックと整合する目標の対を増やし、大きいブロック（6 窓）と少ないハンドル窓（H = 34）を誤りなく使えるようにした。注文ごとの操作（計画探索と穴埋め紙）は search-bf2 と同じ。

## 変更点

- 背景: 対 (u, v) は、触れる全ブロックで整合（違う窓で A_u が Y_b か ~Y_b に一致）していなければ使えない。ブロックを大きくするか H を減らすと、整合しない対が残って誤りになっていた。
- (1) 焼きなましの前に、どの窓を G にするか、G のブロック分け、各ブロックの色 Y_b を山登りで決める。
  - 目的関数は「ブロックごとの、整合する目標対の割合の対数」の全ブロックでの和（対は触れる全ブロックで整合する必要があるので、使える対の割合はおよそ積になる）。
  - 各ブロックの Y_b は、そのブロックで整合する対の数が最大になるものを全通り調べて選ぶ。整合は「Y_b との差の模様が包含関係にある」ことなので、ブロック内の局所模様ごとの目標数から部分和変換（ゼータ変換）で数える。
  - 近傍は、2 ブロックの間の窓の交換と、G の窓とハンドル窓の交換（確率 30%）。改善するときだけ採り、3000 回行う。ハンドル窓の列の順は、窓の番号順で始める（後の焼きなましでハンドル窓の入れ替えはある）。
- (2) 焼きなましの 10% 以降は Y_b を固定し（Y_b のビット反転の近傍を止める）、対の組み替えの 90% で、新しい相方を「残す目標と整合する目標」の中から選ぶ（ランダムな組み替えはほとんど整合せず捨てられるため）。
- (3) 焼きなましと修復の後も整合しない対が残ったら（H = 34 で約 2% のケース）、整合しない窓の部分をそのブロックから切り出して新しいブロックにする（反転紙が 1 枚増える。切り出しは他の対の整合を壊さない）。紙は単位を 1 つ減らして作る: 単独の目標 2 つを整合する対にまとめる。それができなければ増大路（ある対 (a, b) の a を単独の c と組ませ、b を別の単独 d と組ませる）。どちらも見積りが最小のものを選ぶ。
- 既定を `CB_S` = 4 → 6（ブロック 6 窓）、`HUB_H` = 36 → 34 にした。

## パラメータと指標

- 環境変数（search-bf2 のものに加えて）: `CB_PSWAPS`（山登りの回数、既定 3000）、`CB_PGH`（G とハンドル窓の交換を試す割合、既定 0.3）、`CB_PMOVE`（ブロックの大きさを変える窓の移動の割合、既定 0 = 使わない）、`CB_TGT_START`（Y_b を固定して相方を整合する目標から選び始める進み具合、既定 0.1）、`CB_TGT_RATE`（そのときに整合する目標から選ぶ割合、既定 0.9）、`CB_SPLIT`（(3) の分割、既定 1 = する）。
- stderr に足したもの: `block_log_consistency`（山登り後の目的関数の値。小さい（負に大きい）ほど整合する対が少ない）、`split_fallback`（(3) で分割したブロックの数）、`split_failed`（(3) で紙を払う組み方が見つからず分割できなかった数）、`anneal_iters`（焼きなましの反復回数）。
