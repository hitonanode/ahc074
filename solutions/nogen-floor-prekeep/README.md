フィラーの挿入位置、前の紙の保持、背景ヘルパーの取得前DPを統合する。設計はnogen-core-post5と同じで、全て実商品の所有紙。capは物理窓63に固定する。

- 通常フィラーは背景6枚より下へ挿す。背景の仮想取っ手はcap窓であり、その上へ置いても実取っ手を余計に覆えるわけではない。背景比較を壊す候補を避ける。
- 注文が共有主紙のもう一方の商品なら、その主紙を保持した背景順序変更も試す。
- 前の背景ヘルパーや前主紙をヘルパーとして残す候補を、背景6枚との7枚の実可視移動で探す。最大512状態・深さ3。実際の可視性、完成表示、列へ戻せる状態を検査してから通常候補へ渡す。
- ヘルパーを使う計画では、主紙を上げる前にフィラーを取る区間DPも試す。単独・二枚ヘルパーの各上位2候補を対象とし、候補ランキングと列の深さ表を共有する。
- 通常後処理を5から4候補へ減らして、上の候補生成に時間を回す。中立書換は2巡。
- 提出時は残り注文割合×0.14秒を予約し、`elapsed_sec() >= 1.70 - reserve` で軽量処理へ切り替える。LOCAL_BENCHでは通常通り切替を無効にする。

`helper_prefill_trials/plans/papers`は取得前DPの試行・成功計画・取得紙数、`retained_*`は保持探索の規模、`same_primary_*`は共有主紙保持の指標。既存の所有色・cap監査、DesignStore v2、@paper/@ops、段の目次、CLOCK_SCALEを維持する。新しい操作は既存のgen/help/fill/reuse等のラベルを使う。
