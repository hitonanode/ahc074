深い 2 列以外で「自列のハンドルに両色の紙が必要」という制約を緩める。空の列と深い 2 列の色欠けには元の大きな罰を残す。その他の単色列には、少数色の穴需要 × 0.6 × 4 × kHoleWeight の費用を置く。これは合計目的関数では列費用だが、穴需要の変化を正しく差分更新するため hcost と一緒に計算する。焼きなましの全移動で列の色欠け・穴需要の変化を計算し、初期化は浅い列で両色を強制しない。

存在しない頭色は仕上げ・穴あけ・V で確率 0 とし、その紙番号を参照しない。再割り当ては浅い列の単色化を許す。V の学習係数は変えない。

注文側はその色への掘りを費用 10000 の「不可能」として扱い、区間 DP が深い列の穴埋め紙を優先する。set_handle は元からある不正計画の判定で止まる。ColumnMdp の存在しない色の fix 値も 10000 とする。将来費用の先頭深さは元から列長に丸められており、初期列順序の DP は空の色群を扱える。

LOCAL_BENCH の D30A_MONO=0 は単色列の許可を止める。D30A_MONO_FILL は軟らかい罰の係数（既定 0.6）。新しい stderr 指標 mono_columns は最終設計の単色列数。plan_failures と E は既存指標で確認する。

`D30A_MONO_CHECK=1` は各焼きなまし区間の終わりにスカラーの目的関数を再構築し、SIMD 差分更新との差が 0.1 を超えれば停止する検証用切替。通常の探索・反復数は変えない。

`mono_candidate_count` は単色列を含む完成候補数、`mono_candidate_max` は完成候補中での単色列数の最大。

固定反復・決定的な乱数列を保ち、時間による打切りや新しい時計読みは加えない。CLOCK_SCALE、DesignStore、@paper/@ops、既存の指標・プロファイラ・切替・段目次を引き継ぐ。評価と採否は solutions/impla-notes/PROGRESS.md に記録する。

係数 0.6 は既存の穴費用との重複を考慮した値。両色の穴需要が等しいと既存 hcost が少数色需要の 0.76 倍なので、追加の 4 × 0.38 × 0.6 = 0.912 倍と合わせて約 1.67 倍となり、穴埋め紙の配置・返却の 1.7 手に近い。

単色列がない状態では、既存の穴需要変更に対する追加費用は厳密に 0 なので SIMD 加算を省く。色欠けの状態が変わる列だけは常に調べる。
