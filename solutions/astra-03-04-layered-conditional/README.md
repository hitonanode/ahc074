# astra-03-04-layered-conditional

改良元: solutions/astra-03-03-pair-reuse

## 改良元との差分

- 制御用補助紙を複数枚使い、差し込むバンク境界も探索する。上の紙に隠れる窓に限って、補助紙の色が目標と違うことを許す（実際に見える部分の整合だけを要求する）。
- 補助紙の選択は幅 16・深さ最大 4 のビーム探索。状態は、どの制御窓まで処理したか、使ったバンク、隠れた窓、前注文からの再利用。
- 設計: 各バンクに制御窓の 0・1 の紙を最低 1 枚ずつ確保し、残りを改善効果に応じて配分する（大きいバンクほど取り出しが高いことも評価に入れる）。
- 採用した操作列を別の紙順で再生して照合する検査（assert）を足した。

## パラメータ

- H=36（データ窓 28）（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra-03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（layered_conditional.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 1.1 秒。
