# 窓の割り当て探索の改良

## 1. 要約

**採用版は [main.cpp](main.cpp)。同じ時間で gobj_after を下げ、指定の模擬計測でも最終手数を減らした。** 基準は `solutions/astra-anneal/main.cpp`。以下は最終ソースの seed 24〜87、64ケースでの同時比較。

| 指標 | 基準の平均 | 採用版の平均 | ケースごとのlog比平均 ± 標準誤差 | 勝/分/敗 |
|---|---:|---:|---:|---:|
| 通常版の gobj_after | 11.982208 | 11.652581 | **−2.7867 ± 0.1460%** | 62/0/2 |
| 指定模擬条件の sim_moves | 10.566861 | 10.500631 | **−0.6287 ± 0.0912%** | 52/0/12 |

通常版の `end_sec` 最大は **1.57488秒**（CLOCK_SCALE適用済み）で、指定の1.75秒以下。平均は1.56657秒。通常版の1024注文の手数も −0.5241 ± 0.1616%、44勝20敗だった。通常版の誤表示・軽量モードへの切替はゼロ、模擬版の `sim_wrong` も全件ゼロ。

GCC 13.3.0、Clang 18.1.3で指定オプションのビルドに成功。変更は `assign_windows` 内だけ。目的関数、距離上限26、kMapEnd=0.50 / kGoptEnd=0.61、その他の段は維持した。

選定に使わなかったseed 88〜151の追加64ケースでも、同じ模擬条件で **sim_moves −0.7105 ± 0.0975%**、52勝0分12敗だった。gobj_after は −2.6767 ± 0.1412%、64勝。こちらも誤表示ゼロ。

## 2. 改良の内容

### 2.1 選択中のマッチングを大きく壊す候補を先に除く

現在の貪欲マッチングで選ばれた70対を保持する。候補がそのうち**4対以上を互換でなくするなら、約3400対の更新とソートを始める前に捨てる**。70対をまだ選べていない状態では除外しない。

これは近似であり、改善する候補も捨てる。元版の固定回数診断（seed 24〜31）では、受理した平均695.125候補のうち537.5候補、約77%が4対以上を壊していた。したがって「改善不能の下界」ではない。現在のマッチングを少しずつ変える候補へ計算時間を集中させる探索上の偏りである。

通過した候補は、従来どおり費用 `2340 hd + 5 rel + 144 d` で安定ソートし、頂点の重ならない70対を貪欲選択して評価する。費用の正規化、対が足りない場合の罰則、温度、受理判定は同じ。

### 2.2 窓交換の閉路判定をビット集合にする

汎用窓aを取り除き、同じ比較器の組へハンドル窓bを加える交換を考える。選択済みの対の制約はDAGなので、窓aを取り除いた制約もDAGである。その比較器をuとvとすると、新しい辺u→vが閉路を作る条件は「残った制約でvからuへ到達できること」。逆方向も同様。

この禁止方向を、選択済み70対について二つの集合にまとめる。各集合は64 bit整数2本。商品対が窓bで異なるか、最初の商品の色が何かを表す集合とのAND/ORと**2回のpopcount**で、交換により壊れる対の数を求められる。新しい窓の色の向きもこの照合に含める。

禁止方向の集合は、窓aごとに初めて必要になったとき作る。状態を受理するまで再利用する。窓群の残った制約が元と同じ対には、元の推移閉包も再利用する。色反転・組交換・組移動の除外判定では、選択された対だけを直接調べ、4対壊れたところで止める。

### 2.3 同じ状態の同じ候補を再評価しない

状態が変わるまで、各候補の除外結果と厳密な目的値を保存する。キーは物理窓、移動先の比較器、新しい色の向きを区別し、2窓の組交換は順序を正規化する。表は16384項目で、受理時に世代番号を進める。焼きなましの最良状態へ戻すときも無効化する。

目的値を再利用した候補にも通常の受理判定を行う。その候補を受理するときだけ、全対の関係とマッチングを再構築する。これにより、反復数固定ならキャッシュ導入前と同じ探索を保つ。

8ケースの固定100万候補＋山登り25万候補では、導入前後の目的値と最終手数が全件一致した。`map_end_sec` 平均は0.352577→0.204840秒。ただしこの時間は入力・初期化も含む。時間制64ケースでは、再利用なしの同じ探索との gobj_after の差が **−0.4503 ± 0.1300%** だった（`memo-normal` 内で直接比較）。

`map_iters` / `gopt_steps` は除外やキャッシュ参照も数えるため、元版との比をそのまま計算速度倍率とは解釈しない。

### 2.4 移動と色の反転を同じ手にする

汎用窓とハンドル窓を交換するとき、移動先の色の向きも乱択する。窓を別の比較器の組へ移すときも同様。元版で2手必要だった変更を1手で試せる。各比較器の組を最低1回使う条件は維持する。

### 2.5 構成要素の比較

すべて64ケース。各行の差は同じ試行内の比較であり、別試行の絶対値を横断して優劣を判定していない。

| 計測ラベル | 候補 | 比較基準 | gobj_after のlog比 ± SE | 勝/分/敗 |
|---|---|---|---:|---:|
| compound-filter-normal | 移動と色反転の同時変更だけ | astra-anneal | −0.8700 ± 0.1506% | 47/0/17 |
| compound-filter-normal | スカラー判定で4対以上を事前除外 | astra-anneal | −1.2896 ± 0.1716% | 52/0/12 |
| combined-cache-normal | 除外判定のビット集合化 | astra-anneal | −1.7836 ± 0.1510% | 59/0/5 |
| combined-cache-normal | 上記＋色の同時変更 | astra-anneal | −2.7624 ± 0.1487% | 64/0/0 |
| memo-normal | 上記＋候補評価の再利用 | astra-anneal | −2.3548 ± 0.1523% | 63/0/1 |

コメント等を整理する前の模擬比較 `memo-sim` でも、sim_moves は −0.6078 ± 0.1007%、49勝15敗だった。要約では、整理後のソースを再計測した `final-normal` / `final-sim` の値を使っている。

## 3. 計測の手順と生データ

### 条件と再実行

作業日: 2026-11-02（日本時間）。通常版は指定テスター `/home/sato/ahc074/tools/target/release/tester` へ解法を渡し、`tools/in/0024.txt`〜`0087.txt` を入力した。テスターのstdoutは保存せず、終了状態とstderrの数値を保存した。

計測は原則3並列。各実行枠をCPU 0 / 1 / 2へ固定し、同じseedの基準・候補を同じCPUで続けて実行する。隣接seedで実行順を逆転する。通常版は解法3個＋テスター3個＋計測Python1個で7プロセス。最初の疎評価だけ4並列、最大9プロセス。計測中に別の計測やコンパイルは併走させていない。

```sh
python3 solutions/astra-search/build.py base main
python3 solutions/astra-search/measure.py reproduce-normal base main-bin --jobs 3

python3 solutions/astra-search/build.py base main --sim
python3 solutions/astra-search/measure.py reproduce-sim base-sim main-bin-sim --sim --jobs 3

python3 solutions/astra-search/build.py main --compiler clang++
```

GCCの指定は `g++ -std=c++23 -O2 -DCLOCK_SCALE=1.1`。Clangも同じオプションで、AVX2等は既存の関数target属性を使う。ビルド情報は [build-info.json](build-info.json)。計測ラベルは既存のものを上書きできないため、再実行時は別ラベルを指定する。

模擬版は `-DSIM_HARNESS` を追加し、次の環境変数を設定する。

```text
SIM_SEQS=8
ANNEAL_ITERS=15500000
CLIMB_ITERS=66000
MAP_ITERS と GOPT_STEPS は未設定
```

`measure.py --sim` はこれらを設定し、継承された固定回数指定を消す。割り当ては時間制のまま。256回単位の終了検査により、設計の焼きなましの実回数は両版とも15500032回、穴埋めは66000回だった。

`build.py --sim` は計測コピーだけ `kHelperGiveUp=1000.0` にする。最終ソースの1.55秒は変えない。全128実行で補助紙表の候補があり、`sim_helper_papers` 最小は2320。この指標は商品ごとの表の登録数の合計で、物理的な紙の枚数ではない。

比較値は `d_s = 100 log(候補_s / 基準_s)` のケース平均、標準誤差は `stddev(d_s, ddof=1) / sqrt(n)`。負が改善。差が標準誤差の2倍に満たないものは優劣を判断しない。

## 4. 試してだめだった案

すべてseed 24〜87の64ケース。基準が異なる行を直接比較しない。

| 案 | 比較基準 | gobj_after のlog比 ± SE | 勝/分/敗 | 計測ラベル |
|---|---|---:|---:|---|
| 変更する辺を除いても閉路が残る商品対を先に除き、残る対だけを厳密に評価 | astra-anneal | +0.6436 ± 0.1790% | 21/0/43 | sparse-normal |
| 2対以上で除外 | 採用方式・境界4 | +14.4446 ± 0.4456% | 0/0/64 | neighborhood-normal |

疎な厳密評価では、1辺変更で候補の商品対は約262対まで減った。しかし集合再構築と疎なスカラー処理を含む実装全体は遅くなった。固定79008＋19750回の8ケースで目的値・手数は一致したが、map_end_sec平均は0.5082→0.7460秒。時間制の探索候補数も106174→74304へ減った。

停滞時の緩和は、状態が4096 / 16384 / 65536候補変わらなければ境界を6 / 8 / 71へ上げ、受理時に4へ戻すもの。明確な改善なし。比較器同時変更は窓交換の20%で試し、元の組を最低1窓残す条件を守った。こちらも差を確認できなかった。

窓群の変更は、同じ組に属する全窓の反転、または2組の窓群の交換。直接逆向きになる2辺の矛盾を保ったまま、長さ3以上の閉路を変える狙いだったが、改善を確認できなかった。

## 5. 残りの案

1. **除外した候補の救済を構造で選ぶ。** 単純な閾値緩和は効かなかった。壊れる選択済み対の費用と、新しく互換になりそうな未使用頂点間の対を合わせて調べ、少数だけ再評価する余地がある。
2. **閉路を直接指定した複合手。** 全窓群の一律な反転・交換は効果が小さかった。安い未選択対の閉路と、それを壊しても残せる選択済み対を同時に使い、変更する窓を決める方法は未実装。
