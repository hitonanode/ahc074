# astra-search

改良元: solutions/astra-anneal

`assign_windows` の候補生成と評価を改良する。目的関数は元と同じ、距離26以下の互換な商品対から70対を費用順に貪欲選択した費用である。

- 汎用窓とハンドル窓の交換、および窓を別の比較器の組へ移す手で、色の向きも同時に乱択する。元は2手必要だった変更を1手で試す。
- 現在選ばれている70対のうち4対以上を互換でなくする候補を、全商品対の評価前に除外する。これは近似であり、改善する候補を捨てることもある。通過した候補には元と同じ目的関数と焼きなましの受理判定を使う。まだ70対選べていない状態では除外しない。
- 窓交換の除外判定は、窓を取り除いた後の制約の推移閉包から「追加すると閉路になる向き」を求め、70対分のビット集合にまとめる。追加する窓の色別の差分集合と組み合わせて、壊れる対の数をpopcountで数える。窓ごとに必要になったとき作り、状態が変わるまで再利用する。
- 同じ状態で再び出た候補には、除外判定と厳密な目的値を再利用する。目的値を再利用した候補が受理されたときは、全ての商品対の状態を再構築する。候補のキーは移動先の色も区別し、受理ごとに世代番号を更新する。

主な定数は、除外の境界4対、候補キャッシュ16384項目。手の基本比率と温度は改良元と同じ。割り当て0.50秒・山登り0.61秒の区切り、後続の設計・注文処理も同じ。時計は `CLOCK_SCALE` 倍する。固定回数の環境変数も改良元と同じ。

追加のstderr指標:

- `search_accept`: 割り当てと山登りを通じて受理した候補数。同点を含む。
- `search_rejected`: 事前除外した候補数。
- `search_screen_checks`: スカラー除外判定で調べた選択済みの対数。ビット集合の構築・照合は含まない。
- `search_memo_hits`: 厳密な目的値を再利用した回数。
- `search_exact_evals`: 事前除外を通過し、新しく全商品対を評価した回数。受理時の再構築と初期化を含まない。
- `search_screen_hits`: 以前の除外結果を再利用した回数。

`map_iters` と `gopt_steps` は事前除外・キャッシュ参照も含む候補生成回数である。実験方法と結果は [REPORT.md](REPORT.md) に記録する。
