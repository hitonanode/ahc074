# cmp-gobj

改良元: solutions/cmp-fast

汎用窓の割り当て（assign_windows）の焼きなましの後に、gsel / gopt（clean-base 系）の指標での山登りを 3000 回足した。

- 指標 gobj: 割り当ての対のリスト（距離 26 以下）のうち両立する対を、ハンドル窓での違いが少ない順に貪欲にマッチングし、必要な 70 組の平均の違い（足りなければ 1 組 10 の罰）。割り当ての目的（両立する近い相手の重みの凹関数の和）は、近い相手どうしを互いに重ならずに組めるか、違いがハンドル窓にあるか汎用窓にあるかの差をほとんど見ないため。乱数を変えた割り当て 8 個の比較で、gobj は焼きなまし後の期待手数と相関 0.44、割り当て自身の目的は 0.27 だった（trial_log の cmp-）。
- 山登り: 焼きなましの最良の状態から、同じ近傍の手を、gobj が増えず、割り当ての目的の低下が開始時の 5% 以内なら受理する。約 0.1 秒（空いた状態）で、その分だけ焼きなましの開始が遅れる。汎用窓を減らす再試行では行わない。
- assign_windows の手の生成・適用・取り消しを propose / apply_move / undo_move にまとめ、焼きなましと山登りで共有した（山登りなしなら出力は cmp-fast と同じ）。
- 模擬（probe の同じ処理、回数固定、seed 24〜87）で −0.13 ± 0.064%（3000 回、低下の許容 5%）、許容 1% / 2% は −0.08 / −0.09%、1000 回は +0.03%。この解法の模擬（seed 88〜215）で −0.244 ± 0.047%（87/41）。
- 実験用: 環境変数 `GOPT_STEPS`（山登りの回数、−1 でなし）。stderr: `gobj_before` / `gobj_after`。
