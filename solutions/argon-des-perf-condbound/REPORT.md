# D2: 穿孔の条件付き差分評価と利益上限

**このディレクトリをマージ対象として確定する。** 基準は `solutions/argon-req-filldp-positive`（PR #137）。
通常2000件で **−0.008299 ± 0.002444%**、追加judge平均 **0.006150秒**。
採用基準を全て満たしたので、ユーザーの指示に従い、この版で作業を止める。
広い検証と不採用案は [D2共通報告](../argon-des-perforation/REPORT.md)、
各比較の両側の時間・得点・run-idは [全測定表](../argon-des-perforation/MEASUREMENTS.md)。

## 助言と原因の診断

助言01-1は「列内の全シングル紙（あるいは上位複数枚）に定常状態での露出確率の重みをつけ、穿孔の対象を広げます」と提案した。
現行`Handle perforation`の`Perforation::best_heads`、`Filler climb`、Hungarianの`ProbabilityHead`が
列・色ごとに1枚だけを代表にする、という指摘は正しい。

200ケース、204800注文の再生では、新規フィラーに使う回数はhead 52563回、第2候補2499回、第3候補413回。
対象を広げても表示費用を回収できず、最初の500件は+0.000160 ± 0.003775%だった。
診断すると、予測利益の約91%はその紙を他目標のフィラーとして使う利益ではなく、
穴が増えた自目標に対するDP利益だった。非headの露出確率を0にしても同程度の穴が採用された。
自目標1〜2個には8〜16個の色標本しかなく、多数の穴候補から標本の偏りに有利なものを選んでいた。

## 変更

変更箇所は `Perforation::total_profit` / `run` と、`design_papers: handle perforation` の指標出力。
候補は従来のheadだけ。候補順、8標本、一次判定、穴費用、係数0.5は保持する。

1. 変更紙自身の目標について、変更窓の列頭色を反転した標本も評価する。
   両色の変更前後差分を既存の色確率で平均し、当該色の標本数に依存しない受理判定にする。
   キャッシュと`profit`は元の標本値を保持し、受理時だけ差分を補正する。
2. 穴を開ける前の自目標はその窓を覆っている。列頭色の反転は、その1列のdonor価格しか変えない。
   旧状態の全列DPを解き直さず、`avoid` / `forward` / `backward`と1列の辺から同じ値を求める。
   穴の復元の場合はこの性質を使わず、全列を計算する。
3. 他目標のdonor差分を先に計算する。自目標に1穴を加えると、既存の合法区間は狭まるか不変で、
   報酬の増分はその窓1個以下。区間は重ならないため、その誤色確率が条件付き利益の上限になる。
   他目標の利益とこの上限でも穴費用を回収できない候補は、重い自目標DPを省く。
   穴の復元には適用せず、数値境界は1e-8の余裕を持たせる。

未来の注文は使わない。追加のスイッチや予算変更はない。
上限版は浮動小数点の加算順も維持する。平均333.8725回の上限判定のうち306.142回（91.7%）を棄却し、
穿孔時間は基準の15.557 msから12.592 msへ短くなった。

## 得点と時間

最終比較: `20261106-005414_argon-req-filldp-positive` /
`20261106-005414_argon-des-perf-condbound`、通常2000件、両側`--save-design`。
最初の500件と延長前にBASE.mdを読み、終了時にもPR #137から変更がないことを確認した。

得点は3.40 SE、実用閾値0.005%以上。judge平均増加は6.15 msで0.01秒未満、換算しても約1.35%/秒。
平均≤1.600秒、p99≤1.770秒を満たす。WA、`self_wrong`、`op_label_errors`は全件0。
初回/延長の外部負荷は平均0.13/0.12コア、最大0.27/0.28コアで警告なし。

条件付き評価による設計変化の事後分析では、変更紙自身の注文で−2154手、その他で+438手、合計−1716手。
条件付けだけの遅い版から今回まで得点は同一。
穴の追加先を非headにも広げる版の追加効果は約−0.00014%に留まり、約13 msを費やしたため含めない。
