D2の診断に基づき、列頭の代表紙に穴を開ける際の差分評価を補正する。
変更紙自身の目標には8〜16個しか色標本がなく、多数の穴候補から選ぶと、その色の標本の偏りを拾う。
変更窓の色を反転した標本の差分も計算し、両色を既存の列頭色確率で重み付けする。
受理だけにこの条件付き差分を使い、DPキャッシュは元の標本値を保持する。
候補は従来のheadのみ。候補順、他窓の標本、標本数8、一次判定、穴費用と係数0.5は維持する。

条件付けの旧状態側では、穴を開ける前の窓は商品紙で覆われている。
その窓の列頭色を変えても、当該列から取るフィラーの価格しか変わらない。
全列DPの再計算を避け、既存のavoid/forward/backwardと1列の再評価で同じ最適値を求める。

他目標の差分を先に計算する。追加穴が自目標で生むDP利益は、その窓の誤色確率以下。
この上限を加えても穴費用を回収できない候補は、自目標の条件付きDPを計算せず棄却する。
元の浮動小数点加算順序を維持し、境界には1e-8の余裕を持たせる。
穴を復元する場合は、この上限と旧状態の再計算省略を使わない。

追加のstderr指標:

- `perf_owner_raw` / `perf_owner_conditioned`: 受理した変更の自目標のDP利益、補正前後（手/注文）。
- `perf_donor_gain`: 受理した変更の他目標でのDP利益（手/注文）。
- `perf_owner_bound_checks` / `perf_owner_bound_skips`: 上限を調べた候補数と、重い評価を省いた候補数。

追加の環境変数はない。既存のログ・指標・@paper/@ops・プロファイラ・予算スイッチ、
CLOCK_SCALE・LOCAL_BENCH・DesignStore・段の目印と目次を保持する。未来の注文は使わない。
