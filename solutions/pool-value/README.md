# pool-value

改良元: solutions/hole-relax

注文ごとの計画の候補に、列の外にある紙（プール）と新しい穴埋め紙を 1 つの区間スケジューリングでまとめて選ぶ計画（run_joint、fret_mode 5）を足した。紙の設計（焼きなまし）は hole-relax と同じ。

## 変更点

- hole-relax の計画は、前の注文で持ち上げた専用紙（以下、前の専用紙）と前の注文の穴埋め紙（以下、古い穴埋め紙）をどう扱うかと、列の上端から取る新しい穴埋め紙を、別々の手順で決めていた。run_joint は、次の候補をすべて「ハンドルの区間 [段, 列]」として並べ、利得の和が最大になる重ならない組を区間スケジューリングの DP で選ぶ。
  - 新しい穴埋め紙（列 c の深さ p ≤ 3 の紙）: 利得 = 省ける掘り − 1 − p。hole-relax と同じく「2 + 深さ」以上省くときだけ候補にする。
  - 古い穴埋め紙・前の専用紙を新しい段へ移す: 移す 1 手が列へ戻す 1 手の代わりになるので、利得 = 省ける掘り − 0.5（古い穴埋め紙は `JOINT_RELEVEL`、前の専用紙は `JOINT_PREV`）。
  - 害のない古い穴埋め紙を今の段のまま残す: 利得 = 省ける掘り + 1 − 0.8（`JOINT_STAY`。戻しの 1 手が要らず、列の外に残す費用 0.8 を払う）。
  - 選ばれなかった古い紙は列へ戻す（前の専用紙の戻し先は、上端と下端の 2 通りを別の計画として試す）。
- 注文の専用紙が古い穴埋め紙として列の外にあれば、列へ戻さずにそこから直接持ち上げる（掘りと戻しが要らない）。この紙は「巡回順の前の紙」（top_pred）を覚えておき、後で列へ戻すときはその紙のすぐ下へ入れる。上端や下端へ戻すと、列の中の色の交互が崩れるため。
- run_joint は hole-relax の計画を置き換えず、それらと並べて計画探索に入れ、費用（手数 + 列の外の紙 1 枚につき 0.8）の最も小さいものを採る。

## パラメータと指標

- 環境変数 `JOINT`（既定 1）: 0 で run_joint の計画を使わない（hole-relax と同じになる）。
- `JOINT_RELEVEL` / `JOINT_PREV`（既定 0.5 / 0.5）: 古い穴埋め紙 / 前の専用紙を新しい段へ移すときに利得から引く値。`JOINT_STAY`（既定 0.8）: その場に残すときの費用。
- stderr の `joint_plans_used`: run_joint の計画が選ばれた注文の数。`pool_lifts`: 注文の専用紙を列の外から直接持ち上げた注文の数。
- fillsim.py は解法とは別の道具で、1 注文の穴埋めの toy model（三角形の穴の数や、候補の深さ・枚数を変えて、穴 1 個あたりの手数を出す）。`python3 fillsim.py [T]`。
