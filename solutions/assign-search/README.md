改良元: solutions/esw-clean

窓の割り当てで、停滞時に良かった割り当てへ近づく経路を探索する。状態のハッシュで8区画に分け、各区画の最小gobjの割り当てを保存する。現在と異なる保存状態を選び、汎用・ハンドルの役割、汎用窓の辺、極性の違いを1つずつ埋める。既存の3組損失による事前除外を通る未評価候補から選び、受理される間は同じ目標へ進む。目標へ着けば次の保存状態を選び、候補がなくなるか拒否されたら通常の探索へ戻る。独立した再始動はしない。

追加時間を抑えるため、反転・汎用窓同士の交換の判定を省力化した。同じ辺に両向きの弧が生じる採用組をビット集合で数え、それだけで3組以上が無効なら閉包計算を省く。残る候補は元の閉路判定へ進む。この簡易判定は元の棄却条件の十分条件であり、探索結果を変えない。

目的関数、通常の近傍比率、温度、停滞閾値、焼きなまし450,000回・climb133,000回は変更しない。設計の後段と注文処理はesw-cleanのまま。

| 追加スイッチ | 既定 | 意味 |
|---|---:|---|
| AS_ELITE | 1 | 0で保存状態への経路探索を無効にする |
| AS_SCREEN | 1 | 0で両向き弧の簡易判定を無効にする |
| AS_WORK | 1.0 | 正の反復倍率。開発時の同時間比較用。最終版では増減しない |
| AS_PROFILE（コンパイル時） | 0 | 1で演算子別の時間・改善量を`#assign`行に出す |

追加のstderr指標:

- `as_elite / as_screen / as_work`: 使用設定。
- `elite_updates / elite_attempts / elite_candidates / elite_accepts`: 保存状態の更新、経路候補の生成試行、厳密評価、受理の回数。
- `path_starts / path_complete / path_blocked`: 目標選択、割り当ての一致、適格候補がない終了の回数。拒否による終了はpath_blockedに含めない。
- `path_internal`: 汎用窓の辺・極性を合わせる候補数。
- `direct_checks / direct_rejects`: 簡易判定の回数と、そこで証明できた棄却数。既存のsearch_screen_checksは従来のスカラー判定に到達した組数なので減る。
- `#assign`: phase、演算子、提案、評価、memo、受理、降下、最良更新、降下量、最良更新量、新採用組、新規有効組、提案百万cycle、matching百万cycle。phase 0〜3は焼きなましの四等分、4はclimb。eliteは経路探索の全演算子を集計する。

既存の全指標・ログ・実験スイッチ・プロファイラ、CLOCK_SCALE、LOCAL_BENCH、DesignStore、@paper/@ops、非常用設計と段の目印を保持する。制限時間不足時のフォールバックに関するヘッダの注意も保持する。

検討・測定・採否は[REPORT.md](REPORT.md)。`analyze.py`と`profile_summary.py`は保存済みrunだけを読み、解法を実行しない。
