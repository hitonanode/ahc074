# astra-overlap

改良元: `solutions/astra-search4`。

穴埋め紙を2枚使うときに、2枚を**異なる深さに差して、担当する区間を重ねる**候補を追加する。
元の解法の2枚組・最大4枚の鎖は、全ての紙を同じ深さに置く。一方、上側の紙Uを早い位置に置き、下側の紙Lを遅い位置に置けば、Uの穴でLの色が間違う早い窓を避けながら、Uの正しい色は早い窓にも使える。

- Uの開始位置はU自身の最深の不一致の直後。
- Lの開始位置は「Uで隠れないLの不一致」の最深位置の直後。
- Uの開始 < Lの開始 <= Uの元の列 < Lの元の列、となる交差だけを追加する。
- 紙の持ち上げ前後の可視性と、既存の穴埋め紙との干渉は従来と同じ条件で検査する。
- 2枚の実効被覆で省ける掘りを数え、2枚の取り出し費用を引いた利益を、区間DPの1個の候補として渡す。Uを先に、Lを後に配置する。
- 追加探索は各注文の最良通常計画に対する鎖探索の段階だけで行う。設計・時間配分・比較器の方策は改良元と同じ。

例: Uが区間[2,8]、Lが[5,12]を担当し、UがLの区間[5,8]の不一致を隠す。Lを開始2へ前倒しすると、Uの穴である窓4を誤色にする場合、共通の開始位置ではこの被覆を実現できない。

`overlap_candidates` は追加した交差候補の数、`overlap_selected` は最終計画として選んだ交差2枚組の数（後処理で紙が消える前）。従来の `chain_selected` は交差候補を含む追加探索の選択回数になる。

## 階段状の最大4枚への拡張

`staircase.cpp` は `main.cpp` とは独立に、改良元の共通levelの鎖探索を保ち、追加の幅24のビームで各紙のlevelが異なる最大4枚の鎖を探す。
上から下への紙順を固定すると、各紙の開始位置は「直前の紙の開始位置」と「上側の紙で隠れない最深の不一致の直後」の大きい方にできる。
すでに覆ったハンドルの集合へ、この開始位置以降の不透明セルだけを加える。これで、上側の紙が先に覆ったセルを、後の紙の不一致のために捨てる必要がなくなる。
実際の取り出しは元の列の昇順に行い、同levelの紙だけ鎖内の相対位置を指定する。異なるlevelの間には元の列の紙が残るため、同levelのように隣接させてはいけない。

追加の指標は `stair_candidates`（階段候補数）、`stair_selected`（最終採用群数）、`stair_immediate_saved`（採用した注文で通常計画から減った即時手数）、`stair_objective_saved`（同じ比較での目的値の減少）。後2つは後処理前の比較であり、後続注文も含むスコアの改善量ではない。
