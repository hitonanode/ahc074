# 設計の段の高速化と中立候補の順位の改良を合わせた版（esw-speed）

改良元: solutions/climb4-fast

## 改良元からの差分

3 つの版の差分（どれも climb4-fast からの差分で、変えた場所が重ならない）を合わせた。

- **窓の割り当ての、出力を変えない高速化**（solutions/design-fast。設計の高速化の agent）
  - 主な変更:
    - 対の関係の閉路の判定を閉包の計算なしで行う（AVX2 で 4 つずつ）。
    - PosetSums の表を小さくする。
    - 並べ替えと貪欲マッチングを軽くし、足切りの判定をまとめて行う。
  - 1000 件で出力は完全一致。窓の割り当ての時間は 0.676 → 0.463 秒（0.685 倍）。
- **窓の割り当てより後の設計の、出力を変えない高速化**（solutions/anneal-fast。Astra）
  - 対象: 焼きなまし、filler climb、再割り当て、穴あけ、補助紙の表。
  - 1000 件で出力は完全一致。この部分の時間は 0.726 → 0.613 秒（−15.6%）。
- **中立探索で残す候補 2 個の順位の改良**（solutions/opsearch-fast3。Astra）
  - 親の操作列で表示を担っていた紙が、候補では隠れる数を、手順の短さの次に優先する。
  - 設計固定 2000 件 × 2 本で −0.009 ± 0.0006%、時間は同じ。
- 設計の反復回数、目的関数、注文処理の予算は改良元と同じ。設計（紙の模様）は改良元と同じになり、注文の操作だけが opsearch-fast3 の分だけ変わる。
- 目的: ジャッジでの TLE を減らす。esw-climb4 の提出は 50 件中 31 件が TLE だった。
