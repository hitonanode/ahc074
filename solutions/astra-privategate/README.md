# astra-privategate

改良元: solutions/astra-sparsegate

6枚の汎用紙のうち紙0に、他の汎用紙が全て穴になる窓を一つ与える。紙0はその窓だけ白く印刷し、汎用層を操作する間は最下位にいても必ず見える。残る紙1〜5には全10組の比較窓を一つずつ残す。保護する窓は計11個となり、従来の15個から4個減る。36汎用窓の場合、残る25窓では白黒穴の602種類のゲートを学習する。

専用紙Dは、この私有窓では必ず要求色を印刷する。このため、対にする二商品は私有窓の色が一致しなければならない。最終表示はDが担うので、私有窓の色を毎注文汎用紙で直す操作は必要ない。紙を追加することもない。これは「全専用紙を私有窓で穴にして、補助紙だけに表示を任せる」構成とは異なる。

私有窓の選び方:

- 紙1〜5の唯一の比較窓を壊す候補は除く。
- 変更前の比較器で互換かつ全ハミング距離26以下の商品対を費用順に並べる。
- 各候補窓で色の違う対を除き、70対の貪欲マッチングを作る。取れる対の数が多く、同数なら費用が小さい窓を選ぶ。
- その窓は以後固定し、他の25窓を学習する。他の窓が全て2枚比較器に留まっても、私有窓は必ず維持する。

学習中の操作グラフでは、紙0と、紙1〜5のうち最下位以外の紙を動かせる。設計後に実際の模様から720状態の可視性と全点対の合法距離を作り直し、商品対の選択と注文処理にはこの実際の距離を使う。紙0が最下位にいる場合の移動も列挙する。

時計は全て `CLOCK_SCALE` を掛ける。窓割り当ての終了は0.40秒、最後の区間は0.46秒、ゲート学習は0.75秒まで。`DECODER_ITERS` を正にすると診断用に学習反復を固定できる。初期設計が作れない場合は、私有窓を保った同じ構造で汎用窓数を36→32→28→24→20→16と減らして再試行する。旧解法へは切り替えない。全て失敗した場合は `private_design_failed` を出して終了し、そのケースは評価で失敗として数える。

主な追加のstderr指標:

- `private_window_internal` / `private_window_original`: 私有窓の内部番号と入力中の窓番号。
- `private_initial_matching_size` / `private_initial_matching_cost`: 私有窓の選定時に得た対の数と費用。
- `private_initial_close_pairs`: 選んだ私有窓で一致する、変更前に互換だった近い対の数。
- `private_initial_pair_breaks`: 私有窓の制約で、変更前の70対のうち使えなくなった数。
- `private_design_attempts`: 私有窓を保った設計の試行回数。
- `private_design_failed`: 初期設計を作れず終了した場合だけ出す値。
- `decoder_proxy_before` / `decoder_proxy_after`: 近い対を70対取れた場合の代理費用。**3906250は70対未達のsentinelであり費用ではない**。この値を含めた平均は解釈せず、有効件数を別に数える。

継承した `decoder_initial_close_pairs` などの「初期比較器」は、私有窓を設置する前の2枚比較器の互換性を基準にする。私有窓の制約を課した直後の量は `private_initial_*` で区別する。

`verify.cpp` は提出用ではなく、可視性と合法距離の構造検査用である。結果とソースのSHA-256は `verification.json` / `verification.txt` に保存した。
