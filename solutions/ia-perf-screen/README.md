穴あけの `separate_profit` による事前除外が、現在の区間 DP と所有商品の条件付き費用の判定で改善する変更を捨てていないかを調べる監査版。通常は事前除外された変更も影で評価するだけで、受理する変更、乱数、設計と注文の出力を変えない。新しい提出解法ではない。

- `IA_PERF_SCREEN_PERIOD`（既定 1）: 事前除外された候補の何件ごとに完全評価するか。1 なら全件、32 なら 32 件に 1 件。
- `IA_PERF_SCREEN_BYPASS=1`: 事前除外を無効にし、現行の DP と条件付き費用で良い変更を実際に受理する試験。既定は 0。
- `ia_screen_rejected_<id>` / `checked` / `missed`: 候補設計 id ごとの事前除外数、監査数、実際の判定では改善する変更数。
- `ia_screen_missed_restores_<id>`: 漏れた改善のうち、既存の穴を塗り戻す変更の数。
- `ia_screen_gain_<id>` / `max_gain`: 漏れた改善の模型差の和 / 最大を 256 で割った値。候補間・変更間で重複するので最終スコア改善の予測値ではない。
- id 0〜3 は焼きなましの 4 枝、4 と 6 は通常の再仕上げ、5・7・8 は既存の穴を引き継ぐ再仕上げ。

監査は評価を増やして時間制限を超え得る。実行と記録は共通の pahcer_run.py を経由する。
