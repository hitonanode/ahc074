# gopt2

改良元: solutions/gopt

- ハンドル窓の数 H を 34 → 33 にした（汎用窓 31 窓、ブロックは 7, 6, 6, 6, 6 窓）。gopt の上で H を模擬（焼きなまし固定、32 本の乱数注文列）で振り直すと、H34 比で H33 は seed 24〜87 で −0.11 ± 0.08%、seed 88〜215 で −0.19 ± 0.05%（H32 −0.02 ± 0.12%、H35 +0.28%、H36 +0.68%）。ただし 7 窓のブロックは best_y が約 4 倍重く、gopt のままでは G の段が長くなって焼きなましが 7% 減り、時間制の 500 件では gopt 比 −0.078 ± 0.073%（solutions/gopt-h33、021116）にとどまった。
- そこで best_y を、全 y を一度に数える方法にした（出力は同じ）: nested(y) = Σ_a cnt[a] W_y[a]、W_y は cnt を各ビット i について y_i = 0 なら部分集合、y_i = 1 なら上位集合の方向に足し合わせたもの。ビットごとの変換は可換なので、ビットを深さ優先に決めて途中の配列を共有する（約 T^2 の仕事）。6 窓で 3.7 → 1.6 µs、7 窓で 13.7 → 4.9 µs。G の段は H34 で 0.22 → 0.17 秒、H33 で 0.29 → 0.20 秒（手元、空いた状態）。
- H はコンパイル時の定数 `HUB_H`（-DHUB_H=n）。
