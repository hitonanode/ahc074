# legal-roll（段階 2: 終状態の候補をロールアウトで選ぶ閉ループの研究版。提出用ではない）

改良元: `solutions/deval-helper-wide`（SOTA）。設計は変えない（`--design-from` で保存した設計を読む前提）。`-DLOCAL_BENCH` でだけビルドできる（ラベルを使うため）。

## 改良元との差分

- **候補の収集。** `ROLL_EVERY` 注文ごとの 1 回（注文番号 r が `r % ROLL_EVERY == 0`）、process() の中で、仕上がった計画を評価する箇所（後処理の後、eject の後、別の計画の後処理の後、中立探索の各候補の短縮の後、重み付きの計画）で、その終状態・操作列・ラベル・plan_cost を記録する（終状態の重なり順ごとに plan_cost が最小のもの）。SOTA の選択は変えない。
- **選択（rollout_choice）。** process() の最後に、SOTA の選択 c0 と、記録した候補のうち plan_cost が小さい順に最大 `ROLL_N − 1` 個（c0 との差が `ROLL_GAP / 100` 以内、重なり順が違うもの）を並べる。各候補は再生で独立に確かめる（動かす紙が見えている、終状態が記録どおり、表示が注文、補助紙が回収できる）。
  - `ROLL_MODE 2 / 3` では、c0 の局所的な変種も足す: 1 手の差し込み先だけを変える（後の手は同じ深さ）、1 手を消す、1 手で動かす紙を別の見えている紙に替える（同じ深さ）、隣り合う 2 手を入れ替える、最後に 1 手（見えている紙を別の深さへ。表示は変えない）足す。合法で表示が注文どおりのものを plan_cost の小さい順に最大 `ROLL_NEW` 個。
  - 各候補の終状態から、ソルバーの複製で、同じ乱数の将来の注文列 `ROLL_S` 本 × `ROLL_H` 注文（一様、直前と同じ商品は出ない。実際の将来の注文は使わない）を SOTA の方策で処理し、その手数（表示が違えば 1 注文 2K = 384 手を足す）の平均 + `ROLL_TERM / 100` × 最後の状態の価値 plan_cost(0) に、その注文の手数を足した値が最小の候補を選ぶ。乱数は (ROLL_SEED, 注文番号) で決まり、全候補で共通。
  - 変種は、その終状態から乱数の次の注文 3 つをそれぞれ複製で処理し、どれかで表示が違うか計画に失敗したら捨てる（state_ok。任意の重なり順はソルバーの前提（汎用紙の並びなど）を壊すことがあり、最初の試運転では誤りの 2K 手を数えなかったため、計画できない状態をロールアウトが好んだ）。
  - 複製は in_rollout を立て、候補の収集も入れ子のロールアウトもしない。ソルバーの注文の間の状態は State（重なり順、持ち上げた紙、補助紙の記録）と完全一致のキャッシュだけなので、複製は本体の状態を変えない（`ROLL_MODE 9` で確かめる）。
- **外からの候補（ROLL_EXT）。** ROLL_EXT（ファイルの絶対パス。同名の環境変数でも可）があれば、その各行 `key r k:d ...`（key はケースの最初の 2 つのバーコードから作る値、紙は出力の番号）の操作列を、注文 r で候補に加える（再生で合法性と表示を確かめ、state_ok を通ったものだけ。由来 7）。solutions/legal-search の段階 2b の列を開ループで比べるのに使う。
- `ROLL_MODE`: 0 なし（SOTA と同じ）、1 SOTA の候補だけからロールアウトで選ぶ、2 局所的な変種も加えてロールアウトで選ぶ、3 局所的な変種を plan_cost で選ぶ（診断用）、8 開ループ（SOTA の選択を保ち、各候補の各注文列での費用を `#rollmat` / `#rc` 行に記録する。open_loop.py で、k 本で選んで残りの本数で測る得を求める）、9 ロールアウトを計算するが SOTA の選択を使う（本体の状態が変わらないことの確認用）。
- 設定はファイル冒頭の `#define`（同名の環境変数で上書き可）。既定: ROLL_MODE 1、ROLL_EVERY 8、ROLL_N 4、ROLL_NEW 3、ROLL_S 8、ROLL_H 4、ROLL_TERM 100、ROLL_GAP 300、ROLL_SEED 1、ROLL_VAL 16、ROLL_VAL_H 8、ROLL_Z 0、ROLL_FEAT 0、ROLL_EXT なし。比較の変種は、このディレクトリを複製して `#define` を変える。
- **慎重な切り替え（ROLL_Z）。** ROLL_Z > 0 なら、SOTA の選択との差を注文列ごとに対にして、平均が標準誤差の ROLL_Z / 100 倍を超える候補のうち平均の差が最大のものにだけ切り替える（標本の少ない推定での勝者の呪いを抑える）。
- **選択の検証（ROLL_VAL）。** SOTA 以外を選んだときだけ、選択に使っていない別の乱数の注文列 `ROLL_VAL` 本 × `ROLL_VAL_H` 注文で、c0 と選んだ候補を同じ方法でもう一度見積もる（選択には使わない。1 回の選択の得の偏りのない推定）。
- 時間: 1 回の選択でおよそ（候補数 × ROLL_S × ROLL_H）回の process() が増える。2 秒の制限は守らない（研究用。`--design-from` で評価する）。

## stderr の指標

- `#roll r u 既存の候補数 全候補数 選んだ番号 (由来:手数:plan_cost:推定)...`: 選択ごとの行（由来 0 = SOTA、1 = 記録した候補、2 = 差し込み先の変種、3 = 削除の変種、4 = 1 手足す変種（足した手のラベルは other）、5 = 紙を替える変種、6 = 入れ替えの変種、7 = 外からの候補）。
- `roll_decisions`（選択の回数）、`roll_changed`（SOTA 以外を選んだ回数）、`roll_changed_new`（そのうち変種）、`roll_cands_exist` / `roll_cands_new`（比べた候補の数の合計）、`roll_invalid`（再生の確認で捨てた候補）、`roll_variants_valid`（合法で表示が正しい変種の数）、`roll_variants_better`（plan_cost が c0 より小さい変種）、`roll_len_diff`（選んだ候補の手数 − c0 の手数の合計）、`roll_pred_gain`（推定の差の合計）、`roll_value_loss`（plan_cost の差の合計）、`roll_val_n` / `roll_val_gain` / `roll_val_gain2`（検証した選択の数、検証での c0 − 選んだ候補の差の和と 2 乗和）。`#rollval r 由来 c0 の推定 選んだ候補の推定` は検証の行。
- `#rf plan_cost の補助紙の項 次の注文の費用 汎用紙の項 補助紙の数 汎用層の下の補助紙の数 持ち上げた紙の担当数 補助紙の担当数 列の先頭と逆の色の需要 ラベルごとの手数...`（ROLL_FEAT 1 のとき、mode 8 の各 `#rc` 行の後。ほぼ同点の選択の補正の研究用）。
- `roll_unplannable`（state_ok で捨てた変種の数）。`#rollmat r u 候補数` に続く `#rc 由来 手数 plan_cost 費用...`（mode 8）。
- 集計: `roll_stats.py RUN...`（全注文列の `#roll` / `#rollval` 行）、`open_loop.py RUN`（mode 8 の行）。
