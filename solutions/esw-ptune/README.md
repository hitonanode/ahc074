# 注文処理の定数の調整（esw-ptune）

改良元: solutions/esw-noprune

設計を固定した比較（`--design-from` / `--orders`、標準誤差が通常の比較の約 1/9）で、注文処理の定数を 1 つずつ上下に振り、良かった変更を組み合わせた版。紙の設計・時間配分・乱数・CLOCK_SCALE・LOCAL_BENCH・DesignStore は改良元と同じで、変えたのは注文処理（Solver の将来費用の模型・計画・補助紙・後処理）の定数だけ。変えた所には `esw-ptune:` のコメントがあり、`grep -n 'esw-ptune' main.cpp` で一覧が出る（solutions/esw-fast などに移すときの目印）。

## 変えた定数

| 段 | 定数 | 改良元 → esw-ptune | 意味 |
| --- | --- | --- | --- |
| 将来費用の模型 | kTopPenalty | 0.35 → 0 | 返却（mode 1）で列の一番上に入れるときの罰。0 にすると ret_mode 1 と 2 は同じ計画になる |
| 将来費用の模型 | add_filler_demand の 2 窓目の費用 | 0.6 → 0.8 | 穴埋めの追加需要 = E[直す窓数] − P(1 窓以上) − c·P(2 窓以上) の c（設計側の filler_gain は 0.6 のまま） |
| 将来費用の模型 | kFillerCharge | 0.6 → 0.7 | 列の外に残した紙 1 枚の費用 |
| 将来費用の模型 | filler_charge の残存確率の基準 | 0.4 → 0.3 | 汎用層の下の穴埋め紙の費用 kStayStrength·(基準 − 次の注文でも正しいままの確率) の基準 |
| 計画 | kFillerDepth | 3 → 4 | 穴埋め紙の候補にする列の紙の深さの上限 |
| 計画 | refill_or_return の条件 | save >= 2 → save >= 0 | 古い穴埋め紙を新しい水準へ動かすのに要る、省ける掘りの数（D の穴を覆えるなら動かす） |
| 計画 | 2 枚重ねの穴埋めの閾値 | gain >= 2 → gain >= 1 | 2 枚重ねの候補にする利得（事前の打ち切り `fsum < … + 2` も `+ 1` に） |
| 計画 | kChainLength / kBeamWidth | 4 / 24 → 3 / 16 | 穴埋めの連鎖の長さとビーム幅。損は測れないほど小さく、注文処理の時間が約 3% 減るので入れた |
| 補助紙 | try_helpers の試す数 | 4 / 4 → 6 / 6 | 1 枚の補助紙の計画と 2 枚の補助紙の計画を、見積りの良い順にいくつ試すか |
| 後処理 | 2 削除 + 1 修復の繰り返し | 最大 2 回 → 最大 4 回 | 2 削除 + 1 修復が受理されるたびに、編集の段ともう 1 回の 2 削除 + 1 修復を行う回数の上限 |

## 変えなかった定数（振って良くならなかったもの）

kEndWeight（1.0）、kFillerDemandWeight（0.25）と重みの下限（0.25）、kStayStrength・kCoverStrength（0.25）、kRelevel（0.5）・kStay（0.8）、kFillerCost（1）、kChainDepth（2）、adaptive_insert のこの注文の掘りの重み（1）、取っ手の穴の項の重み（1）、補助紙の深さの上限（5）と 2 枚の組の候補数（12）、後処理の差し込み先の変更の対象（前の注文の紙と 2 回動かす紙だけ）。結果は trial_log.md にある。

stderr の指標は改良元と同じ。
