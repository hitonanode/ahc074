# D2 続き: 受理係数の再調整と不変なDPキャッシュの再利用

基準は `solutions/argon-des-perf-condbound`（PR #138）。
**このディレクトリをマージ対象として確定する。** 通常2000件で−0.022316 ± 0.004631%、
judge平均は1.565318→1.554189秒。採用条件を全て満たしたため、指示どおりこの版で停止する。
助言01-1の非headへの穿孔拡張を起点にしたD2の追加検証。
広い調査と全runの時間は [D2続きの報告](../argon-des-perf-variance/REPORT.md) と
[測定表](../argon-des-perf-variance/MEASUREMENTS.md) にまとめた。

## 問題と変更

自目標の色標本の偏りを補正した後も、穿孔の受理係数は従来の0.5のままだった。
係数0.4/0.6/0.7/0.8/1.0を比較すると、0.7付近で得点が改善する。
ただし係数だけを変更した版は、2000件の再測定でもjudge p99 1.804秒で時間枠を外れた。
本版は受理係数を0.7にし、同じ結果を得るキャッシュ再利用を加える。

変更は`Handle perforation`の`Perforation::total_profit` / `refresh_cache` / `run`と、
`design_papers: handle perforation`の係数・2指標の出力のみ。基準との差は18行追加、4行削除。

穴を1個受理したとき、変わるのはその紙の自目標と、同じdonor列を使う他目標の一部だけである。
`total_profit`は既に、両headの合法な区間開始点と被覆窓が不変かを`same[u]`として判定している。
不変なら全色標本で全DP辺が同じなので、forward/backward/avoidも再利用できる。
その結果を受理後まで保持し、不変な目標の再構築を省いた。
変更紙の自目標は常に再構築し、初回も全件構築する。
探索中にheadの選択・色・色標本とその確率が固定されることが、この高速化の前提である。

標本数8、標本生成、候補順、自目標の条件付き評価、利益上限、他段の探索量は保持した。
新しい実験スイッチはない。追加の`perf_cache_rows` / `perf_cache_skips`は構築・再利用した目標×標本数。

## 最終2000件の結果

基準 `20261106-015207_argon-des-perf-condbound` /
候補 `20261106-015850_argon-des-perf-gaincache`。
最初の500件の`--save-design`を継承して2000件へ延長し、両側全件の設計を保存した。
延長前と結果の確認時にBASE.mdを読み、PR #138のままであることを確認した。

得点改善は4.82 SEで実用閾値0.005%以上。judge平均は11.13 ms短く、追加時間に関する条件にも抵触しない。
平均≤1.600秒、p99≤1.770秒を満たす。穿孔自体の短縮は2.47 msで、全体時間差の全てを
この局所処理だけの短縮と解釈しない。採否は両側の全体実測に基づく。

全件でキャッシュ構築は平均3083.156行、再利用は14453.868行。
初回を除いた再構築の93.3%を省いており、500件で見えた高速化を維持している。

## 検証

GCC/Clang、`-std=c++23 -O2 -Wall -Wextra`、LOCAL_BENCH有無の4構成で警告0。
コマンドとソースSHAは`build-results.json`。
確認用実行ファイルは/tmpの一時ディレクトリに作成し、削除済み。
全既存のログ・指標・@paper/@ops・プロファイラ・予算スイッチ、CLOCK_SCALE、LOCAL_BENCH、
DesignStoreと他部分のインターフェースを保持した。段の追加・改名・削除なし。
最終ソースと評価保存ソース、4ビルドのSHA、保存設計2000件、変更範囲を`final-audit.json`で照合した。
共有ファイルの編集とコミットは行っていない。

## 残るD2の範囲

前段のfiller climbとHungarianは色確率から解析的な期待値を求めており、穿孔と同種の少数標本の偏りはない。
標本の均等化、32標本、512標本の測定版、donor価格の条件付けは、係数0.5のままでは明確な改善を示さなかった。
今回の係数変更と高速化を基準に、0.7近傍の係数、標本分散の削減との組合せ、
donor側の条件付けの範囲、非head候補への拡張を再確認する余地がある。
D2全体が飽和したとはまだ主張しない。D3〜D5は未着手。
マージ後の再開時にBASE.mdを読み直し、同じD2の検証を続ける。
