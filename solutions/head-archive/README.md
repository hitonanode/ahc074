# 1回の設計探索から途中の候補を選ぶ

改良元: solutions/tight-thirty-eight。

列共有探索の後半2区間について、各区間の最良解を4回ずつ保存する。探索の回数と乱数列を保ったまま最大8候補を残し、最終候補だけを使う基準と、先頭紙の穴埋め利益を引いた目的で選ぶ版を比べる。別条件では各候補を6000回だけ穴埋め山登りしてから選び、選んだ候補だけ残り59000回を行う。一括再割当・追加穴・補助表は選んだ候補だけ計算する。

研究用probe.cppは公開バーコードと保存した窓割当のみを読み、独立な固定乱数の注文で比較する。全表示と、各条件1系列の可視性・操作後の順序を検査する。main.cppは途中候補の保存だけを追加した研究用で、まだ提出候補ではない。全時計はCLOCK_SCALE倍。
