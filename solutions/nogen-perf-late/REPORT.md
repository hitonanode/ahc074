# 商品紙ライン: SOTA部品の移植と穿孔後の再割当

最終マージ候補と時間目標の達成結果は [nogen-perf-reuseの報告](../nogen-perf-reuse/REPORT.md) に記載。

起点は `solutions/nogen-v6-balanced`（PR #153）。汎用紙は追加せず、191枚の商品紙と1枚のキャップを維持する。以下の差はケースごとの log 比の平均、± は標準誤差。最終候補の2000件比較は後半と上記の最終報告に記す。

## 注文側: 同じ設計で有効な移植を選ぶ

保存設計 `20261106-104218_nogen-v6-balanced`、seed 0–499、注文列2本で比較した。

初回固定設計runでは `value_filler_gain` に「既存の有効計画なし」の1e18番兵との差が混ざった。意思決定には影響しない診断上の問題で、以後の版は有限の既存計画からの改善だけをgainに加え、救済数を `value_filler_rescues` に分離した。初回runのgain値を利得の根拠に使ってはいけない。

## 大きい変更の前に行った模型評価

`nogen-perf-model` / `20261106-110530_nogen-perf-model` は保存設計64件のコピーに条件付き穿孔を適用した。通常列だけを対象にし、v6の仮想背景ハンドルを除いた座標へ変換する。32層別標本、係数0.7で、追加穴は7.28±0.30個、模型改善0.008810±0.000635手/注文、計算約0.063秒。補完証明は全件成立した。商品所有色の制約上、追加穴は安全な自由度である。

`nogen-window-model` / `20261106-110531_nogen-window-model` は32件で背景窓数34/36/38/40の設計を比較した。列探索11Mなどを同じにして、colcost+hcost+背景比較費用−先頭フィラー価値を測った。各平均は7.58385 / 7.62026 / 7.69258 / 7.88490。40は2件で設計不成立。34は36より模型上約0.0364手低いが、設計時間1.111秒対0.847秒と高価だった。

`nogen-late-model` / `20261106-111707_nogen-late-model` は64保存設計の穿孔後に、追加穴を紙へ固定した再割当を比較した。1回・フィラー係数1.05で模型改善0.002859±0.000449手/注文、時間0.006490秒。穴を無視する対照との差は0.002752±0.000419手、変更単位22.78個。通常の再割当を単にもう1回繰り返す模型改善は0.000107±0.000243手にすぎない。これを根拠に穴を考慮する版を実装した。

模型は将来の注文を読まず、入力の商品集合と保存済み設計だけを使う。模型版の実際の出力は元設計のままで、模型値と実スコアは分けている。

## 出力を変えない設計高速化

`nogen-owner-cache` は潜在所有者との最小不一致数を、不透明集合と黒集合の完全一致キーで4096枠にキャッシュする。キャッシュ衝突は再計算、最小不一致0なら厳密下限なので走査終了。候補順・乱数・費用・反復予算は不変。

`20261106-111706` の通常500件同時比較ではreq-completeとstdoutが500本とも完全一致。control_map_secは0.461975→0.411007秒、judge平均は約0.053秒短縮した。owner-cacheのjudge平均1.626611秒、p99 1.793823、最大1.844569、2秒超0。外部負荷0.06/0.27コア。この時間を穿孔と列探索11Mに充てるのが `nogen-perf-cache`、さらに穴を考慮した再割当を加えるのが `nogen-perf-late`。

## 実装上の境界

- 背景6枚の印刷はそれぞれの実商品と一致し、キャップ以外に無所有紙はない。
- 穿孔は背景・自身のハンドル・キャップを変更しない。普通列のハンドル座標だけで評価する。
- 再割当は各物理紙の列とハンドル色を固定する。新しいペアが背景6枚で補完できることを適合表で確認し、最後に256商品すべてを証明する。
- 窓0–62の全所有色と窓63の承認済み白ペア/黒キャップ規約を実際の印刷に対して監査し、LOCAL_BENCHでは違反を停止する。
- 窓探索0.85秒、列探索1.15秒、フィラー1.20秒、穿孔1.27秒、追加再割当開始1.28秒に時計ガード。注文の軽量化は1.70秒から、通常のLOCAL_BENCH評価では無効。
- DesignStore v2、@paper/@ops、時計指標、flushと−1終了を維持。全ビルド・外部解析は共有flock下、評価はlocked g++ wrapper経由のpahcer_run.pyだけで行った。

追加再割当の模型単体は約0.0065秒だったのに、実装のd2_rematch_secは0.02106秒だった。差の大半は、変更しない背景6枚についてFeasのControlTableを再構築する費用である。`nogen-perf-reuse` は最初の証明検査の背景表を再利用し、穿孔後・再割当後とも紙と主所有者だけ更新して全256商品を再検査する。最終印刷に対する独立した監査は維持する。出力同一性と時間を改めて通常比較し、最終報告に結果を記した。

G34−G36の32件模型差の対応付き標準誤差は−0.036404±0.011347手。模型上の差も実スコアの保証にならないという今回の判断は変わらない。

## 安全性の確認

`20261106-112732_nogen-perf-lightcheck` は、perf-lateの保存設計500件×注文列2本で全注文を軽量処理へ固定した検証。1000件すべてWA・表示誤り0、全注文1024回で軽量処理を通り、所有色・キャップ規約・操作ラベル違反も0。req_sec平均0.02777秒、最大0.03328秒。実際の提出では1.70秒以降だけ軽量化し、通常のLOCAL_BENCHでは軽量化を無効にする。

perf-lateはGCC/Clang、提出用/LOCAL_BENCH+CLOCK_SCALE=1.1の4通りで、C++23 -O2 -Wall -Wextra -Werrorによる実ビルドを完了。実験15版もGCC提出用・Clang提出用/評価用の構文検査が警告なし。実行ファイルは/tmpに作成して削除した。

## 残る差と次の設計課題

perf-lateとSOTAの平均差は89.89操作/ケース、0.08778手/注文。ラベル差はfix +0.15651、help +0.04605、fret +0.01758、lift +0.04351、dig −0.12375、repair −0.05953、gen −0.03880手/注文など。ラベルは経路が変わると付け方も変わるため、独立した改善可能量として足し引きしない。

次は実列・実ハンドルを含むペア適合費用と、背景補完計画を区間DPへ直接入れる構造を検討する。G34の失敗を踏まえ、静的模型の最小値だけで決めず、保存設計の状態を使う軽い注文シミュレータで潜在利得を見積もってから実装する。SOTAの移植済み小改良だけでは残り0.088手を埋められていない。
