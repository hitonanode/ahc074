# astra-assign

改良元: solutions/imp-gla

`assign_windows` とその専用の下請けだけを高速化する。距離 26 以下の対、目的関数、同値の費用の順序、乱数列、焼きなましの温度と受理判定を維持する。`Design` と `Solver` は変更しない。

- 正負判定にしか使われていなかった指数重みを省き、互換性と `rel` を一つの整数にまとめる。
- 関係を「15 組の順方向・逆方向」のビットに詰め、両方向の矛盾を SIMD で判定する。
- 閉包と汎用紙の費用を完全一致のキー付きキャッシュに保存する。逆向きの関係は同じ費用なのでキーを共通化する。閉包は 6 紙分の計算を展開する。
- 受理時は候補配列と現在の配列を交換する。マッチングの鍵の計算には関数単位で `popcnt` を有効にする。
- 互換な対の番号を SIMD の評価時に集め、マッチングはその対だけを走査する。対の番号順を維持する。
- 1 組だけ変える手と 2 組を変える手の評価をテンプレートで分け、同じ組の二重計算を省く。
- SIMD での関係更新と、閉包キャッシュの参照を別の走査に分ける。
- 各窓で異なる商品の対をビット集合として前計算し、変更する組の関係をその OR と小さな展開表で作る。
- 基数ソートは下位 8 bit と上位の使用範囲に分け、空のバケツの累積和を減らす。頂点の使用済み判定には 256 byte の配列を使う。

閉包キャッシュは 262144 エントリ（約 2 MiB）。ハッシュ衝突時はキーの完全一致を検査して再計算する。距離上限 26、窓交換率 0.6、時間配分、目的関数の整数費用と最後の浮動小数点式は改良元と同じ。

実装と計測の記録は `REPORT.md` にまとめる。固定反復数の指定は元版と同じ `MAP_ITERS`、`GOPT_STEPS`、`ANNEAL_ITERS`、`CLIMB_ITERS`。時計には `CLOCK_SCALE` を掛ける。
