# clock-probe

改良元: solutions/audit4-flip

ジャッジの速さを測るための計測用の版（得点は狙わない）。audit4-flip の、時間で打ち切る探索 2 つを、決まった回数で止めるようにしただけで、ほかは同じ。

- 焼きなまし: 1.1 秒で打ち切る代わりに 1000 万回（`HUB_ANNEAL` の既定値を 0 → 10000000）
- 山登り: 1.15 秒で打ち切る代わりに 4 万回（`CLIMB_ITERS` の既定値を 0 → 40000）

1 ケースの計算量がマシンの速さによらず決まるので、ジャッジで出る 50 ケースの最大実行時間を、手元の同じ版の実行時間（24 並列の評価と、空いた状態での逐次実行）と比べると、ジャッジが手元の何倍遅いかが分かる。手元では焼きなましが約 0.7 秒（24 並列の評価で 1.4e7 回/秒）、全体で 1.1 秒前後の見込み。

- seq_bench.py: seed を 1 件ずつ逐次に実行して、実行時間と stderr の `*_sec` 行を出す（runs/.lock を取って、ほかの評価と CPU を取り合わない。記録は残さない）。
