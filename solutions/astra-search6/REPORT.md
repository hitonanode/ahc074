## 2. 改良の内容

### 窓交換と組変更を一手にする

基準の窓交換は、汎用窓aとハンドル窓bを入れ替えても、aの比較器の組をbへ引き継ぐ。
新版の複合手は、aを外し、**別の組へbを入れる**。窓の色も選ぶ。
窓交換と組移動を別々に行うと途中で多くの対が不適合になる場合にも、直接進めることを狙う。
元の組に窓が2個以上ある場合だけ提案し、15組すべてに少なくとも1窓が残る条件を保つ。

### 実行できる複合手を先に列挙する

現在選ばれている70対について、aを取り除いた後のDAGの閉包を計算する。
各閉包を、15組×2方向のうち新しい辺を加えると循環する方向の30bitへ変換する。
これを各ハンドル窓の差分・色と合わせ、26ハンドル×28方向（別の14組×2色）の損失数をビット並列で数える。
3対以上を不適合にする候補を除き、残りを表にする。除外境界は基準と同じ。

候補を選んだら表のbitを消し、同じ状態では繰り返さない。状態を受理したら世代を進め、表を無効にする。
全対評価と受理には元の `evaluate_move` と `matching_cost` を使う。
複合手のキャッシュキーにはa・b・移動先の組・新しい色を含め、逆手禁止のキーにも元の組と色を含める。

### 3候補の違い

| 候補 | 窓交換を複合手にする割合 | 候補の選択 |
|---|---:|---|
| main | 1/8 | 失う対が0/1/2対の候補を4/2/1倍の確率で選ぶ |
| cand2 | 1/16 | 同じ4/2/1の選択 |
| cand3 | 1/16 | 残る候補から一様に選ぶ |

4/2/1は提案の確率だけで、目的関数の重みではない。損失の大きい候補も探索できる。
一様選択に対する4/2/1の追加効果は、直接比較では確認できなかった。
1/16では +0.1055 ± 0.0990%、1/8では +0.0061 ± 0.1022%（各64件、[weight16-vs-uniform.csv](weight16-vs-uniform.csv)、[weight8-vs-uniform.csv](weight8-vs-uniform.csv)）。
各版はas5-g38に対して2SE以上改善しており、本番で選ぶための候補として残す。

変更は `assign_windows` 内だけ。関数の前後と `matching_cost` は基準とバイト一致した（[scope-summary.json](scope-summary.json)）。
目的関数の係数1800 / 5 / 144、距離上限26、G=38、kMapEnd=0.50 / kGoptEnd=0.61、温度・停滞判定・ほかの段・固定乱数seed・CLOCK_SCALEは維持した。
追加指標は `cross_rows`（候補表を作った窓数）、`cross_samples`（複合手の全対評価数）、`cross_accepts`（その受理数）。

## 4. 試してだめだった案

未採用の改良方向もここに含む。数値は全てseed24〜87の64件、基準はその都度同時計測したas5-g38。
全ラベルとSE・勝分敗は [EXPERIMENTS.md](EXPERIMENTS.md) を参照。

- **閉包の差分キャッシュ、汎用窓交換時の色変更、評価済み近傍の再提案禁止:** cached −0.0786 ± 0.1116%、colored +0.0411 ± 0.1282%、colored4 −0.0112 ± 0.1247%、unique +0.1322 ± 0.1027%。改善未確認。
- **疎な全対評価:** 変更する組以外に矛盾が残る対を省く。scalar / SIMD / 長い循環も事前除外の3版は +0.6446 / +0.7006 / +0.3536%。固定回数の結果は一致するが、集合構築と受理時の更新が重く、評価回数が約半減した。
- **全対更新の分岐とgather:** 不要な書込みを分岐で省く、prefetch削除、4件のキャッシュ照会をまとめる方式は、固定回数で結果を保つが速度改善なし。branch / noprefetch / gather / gatherbranchの通常計測も有意な改善なし。
- **早期終了と小さい管理処理:** earlyは初回 −0.2402 ± 0.1162%だったが、再計測 +0.0376 ± 0.1078%。乱数・除算の削減、色反転のビット判定、popcnt等の属性追加（lean / leanflip / native）も改善未確認。cross16earlyは −0.4277 ± 0.0928%だが、複合手への追加効果を確定できず、追加候補にはしない。
- **停滞判定と履歴:** 全対評価16/32件で停滞とする exact16/exact32 は +0.4762 ± 0.1209% / +0.0538 ± 0.1261%。状態の訪問回数を脱出先の順位へ加える history005/02/05 は +0.0789 / −0.0773 / −0.0441%。逆手禁止しか残らない場合の解除 unstick は −0.0220 ± 0.1065%。いずれも不採用。
- **組全体の色反転:** groupflip/2/4 は +0.0732 / +0.0088 / +0.1844%。単独の色反転で進めない状態を狙ったが改善なし。
- **除外をさらに厳しくする:** loss2は +13.3825 ± 0.3747%。全対評価が約9万→約2000回に減り、探索が止まりやすくなった。最初だけ2対のmap2も +2.0682 ± 0.1659%、最後だけ2対のclimb2は +0.2346 ± 0.1227%。4対のloss4は +0.0599 ± 0.1069%。3対を維持する。
- **複合手の派生:** 一様選択の頻度1/4・1/8・1/32・1/64、閉包を共用するfast、損失が最小の候補を優先するcrossrankも試した。fastは固定回数の結果を保つが、追加効果は未確認。crossrankは −0.2310 ± 0.1107%。主案3候補以外はソースを残さず、再生成設定と結果を保存した。

最初に試した軽量化の多くは、計算量を減らしても管理費用や分岐が増え、元のSIMD実装を上回らなかった。
今回の改善の中心は、新しい実行可能な複合手による探索範囲の拡張である。
