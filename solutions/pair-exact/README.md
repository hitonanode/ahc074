# 対の組み方を厳密な最小費用マッチングで求める試み（pair-exact）

改良元: solutions/esw-clean

## 改良元からの差分

- ユーザーの biglib にある一般グラフの最大重みマッチング（maximum_weight_matching.hpp、CC0）を、そのまま貼り付けた。
- `exact_pairs`: 256 個の目標から、ちょうど `need` 組（71 組）の互いに素な対を、費用の和が最小になるように選ぶ。
  - 単独のまま残る目標の数（256 − 2 × 71 = 114 個）だけダミー頂点を足す。
  - ダミー頂点はどの目標とも費用 0 で組めるとして、最大重みの完全マッチングとして解く。
- **計測（既定で有効、`PAIR_EXACT_MEASURE=0` で無効）:** 窓の割り当ての最終状態で、使える近い組から選ぶ 71 組の費用を 2 通り出す。出力は変えない。
  - `gobj_greedy_check`: 今の貪欲（gobj_after と同じ値になるはず）。
  - `gobj_exact`: 厳密なマッチングの費用。
  - `pairs_valid_final`: 使える組の数。
- **`PAIR_EXACT_INIT=1`:** 設計の初期化（Design::initialize）で、目標の対を貪欲（と長さ 3 の増加路）の代わりに厳密なマッチングで決める。
  - 費用は元と同じ「0.65 × 取っ手の違い + 2 × 汎用層の手数 + 0.04 × 違い」を、1e-6 単位の整数にしたもの。
  - `init_pair_cost` に、初期の対の費用の和を出す（貪欲のときも出す）。
