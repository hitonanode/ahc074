窓探索を出力同一で高速化する。状態用・作業用のrelation費用配列について、それぞれの非ゼロ位置を保存する。試行時は作業用配列の前回の非ゼロだけを消去し、旧互換ペアのうちrelation不変の費用と、今回閉包を計算した互換ペアの費用だけ書く。受理時は配列と非ゼロ一覧を対にして交換する。その他の費用は常にゼロである。

互換ペアの一覧は、小さなbitsetに「旧互換でrelation不変」と「今回新たに互換」を入れ、番号の昇順に取り出す。元のSIMD全走査と同じ順序なので、matchingの同点処理まで保つ。近似演算やfast-mathは使わず、窓探索の乱数と反復数も不変。

dcomp-ten-lateと同じ10候補目を追加する。既存9候補のsalt・反復数・Vと選択規則はそのまま。10候補目(id=9)は、その時点の最良の完成割当と穴を引き継ぎ、climb・前rematch・穿孔探索を省いて後段rematchとVだけを行う。追加候補がVを下げた場合だけ採用する。初期列順DPとDesignStoreは、最後に選ばれた設計に適用する。

map450k、gopt133k、annealと既存仕上げの予算は固定。時間による打切り、候補数変更、軽い注文処理はない。注文処理はdcomp-nineと同じlegal-tie-fast。CLOCK_SCALE、ログ、@paper/@ops、DesignStore、段の目印、実験スイッチ・プロファイラを保持する。dv_candidatesは10。
