# 報告: PR 115「列の部分列MDP」の esw-fixiter への移植（solutions/colmdp）

（実装と計測は別の Claude エージェント。この REPORT.md はその最終報告をそのまま保存したもの）

## 結論

- **設計固定の 2000 seed × 注文の列 2 本で、esw-fixiter 比 −0.100 ± 0.003%（勝/分/敗 1534/0/466、run 20261105-020341）。**
  - 全部の注文の列の平均スコアは 10419.02 → 10408.60。
  - WA 0。self_wrong と op_label_errors は 4000 本すべてで 0。
  - PR の報告（−0.0997 ± 0.023%）とほぼ同じ大きさ。
- **通常の `--compare` 2000 件（20261105-020750、pahcer/ に記録された）: −0.099 ± 0.004%（1381/36/583）。**
  - esw-fixiter の設計は固定回数で決定的なので、両者の設計は同じになる。このため出力は設計固定の run の 1 本目と全 2000 件で一致した。
- **COLMDP=0:** 設計固定 2000 件の出力が、esw-fixiter とバイト単位で全件一致した（20261105-020614）。200 件 × 2 本でも一致した（013959）。
- **時間:**
  - 注文処理の req_sec は、通常の比較で平均 0.2472 → 0.2614 秒（+5.7%、+14 ms）。
  - 前計算の colmdp_sec は平均 9.2 ms、最大 34〜41 ms（倍率込み、24 並列）。
  - 通常の比較では、手元の 1 ケースの実時間は平均 1.655 → 1.673 秒。2 秒を超えたのは 13 → 26 件、end_sec が 1.8 秒を超えたのは 800 → 924 件。
  - ジャッジ（Clang）では約 +25 ms と見積もる。
- **見立て: 採用してよい。** 改善は標準誤差の 25 倍以上ある。時間の増加は注文処理の約 6% と、前計算の約 10 ms。

## 実装（solutions/colmdp/main.cpp。改良元 esw-fixiter からの差分）

- **新しい段「Column MDP: long-run values of the order of a column」。**
  - `struct ColumnMdp`:
    - 紙の種類は 2 ×（2 目標を担当する紙か）+ 取っ手の色。
    - 全部の部分列に番号を付ける。番号は、枚数のベクトル（混合基数）と辞書順の順位で決める。
    - `insertion_indices` は、1 枚差し込んだ列の番号を全部の隙間について O(長さ) で出す。
  - `build` は次を行う。
    - 「1 枚消す」DAG の辺を作る（H には先頭を消す辺を使わない）。
    - PR の式（事象ごとに W で割る）で相対価値反復を 8 回行い、毎回 F と H を長い列から短い列へ伝える。
    - 最後に fix[b]（色 b まで掘った後の H）を作る。
  - 上限は PR と同じ（14 枚、全部の並び 40000、部分列 250000）。
  - `ColMdpConfig` / `colmdp_config()` は環境変数のノブ。
  - 総当たりとの突き合わせ（523 部分列）で、番号の全単射、差し込みの番号、F・H・fix が誤差 1e-7 以内で一致した。
- **新しい段「Solver: column MDP values in the future-cost model」。**
  - `init_colmdp` は `init_adaptive` の最後で呼ぶ。率は 1 手先の模型と同じ単位にした（種類の率は adaptive_weights の種類平均 / P、色の率は adaptive_holes）。
  - `colmdp_gap_values` は差し込みの種類で値を変える。
    - 戻し: F。この注文でこの列を掘るときは fix。
    - 出ていく紙のための掘り: 目標の紙より下の並びの F。
    - 色合わせの掘り: 目標の紙とその下の並びの H。`dig(l, barrier, stays)` を足し、`set_handle` は true を渡す。
  - `colmdp_scan_begin` / `colmdp_next_scanned` は、adaptive_next_cost の既存の走査の中で列ごとの順位を追う。列ごとに直前に読んだ F を覚えておく。
  - `colmdp_next_term` は、MDP の対象外の列があるときの走査。
- **adaptive_insert:** 隙間の評価を 0.5 × 1 手先の模型 + 0.5 × MDP の値 + 改良元の need の項にした。
- **adaptive_next_cost:** 改良元の値に 0.5 × Σ 列の F を足した。
- **その他:** 目次と段の目印を足した。stderr に `colmdp_columns`・`colmdp_full_states`・`colmdp_sequences`・`colmdp_sec` を出す。g++（-DCLOCK_SCALE=1.1 -DLOCAL_BENCH -Wall -Wextra）と clang++ で警告なしにコンパイルできる。
- **既定値:** UNIT=1（V を事象ごとのまま。PR の式どおり）、MIX=0.5、KEEP=0.5（adaptive_insert）、NEXTMIX=0.5、NEXTKEEP=1（adaptive_next_cost には足すだけ）、ITERS=8、CASES=15、NEEDFIX=1。
- 2000 件では、対象の列は平均 24.91 列（最小 23 列）だった。列の紙がほぼ 1 色にそろっているので状態は小さく、部分列の数は 1 ケースの和で平均 6 万、最大 21 万。

## 分かったこと

- **効いているのは MDP の値の「形」で、大きさではない。** 1 手先の模型を定数倍しても出力はほぼ変わらない。1 手先の模型を全部置き換える（MIX=1）と +0.37% 悪化する（種類にまとめた MDP は、紙ごとの重みや同じ種類の中の並びを区別できないので、半々に混ぜるのが良い）。
- **寄与の内訳:** adaptive_next_cost への加算が約 −0.044%（W を掛ける版では効かない）、持ち上げ・穴埋め紙のための掘りの差し込みが約 −0.05%、色合わせの掘りが約 −0.02%、戻しは約 0%。PR は adaptive_insert での利用だけを書いていた。
- **ラベル別の手（2000 件、1 注文あたり）:** 合計 10.176 → 10.166。fix −0.035、dig −0.009、ret −0.010、fret +0.014、reuse +0.010、fill +0.009（穴埋め紙をやや多く使い、取っ手の色合わせの掘りが減った）。
- V は 8〜16 回の反復でほぼ収束する。NEEDFIX は出力を一つも変えなかった。
