# hub

改良元: なし（汎用層の作り方は solutions/bit-pair と同じ）

目標（バーコード）ごとの専用紙を汎用層の下に隠しておき、「ハンドル窓」から掘り出して一番上に出す解法。誤りは出ない（E = 0）。以後の hub 系・gen- 系・hole- 系の解法はすべてこの枠組みの上にある。

## 紙の設計

- 窓を汎用窓 G と、ハンドル窓 h_0..h_{H−1} に分ける（H = 16。今は最後の 16 窓をハンドル窓にする）。
- 汎用層（並びの一番上）: G の各窓 j に、窓 j だけが不透明な白と黒の紙を 1 枚ずつ（bit-pair と同じ。多数決の色を上）。汎用層は常に G 全体を覆う。
- 専用紙 D_u: 残りの紙を、ランダムに選んだ目標 u 専用の紙にし、H 本の「列」に分ける。列 l の紙は G と h_0..h_l で A_u の色、h_{l+1}..h_{H−1} で穴。
- 列 0, 1, ..., H−1 の順に汎用層の下へ積む。列 l の一番上の紙は h_l だけで見える（列 0..l−1 の紙はそこで穴、深い列はその下にある）。ほかのセルはすべて隠れている。
- 列の大きさは均等（偶数にそろえる）で、列の中ではハンドル窓 h_l の色が白黒交互になるように目標を選ぶ。余った紙は全面が穴。

## 注文ごとの操作

- 最初に、前の注文で一番上に出した専用紙を、その列の一番下へ戻す。
- 掘り（dig）: 列 l の一番上の紙を列の一番下へ移す。h_l の表示しか変わらない。列の色が交互なので、1 回の掘りでハンドル窓の色が反転する。持ち上げと戻しでも列の巡回順は崩れないので、交互は保たれる。
- 専用紙 D_u（列 l）がある注文: D_u が列 l の一番上に来るまで掘り、D_u を一番上（深さ 0）へ移す。これで G と h_0..h_l は A_u になる。D_u が穴の深いハンドル h_{l+1}.. は、それぞれの列を色が合うまで掘る。
- 専用紙がない注文: G は汎用層で（bit-pair と同じく窓ごとに 1 手）、各ハンドル窓はその列を掘って合わせる。
- 時間で打ち切る探索はない。

## パラメータと指標

- 環境変数 `HUB_H`（既定 16）: ハンドル窓の数 H。乱数の seed は 12345。
- stderr: `moves`（操作の総数）、`ded_requests`（専用紙のある注文の数）、`ded_moves_per_req` / `gen_moves_per_req`（専用紙のある / ない注文の平均手数）、`self_wrong`（解法が自分で再生した表示が目標と違った注文の数。0 のはず）。
