# cmp-speed

改良元: solutions/cmp-ret

設計の探索を速くし、時間の予算を延ばした。アルゴリズムは同じで、回数を固定すれば（MAP_ITERS, GOPT_STEPS, ANNEAL_ITERS, CLIMB_ITERS）出力は cmp-ret と同一（solutions/cmp-base/eqcheck.py で確認）。同じ時間でより多く探索することだけが違う。

## 速くしたところ

- 汎用窓の割り当て（assign_windows）の手の評価（evaluate_move）: 約 3400 の近い対のうち手で変わる約 2000 を、対ごとに分岐の多い処理で数え直していた（割り当ての時間のほぼ全部）。これを AVX2 で 4 対ずつ、全部の対について分岐なしで計算するようにした。
  - 対のデータを欄ごとの配列（WindowPairs）にし、末尾を差のない対で 4 の倍数に詰めた。変わった窓 a, b で異ならない対は、計算しても値が変わらない。
  - 関係が変わった対の約 86% は「x が上」と「y が上」を両方含む（関係の行列とその転置の積が 0 でない）ので、閉包を計算せずに両立しないとする。閉包は残りだけ。
  - 重みの変化は対の順に足すので、浮動小数点の結果も元と同じ。
  - gobj の山登りで採らなかった手の戻しは、対の新旧の値の交換（swap_pairs）と、作業用の配列の使い回しにした。
  - 割り当て 8000 回 + 山登り 2000 回（と初期化）が、空いたマシンの逐次で約 0.44 秒 → 0.15 秒（初期化の約 0.035 秒を除くと約 3.6 倍）。
- 焼きなまし（Design::anneal）:
  - ハンドルの交換 a ↔ b ができる（列 a の対が h_b で、列 b の対が h_a で異ならない）かを、列ごと・ハンドルごとの「その位置で異なる対の数」（pdiff。採用した手で更新）で先に判定する。交換の候補の約 9 割はできない。
  - 却下した手で穴の数を戻すのを、触ったハンドルのループから、全ハンドルの配列のコピーにした。
  - 600 万回が空いたマシンの逐次で約 0.37 秒 → 0.31 秒。浮動小数点の結果を変えないため、費用 cur への足し引きの順（手ごとに数十回の依存した加減算）は変えられず、これ以上は難しい。
- AVX2 は evaluate_move だけで `__attribute__((target("avx2,popcnt")))` を付けて使う。手元の評価は -march=native なしでコンパイルするため。ジャッジの Xeon も AVX2 を持つ。

## 時間（倍率の掛かった秒）

| 区切り | cmp-ret | cmp-speed |
|---|---|---|
| 割り当て（kMapEnd） | 0.45 | 0.50 |
| 割り当ての山登り（kGoptEnd） | 0.55 | 0.61 |
| 焼きなまし（kAnnealEnd） | 1.28 | 1.425 |
| 穴埋めの山登り（kClimbEnd） | 1.33 | 1.48 |
| 初期化の打ち切り（kInitGiveUp / kInitExpiry） | 1.15 / 1.20 | 1.30 / 1.35 |
| 軽量処理への切り替え（kFastAfter） | 1.80 | 1.80 |

各段の時間の比はほぼ元のまま、全体を約 1.11 倍にした。注文の処理（時間で打ち切らない）と対話の待ちは cmp-ret の 24 並列の評価で最大 0.29 秒なので、終了は最大で約 1.77 秒（ジャッジでは時間で打ち切らない部分が約 1.045 倍かかるとして約 1.78 秒）の見込み。

stderr の指標は cmp-ret と同じ（map_iters、gopt_steps、anneal_iters、climb_iters、*_sec など）。
