# 途中修復を軽くし、修復後も操作を削る

改良元: solutions/eject-one。短縮は solutions/eject-lazy、solver-scan、solver-tops、eject-prefix、追加削除は solutions/eject-trim。

修復紙が最初と最後に見える時点だけを候補にする。修復が採用された場合には、残りの操作から1個ずつ取り除けるものを最大3巡調べる。全候補を可視性付きで再生し、正しい表示と次注文への状態費用を確認する。

修復候補が見つかった時だけ窓ごとの不透明位置を求める。列ごとの色合わせ費用と先頭4枚は一度の走査で集め、窓ビットの並べ替えは8ビット単位の表を使う。これらの短縮部分は同じ操作を出すことを模擬で確認した。

紙の設計と時間配分はeject-oneと同じ。列探索1.205秒、穴埋め山登り1.26秒、先頭再割当1.345秒、補助穴1.39秒、補助表1.45秒、軽量処理1.80秒。全時計はCLOCK_SCALE倍。eject_pairs、eject_trials、eject_accepts、eject_insideの意味も同じ。

先頭色の微分計算の作業配列も最大64窓に対応させ、汎用窓を減らして設計し直す経路でも窓数の上限を守る。各要素は使用前に代入し、不要な全体初期化を省く。
