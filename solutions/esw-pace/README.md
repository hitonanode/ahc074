# 設計の締め切りの短縮と、注文処理のペース配分（esw-pace）

改良元: solutions/esw-fast-ptune（esw-ptune の定数 + esw-fast の高速化）

ジャッジでは注文処理が手元の見積りより約 1.4 倍遅く、esw-tidy・esw-noprune は多くのケースで 1.80 秒以降の軽い計画（1 注文あたり約 0.011〜0.014% の損）に入った。改良元の高速化に加えて、次の 2 つを入れた。

1. 設計を早く終える。
2. 時間が足りなくなりそうなときは、軽い計画に一気に切り替える代わりに、価値の小さい後処理から順に省く。

## 変えたこと

- **設計の締め切り（kDesignScale = 0.90）**
  - solutions/esw-early90 と同じく、設計の段の締め切りをすべて 0.90 倍にする。対象は、窓の割り当て、焼きなまし、山登り、再割り当て、穴あけ、緊急設計への切り替え、補助紙の表の打ち切り、割り当てのやり直しの時間。
  - 設計の探索は約 1.2 秒で飽和していて、0.85 倍までは手元の損がほぼない（trial_log「esw-early90/85」と PR 102）。
- **注文ごとの手間（Solver::effort）**
  - 0: 改良元と同じ。
  - 1: 2 削除 + 1 修復（eject）を省く。
  - 2: さらに 2 番目の候補の後処理（post-two）を省く。
  - 3: 軽い計画（改良元の fast_mode）。
  - 設計を固定した手元の測定（全注文をその手間にしたとき）では、手間 0 に対する損は +0.22%・+0.41%・+11.3%、計画時間の比は 0.71・0.58・0.02。省いて浮く時間あたりの損は、手間 1 → 2 → 3 の順に大きい。
- **ペース配分（main の Pacer）**
  - 各注文の前に、手間 e で残りの注文を処理したときの終わりを見積もる。見積りは「今の時刻 + 残りの注文数 ×（待ちの平均 + kEffortShare[e] × full）」。
  - 手間 0, 1, 2 の順に見積り、kPaceEnd 以下になる最小の手間を使う。
  - どれも超えるときは、手間 2 の見積りが kFastAfter 以下なら手間 2、超えるなら軽い計画にする。kFastAfter を過ぎたら常に軽い計画。
  - full は手間 0 の計画時間の推定（手の出力を含む）。最初の kPaceWarmup 件は手間 0 で処理し、full はその平均から始める。以後は、手間 e < 3 の注文ごとに「計画時間 / kEffortShare[e]」へ kPaceAlpha だけ近づける（移動平均）。
  - 移動平均にしたのは、計画時間が注文の列の後ろほど短くなるため（最初の 4 分の 1 から残りへ約 15%）。全体の平均では終わりを遅めに見積もり、早く手間を落としすぎた。
  - 5 件目からは、計画時間も待ちも kPaceClip × full で頭打ちにする。1 回の停止（機械の遅れ）で推定が膨らむと、軽い計画（推定を更新しない）から戻れなくなるため。
- LOCAL_BENCH（手元の評価）では、改良元と同じく常に手間 0（機械の負荷で操作が変わらない）。

## 主なパラメータ（時計の倍率込みの秒。ジャッジでは実時間）

- kDesignScale = 0.90（PACE_DESIGN_SCALE で上書きできる）
- kPaceEnd = 1.85（注文の処理を終える目標）、kFastAfter = 1.92（手間 2 でも間に合わないときの軽い計画の境と、常に軽い計画にする時刻）
- kEffortShare = {1.0, 0.71, 0.58, 0.02}、kPaceWarmup = 32、kPaceAlpha = 1/64、kPaceClip = 4

## 計測用のスイッチ（main.cpp 冒頭の「Test switches」）

計測用のコピー（solutions/esw-pace-*）が使う。main.cpp の先頭に数行を足しただけで、提出用ではない。

- PACE_FORCE=e: LOCAL_BENCH でも全注文を手間 e で処理する（esw-pace-e1〜e3）。手間ごとの損と時間を、設計を固定して測る。
- PACE_SIM=f: 注文処理の段の時計の読みを f 倍に伸ばし、LOCAL_BENCH でもペース配分を使う（esw-pace-slow14・17・20）。ジャッジの遅さを手元で真似る。`--design-from` で使える。
- PACE_CLIFF=1: ペース配分の代わりに、改良元と同じく kCliffAfter = 1.80 秒から軽い計画にする（esw-pace-slow*-cliff。対照）。

## stderr の指標

- effort1_requests・effort2_requests・effort3_requests: 手間 1・2・3 で処理した注文の数
- pace_wait_sec: 注文を待つ時間の平均（頭打ち込み）
- pace_full_sec: 最後の full（倍率込みの秒）
