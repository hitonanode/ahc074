改良元: `solutions/opsearch-heavy`（`solutions/neutral-port` の子孫）

同手数で補助紙を交換して終了状態を改善し、交換によって不要になった操作を再短縮で消す。安い1→1 修復を使い、再短縮の候補を新しい紙を使うものに絞る。2→2 を有効にした場合は、削除する2操作の紙が終了表示で見えている組を優先する。通常の計画・後処理・評価関数・完全再生検査は継承する。

既定値は `NS_ONE=1`、`NS_TWO=0`、`NS_RECHECK=0`、`NEUTRAL_WIDTH=2`、`NEUTRAL_SLACK=0.25`、`NEUTRAL_DEPTH=2`、`NS_SHORT_ROUNDS=0`、`NS_ROUNDS=2`、`POST_CANDIDATES=2`。1→1修復と候補の再短縮を最大2周、評価値が改善した間だけ行う。候補へ編集パスだけを再適用し、余分な eject の反復を省く。その他の探索設定と stderr の `ns_*` / `neutral_*` / `triple_*` は[改良元の README](../opsearch-heavy/README.md)と同じ。

- `NS_NEW_ONLY=1`（既定）: 新しい紙を使う候補だけを再短縮用に保存する。即時に評価値が改善する候補の採用は制限しない。0 でこの選別を無効化。
- `NS_PAIR_FILTER=1`（既定）: 2→2/3→2 の削除する組は2枚とも現在の終了表示の所有者。2 は少なくとも1枚、0 は制限なし。可視性は最良状態から求め、探索中に状態が変わってもこの列挙の基点を保つ。
- `HEAVY_TRACE=0`、`HEAVY_PREDICT=0` が既定。1 にすると改良元と同じ分析ログを出す。
- `NS_DELETE_ONLY=0`（既定）: 1 なら中立候補の最初の編集パスを単独削除だけにする。修復担当を交換した結果、不要になった掘り出し・返却などを消す。通常の計画に対する編集パスは変えない。
- `NS_ALTERNATE=0`（既定）: 1 なら通常の編集パスで既に短縮した、選ばれなかった方の計画を保存して eject だけ追加する。通常処理後の最良値からの差が `NS_ALTERNATE_GAP=0.75` 以下の場合に限る。計画や編集パスを作り直さず、重い版で見られた「eject まで行うと計画の優劣が逆転する」場合を探す。
- `NEUTRAL=0` で追加探索全体を止め、esw-fixiter の標準出力を再現する。

すべての設定は初回だけ読む。提出時の Pacer、`CLOCK_SCALE`、LOCAL_BENCH の手間固定、設計の保存・読み込み、紙の属性と操作ラベルは継承する。
