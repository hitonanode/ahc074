# 同じ最終紙順を保つ操作短縮の限界

対象は `20261101-160151_imp-combo` と `20261101-160151_imp-combo-2`。同じ新規生成4ケースを2回実行した計8192注文であり、独立した8ケースではない。結果の詳細は `relocation-legal-analysis.json`、再現プログラムは `analyze_relocations.py`。

## 結果

| 指標（注文あたり） | 1回目 | 2回目 |
|---|---:|---:|
| 実際の操作数 | 10.59888 | 10.60425 |
| 可視性を無視した `K-LCS` 下界 | 8.43335 | 8.43970 |
| 見かけの差 | 2.16553 | 2.16455 |
| 同じ紙の重複移動 | 0.00610 | 0.00684 |
| 固定紙の不可視障害により下界に追加される操作数 | 2.12524 | 2.12769 |
| 強化下界を考慮した残りの改善余地の上限 | **0.04028** | **0.03687** |
| 合法な各紙1回の操作合成で実際に削減できた操作数 | 0.00415 | 0.00317 |

実際の削減は1回目が9注文で17手、2回目が6注文で13手。下界計算は全対象で終了し、探索上限による打ち切りは0件。操作合成はそれぞれ18件・16件で探索上限に達したが、上記の改善余地の上限は変わらない。

したがって、この出力に対して各注文の開始時・終了時の全192枚の順序を保存する後処理では、どれだけ強い探索を使っても短縮量の上限は平均 **316/8192 = 0.03857421875手/注文（約0.03857手）** となる。これは測定した紙順についての上限であり、未知の全ケースに対する確率的保証ではない。0.3手以上の改善を狙うなら、紙の設計、問い合わせ処理の状態遷移、または最終紙順そのものを変える必要がある。

## 可視性を使った下界

問い合わせ前後の紙順をそれぞれ `before`, `after` とする。操作列で一度も動かさない紙の集合を `U` とすると、`U` は両方の順列の共通部分列をなす。これだけなら操作数の下界は `K-LCS(before, after)` である。

さらに、`U` に属さない紙 `x` の初回移動を考える。`before` で `x` より上にある `U` の紙は、初回移動時にもすべて `x` より上にある。それらの紙が `x` の不透明部分をすべて覆うなら、`x` は絶対に可視にならず、初回移動できない。

よって、合法なすべての操作列は次を満たす。

```
すべての x ∉ U について:
opaque[x] & ~OR(opaque[u] : u ∈ U かつ before 内で u が x より上) != 0
```

この条件を満たす共通部分列の最大長を `L_visible` とすると、合法な操作数は少なくとも `K-L_visible` である。この条件は必要条件なので、実際にはそれより多くの操作が必要でもよい。紙を複数回動かす計画に対しても下界は成立する。

プログラムは `before` を上から走査し、各紙を `U` に残すか、動かす側に入れるかを分岐する。残す場合は `after` 内の順位が直前に残した紙より後でなければならず、不透明部分の和集合を更新する。動かす場合は上記の可視性条件を検査する。残りの最大 LIS 長による枝刈りと memo 化を行い、`K-LCS` から順に動かす枚数を増やす。全下界探索が完了したため、上表は任意に選んだ1本の LCS に対する値ではない。

下界の実装は、小さいランダム順列300例のすべての集合サイズについて、全部分集合の列挙と一致することも確認した。

## 指定した固定集合に対する合法な操作合成

候補 `U` を固定し、そのほかの紙を各1回だけ動かす計画を探す。`U` と、すでに動かした紙の集合を `F` とする。`F` の相対順序は常に最終順序と一致していなければならない。したがって、未移動の紙 `x` を動かす場合、その挿入位置は、最終順序で `x` の直前・直後にある `F` の紙の間に限定される。

現時点で可視な未移動紙と、その区間内の全挿入位置を列挙する。状態は「すでに移動した紙の bitmask と現在の全紙順」で memo 化する。これにより、指定 `U` に対して各紙を1回動かす計画を完全に探索できる。動かしても状態が変わらない操作は、最短計画から除けるため列挙しない。

実装は1注文20000探索状態で打ち切る。操作合成では、アクセス可能な最大共通部分列の最初の1つを使っている。ほかの最大共通部分列や、紙を複数回動かす計画には未探索の余地がある。ただし、すべて成功しても改善は強化下界が示す平均316/8192手以内に限られる。見つけた短縮列は `replay.Game` の可視性検査付きで再生し、最終紙順が元の操作列と完全一致することを確認した。
