# 冗長な専用紙から状態ごとに選ぶ実験

改良元: `solutions/imp-gla`。

## 変えたこと

現解法の「1 商品につき専用紙は 1 枚」という制約を外す。元の紙の設計が終わった後、単独の商品 `a` を担当していた紙の一部に、別の列にある商品 `v` の担当を追加する。紙は `a` と `v` が一致する場所だけを印刷し、違う場所は穴にする。`v` は元の専用紙とこの追加紙の 2 通りから選べる。`a` の表示も引き続き可能だが、穴が増える費用を負担する。

追加先は、(1) 汎用比較器で二商品の穴をどちらも表示できる、(2) 元の列のハンドルの色が同じ、(3) 元の専用紙と少なくとも 2 列離れている、を満たすものに限る。元の列のハンドルは穴にならず、両色の紙が残るので、列へのアクセスの不変条件を保つ。

候補は「元の商品に増える汎用操作と穴の費用」と「別商品が二つの列の軽い方を選べる得」の粗い期待値で並べる。列内順位は一様、穴の費用は 0.40、差の揺れは三点分布で近似する。これは候補選択のための模型であり、実スコア予測や下限ではない。模型が損と予測しても指定数まで変更し、実測で判断する。

注文処理では全候補を同じ現在状態から実際に計画し、従来と同じ `手数 + 0.6 × 列外の穴埋め紙数 + 次注文の期待費用` が最小の合法な計画を採用する。汎用層の到達可能順序は候補紙ごとに前計算し、切り替える紙と必ずセットで使用する。元の紙用に前計算された補助紙の interleave は元の候補だけで使う。列内の将来要求重みは商品の候補数で等分し、冗長化で注文の総重みが増えないようにする。

## パラメータと時間

- `ALIAS_LIMIT`: 追加する紙の最大数。既定 32。コンパイル時 `-DALIAS_LIMIT=16` または環境変数で指定できる。0 は追加を行わない。同じ商品に追加する候補は最大 1 枚、単独紙の改造は各 1 回。互換な候補が少なければ実追加数は上限に届かない。
- 窓の割り当て 0.35 秒、山登り 0.43 秒、主設計 1.04 秒、穴埋め設計 1.09 秒まで。補助紙前計算は 1.40 秒まで。注文処理用の時間を確保するために `imp-gla` の設計時間から短縮した。
- `CLOCK_SCALE` は元と同じで、全ての壁時計に適用する。1.80 秒以後は元からある軽量計画を各候補に用いる。
- 乱数 seed、対話の flush、可視性検査は元の実装を引き継ぐ。

この試作は専用紙の配置・ペアを作った後に追加先を選ぶので、冗長性を含めた同時設計にはなっていない。最初のマッチングが良い互換相手を既に使っており、残る単独紙に良い追加相手が少ない可能性がある。候補選択と元の紙の改造費用を切り分けるための実験である。

## stderr の追加指標

- `alias_limit`, `alias_added`, `alias_edges`: 指定上限、実際の追加数、列と色の条件を満たす候補辺数。
- `alias_model_damage`: 候補選択模型の損失見積りを 256 で割った合計。実スコアではない。
- `alias_selected`: 別の専用紙を選んだ注文数。
- `alias_candidates_evaluated`: 複数候補のある注文で実行した候補計画数。

元からある計画探索の試行数・節約数等のカウンタには、別の候補として試し、最終的には採用しなかった計画も含まれる。`total_moves` と `self_wrong` は採用した操作列だけを数える。

## 設計仮説を調べる補助プログラム

- `cluster_probe.cpp`: 一様な 32/64 ビットの目標 256 個と、ランダムに窓を割り当てた比較器を作る。各構成で、各々が相異なる3目標からなる三つ組を10万回抽出し、可変ビットを全部穴にした紙を三目標が共有できるかを DAG で厳密に判定する。窓割り当てを最適化した解法に対する下限ではない。

評価結果と採否は `trial_log.md` と検証報告に記載する。
