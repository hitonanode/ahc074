# search-ops

改良元: solutions/hub8

紙の設計は hub8 のまま、注文ごとの操作を「いくつかの選択肢の全組み合わせを試して最良を採る」計画探索にし、新しい手段として穴埋め紙を入れた。

## 変更点

### 穴埋め紙

- 専用紙 D を一番上へ持ち上げた後、D のハンドル窓の穴 h_c の列 c から、一番上の紙 X を汎用層のすぐ下（すでに置いた穴埋め紙があればその下）へ移す。X は列 c の紙なので h_0..h_c で不透明で、D の穴のうち h_c までをまとめて覆う。X の色がそこで目標と一致していれば、覆った列は掘らずに済む。
- 採る条件: X が覆う穴の色がすべて目標と一致し、それで省ける掘りの手数（各列を set_handle で合わせる手数の和）が 3 手以上のとき（移す 1 手 + 次の注文で戻す 1 手より得になるとき）。最も得の大きい列を選ぶ。1 注文に最大 4 枚まで重ねる。
- 列の 2〜4 番目の紙（深さ p = 1..3）も使える: 上の p 枚を、使う紙のすぐ下へ順に移してから（列の巡回順を保ったまま使う紙が列の一番上になる）、その紙を穴埋めに使う。省ける掘りが p + 3 手以上のときに採る。次の注文で、その紙は列の中の直前の紙のすぐ下へ戻す（列の巡回順と色の交互が保たれる）。
- 穴埋め紙は次の注文の最初に列へ戻す。

### 計画探索

- 注文ごとに、次の選択肢の全組み合わせ（最大 16 通り）を、状態のコピーの上で最後まで実行する。
  - 前の専用紙を列の下端へ戻すか、上端へ戻すか（hub7 の規則で選ぶ代わりに、両方試す）。
  - 列の一番上から取った前の穴埋め紙を、列の下端へ戻すか、上端へ戻すか。
  - 穴埋め紙を使うか。
  - 前の専用紙が今の目標の紙でもある（対の相方が続いた）なら、列へ戻さずに一番上に据え置くか。
- 各手で、動かす紙が見えているかを検査し、見えていない紙を動かす計画と、最後の表示が目標と違う計画は捨てる。
- 残った計画のうち「手数 + 列の外に残した穴埋め紙の数（次の注文で戻す手数の見込み）」が最小のものを採る。

## パラメータと指標

- 環境変数（hub8 のものに加えて）: `SEARCH`（既定 1。0 なら探索せず hub8 と同じ手順）、`FILLER_DEPTH`（穴埋め紙に使う列の紙の深さの上限、既定 3）、`MAX_FILLERS`（1 注文の穴埋め紙の枚数の上限、既定 4）。
- stderr に足したもの: `partner_hits`（前の専用紙が今の目標の紙でもあった注文の数）、`kept_partner`（そのうち据え置いた数）、`fillers_used`（各注文の後に列の外に残っていた穴埋め紙の枚数の合計）、`total_moves`（操作の総数）。hub8 の `dig_per_ded`・`tri_per_ded`・`gcare_*`・`handle_holes_per_ded` はなくなった。
