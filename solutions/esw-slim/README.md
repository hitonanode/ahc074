改良元: solutions/time-alloc

time-alloc を、注文処理の側（solutions/clean-req、Astra 1）と設計の側（solutions/clean-design、Astra 2）に分けて整理し、2 つの差分を合わせた版。行数は 9455 → 8930。

## 削った機能（ablation で効いていないことを確かめたもの）

- **注文処理**（設計固定 2000 × 2 本で、削っても差が +0.003% 以内）:
  - 同じ目標の前回の補助紙の置き方の再利用（query-memo）: +0.0012 ± 0.0007%。今の予算では効きがほぼ消えていた。
  - 前の商品紙をその場に残す返却の型（ret_mode=4）: +0.00003 ± 0.0001%。
  - 既定で無効の実験経路 3 つ（区間一括の正規化 CANON、可視時点の共有 SHARED_VIS、編集パスをまたぐキャッシュ CROSS_MEMO）。有効にしても得点は同じで、速くもならなかった。
- **設計**（通常の 2000 件で +0.011 ± 0.026%）:
  - 窓の割り当ての通常の「汎用窓の極性の反転」と「汎用窓どうしの交換」の手と、その専用コード。ほとんど受理されない手。
  - 両向きの弧の事前判定（AS_SCREEN）。上の手のためのもの。

## 動作を変えない整理

- **注文処理:**
  - 次の処理を共通化した。
    - 操作の深さから直前の紙のアンカーへの変換。
    - 計画の開始時の積層の復元。
    - 紙の配列とリンク列の移動。
    - eject → 再編集の繰り返し。
    - 補助紙 1 枚・2 枚の汎用層の並べ替え。
  - SearchConfig の型・環境変数名・既定値を 1 つの宣言にまとめた。
  - 後処理の初期積層の二重の保存（int 配列と byte 配列）を、byte 配列に統一した。
  - 長い説明を短くした。
- **設計:**
  - 候補の処理・費用の式・DP の重複をまとめた。
  - 窓の割り当てを段に分けた（候補の足切りと表、通常の手、保存状態への経路、受理と探索のループ）。
  - 設計の焼きなましの手の提案を、別の段にした。
- 合わせた後に、削った機能の指標を 0 で出していた残り（qm_*、f2_canon_*、f2_visibility_*）を消し、冒頭の目次を実際の段に合わせた。
