# astrasearch-joint-hot

改良元: `solutions/astrasearch-joint`（元は `solutions/imp-gla`）。

汎用窓・比較器の模様・商品の対・列を一体として探す、大近傍の焼きなまし。
汎用窓とハンドル窓の交換に加え、汎用窓の白黒反転と比較する紙の対の交換を使う。
大近傍で壊れた商品対を単独紙へ分解し、単独紙の再マッチングで192枚へ戻す。
列の両色と商品対の整合性を修復してから、列・対・ハンドルの焼きなましで周辺を再最適化する。

- 最初の列の焼きなましを 0.86 秒で止め、1.305 秒まで大近傍を探索する。
- 大近傍ごとの列焼きなましは既定30万回。大近傍の温度はモデル費用の総和で 4.0 → 0.03。
- 焼きなまし中は悪化も確率的に受理するが、最後には最小費用の有効な設計を出す。
- 注文処理は `imp-gla` と同じ。未来の注文は使用しない。

## 研究用の計算量の指定

`JOINT_RESEARCH=1` では最初の列設計を 1.305 秒まで行った後、既定64回の大近傍を各100万回の列焼きなましで調べる。
この場合は補助紙の前計算と注文処理を壁時計で省略しないため、**2秒制限を超える研究専用モード**になる。
`JOINT_STEPS` と `JOINT_ANNEAL_ITERS` が正なら、それぞれの既定値を置き換える。
本モードの得点は時間制約を満たす提出解の得点と区別して報告する。

## 診断

`joint_trials/repaired/accepted` は大近傍の試行・修復成功・最良値更新の数。
`joint_uphill` は確率的に受理した悪化の数。
`joint_before/after` は設計モデル費用を256で割った値。
`joint_closest_before/after` は列の再最適化の前後で、出発設計との差の最小値（同じく256で割る）。
`joint_research` が1なら研究専用モード。
モデル費用には注文処理の穴埋めや後処理の効果を正確に含まないため、改善が実測へ移るかは比較評価で判断する。
