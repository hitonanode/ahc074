## 1. What process(u) does for one order (8859-9437)

Every step simulates on the Solver's own stack state (`save()/restore()` snapshots: order[K], top_d, fillers). The single cost function throughout is **plan_cost(moves) = moves + filler_charge + kEndWeight·adaptive_next_cost + generic_bias** (5242-5247), i.e. moves now + a one-order-ahead expected cost of the end state (section 2). Validity of any candidate = `display() == A[u]`, `ops.size() <= 2K`, `fillers_reachable()`, no illegal (invisible) move.

Time shares below: **[P]** = legal-speed-phase breakdown, run 20261108-085843 on legal-tie-fast, seeds 0-299, 487 ms/case (trial_log 1659; legal-notes/PROGRESS.md 150-151, 191). dual30 is 499 ms/case mean (run 20261109-003105) after: legal-speed-fast −28 ms, M1 +5 ms, alt1 speedups −55 ms and NS_ALTERNATE +67 ms, dual25 fast11 −35 ms and additions ≈ +31 ms, dual30 memo −5 ms. **[S]** = pacer stage table on dual30 (jflags-pace-dual30, runs 20261108-232030/232031, fixed designs 500×2): dropping the extra parent and round 3 saves 21 ms (+0.014%); keeping one neutral round and dropping ALT/second parent/round ≥2 saves 125 ms (+0.11%); dropping neutral search entirely leaves 260 ms (+0.59%); the first legal plan alone is 14.5 ms (+4.87%).

### Step 1: setup (8861-8882) — [P] setup 1.6 ms
Reset the whole-post memo epoch, tie pool, `init_adaptive()` (first call only: builds all static tables, section 2). `st0 = save()`. `prev_ok` = a different paper is still lifted on top from the previous order; `any_out` = old fillers exist.

### Step 2: the plan menu (8882-9002) — [P] opts 77.9 ms (16%) + weighted 6.0 ms
Menu of `PlanOpt` (5816): `ret_mode` 1/2 = return the previously lifted paper into its column via `adaptive_insert` (mode 2 vs 1 differ only by kTopPenalty, which is 0, so 2 is replayed from 1's result, 8972-8987); 3 = keep it out as a filler. `fret_mode` 1 = return old fillers, 4 = reposition them, 5 = joint interval DP choosing old and new fillers together (`run_joint` 6049). Menu: rm ∈ {1,2,(3 if prev_ok)} × fm ∈ {1,(4 if any_out)}, plus (if d ≠ top0) {rm1,fm5}, {rm2,fm5}, {rm1,fm5,value_fillers}, {rm1,fm5,value_fillers,complete_value} — 2 to 10 options, ~7 typical. `run_plan` (6216): return/reposition old extras → `set_generic` (order the 6 generic sheets by the Comparator for D's generic holes, ties broken by `future[]`) → pre-lift fillers chosen by weighted interval scheduling over handle indices (`best_intervals` 5850; candidate = a column-top paper at depth ≤ kFillerDepth covering the hole interval [lvl, c], gain = digs saved − (1 + depth)) → `lift(d)` (digs its column above it) → post-lift fillers → `fix_handles` (dig each remaining wrong handle until a paper of the right color heads the column, 5668-5692). Digs and returns insert at the depth of least expected cost (`adaptive_insert` 5253, section 2). Each valid result is scored by plan_cost, recorded for post-processing via `record_future` (8932: merges double moves first, then `collect_future` keeps the `kPostCandidates = 6` cheapest of **distinct end orders and distinct moved-paper sequences**), and noted for the tie pool. `weighted_raw` (8992) remembers the value_fillers joint plan for Step 9.

### Step 3: filler chains on the best normal plan (9005-9018) — [P] beam 20.3 ms (4.2%)
Re-run the best non-joint option with `beam_enabled` (6486): `append_wide_chains` (6505) beam-searches stacks of up to 3 papers (each ≤ 2 deep in its column, beam 16 per length) placed at one level to cover D's handle holes jointly; chains enter the interval DP as kind-7 candidates. Only this one option gets chains. Counters chain_trials/chain_selected/chain_papers.

### Step 4: helper plans (9019-9027) — [P] helpers 38.4 ms (7.9%)
Only if `interleave->ready`, d ≠ top0 and `helpers[u]` non-empty. `try_helpers` (~6760): return previous product and fillers, then insert one helper x of another column between the generic sheets at a goal (s, t) from the `Interleave` table (so it shows A_u on D's generic holes and on handle holes), estimate = distance + handle fixes; keep the **3** best single helpers (after dropping all but one with distance equal to the plain generic cost; `picks.resize(3)`) and the **3** best pairs out of 12 pre-screened (x ≤ 3 deep, y of a deeper column ≤ 3 deep, right on D's holes x leaves). Each is simulated as a full plan, scored, recorded. Source of final plan tracked as 0 options / 1 chain / 2 helpers.

### Step 5: fallback (9029-9041)
If no candidate was valid (`plan_failures`): run the plain `PlanOpt{}` without visibility checks; if still invalid or > 2K moves, output no moves (`unsafe_plans`). In practice E ≈ 0.

### Step 6: ordinary post-processing of the 6 candidates (9042-9087) — [P] post_best 40.7 ms (8.3%) + post_alts 64.9 ms (13.3%) at pc=3; at pc=6 (dual25) +20 ms
`post_optimize` (7237, memo wrapper: 32 entries, 512-byte key = order + top_d + fillers + path + mode + tags; falls back to `post_optimize_impl` for > 64 moves or > 32 fillers) edits the plan as a list of **Edits** "paper goes below anchor" (`anchorize` 7112) replayed from st0 with recomputed depths. Passes: deletions (`delete_singles` 7874), new anchors for old extras and papers moved twice (`anchor_candidates` 7893: top, around the papers of its column, the generic sheet boundary, anchors of its later edits; `one_anchors = 2` adds up to two extra; `promising_slack .75`), deletion + re-anchor pairs; accepted only if legal, display A_u, fillers reachable and plan_cost lower (`evaluate` 7428, with the O(1) display screens `prepare_screen`/`screen_rejects` 7792/7842 from legal-speed-fast). Then every other candidate with a different end order is edited the same way (9062-9084); the lowest plan_cost wins (`post_alternate` counts a change). All edited results are cached in `plan_cache` (raw path+state → edited path+state) and pushed to `edited_candidates` for Step 8.

### Step 7: ejection of the winner (9088-9095) — [P] eject_main 65.9 ms (13.5%) at 4 rounds; ej2 saves 2.9 ms
`polish_ejects(st0, path, u, 2, true)`: up to 2 rounds of `eject_repairs` (8063): for every pair of edits i<j (latest first), drop both and repair the display with one new move of a paper k that is opaque and right on exactly the wrong windows, inserted in the feasible gap interval [lo, hi] at the earliest/latest visible time. Breakdown of eject (legal-speed-ejprof 20261108-095824, 100 seeds): pair preparation 23.7 ms (75k pairs), candidate loop 7.6 ms, 97k surviving candidates 39.4 ms, their evaluate 49 ms. Result → `neutral_seeds[0]`.

### Step 8: NS_ALTERNATE — eject the other edited plans (9116-9140) — alt1: +67 ms incl. width 6 (REPORT10 §; trial_log 1725)
Every `edited_candidates` entry with a different end order and `cost ≤ baseline + 1.0` gets `polish_ejects(..., 2)`; a result below the incumbent replaces it (operator "plans"=4). Each result is also a `neutral_seed`. Gap sweep (fixed designs 500×4): .25/.5/.75/1.0/1.25/1.5 → −0.011/−0.020/−0.028/−0.034/−0.037/−0.039% for +28/+46/+66/+60/+74/+83 ms (REPORT10.md 88-96; restricting to 1 candidate or 1-to-1 repair loses most of it).

### Step 8b: "expanded" plan pass (9142-9252) — [P] expanded 17.9 ms (3.7%) at POST_CANDIDATES=5 > pc=3
Screens `expanded_candidates` (width POST_CANDIDATES=6) by a cheap delete-only post_optimize, sorts, and fully edits + ejects (`plan_ejects = 2`) at most `PLAN_LIMIT = 2` of them, skipping ones already in `plan_cache` when `plan_skip_edited` (true) and those not shorter than the incumbent (`plan_shortlist = 3`). **See open question 5.1: with POST_CANDIDATES = kPostCandidates = 6 both collectors receive identical candidates, and all of them are already cached from Step 6, so this pass most likely does no work in dual30.**

### Step 9: neutral search rounds (9253-9400) — [P] neutral1 111.4 ms (22.8%), neutral2 38.9 ms (8.0%, entered in 232/1024 orders); dual25 second parent +23 ms (12.4 ms measured in REPORT12 line 30)
Up to NS_ROUNDS = 3 rounds. Each round: `post_optimize(..., eject=true)` with `neutral_collect` on, which besides accepting improvements **collects** rewrites with equal or slightly worse value (within NEUTRAL_SLACK = 0.30) into `neutral_candidates` (collection at ~7703-7780; operators: two-deletions-two-repairs `neutral_repairs` 8369 (op 1 "22"), one-to-one rewrites (op 2 "11", NS_ONE), three-to-two (op 3, NS_TRIPLES=0 off); candidate_mode 2 prefers candidates with a new paper / repeated paper / hidden display owners; `hidden_rank`). In round 1 only, the best **other** `neutral_seed` (a completed ALT plan with a different end order, cost ≤ parent + 0.3) is used as a **second parent** (9275-9311, dual25): its collected candidates are merged by signature with the primary pool, sorted (shorter path, more hides, more repeats, then value), truncated to NEUTRAL_WIDTH = 6. Then every surviving candidate (≤ 6) is re-edited in full (`post_optimize` non-eject, then eject rounds while `short_rounds`=0 → none) (9317-9378); the best replaces the incumbent if better (`neutral_accepted`, `winning_escape`). Another round only if the round improved by ≥ REPEAT_MIN = 0.05 (9399). `refine_best = 0` (off).

### Step 10: weighted joint plan finish (9404-9413) — [P] weighted 6.0 ms
If the value_fillers joint plan was edited in Step 6 but never ejected and its edited cost ≤ incumbent + 0.5, run `finish_weighted_plan` (8834: 4 eject rounds) and take it if better (`value_seed_*` counters).

### Step 11: near-tie correction (9434) — [P] tie 2.6 ms
`tie_choice` (8778), section 4 for history: among all noted complete plans (`note` 8740 keeps the cheapest per end order within kTieGap = 0.3 of the running minimum), those within 0.3 of the chosen plan's plan_cost compete by `value − v0 + kTieConst + Σ kTieCoef·(f − f0)` with the 9 `tie_features` (8751): filler_charge, adaptive_next_cost, generic_bias, #fillers, #fillers below the generic layer, adaptive weight of the lifted paper (coef 0), Σ adaptive weights of fillers, demand of the opposite color at the column heads, path length. Lowest score < −kTieMargin (0) wins after replay verification (legal visibility, same end order, display, fillers reachable). Counters tie_decisions/tie_switches/tie_rejected.

### Step 12: merge double moves (9435) — [P] merge 0.8 ms
`merge_double_moves` (8633): if a paper moves twice, drop the second and send it directly at the first; kept only if all moves stay visible and the end order is identical (pure saving; ~0.08% of requests).

## 2. The future-cost model and the column MDP

**What plan_cost prices beyond the moves (5242):**
- `filler_charge` (4907): 0.7 per paper left out of its column (`kFillerCharge`), minus/plus `0.25·(0.3 − stay_probability)` for fillers below the generic layer (`stay_table` 4861: share of targets for which this filler, left where it is, shows the right colors on all handle holes it covers).
- `adaptive_next_cost` (ref ~4972, SIMD ~5050): expected digs of the next order = Σ over in-column papers k of `adaptive_weights[k] · depth_in_column(k) / P` + Σ over handles c and colors b of `adaptive_holes[c][b] · (depth of the first paper of color b in column c)`, with the stay-table `cover` credit (0.25) for fillers below the generic layer, and the column-MDP term (below). `adaptive_weights[k]` = number of targets whose dedicated paper is k (1, or 2 for a shared pair) + `kFillerDemandWeight · (its filler utility / column mean − 1)` (floored at 0.25) from `add_filler_demand` (4779); `adaptive_holes[c][b]` = share of targets with a hole at handle c needing color b. All are computed **once** from the design in `init_adaptive` (4826) and never updated with the observed orders (orders are i.i.d. uniform, so nothing to learn except the horizon).
- `generic_bias` (5232): 0.5 · `future[rank of the current generic order]`, where `future[s]` (4739) = mean over targets with generic holes of the minimum comparator distance from s to an order satisfying them.
- `adaptive_insert` (5253) uses the same terms locally to choose the depth of a dig or return (never above its barrier), plus `handle_fix_cost` when the dug column's handle is a hole of D.

**The column MDP (4294-4565, used at 5331-5550).** A column's papers are abstracted to 4 types (two fitted weight classes × handle color, `init_colmdp` 5347-5376). State = type sequence (≤ 14 papers, `max_length`; columns whose sequence space exceeds `max_full` 40000 / `max_sequences` 250000 are **not covered**, `colmdp_columns` is printed). Events per order: paper i requested with rate p_i (costs i digs, suffix kept in order, **dug papers may be reinserted anywhere = optimal reinsertion assumed**), or handle color b demanded with rate λ_b (costs the depth of the first paper of that color). Relative value iteration (8 sweeps, converged by 8 per colmdp measurements, trial_log 646) over the sequence-deletion DAG gives F(s) (best completion), H(s) (head fixed), fix[b](s). It is mixed in two places: (a) `adaptive_insert`: for insertion kinds in `cases` = 15 (returns, digs for a lift/filler, digs that keep the barrier, returns with a pending handle fix), the one-step cost term is reduced by `drop = 0.5` and `mix = 0.5 · F/H` of the column after the insertion is added (`colmdp_gap_values` 5400); (b) `adaptive_next_cost`: `next_keep = 1.0` (nothing removed) and `next_mix = 0.5 · F` of each covered column added (`colmdp_next_scanned` / `_partial` / `_term`). Unit 1 means F is in digs per order already (rate W folded in).

**Horizon.** There is none: `kEndWeight = 1.0` and all tables are stationary for all r = 0..1023 (`process` receives only u, not r; grep finds no `remaining`/`R−r` logic in the Solver). The last orders still pay the full next-order cost for fillers left out, lifted paper not returned, deep columns, etc. The MDP is average-cost (infinite horizon).

**Tuning history of the model** (all fixed-design unless noted): kFillerCharge 0.8→0.6 −0.071% then 0.6→0.7 −0.011% (11-03/11-04, trial_log 206, 435); 0.65/0.75 on dual25 +0.043/+0.132% (REPORT12 line 70-71, 214056). kEndWeight 0.6→1.0 −0.041%, 1.3 −0.059% in the 11-03 sim but +0.071/+0.112% at 1.3/1.5 on the real pipeline (trial_log 420, runs 130741/131620/132032), 0.8/0.9/1.1 +0.019/+0.008/+0.005% (435-436), 0.90/0.95 +0.059/+0.020% (1512); end-state coefficient 1.05 on dual25 −0.0055 ± 0.0029% but +13.5 ms (REPORT12 line 73). kTopPenalty 0.35→0 −0.007%. Filler demand second-window coefficient 0.6→0.8 −0.012%; stay threshold 0.4→0.3 −0.003%; kStay 1.0 +0.018%; kFillerDemandWeight, kStayStrength/kCoverStrength, kRelevel within ±0.003%. Column MDP: added 11-05 (PR 115 port, `solutions/colmdp`) −0.100 ± 0.003% alone (20261105-020341) and −0.589% together with the neutral search (021953) — "the shape of the value matters, not its scale" (constant multiples of the one-step model do nothing; replacing it entirely +0.37%); next_mix 0.25/0.75 +0.086/+0.005% (1513); covering all columns (argon-des-colmdp, 20261106-071307) −0.0009 ± 0.0006% — closed. ## 5. Open questions and suspicious spots

1. **Expanded plan pass is probably dead (9142-9252).** `collect_future(expanded_candidates, POST_CANDIDATES=6)` and `collect_future(future_candidates, kPostCandidates=6)` (8940-8942) receive the same candidates in the same order with the same width, so the two lists are identical. Step 6 caches every one of them as `edited` (9046, 9066-9070); in Step 8b `cached && (complete || plan_skip_edited=true)` skips them all (9152, 9209). PLAN_LIMIT=2 (pl2, +3 ms, −0.0026% when pc was 4) would then buy nothing now — consistent with REPORT11's "PLAN_LIMIT 1: +0.0003%, −0.2 ms". Verify with `f2_plan_screens`/`f2_plan_skipped`/`f2_plan_wins` in `observe.py stats 20261109-003105_dcomp-combo-dual30`. If dead, either remove it (saves little time) or make it do something distinct (e.g. candidates of a different family than the 6, or shortlist by moved-paper multiset), which has never been tried since pc=6.
2. **No horizon handling.** For orders r ≥ ~1020, filler returns, lifted-paper returns and depth-optimal digs are paid for a future that does not exist. A time-dependent kEndWeight (e.g. 0 for the last order, scaled over the last few) or skipping returns at r = R−1 was never tried (no recorded experiment; `process` does not know r — main would have to pass it). Potential ~1–3 moves per case ≈ 0.01–0.03%; cheap and design-independent, testable with `--design-from --orders 4`.
3. **Stationary tables vs. known per-product frequencies.** `adaptive_weights`/`adaptive_holes` are design-derived expectations. Since the order sequence is i.i.d. uniform there is nothing to learn, but a cheap check is whether conditioning on "this product was just asked" (P(same product next) = 1/256) matters — probably not; included for completeness.
4. **kEndWeight = 1.0 vs. the tie fit.** The fitted correction weights filler_charge ×1.32, next_cost ×0.19, generic_bias ×1.37 **on top of** plan_cost, i.e. the end-state value is mis-scaled per component, yet every direct re-weighting of plan_cost lost (kEndWeight, kFillerCharge .65/.75, generic .6). The planner and post-processing are co-adapted to the current plan_cost; a component-wise change needs the search re-tuned with it (never attempted jointly). Leaving the correction only in the last selection is the recorded equilibrium.
5. **Neutral round 2+ gate (9399):** REPEAT_MIN=0.05 lets a round continue only after an improvement ≥ 0.05; REPEAT_MIN 0 is worth −0.0058% for +23 ms (0.025 %/100 ms). The round-1 second parent happens only in round 1 (`if(round==1)`, 9275), `++second_count==1` means exactly one extra parent; "広く使う funded-pc6" (−0.032%, +11 ms) was dropped only for Clang timing. These are the last known sub-rate options, not closed by principle.
6. **Helper plans ignore `future`/chains:** `try_helpers` is only taken when `d ≠ top0`; chains (Step 3) run only on the best normal option, not on joint (fm5) or helper plans; `finish_weighted_plan` ejects only when within 0.5. None of these asymmetries have recorded experiments beyond "h8/pick8 ±0".
7. **Depth-value model error** (section 2): the model under-prices depth changes 3–5× yet depth neighbourhoods never gained. Unexplored: whether the *digs' own insertion depths* (adaptive_insert for digs during `lift`, barrier rule "never above the barrier") are systematically too shallow/deep — the delprobe only looked at post-hoc re-anchoring of returns.
8. **Uncovered MDP columns** (colmdp_columns < H in some cases): slow path in next_cost (+35 ms on slow cases, trial_log 1745) and a different value scale between covered and uncovered columns in the same stack; covering all columns gave −0.0009% so the value effect is nil, but the time effect on the final pacer's tail is real.
9. **Plan menu redundancy:** ret_mode 2 is identical to 1 (kTopPenalty 0) and is replayed, costing nothing; `fm4` (reposition old fillers) vs `fm1` and the complete_value option exist only to seed post-processing with different families. `fm1` removal costs 0.142 %/100 ms, so the menu is valuable; nobody has tried *more* families since (e.g. ret_mode 3 with fm5, or chains on the joint plan).
10. **Constants with no recorded sensitivity on the current pipeline:** kTieGap 0.3 (chosen with the fit; "差 0.3 以上の代替は損"), tie pool "one per end order", `kMaxFillers 8`, `alternate_gap` sweep done only up to 1.5 (−0.0039% for +21 ms beyond 1.0), `promising_slack .75`, `one_anchors 2`, `candidate_priority` ordering (shorter path first, then hides, repeats) — set in MODE=1 presets on 11-05 (opsearch-fast2) and never re-swept on dual30.
