# astra-matching

改良元: `solutions/astra-search4`

窓を比較器へ割り当てる探索の目的関数を変更する。従来の費用順の貪欲70対を出発点に、短い交代路で費用を改善した70対を毎候補の評価に使う。初期の対だけを改善しても後の焼きなましが直す、という過去の実験とは異なり、後段では変更できない汎用窓と比較器の割り当てを評価する地形そのものを変える。

- 1対の端点を未使用の商品へ差し替える。
- 2対を交代4サイクルで組み替える。
- 2対を、未使用の商品を端点とする短い交代路で組み替える。
- 1対から長さ3の増大路で2対を作り、別の最も高い対を外す。

各周回で最も費用を減らす変更を1つ適用する。既定の周回数は `MATCH_PASSES`（コンパイル定数、既定2）。`MATCH_PASSES=0` は診断用の貪欲目的関数。互換性判定、辺の費用、時間配分、後の焼きなましと注文処理は改良元と同じ。紙の互換性を壊す候補の事前除外は、この改善後のマッチングを使う。

終端診断の `matching_greedy` と `matching_improved` は、同じ最終割り当てにおける貪欲費用と改善後の費用。`matching_changes` は候補評価中に適用した交代路の総数。評価結果は別の検証報告にまとめる。
