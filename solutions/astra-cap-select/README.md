# astra-cap-select

改良元: `solutions/astra-cap`。

キャップ窓を入力に合わせて選ぶ。汎用窓の割り当ての焼きなましが終わった時点で、汎用に使っていない28窓（27ハンドルと現在のキャップ）を全て試し、共有71対の割り当て目的値が最も小さくなる窓をキャップにする。
その後は選んだキャップを固定して、従来どおり割り当ての最後の山登りと紙設計を行う。

- 比較器の配置は全列挙中には変えないため、互換性の再計算は不要。各候補で71対の貪欲マッチングを計算するだけでよい。
- 割り当て中は元の64ビットを保持し、キャップのビットをハンドル費用・全体の距離費用から除く。元のバーコードのHamming距離は偶数なので、1ビットを除いて26以下になる辺は、元から26以下の辺と同じである。
- 汎用↔ハンドル交換は選択後もキャップを含まない27ハンドルだけを使う。
- 割り当てが返るときに、選んだキャップを内部窓63へ移す。紙の設計中はそのビットを外し、実際の印刷・注文処理の前に戻す。
- キャップ制御・1回だけの初期移動・可視性検査・時間配分は改良元と同じ。

`cap_gobj_before / cap_gobj_after` はキャップ選択前後の割り当て目的値であり、実際の手数ではない。`cap_window` は選んだ物理窓番号（0始まり）。
