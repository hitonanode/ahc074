# legal-search（段階 1: 同じ終状態への合法な短縮の探索。解法ではなく分析の道具）

改良元: なし（分析用の道具。提出用の解法ではない）。

## 何をするか

SOTA の出力の各注文 r について、注文の前の重なり順 S と、SOTA の操作の後の重なり順 T を再生で求め、S から T へ、SOTA の手数 m より少ない合法な操作列（動かす紙はその時点で少なくとも 1 窓で見えている）を探す。終状態が同じなので、表示も以後の注文も変わらず、見つかれば純粋な改善になる。

- `endpoints.py RUN A B OUT.tsv`: seed A〜B−1 の各注文の m、LB = K − LCS(S, T)、同じ紙を 2 回動かした紙の数、操作のラベルを表にする。
- `same_end INPUT OUTPUT SEED [予算ノード数] [mode] [r_from r_to]`（same_end.cpp）: 探索。1 注文 1 行で `seed r m LB 最短 状態 ノード数 [k:d ...]` を出す。
  - 状態: `opt0`（m = LB で最適）、`opt1`（1 回移動の類に m 未満の解がない）、`imp`（短い解を見つけた。最短の長さと操作列）、`opt1m`（SOTA が同じ紙を 2 回動かしていて、1 回移動の類には m 以下の解がない）、`unk`（予算切れ）、`BUG`（SOTA の列が 1 回移動なのに m 以下の解が見つからない。探索の誤りの検出用）。
  - mode 1 / 2 は、紙を 2 回まで動かしてよい類を、仮置きの位置（一番上、汎用層とキャップの直下、一番下）だけ足して探す（制限つきで、解がなくても証明ではない。m − LB ≥ 2 の注文だけ）。mode 9 は健全性の検査（下記）。
  - mode 4: SOTA が同じ紙を 2 回動かした注文だけを、上限 m − 1 の 1 回の反復で、与えた予算のノード数まで探す（速い規則の見込みの計測）。
  - mode 5: 仮定と可視性の下界を使わない探索（下界は K − LIS だけ）。強い枝刈りが解を落としていないかの確認用。
  - mode 6: SOTA の手を 1 手（または 2 手）消しても、残りの手が同じ深さで合法で表示が注文どおりになるかを数える。
  - mode 7: SOTA の各手が LCS(今, T) を 1 増やしたか（+1 / 0 / −1）を出す（m − LB の手の種類への割り振り）。
- `verify.py RUN 結果...`: `imp` / `mimp` の操作列を scripts/replay.py で独立に再生し、可視性・終状態 = T・表示 = 注文を確かめる。
- `run_stage1.sh RUN_DIR A B OUT_DIR [予算] [mode]`: seed A〜B−1 を評価のロックの下で 23 並列に回す。`run_chunks.sh`（seed を注文の区間に分けて回す）、`run_orders.sh`（注文の一覧を回す）、`run_checks.sh`（制約なしの探索との一致、2 回移動の類、未決の再探索）も同じくロックの下。
- `summarize.py RUN DIR [例の数]`: 状態ごとの件数、短縮の割合と 1 注文あたりの削減、m − LB ごとの内訳、短縮で減った手の型、例。`summarize_checks.sh`: 追加の確認の集計。
- `merge_rule.py RUN A B [DIR]`: 安い規則（2 回動かす紙の 2 回目を消し、1 回目で T の位置へ直接送る）が成り立つ注文を数え、探索の短縮と突き合わせる。
- 結果: results/stage1/<seed>.txt（seed 0〜99、300 万ノード）、results/plain、results/multi、results/unk。

## 探索（1 回移動の類では厳密）

- IDA*。h = K − LIS（T での順位を今の順に並べた列の最長増加部分列）は 1 手で高々 1 しか変わらない下界。
- **差し込み先の限定（1 回移動の類で完全）。** 各紙が高々 1 回動く解 σ を考える。動かない紙の集合を C、紙 x が動く時点で、C と既に動いた紙を「確定した紙」と呼ぶ。確定した紙どうしの相対順はその後変わらないので、T の順と同じでなければならない。x の差し込み先は、T で x より後の確定した紙のうち最初の紙 q の直上（q がなければ一番下）に替えてよい:
  - 終状態は変わらない: 確定した紙に対する x の相対順は T のとおりで、まだ動く紙との順は後でその紙が直す。
  - 後の手の合法性は保たれる: まだ動く紙 z について、z の上にある紙の集合は、元の σ での集合の部分集合になる（C とまだ動く紙の z に対する順は S のまま。確定した紙 w が z の上にあるのは q_w が z の上にあるときだけで、元の σ でも w は q_w の上にある）。上の紙が減れば、見えている窓は減らない。
  - この q は「T での j 番目の後続の紙」で、間の j − 1 枚は後で動くので j ≤ 残りの手数。探索は各可視の紙について j = 1〜残りの手数と一番下を試す。
- **仮定による枝刈り。** j を選ぶと、飛ばした後続 j − 1 枚は「後で動く」（pending）、q は「もう動かない」（frozen）と決まる。動いた紙も frozen。frozen の紙は動かさず、pending の紙を q に選ばない。各 1 回移動の解の標準形は、矛盾しない仮定で 1 回だけ生成される。
- **下界。** 次の和と K − LIS の大きい方: 必ず動く紙の数（frozen の紙と順が逆の紙、pending の紙、逆の組の数が残りの手数を超える紙）+ max(残りの紙の逆の組の頂点被覆 = |U| − LIS(U)、必ず動く紙が見えていないときに、その紙の窓のうち frozen の紙に覆われていない窓で、上にある（必ず動く紙以外の）不透明な紙の数の最小)。frozen の紙どうしが逆順、または必ず動く紙のすべての窓が frozen の紙に覆われていれば、その枝は不可能。
- 置換表: 重なり順・frozen・pending の Zobrist ハッシュ（splitmix64）→ その反復で展開した最小の深さ。

## 健全性の確認

- mode 9: 実際の注文の前の状態から、乱数の合法な 1 回移動の列（差し込み先は一様・近く・上下の端）と、隠れた紙を 1〜3 枚掘り出して持ち上げる列を作り、探索が列の長さ以下の解を見つけること、列に沿った下界が残りの手数を超えないことを確かめる。
- 通常の mode 0 でも、SOTA の列が 1 回移動なら、上限 m の探索で解が見つかることを毎回確かめる（見つからなければ `BUG`）。
- 誤りの記録: 最初の版は Zobrist の乱数（2 シフトの xorshift）が弱く、置換表の衝突で解を見落とした（偽の「最適」）。splitmix64 に替えて mode 9 の見落としが 0 になった。
