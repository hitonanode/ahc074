# imp-colswap

改良元: solutions/cmp-anneal

設計の焼きなまし（Design::Annealer）に、外部 agent の解法で効いていた近傍を 2 つ足した。ほかの手・モデル・時間の区切りは cmp-anneal と同じ。

## 列の入れ替え（ハンドルの窓ごと）

位置 a < b（距離 1〜kColSwapDist）の 2 列を、中の紙全部とハンドルの窓ごと入れ替える（solutions/gpt6pro-08-01-colswap の隣どうしの入れ替え、gpt6pro-06-02-regroup の swap_columns）。

- どの紙も自分の列のハンドルの窓を持ったまま動くので、対が自分のハンドルで一致する条件は崩れず、列の費用（紙の数・色の数）も変わらない。変わるのは穴の数だけ。
- 新しい位置で数えると: 位置 a（元の h_b の窓）は元の h_b の穴の数から、元の列 a..b−1 のそこでの穴を引く（元の列 a は深くなり、間の列は上になるため）。位置 b（元の h_a の窓）は元の h_a の穴の数に、元の列 a+1..b のそこでの穴を足す。間の位置 a < j < b では、元の列 a の穴がなくなり、元の列 b の穴が増える。どれも対の違いの窓（もともと穴）は除く。
- 列ごと・ハンドルごとの「色 1 の目標の数」と「違う対の数」の表（cmp-anneal の rows）から、違いを除いた穴の数は色 1 が t1 − pd、色 0 が nt − t1 − pd で求まる。手の評価は列 a..b の和と、全ハンドルの q の差の一括計算（AVX2）だけ。受理したら、全目標のハンドルのビット、表の 2 レーンと 2 列、列 a, b の紙の列番号を入れ替える。
- 元の「ハンドルの窓だけの交換」（15%）は、対が新しいハンドルで一致しないと使えず、列の色の数も変わる。列ごと入れ替えるとこの制約がなく、列の深さと穴の分布だけを動かせる。

## 対の組み替え

対 x = (a, b)、単独 y = c、c と整合する単独 z = d を、対 (c, d) と単独 a, b に変える（solutions/gpt6pro-07-02-replace の pair replace。gpt6pro-06-02-regroup の pair shift はこの結果の 1 つ）。

- 新しい対は x に入れ、a と b は y, z に乱数の順で入れる。REPLACE_REPAIR なら、新しい対は 3 つの列のうち自分のハンドルで一致する列から乱数で 1 つを取り、残りの 2 枚が残りの 2 列を取る（3 列の紙の数は変わらない）。
- 既存の「2 単位の間で目標を交換する」手では、どの単位が対かが変わらず、整合性のグラフの連結成分ごとの対の数も変えられない。この手はそれを変える。
- 評価は 3 単位の除去と追加を、列ごと（最大 3 列）の数と全ハンドルの穴で一括に数える（multi_move）。

## 手の割合（乱数 1000 通りのうち）

- ハンドルの交換 150（cmp-anneal と同じ）、列の入れ替え COLSWAP_RATE、対の組み替え REPLACE_RATE。新しい 2 つの分は、整合する相手への目標の交換（cmp-anneal では 230）から取る。残りは cmp-anneal と同じ。
- 列の入れ替えを受理したときの全目標のハンドルのビットの入れ替えは分岐なしで書いた（目標ごとの分岐は半分が予測を外し、受理の多い隣どうしの入れ替えで焼きなましが目に見えて遅くなった）。

- 注: 時間制の評価では焼きなましの回数が cmp-anneal より約 9% 少ない。-DSIM_HARNESS のビルドで回数固定・1 コアの CPU 時間を測ると、対・単独の単位の一覧を焼きなましの本体の局所変数に持つことでループ全体が約 7% 遅くなっていた（solutions/imp-colswap-rp2 でメンバに移した）が、提出と同じビルドでは移しても回数は変わらなかった（原因は未特定）。

## パラメータ

- ファイル冒頭のマクロ: HSWAP_RATE = 150（ハンドルの交換）、COLSWAP_RATE = 20（列の入れ替え）、COLSWAP_DIST = 4（入れ替える 2 列の距離の上限。距離は 1〜4 から一様）、REPLACE_RATE = 0（対の組み替え。この版では使わない。使う版は solutions/imp-colswap-rp）、REPLACE_REPAIR = 1（組み替えで新しい対の列を 3 列から選ぶ）。どれも千分率。
- 実験では `-DCOLSWAP_RATE=50` のようにコンパイル時に変える。

## stderr

cmp-anneal の指標に加えて:

- `colswap_tried` / `colswap_accepted`: 列の入れ替えを評価した回数・受理した回数
- `replace_tried` / `replace_accepted`: 対の組み替えを評価した回数・受理した回数

`-DANNEAL_CHECK` の照合は新しい 2 つの手も含めて通ることを確かめた（H = 28, 32, 36）。
