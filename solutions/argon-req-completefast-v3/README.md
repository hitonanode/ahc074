共同DPの新規フィラー選択に、残りのハンドルを修正した後の積層価値を使う計画を1つ追加する。候補を1枚置いて残りを直す局所計画と、全てを直す局所計画の `plan_cost` 差を区間の重みにする。取り出し直後の価値だけでは、省いたハンドル修正が列の終状態を変える効果を落としていた。

従来の整数利得が正の区間だけを調べる。局所仮評価は既存の `filler_value_increment` に統合し、状態・操作列・ラベルを保存して復元する。従来の全計画を残し、完成後の可視性・表示・回収可能性を検査した上で、従来の目的関数で比較する。設計・後処理の予算は変えず、将来の注文も参照しない。

従来の状態価値付き共同計画と追加計画は、同じ開始状態・同じ返却方法で続けて実行する。このため、選んだ区間の紙・位置・種類・順序が全て同じなら操作生成の再実行を省ける。基準となる局所修正が不可能な場合も、従来の重みに戻る重複案なので省く。

既存のログ、実験スイッチ、プロファイラ、CLOCK_SCALE、LOCAL_BENCH、DesignStore、`@paper` / `@ops`、段の目印と目次は維持する。常に0だった `value_filler_zero` / `value_filler_zero_useful` のみ削除した。新しい環境変数はない。

追加のstderr指標:

- `complete_value_calls`: ハンドル修正を含む局所価値の評価回数。
- `complete_value_invalid`: その仮修正ができなかった回数。
- `complete_value_duplicates`: 従来の計画と重複するため省いた追加計画数。
- `complete_value_plans`: 検査を通った、重複しない追加計画数。
