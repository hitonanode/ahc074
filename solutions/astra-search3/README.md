# astra-search3

改良元: solutions/imp-s2hd

`assign_windows` の「1つの汎用窓を別の比較器の組へ移す」手を改良した。現在の70対について、その窓を外した後のDAGを使い、移動先14組×色2通りをまとめて調べる。4対以上を互換でなくする候補を除き、残った候補から直接選ぶ。

選ぶ順序には、現在の70対に対する汎用層の費用増加の和を使う。最小の候補から同点を乱択し、選んだ候補は現在の状態の候補集合から除く。互換でなくなる対の費用増加は0として扱う。候補を実際に評価・受理するときは、元の全対の更新と70対の貪欲マッチングを使う。

辺を加えたときの費用増加は、元のDAGの推移閉包が同じなら等しい。閉包をキーに30方向分を4096項目の表へ保存し、キーが一致した場合だけ再利用する。表のデータは約256KiB。各窓の候補集合と優先順位は、状態が受理または復元で変わるたびに作り直す。

目的関数 `1800 × ハンドル窓の違い + 5 × 両側の汎用層の値 + 144 × 全窓の違い`、距離上限26、時間区切り0.50 / 0.61秒、停滞閾値2048 / 4096試行、逆手の禁止4受理分は改良元と同じ。他の段とCLOCK_SCALEも変更しない。初期乱数seedも同じ定数を使う。

追加したstderrの指標:

- `transfer_rows`: 各状態・各汎用窓の候補集合を作った回数。
- `transfer_samples`: 候補集合から組移動を選んだ回数。
- `priority_hits`: 閉包ごとの費用増加表を再利用した回数。
- `priority_misses`: 費用増加表のキーが不一致で、30方向分を再計算した回数。

計測方法と評価結果は [REPORT.md](REPORT.md) を参照。
