# chatgpt-transition

改良元: `solutions/imp-combo`

汎用紙 6 枚の 720 順列を状態として、要求が独立一様に来る近似モデルの平均費用 MDP を解く。
従来は「今回の最短手数を優先し、同手数なら次回の期待距離」で選んでいた。本案は相対価値反復で、何注文も先まで含めた状態の価値 `h(s)` を作る。

汎用窓に穴のある商品の集合を `U`、その商品の専用紙が汎用窓に開けた穴の上で要求を示す順列を `S(u)`、合法な汎用紙操作の最短距離を `d(s,t)` とすると、

```
T(h)(s) = average_u min_{t in S(u)} (d(s,t) + h(t))
h_next(s) = T(h)(s) - min_x T(h)(x)
```

を既定で最大 16 回反復し、Bellman 残差幅が `1e-7` 未満なら早期終了する。汎用窓に穴のない注文は通常は順列を変えないため、反復から除いた埋め込み連鎖を使う。実際の注文は直前の商品を除く一様分布であり、補助紙も順列に影響するので、このモデルは全解法についての最適性保証ではない。

変更箇所は次の 2 点。

- 通常の汎用層の目標順列は `d(s,t)+h(t)` の最小で選ぶ。
- 補助紙経路・全体の計画・後処理の評価にも最終順列の `h` を加える。従来はここで汎用状態の将来価値を無視していた。

設計・紙の模様・列の挿入規則は改良元と同じ。`GENERIC_MDP_ITERS` を正の整数にすると反復回数を変更でき、`-1` で従来の 1 段評価に戻す実験をできる。`GENERIC_MDP_ITERS=-1 GENERIC_MDP_SCORE=1` は従来の 1 段評価を使ったまま全体採点だけに加えるアブレーション。`GENERIC_MDP_SCORE=1` の単独指定では価値反復のまま。既定は価値反復と全体採点の両方を使う。プログラム開始から倍率込み 1.58 秒を過ぎたら新しい反復を始めず、最後の完全な反復を使う。ただし最低 1 回は反復し、実行中の反復は最後まで計算する。これは同じ MDP 方策の近似精度だけを調整する。

stderr の `mdp_iterations` は完了反復回数、`mdp_span` は状態価値の最大差、`mdp_residual_span` は直近の Bellman 残差の最大差、`mdp_sec` は `init_lookahead` 全体の時間（要求集合の準備と最初の反復も含む）。残差幅は上記の近似モデル内での平均費用の上下界の幅を表す。

`GENERIC_MDP_PROBE=1` は解析用。汎用層だけの近似モデルで従来方策と新方策それぞれの定常分布を計算し、全注文 1 回あたりに換算した期待汎用手数を `mdp_model_myopic` / `mdp_model_policy` に出す。通常の時間制評価では指定しない。指定した実行では、この解析時間も実際の経過時間と `mdp_sec` に含まれる。

## 設計を固定した研究用比較

`probe.py` は既存 `SIM_HARNESS` を使い、同じ紙設計・同じ要求列で注文処理だけを比べる。

```sh
python3 solutions/chatgpt-transition/probe.py --seeds 0-32 --workers 3 --sim-seqs 8
```

既定の設計予算は窓割当 20 万、山登り 6 万、焼きなまし 400 万、穴埋め山登り 2 万回。両解法の一時コピーで補助紙表の打ち切りを外し、新解法では MDP の打ち切りも外す。提出用ファイルは書き換えない。SIM_HARNESS は通常の注文ループを通らないため、経過時間による軽量処理への切り替えも起こらない。

各ケースの紙・列・商品対応・ハンドル・窓置換の 64 bit fingerprint が一致することを検査し、不一致なら比較を失敗にする。既定では各設計で生成する要求列は 8 本、各 1024 注文で、直前と同じ商品を出さない。元ソースと生成ソースの SHA-256、予算、入力 SHA-256、全 stderr、各ケースの結果、対になった log 比の平均・標準誤差・勝敗を出力先に保存する。これは 2 秒制約下の公式スコア比較ではなく、設計と速度の揺らぎを除いた研究用比較である。通常の時間制約を含む評価は `scripts/pahcer_run.py --compare` で別途行う。

`sim_wrong` は解法内の表示照合であり、独立テスターでの合法性検査とは区別する。入力の生成法、通常の対話比較、独立再生の手順は [評価環境の説明](../chatgpt-study/README.md) を参照。
