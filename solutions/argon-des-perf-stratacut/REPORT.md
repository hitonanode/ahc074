# D2 採用候補: 層別32標本とownerの区間DP差分

基準: `solutions/argon-req-completefast-v3`（PR #140）。
外部助言01-1「穿孔処理とフィラー評価の対象拡大」の継続検証で、色標本の誤差を抑える変更を得た。
前段のモデルや注文処理は変えず、8独立標本を32層別標本にする。単純な移植版は時間枠を超えたため、
`Handle perforation` のowner側DPの計算量を減らす。

## 1窓の変更の差分評価

ownerの窓hの穴だけが変わるとき、区間の利益や合法性が変わるのはhをまたぐ区間だけ。
hより前で終わる区間はその窓を印刷せず、hより後から始まる区間はその窓を覆わない。
色反転についても、hの修復報酬とdonor列hの価格だけが影響を受けるので同じことが成り立つ。

非重複な区間集合にはhをまたぐ区間は高々1つ。その区間を[lo,c]とすると、
前後の最適値は変更前のforward[lo]とbackward[c+1]をそのまま使える。
したがって新しい値は次の最大値である。

- hをまたぐ区間なし: forward[h] + backward[h+1]。
- hをまたぐ区間あり: forward[lo] + new_edge[c][lo] + backward[c+1]、lo ≤ h ≤ c。

`changed_window_value`でこの式を評価する。ownerの穴追加・復元と、変更窓の色反転に使う。
初回と受理後の完全なDP構築は維持し、既存のキャッシュ整合assertも残す。
DP値を保存する連続配列の実験は、この版には含めない。

## 検証

最初の500件 `20261106-032336_*` は元v2とstdout・非時刻stderrが500/500一致したが、
外部負荷平均0.69/最大2.14コアの警告が出たため、採用判定に使わない。

新しい通常2000件は、基準 `20261106-032942_argon-req-completefast-v3`、
候補 `20261106-032942_argon-des-perf-stratacut`。両側設計保存・記録あり。

後続の変更では必ず新しい基準との時間を再測定する必要がある。

- 元の32標本v2の通常2000件と、stdout・時刻以外のstderrが **2000/2000一致**。
- 旧基準の層別版とも、保存設計・前段のgobj/model/proxyが全2000件一致。
- WA・self_wrong・op_label_errorsは全件0。
- GCC/Clang、LOCAL_BENCH有無の4構成で警告0。ビルド用実行ファイルは/tmpで作り、削除済み。
- `build-results.json` / `final-audit.json` でソースのSHA、評価保存ソース、段の保持と正当性を照合した。
- 基準との差は+29/−7行。全ログ・profiler・switch・CLOCK_SCALE・LOCAL_BENCH・DesignStore・目次と段の目印を保持する。

同じ比較の層別24標本は−0.020351 ± 0.004741%、1056/61/883だったが、
judge平均1.601483/p99 1.782794秒で時間条件を満たさなかった。
単純な32標本版と値だけの連続キャッシュ版も時間条件未達だった。
局所の穿孔時間だけで全体時間を説明せず、両側同時比較の時間枠で採否を判断した。

**全採用条件を満たしたため、この版をマージ対象として停止する。**
