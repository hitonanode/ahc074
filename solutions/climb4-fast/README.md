# 注文処理を同じ結果のまま速くする（climb4-fast）

改良元: solutions/esw-climb4

## 改良元からの差分

- Astra が esw-colmdp の上で作った、出力を変えない注文処理の高速化（solutions/colmdp-fast。中身と検証は solutions/colmdp-fast/README.md・REPORT.md）を、そのまま esw-climb4 に移した（esw-colmdp → colmdp-fast の差分を当てただけ。esw-climb4 が変えたのは設計の filler climb だけなので、衝突はファイル冒頭のコメントの 1 か所）。
  - 積層を 192 バイトの固定配列で持つ。紙の位置は memchr で探す。
  - 正規化と補助紙の回収可能性の判定で、全紙の走査を減らす。
  - 列 MDP の部分列の種類を完全一致で照合して、列ごとに F 値を 16 個まで保存する。
  - 次の状態の価値を、列内の紙順と汎用層より下の補助紙の並びの完全一致で照合し、256 個まで保存する。
  - 深さの重みの項を前もって計算する。
  - 上端の罰が 0 で同じ計画になる返却モード 1・2 は、モード 1 の模擬の結果をモード 2 にも使う。
  - 1→1 修復・2→2 修復の小さな重複計算を省く。
- 探索の候補・列挙の順・浮動小数点の足し算の順は変えていない。出力は esw-climb4 とバイト単位で同じになるはず（評価で確かめる）。
- 目的: 注文処理の時間（req_sec）を約 8% 減らす（colmdp-fast の 300 seed での比 0.916）。減った時間は、後で探索を広げるのに使う。

## スイッチと stderr の指標

- `COLFAST_PROFILE=1`（ソースのマクロ。既定 0）で、注文処理の各部の時間と呼び出し回数を `cfprof_*` に出す（計測自体が重いので、速さの比較には使わない）。
- 改良元の指標に加えて `cf_value_hits` / `cf_value_misses`（次の状態の価値の保存が当たった・外れた回数）。
