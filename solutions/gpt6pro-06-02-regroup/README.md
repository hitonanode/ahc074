# gpt6pro-06-02-regroup

改良元: solutions/gpt6pro-06-01-comparator（外部 agent gpt6pro-06 に「さらに改善して」と頼んだ 2 版目。手数優先版）

## gpt6pro-06-01-comparator との差分

汎用紙 6 枚・G = 36・H = 28・専用紙 186 枚（70 対 + 116 単独）の構成は同じ。変えたのは設計の近傍、穴埋め紙の扱い、操作列の後処理、計算の省略。

- **設計: 列とハンドルを丸ごと入れ替える**（PaperDesign::swap_columns）: これまでの「ハンドルの窓だけを入れ替える」近傍は、対の 2 商品が新しいハンドルでも同色でないと使えず、ほとんど棄却されていた。列に属する紙全部とハンドルの窓を一緒に入れ替えれば、各紙の自列ハンドルでの条件はそのまま保たれ、列の深さと穴の分布だけが変わる。
- **設計: 対の組み替え 3 枚近傍**: 対 (a, b) + 単独 c + 単独 d → 単独 a + 対 (c, d) + 単独 b。紙の枚数を変えずに「どの 2 商品に紙を共有させるか」を変えられる（端点交換だけでは、互換性グラフの連結成分ごとの対の数が変えられなかった）。
- **設計: 穴の費用の重みを 0.50 → 0.45**（穴埋め紙が複数の穴をまとめて直すぶんを見込む。実験で選んだ値）。
- **穴埋め紙どうしの重なりを許す**: 全部が同時に見えていなくても、上から順に返せば次々に見える状態なら注文の終わりに残してよい。不要な穴埋め紙は実際の重なり順で上から返す。複雑な再利用の計画は、各操作の可視性と最終表示を再生で確かめて採用する。
- **返す位置の評価に今回の掘りの費用を足す**: 今回欲しい紙の列に紙を返すとき、その前に入れると今回の掘りが 1 枚増えるので、その分を加える。候補の状態は canonicalize してから評価する。
- **操作の削除による後処理**: 選んだ操作列から 1 手を消して、開始状態から再生する。後ろの操作の差し込み位置は「どの紙の直後か」で表しておき、再生時に深さを計算し直す。表示が正しく、汎用紙 6 枚が連続し、穴埋め紙を返せて、評価（手数 + 0.8 × 残した穴埋め紙 + 0.6 × 次の注文の期待費用）が良くなれば採用。最終の重なり順が元と同じである必要はない。32 手以下の操作列に、最大 8 回。
- **合流した計画の後半を共有する**: 旧専用紙・旧穴埋め紙の処理の後に、192 枚の順序・記録・前半の操作列などが完全に一致した計画は、後半（穴埋め紙の探索など）を 1 回だけ計算する（ハッシュで絞り、全項目を比較）。出力は変わらず、注文処理の時間が約 4 割減る。
- **時間の配分**: 設計の焼きなましは 400 万回または実時間 1.40 秒まで（改良元は 200 万回・1.00 秒）。軽量処理への切り替えは CPU 時間 1.70 秒（同 1.55 秒）。

## パラメータ

- kDesignIterations = 4000000、kDesignTimeLimit = 1.40 s、kFastModeCpuLimit = 1.70 s、holeWeight = 0.45。

stderr（改良元に加えて）:

- `prefix_checked`、`prefix_hits`、`prefix_stored`: 合流した計画の判定回数・一致数・保存数
- `post_saved`、`post_changed`、`post_trials`、`post_seconds`: 操作削除の後処理で減った手数・変わった注文数・試行数・時間

## 移植について

出所は main checkout の other_agents/gpt6pro-06-02-layered_barcode_v2.zip の solution.cpp（ログは gpt6pro-06.md の後半）。`#include <bits/stdc++.h>` を個別の include に置き換え、stderr の統計を `名前 = 数値` の行に分けただけで、アルゴリズムは不変。

時計の倍率 CLOCK_SCALE は入れていない（時間で打ち切る部分は、手元ではジャッジより約 1.1 倍多く探索する）。

agent の報告（独自生成 100 件）は 10.901 手/注文で、gpt6pro-06-01 の 11.078 手比 −1.59%、94 勝 6 敗。
