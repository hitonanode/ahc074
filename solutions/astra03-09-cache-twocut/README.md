# astra03-09-cache-twocut

改良元: solutions/astra03-08-cache-crossplan

## 改良元との差分

- 兼用補助紙を一般化: 残りのデータに完全に一致する補助紙なら、0 だけでなく 1 も担当させ、基底データ層の上に置く。
- 部分的に不一致でも、適切な深さに差し込めば使える。補助紙の 1 が誤って見える窓ではその上に 0 の単独紙を残す必要があり、補助紙の 1 を見せたい窓ではその単独紙より上に置く必要がある。ここから差し込み位置の下限 L と上限 U を求め、L ≤ U なら区間内に差し込んで 0・1 両方の修正を引き受けさせる。区間を調べるために基底層の修正を仮実行し、巻き戻してから採用した計画だけを実行する。

## パラメータ

- H=38、prior=4、accessUnit=16、cw=0.35（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（cache_twocut.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 1.66 秒（24 並列やジャッジでは 2 秒を超えうる）。
