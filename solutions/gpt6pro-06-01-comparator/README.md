# gpt6pro-06-01-comparator

改良元: solutions/clean-base（外部 agent gpt6pro-06 に clean-base のコードを渡して改良させたもの）

## clean-base との差分

注文処理の骨格（PlanOpt の全組み合わせの模擬、run_plan / run_joint、穴埋め紙の区間 DP と配置、前の専用紙・古い穴埋め紙の再利用、merge_double_moves、canonicalize）はそのまま。変えたのは次の 4 つ。

- **汎用層を「比較符号」に**: 土台 + 反転紙 5 枚（5 ブロック、32 通り）の代わりに、汎用紙 6 枚の相対順で表示する。汎用窓ごとに紙の組 (a, b) を 1 つ割り当て、a と b だけを不透明（片方黒・片方白）にする。表示は「a が b より上か」で決まる。15 組を全部どこかの窓に使うので、6! = 720 通りの順序を区別できる。
  - 対の整合: 専用紙の穴になる汎用窓の要求色を「a が b より上」という有向辺とみなし、表示できる ⇔ 制約グラフが非巡回、で判定する（Comparator::compatible）。対の 2 商品では辺が全部逆向きになるだけなので、片方の判定で済む。整合しない対の分割（split_inconsistent）は無い。
  - set_blocks: 先読みの表の代わりに、動かさずに残す紙の集合 2^6 通りを調べ、残せる紙が最大の並べ替えを使う（Comparator::plan）。最下段以外の汎用紙は必ず見えている。
  - 窓の配分は汎用窓 G = 36、ハンドル H = 28（clean-base は 30 / 34）。設計できなければ G を 32 → 28 に減らして再試行する。
- **列内の巡回順をやめる**（adaptive_insert）: 掘るときに退避させる紙と、前の専用紙・穴埋め紙を返す紙の挿入位置を、毎回次の値の最小で選ぶ。
  - 重み付き深さの増分 / 256（重みは対の紙 2、単独の紙 1）
  - ハンドルの穴の色を直す費用の見込み（白・黒それぞれの最初の紙の深さ × その色を要求する商品の割合）
  - 退避させる紙は取り出したい紙より後ろにだけ入れるので、今回の掘りの手数は増えない。
- **計画の評価の将来の項**: 0.55 × tops_penalty の代わりに、0.6 × 次の注文の期待費用（列の重み付き深さとハンドル色の深さ。adaptive_next_cost）。
- **設計を作り直した**: choose_blocks / anneal_units / filler_climb / ブロックの表の代わりに、次の 2 段で設計する（設計全体で実時間 1.0 秒まで）。穴埋め紙を考えた設計（filler_climb）は無い。
  1. 汎用窓の選び方と、各窓の比較組・色の山登り（2400 回）。近い商品どうしで整合する対が多くなるように。
  2. 対・列・ハンドルの順の焼きなまし（200 万回の上限に手元で約 0.57 秒で達する）。

時間の扱いも変わった。

- プロセスの CPU 時間が 1.55 秒を超えたら、以降の注文は穴埋め紙の探索をやめる軽量処理（fast_mode）にする。
- 設計が時間内にできなければ、窓ごとに白・黒 1 枚ずつの独立ビット設計（1 注文 64 手以下）に切り替える。
- 手元の 500 件では、軽量処理も独立ビット設計も一度も使われていない。

## パラメータ

- 汎用紙 M = 6、G = 36、H = 28。
- 挿入位置の評価の重み adaptive_end_weight = 0.6。
- 設計の rankPriority = 0.85、holeWeight = 0.5。
- 穴埋め紙の係数 kFillerCharge = 0.8 などは clean-base と同じ。

stderr:

- `moves`、`errors`
- `generic`: 汎用紙を動かした手数
- `mapping_iterations`、`design_iterations`: 設計の反復数
- `design_seconds`、`query_seconds`
- `adaptive_fallbacks`: どの計画も有効でなかった注文の数
- `fast_requests`: 軽量処理で答えた注文の数
- `emergency_design`: 1 なら独立ビット設計

## 移植について

出所は main checkout の other_agents/gpt6pro-06.cpp（ログは gpt6pro-06.md）。元から reactive で、注文は 1 件ずつ読む。変更は次の 2 つだけで、アルゴリズムは不変:

- `#include <bits/stdc++.h>` を個別の include に置き換えた。
- 最後の統計を `名前 = 数値` の行に分けた。

agent の報告（独自生成 100 件）は 11.079 手/注文で、渡したコード（11.440 手）比 −3.16%、99 勝 1 敗。
