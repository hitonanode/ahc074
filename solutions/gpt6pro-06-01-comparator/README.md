# gpt6pro-06-01-comparator

改良元: なし（外部 agent gpt6pro-06 の唯一の版。ただし agent に渡された「提示コード」を土台にしており、ログによれば穴埋め紙（filler）の区間 DP・2 枚重ねの filler・旧専用紙の再利用・複数計画の比較・同じ紙への二重操作の統合はそこから引き継いだもの。提示コードは「反転ブロック 5 個で 32 通り」の汎用層・ハンドル列・対の専用紙という、この repo の left-ap 系と同じ構成で、1 注文 11.44 手と報告されている）

## 解法の全体

- 紙の配分: 汎用紙 6 枚、専用紙 186 枚（2 商品で共有する紙 70 枚 + 1 商品専用 116 枚 = 256 商品）。窓は汎用窓 36 個とハンドル窓 28 個に分ける（どの物理窓をどちらにするかは設計で選ぶ）。
- 汎用層 = 比較符号: 汎用窓ごとに汎用紙の組 (a, b) を 1 つ割り当て、その窓は a が黒・b が白（または逆）、他の 4 枚は穴。表示は a と b のどちらが上かで決まる。6C2 = 15 組を 36 窓に全部 1 回以上使うので、6 枚の順序 720 通りを区別できる。専用紙の穴になった汎用窓の要求色は「a が b より上」という有向辺になり、表示できる ⇔ その制約グラフが非巡回（共有紙の 2 商品は辺の向きが全部逆になるだけなので、片方の判定で済む）。最下段以外の汎用紙は必ずどこかの窓で見えている。注文時の汎用層の並べ替えは、動かさずに残す紙の集合 2^6 通りを調べて残せる紙が最大の計画を取る（最下段を動かすときは先に別の紙を下へ入れて露出させる）。
- 専用紙: 共有紙は 2 商品の一致する位置にその色、違う位置は穴（下の層で補う）。専用紙を 28 本の列に分け、列 c の紙は汎用窓とハンドル 0..c を覆い、深い列のハンドルは穴。列を浅い順に重ねると各列の先頭紙が自分のハンドルで見えて取り出せる（提示コード由来の構造）。
- 列内の返却位置（新規）: 列内の固定の循環順をやめ、退避・返却する紙の挿入位置を毎回、重み（共有紙 2、単独紙 1）付き深さの増分 / 256 + ハンドルの色の修復コスト（白・黒の最初の紙の深さ × その色を要求する商品の割合）で選ぶ（adaptive_insert）。取り出したい紙より前から退避させる紙は必ずその紙より後ろに入れるので、今回の掘り出しの手数は増えない。
- 計画の評価: 今回の操作数 + 0.8 × 残した filler 枚数 + 0.6 × 次の注文の期待コスト（列の重み付き深さとハンドル色の深さ）。
- 設計: (1) 汎用層に使う窓と各窓の比較組・色を山登り（2400 回、0.32 秒上限）で選び、DAG 条件を満たす近い商品の組が多くなるようにする。(2) 商品の対・列・ハンドルの順を焼きなまし（最大 200 万回、設計開始から約 1.0 秒まで）。設計できなければ汎用窓を 36 → 32 → 28 と減らして再試行し、それでも駄目なら 1 窓に白紙・黒紙 1 枚ずつの 128 枚の独立ビット設計（1 注文 64 手以下）に切り替える。
- 時間: 設計は実時間で約 1.0 秒まで。注文処理中にプロセスの CPU 時間が 1.55 秒を超えたら、重い filler 探索をやめる軽量処理（fast_mode）に切り替える。

## パラメータ

- 汎用紙 M = 6、汎用窓 G = 36（再試行で 32 / 28）、ハンドル H = 64 − G、乱数 seed 779879（汎用層の初期化）。
- 計画の評価の係数 kFillerCharge = 0.8、adaptive_end_weight = 0.6。設計の rankPriority = 0.85、holeWeight = 0.5。
- stderr: `moves`（総手数）、`errors`（自己判定の誤表示数）、`generic`（汎用紙を動かした手数）、`M`、`G`、`mapping_iterations`・`design_iterations`（設計の反復数）、`design_seconds`、`query_seconds`、`elapsed`、`adaptive_fallbacks`（適応的な挿入が失敗して既定の位置にした回数）、`fast_requests`（軽量処理で答えた注文数）、`emergency_design`（1 なら独立ビット設計）。

## 移植について
