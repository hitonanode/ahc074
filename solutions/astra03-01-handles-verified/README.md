# astra03-01-handles-verified

改良元: なし（astra-03 の最初の版）

## 解法の全体

- 窓を、紙の取り出しに使う制御窓 H 個（窓 0〜H−1）と、データ窓 D = 64 − H 個に分ける。データ窓は、256 商品の多数決の色が 0 になるように窓ごとに色を反転して扱う（正規化）。
- 紙の構成: データ窓ごとの 0 を担当する単独紙（1 窓だけ白）D 枚、データ窓全体を 1 にする背景紙 1 枚、残りがテンプレート紙。初期の重ね順は 単独紙 → 背景紙 → テンプレート紙 で、単独紙と背景紙の並びでデータの残りのビットを直す（基底層）。
- テンプレート紙: 商品そのもの、2 商品の一致部分、近い商品を貪欲に足して共通部分を狭めたものを候補にし（データ窓で一致する窓が不透明、違う窓が穴）、制御窓を 1 つ（バンク）と色を付ける。各商品で「選ばれているテンプレートのうち最も多くの 1 を担当できる紙」の改善量が大きい順に貪欲に選び、その後 1 枚ずつ入れ替える局所探索と、穴から見える色の多数決による正規化のやり直しを 3 回行う。
- 注文ごと: 前の注文で前面に出した紙を一番下へ戻す。目標に一致するテンプレートのうち「基底層の修正手数 + バンクの何枚目か + 1」が最小のものを選び（使わない選択もある）、バンク内で上にある紙を順に一番下へ回してから一番上へ出す。穴から見える部分は基底層（背景紙の位置と単独紙の移動）で直し、最後に色の違う制御窓を、その窓を覆う一番上の紙を一番下へ回して直す。

## パラメータ

- H=16（制御窓 16、データ窓 48）（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（handles_verified.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 0.38 秒。
