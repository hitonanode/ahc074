# 注文処理の高速化（esw-fast）

改良元: solutions/esw-noprune（PR 99 の設計の保存・読み込みを含む版）

注文処理（Solver）の計算を、出力を変えずに速くした版。紙の設計・時間配分・定数・乱数・CLOCK_SCALE・LOCAL_BENCH・DesignStore は改良元と同じ。時計を「読むたびに一定時間進む擬似時計」に置き換えると、stdout と時計を読む回数が改良元と一致する。

## 速くしたところ

段ごとの時間（手元、擬似時計で同じ設計・同じ操作列にした seed 0〜11 の平均。注文 1024 回の合計の実時間）は、改良元で 0.27 秒のうち、後処理（post_optimize）が 0.16 秒、計画の候補の模擬が 0.045 秒、穴埋めの連鎖の探索が 0.027 秒、補助紙が 0.032 秒だった。

- **後処理の evaluate**（1 ケース約 31 万回呼ばれる）
  - 表示の確認: 最終の並びを 1 枚ずつたどる代わりに、最初の並びの連続した区間（動いた紙・その直前・差し込み先で区切る）を、16 位置ごとのブロックの前後の累積（覆う窓と見える色）でまとめて調べる。
  - 動きの合法性: 並びをバイト配列（memchr で位置、memmove でずらす）にし、紙の上の窓の覆いを前から遅延して累積する（各手で上の紙を数え直さない）。
  - 状態の作り直し: restore の代わりに必要な部分だけを入れ、試行の配列を使い回す。
- **2 削除 + 1 修復（eject_repairs）**: 試行・最終の並び・位置を固定長の配列にし、修復紙の候補ごとの可視性は全紙の表ではなくその紙だけを再生して求める。差し込み先の列境界は [lo, hi] の範囲だけを見る（各列の最初の紙の位置を先に求める）。
- **canonicalize・plan_cost**: 固定長の配列にし、汎用層より下かどうかを 1 回の走査で求め、紙ごとの列と色を表にした（足し算の順序は同じ）。
- **差し込み先の候補（anchor_candidates）**: バイト配列で再生し、重複を表で除く。
- **穴埋めの連鎖（append_wide_chains）**: 列の上端は呼び出し元の 1 回の走査から取り、連鎖を固定長の記録に入れ、ビームは (gain, 添字) の組で並べ替える（std::sort は同じ比較をして同じ順列になる）。
- **区間 DP の候補**: 候補の配列を使い回し、節約できる掘りの数をハンドルの添字のビット集合で数える。
- **補助紙の組（best_interleave_pair）**: 汎用層の順序を距離の順に 1 回だけ並べ、2 枚とも穴の窓で表示が違う順序は飛ばす。
- **紙の移動（move・move_after）**: 位置と可視性を 1 回の走査で求め、間の紙を 1 回でずらす。

改良元より注文処理の実時間が約 3 割短い（同じ設計の seed 0〜11 で 0.269 → 0.188 秒。評価の比較は trial_log.md）。
