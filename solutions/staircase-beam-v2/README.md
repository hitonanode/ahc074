# staircase-beam-v2 — 階段側のビーム再構築（研究版）

改良元: `solutions/esw-clean`（元コードの提供版 `esw-clean.cpp`）。2026-11-06 の構築実験。**2秒制限での安定動作も、既存解を超える改善も保証しない。**

## 元から変えたところ

1. 既存解の出力を解析し、64段で各目標を少しずつ被覆する初案を捨てる。共用層6枚と、アクセス窓で掘り出す密な主紙185枚、cap1枚という構造を採用する。
2. 共用37窓／アクセス26段／cap1窓に変更する。段あたりの紙枚数（共有2目標の主紙を含む）を、掘り出しの深さと残余アクセス窓の修復費用のDPで配分する。
3. 共有可能な目標のグラフから関係の深い12枚を集め、**浅い段から順番に**、1目標紙か2目標共有紙かをビームで作り直す。候補の評価は単なる被覆数ではなく、掘り・穴修復・共用層変更・補助紙としての価値を含む。
4. 既知の実行可能な構成を保持する。短い列の焼きなまし・climbで仕上げる。注文処理は既存の合法操作計画器を引き継ぐ。**共用6枚の模様はこの版では自由設計しない**。

主要設定: `CB_G=37`, `CB_PRE=400`, `CB_WIDTH=64`, `CB_POOL=12`, `CB_REFINE=2000000`, `CB_CLIMB=50000`。環境変数で変更可能。設計段階で将来の注文列は読まない。

## ビルド

```sh
g++ -std=c++23 -O2 -march=native main.cpp -o solver
```

このリポジトリの `scripts/pahcer_run.py` での再評価は、このPRでは実施していない。初回の独立Pythonチェッカー検証・集計は `docs/experiments/staircase-beam-20261106/` に保存。**過去結果は実行環境・ビルド条件が異なるため、リポジトリ内の統一評価とみなさないこと。**

実手数・時間・勝敗と採否は `trial_log.md`、再現条件や失敗分析は上記レポートを参照。
