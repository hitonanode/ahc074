# 非線形窓の場所を原子的に移す実験

## 結論

**非線形ゲートの場所を移す操作は働いたが、最終スコアの改善は確認できなかった。現時点では採用しない。**

初手で選ばれた非線形窓を別の窓へ移すには、いったん唯一の非線形窓を比較器へ戻す必要がある。非線形窓を最低一つ残す一窓探索では、この中間状態へ進めない。本実装はその2窓の変更を一括して採否する。64件の評価では、平均27.39回試して2.34回採用され、単なる未発動の案ではなかった。

しかし、`astra-search4` に対する差は −0.222 ± 0.240%、改良元 `astra-structural-fast` に対しては +0.390 ± 0.200%だった。どちらも差が2標準誤差に達しておらず、後者は悪化方向である。代理費用を改善したことを、最終手数の改善とは扱わない。

## 評価条件

独立に生成したseed 80〜143の64件、1件につき1024注文。公式generatorのseed番号とは対応しない。`scripts/pahcer_run.py --compare` を呼ぶ共通の `evaluate.py` を用い、同じseedで基準と候補を続けて実行し、その順をseedごとに変えた。4並列、GCC 13.3.0、`-std=c++23 -O2 -DCLOCK_SCALE=1.1`。詳細とテスターの監査は [共通の評価条件](../astra-frontier/EVALUATION.md) にある。

run-idの共通prefixは `20261101-194532`、各runの末尾が解法名である。これは候補選定用の比較であり、未使用ケースでの採用確認ではない。

|解法|平均スコア|注文あたりの手数|誤表示合計|WA|実時間の最大|
|---|---:|---:|---:|---:|---:|
|astra-search4|10880.047|10.625046|0|0|1.6792秒|

## どの機構が動いたか

次の値は同じ64件のstderr指標の平均である。

|指標|structural-fast|architecture|
|---|---:|---:|
|ゲート候補の延べ評価数|24973.59|25030.03|
|2窓の移動を試した回数|対象外|27.39|
|2窓の移動を採用した回数|対象外|2.34|
|最後の非線形窓数|1.031|1.016|
|学習前の70対の代理費用 / 256|3.17324|3.17462|
|学習後の70対の代理費用 / 256|3.19300|3.17931|
|新たに互換になった近い対|3.36|4.98|
|互換でなくなった近い対|14.22|14.00|
|最終設計が採用した、初期比較器で非互換だった対|0.672|0.969|
|汎用紙の操作数 / ケース|1251.36|1258.86|
|後段の焼きなまし反復数|11277396|11248160|

原子的な位置変更により、最初に非線形ゲートを強制する際の代理費用の増加は小さくなった。一方、非線形窓はほとんど1窓のままであり、初期比較器で不可能だった対の最終採用も平均1対未満である。今回の変更は位置選択の障壁を取り除いたが、複数窓を共同で学習する問題は解いていない。

また、学習中は近い対の費用と70対のマッチングを用い、後段では列への配置・穴埋め・注文列上の状態遷移を最適化する。前段の改善が後段の操作数へどのように伝わるかは、この64件だけでは特定できない。

`visibility_graph.cpp` は、6枚の安全な可視性だけを変えた720状態の操作グラフを調べる独立した診断である。全点対距離は厳密に計算した。

全て未到達状態は0だった。4・8・16状態の合成目標集合についての値も `visibility_graph.csv` に保存した。これらはバーコードの部分要求ではなく、取り出し・穴埋めの費用も含まないため、コンテストのスコアとは別の診断である。

この結果は「全15比較窓を保護しなくても、操作距離の増加が小さい構造がある」ことを示す。学習後に実際の模様から合法グラフを作り直せば、保護対象でない窓が追加で与える可視性も回収できる。この方向は `astra-sparsegate` と `astra-sparse12` の全体比較へ引き継いだ。

## 再現

入力を用意する手順は共通の評価条件を参照する。今回の候補だけを比較する場合は、評価用workspaceで次を実行する。

```sh
python3 solutions/astra-frontier/evaluate.py \
  --compare solutions/astra-search4 solutions/astra-structural-fast solutions/astra-architecture \
  --seeds 80-144 --no-record -c 'atomic nonlinear-window relocation'
```

実行中の速度で探索回数が変わるため、別々のrunの小さい差では判断しない。別環境で今回と同じ絶対手数になるとも限らない。
