**採用した高速化と同一性の根拠**

1. 穴コストの `eval_holes` を強制インライン化した。GCC -O2 では元の関数が別関数になり、
   d0/d1/N0/N1/Q の5配列をスタック経由で渡していた。SIMD の演算と hsum の加算木は同じ。
   最後の SIMD 群に変化がなければ保存済みの値を使う。個数とリセット需要は小さい整数で、
   分子が float で厳密に計算され、同じ除算の結果になるため、差分は厳密に正のゼロ。
2. 列コストの増加が10000を超える移動を、穴コストを作る前に棄却する。
   a+b≤256 より q≤64。全64ハンドルでも穴コスト変化の絶対値は8192未満、
   温度≤2、最大対数値<11なので採用閾値は22未満。必ず正の差で棄却される。
   元の accept が消費する乱数をちょうど1回消費し、乱数列は保つ。
3. 採用時の4回の unit_rows 更新を、両列の差分の作成と加減算にまとめた。
   すべての値と中間結果は小さい整数なので、順序を変えても丸めが生じない。
   72 seed の同時比較では、採用版の焼きなまし0.509769 s、末尾群の省略なし0.518769 s、
   さらに元の行更新を強制インライン化した版0.520810 s。
   採用版 / 末尾群の省略なし = 0.98265。全候補72件ずつ byte-identical。
   記録は `20261105-074123_{climb4-fast,anneal-fast,no-tail,inline-rows}`。
4. filler_gain の被覆集合が空なら、元の漸化式の値である正のゼロを即時に返す。
   1ビットの被覆は丸めで微小な正値になり得るため、そこは元どおり計算する。
5. 再割り当てでサイクルを棄却した直後の先頭価値表の復元を遅らせる。
   次のサイクルは全表を設計から上書きし、途中の表を読まない。
   次のマッチングの前だけ必要なら再構築する。候補の評価順と各評価値は維持する。
   この変更だけを加えた段では再割り当て0.079224→0.053147 s、比0.67085
   （`20261105-072519_{climb4-fast,anneal-fast}`、48 seed）。
6. 先頭選択で最大の重みを持たない紙は選ばれないので、その donor 価値を計算しない。
   同じ重みの紙はすべて計算し、同点の最初の紙を保つ。
   target 価値の加算は beta が非ゼロの紙だけを元の番号順に走査する。
   5との累積で0.079336→0.029899 s、比0.37687
   （`20261105-072857_{climb4-fast,anneal-fast}`、48 seed）。
7. Hungarian の visited をビット参照からバイト配列にし、minv と visited の領域を再利用する。
   全走査と浮動小数点の差・加算・比較、同点処理は元の順序のまま。
8. 穴あけは先頭が一度選ばれると固定されるので、その紙だけの utility / gains を更新する。
   最初の選択では最大頻度の全候補を元の順に評価する。
   コンストラクタ直後に同じ設計を再構築していた2回目の初期化も省く。
   サンプル生成は固定 seed で毎回初期化される独立の乱数で、最初の表が2回目と同一。
9. 穴あけの区間 DP に実在する遷移のビット集合を持たせる。
   元の -1e9 の遷移は非負の DP 値を改善できない。寄与する遷移だけを同じ順序で評価し、
   同じ best が続く区間では同じ加算値を再利用する。forward/backward/avoid の値と、
   total_profit のターゲット・サンプルの加算順は変えない。
   8と9の累積で穴あけ0.029337→0.015299 s、比0.52148
   （`20261105-073839_{climb4-fast,anneal-fast}`、48 seed）。
10. stay_table のターゲットのハンドル色を256件だけ変換して使い回す。
    Interleave は generic の誤りが helper より下に残る最大深さを、単調な prefix 被覆集合で
    求める。その深さで helper 自身の誤色が覆われるか検査する。
    元と同じ最も深い挿入位置を、元と同じ状態順に記録する。
    補助表全体0.039514→0.033129 s、比0.83843
    （`20261105-073352_{climb4-fast,anneal-fast}`、48 seed）。

各時間は、その行に示した同じ compare 内の基準と候補の比較。
異なる記録間の候補時間を割って個別の効果とはしていない。
