# astra03-07-cache-cycles

改良元: solutions/astra03-06-layered-cache-sorted

## 改良元との差分

- 設計の局所探索に 2 枚同時の入れ替えを足す（1 枚では担当を取りこぼすが、もう 1 枚に担当を移せば改善できる場合）。残った商品群の共通部分から作る紙との組み合わせも評価する。
- 主紙で覆えない残りの 0・1 を商品ごとに集め、単独紙（基底層）の並び順を焼きなましで調整する（背景紙を境に 0 を出す紙と 1 を出す位置を少ない移動で分けられる順）。注文時の単独紙の戻し位置にも、将来の修正手数の見積りを使う。
- 退避する紙を、次に取り出す紙の後ろへ直接戻して 2 度動かすのを避ける。上の紙で隠れる制御窓については、バンク先頭の色の条件を緩める。
- H を 36 → 38、制御費用の重み 0.35 を導入。

## パラメータ

- H=38（データ窓 26）、prior=4、accessUnit=16、制御費用の重み cw=0.35（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（cache_cycles.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 1.41 秒。
