# legal-tie-merge（2 回動かした紙をまとめる後処理）

改良元: `solutions/deval-helper-wide`。設計は変えない。注文処理の最後に後処理を 1 つ足しただけ。

## 改良元からの差分

- **2 回動かした紙をまとめる（merge_double_moves）。** 選んだ計画が同じ紙 x を 2 回動かしていたら（手 i と手 j、i < j）、手 j を消し、手 i で x を終わりの重なり順での場所へ直接送る。
  - x の送り先は、終わりの重なり順で x より下にある紙のうち、i より後の手で動かない最初の紙の直上（なければ一番下）。
  - ほかの手は、元の計画でその手の直後に真下にあった紙（アンカー）の直上へ差し込む。結果として動かない手になったものは消す。
  - 動かす紙がそのとき見えていて、終わりの重なり順が元と同じときだけ採る。そのときは状態・表示・以後の注文が変わらず、手が 1 つ以上減る。
- なぜ: 段階 1 の探索（solutions/legal-search、結果は legal-notes/PROGRESS.md）で、SOTA の出力のうち同じ終状態へもっと短く行ける注文のほとんどは、同じ紙を 2 回動かしていた（戻した補助紙をまた掘る、戻した紙をまた持ち上げる、など）。この規則はその一部を、ほとんど時間をかけずに拾う。
- 時間不足の打ち切りなどはない。

## 指標（stderr）

- `merge_trials`（2 回動かした紙を調べた回数）、`merge_saved`（減らした手の合計）。
