# 多者先着ゲートと専用紙の再設計

改良元: solutions/imp-gla

従来は汎用窓ごとに2枚だけ不透明にし、「どちらの紙が上か」で色を決める。
本案は4枚（2白・2黒）が参加する均衡した先着ゲートを導入し、比較器に限らない模様を実際に動かす。

- 元解法の汎用窓の割り当てが終わった後、専用紙の商品対を決める前に汎用ゲートを変更する。
- 15組の紙対について1窓ずつ従来の比較窓を保存する。これにより最下段以外の紙の可視性が保たれ、元の合法移動距離の表をそのまま使える。
- 残る窓から既定で3窓を選ぶ。既定では各窓に異色の2枚を追加する12通りから選び直す（3枚ゲートの場合は1枚追加の8通り）。
- `GATE_FULL=1` では任意の4枚と黒2枚を選ぶ全90候補を調べる。元の比較ペアを残す制限を外し、当該窓の6枚のセルを全て置き換える。15個の可視性用比較窓はこの場合も変更しない。
- 候補ごとに全720順序での表示と、ハミング距離26以下の商品対の互換性を調べる。充足順序数とハンドルでの違いから重みを付け、70組の貪欲マッチングが最も安い候補を選ぶ。
- この実験では比較器と同じ模様に戻らない。比較器より推定が悪くても、指定枚数のゲートで最良のものを採用する。
- ゲート決定後の専用紙設計では、互換性と汎用層の費用を全720順序の**実表示**から計算する。費用は各初期順序から最寄り充足順序までの合法距離の正確な平均で、元解法の列割り当て焼きなましを使う。
- 注文時も実表示から充足順序を列挙して最短路を選ぶ。穴埋め補助紙と次回期待値も新しい模様に対応する。

主な設定: 環境変数 `GATE_ARITY=3` なら3枚ゲート、それ以外は既定の4枚ゲート。
`GATE_FULL` は既定0。4枚ゲートで1を指定すると全90候補を使う（3枚ゲートでは無効）。
`GATE_COUNT` が非指定または0なら3窓、正ならその窓数、負なら変更なし。
既存の設計終了時刻は維持するため、ゲートの評価時間分だけ列割り当ての焼きなましは短くなる。
`gate_arity` はゲートの枚数、`gate_full` は全90候補を使うか、`gate_multiway` は実際に拡張した窓数、`gate_proxy_before/after` はゲート選択用の推定費用、
`gate_end_sec` は倍率適用後のゲート設計終了時刻である。
推定費用には、距離26以下の候補だけでの貪欲マッチングが70組に足りないとき、不足1組あたり1000の罰を含む。
後段の専用紙設計は距離26超を含む全候補と増大路も使うため、この罰が正でも表示可能な設計を作れる。

## 凍結した近傍を調べる対照実装

`frozen_gate.cpp` は先に専用紙70対を固定し、後から任意の729 ternary列へ単窓ずつ変更する対照実装。
全商品の表示可能性を保つ候補だけを対象とし、充足順序数の対数和で上位3候補を提案、
720初期順序からの最小合法手数の平均が厳密に減る変更だけを採用する。
15比較窓を保存し、残り窓を倍率適用後1.48秒まで、最大3巡調べる。
研究用環境変数 `GATE_PASSES` を正にすると、その回数を上限として時間判定を止める。
`gate_accepts / gate_trials / gate_multiway / gate_cost_before / gate_cost_after` が診断指標。

固定された対の制約が単窓の模様を一意に決めることがあるため、`main.cpp` ではゲートと対の選択を組み合わせた。
本実装はゲートと窓割り当て自体を同時に焼きなましてはおらず、表現力を調べる第一段階である。

3枚ゲートは色の確率が1/3と2/3に偏る。1窓だけへの3枚目追加では、その色と逆の目標は元の比較制約を依然として要求するため、元の比較器で互換でなかった商品対は新たに互換にならない。
4枚を2白・2黒にすると両色の確率が1/2で、どちらの目標も追加した同色紙を使って元の比較を回避できる。
この違いを調べるため、3枚版も同じ実装で選べるようにしている。

## 表現力と今後の拡張

6枚の比較器の特徴関数は15比較とその反転の30種類。
4枚を2白・2黒に塗ったゲートだけで90種類、6枚を3白・3黒に塗ったゲートも加えると均衡した特徴は140種類になる。
本実装では元の比較ペアを残す12候補と、任意の4枚を使う全90候補を選択できる。
全140候補、窓割り当て、商品対のマッチングを同時に最適化する余地を残している。

一方、汎用6枚で任意の8商品を常に表現できるという主張は成り立たない。
順序ごとに `x_k = 3^(-rank(k))` とすると窓の表示は `sign(sum(w_k*x_k))`、
`w_k` は白=-1・穴=0・黒=+1で書ける（先頭非穴の寄与が下位すべてを支配する）。
従って6次元の同次線形分類器の部分族であり、VC次元は高々6。
入力依存に限られた64列を表現できる可能性と、任意の全ラベルを表現できることは区別する必要がある。

## 相対順列による合法距離表の圧縮

`permutation_metric_probe.cpp` は、この解法本体とは別の数理検証用プログラム。
6枚固定を外す際に障害となる全状態対の距離表を、1回のBFSへ圧縮できることを調べる。
既存 `solutions/imp-gla/main.cpp` の `Comparator::build_tables` を比較対象としてそのまま使用する。

前提は、各状態で「最下段だけ見えず、残りは全部見える」こと。比較窓を各紙対について1個保存すれば満たせる。
順序を位置から紙番号への置換 `p` とすると、紙番号の付け替え `p^{-1}` は開始順序を恒等順序 `id` にし、
目標 `q` を相対順序 `p^{-1}∘q` にする。合法操作は位置と挿入深さだけに依存し、紙番号に依存しないため、
この付け替えは有向操作グラフの同型写像となる。従って

```
dist(p, q) = dist(id, p^{-1}∘q)
```

である。`id` からの1回のBFSで全距離が分かる。
そのBFSの親と操作を保持し、相対順序までの経路の紙番号 `i` を元の紙 `p[i]` に戻せば、
任意の開始順序から目標順序への合法な最短操作列も得られる。
この距離は有向距離であり、始点と終点の交換で同じになるとは限らない。

距離配列は8枚でも40,320バイト（全状態対を格納すれば1,625,702,400バイト）。
親・操作・順列一覧などの補助記憶は別途必要だが、これらも状態数に比例する。
自己移動を除いた遷移は1状態あたり `(M-1)^2` 本なので、8枚の単一BFSで調べる辺は1,975,680本。
これは計算上の拡張可能性を示すもので、7枚や8枚の設計がより良いスコアを出すという実験結果ではない。

再現コマンド:

```sh
g++ -std=c++23 -O2 solutions/chatgpt-structure/permutation_metric_probe.cpp -o /tmp/ahc074-permutation-probe
/tmp/ahc074-permutation-probe > /tmp/ahc074-permutation-probe.json
```

保存済みの検証結果は `permutation_metric_probe.json`。
2〜6枚の全533,416状態対で既存の全始点BFSとの距離一致を確認し、同じ全状態対で逆写像した経路を再生する。
加えて7枚5,040状態・8枚40,320状態について全状態へ到達し、恒等順序からの全経路を再生する。
