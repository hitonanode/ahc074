# 浅い2列を全順序で制御する部品

改良元: solutions/head-design。平均費用の模型は solutions/front-module の全順列MDP。

先頭2列の6〜7枚を1つの部品として扱い、部品内の順序を列ごとのまとまりに戻さずに使う。全順序と見えている紙の合法な移動を前計算し、全256商品の部分一致要求と指定紙の取り出しから状態価値を求める。

外の商品紙を持ち上げる前に必要な2窓を合わせる。部品内の商品では、指定紙を取り出した後にその紙が隠す窓は操作に使えない。返却は次の注文で行い、その差し込み位置を選ぶ。外側の穴埋め紙が部品の間へ入る配置と、この部品の紙を汎用層へ出す補助紙は使わない構成を研究する。

`module.hpp` は2窓・最大7枚の制御表、`check.cpp` は保存プロフィールとの厳密な費用照合。`main.cpp` は制御表を内包した1ファイルの統合版。部品内の実際の可視性を使って操作し、古い穴埋め紙が後で回収される返却段階は、回収後の窓を想定して返却先を評価する。前2列の紙の補助利用と、部品の間への穴埋めは使わない。

`FRONT_GROUP_CONTROL=0` は研究の切り分け用で、同じ配置制限だけを従来の列制御に適用する。`probe.cpp` は保存した紙と独立した模擬注文を使う。`verify.cpp` は独立に構築した可視性グラフと優先度キューで制御表・経路を照合する。時計は `CLOCK_SCALE` 倍、実際の注文列は読まない。
