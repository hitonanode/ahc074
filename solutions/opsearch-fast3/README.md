# opsearch-fast3

改良元: `solutions/climb4-fast`。

中立探索で保存する候補2個の選び方を変える。親の操作列で動かし、終了時にも窓を担当していた紙について、候補では同じ紙の操作が残っているのに、その紙が完全に隠れた数を数える。新しい修復紙が元の役割を引き受けたため、残った操作を削除できる可能性がある。

候補は、手順が短い順、上記の紙が多い順、再操作が多い順、従来の目的値が小さい順で選ぶ。窓の担当紙は既存の署名計算の走査中に調べるので、追加の全積層走査を候補ごとに行わない。これは探索先の順位付けであり、実際の削除と採用には従来の合法性・表示・補助紙回収・`plan_cost` の検査を使う。

設計、目的関数、列 MDP、探索周回数、保存幅、許容差、後処理する計画数、1→1の差し込み先数は変えない。中立探索は1周、保存幅2、通常の後処理計画2、追加保持計画3のまま。CLOCK_SCALE、LOCAL_BENCH、DesignStore、段の目印と目次、@paper / @ops の解析出力を引き継ぐ。

探索の環境変数は `F3_` 専用で、基準の `F2_` や接頭辞なしの探索変数を読まない。`F3_HIDDEN_RANK=0` で元の候補順位に戻す。`F3_HEAVY_TRACE` / `F3_HEAVY_PREDICT` は既存の研究用ログで、後者の末尾に新しい特徴の値を加えた。

`F3_PROFILE=1` のビルドは後処理の段・候補順位・演算子ごとの時間、試行数、合法数、採用数、目的値改善量を `#f3post` / `#f3op` に出力する。通常ビルドは0。時計は CLOCK_SCALE を適用し、ログは注文処理後にまとめて出す。結果と不採用案は REPORT.md、保存ログの集計は analyze.py / profile.py に置く。
