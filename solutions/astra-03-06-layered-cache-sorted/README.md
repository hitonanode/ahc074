# astra-03-06-layered-cache-sorted

改良元: solutions/astra-03-05-layered-handoff

## 改良元との差分

- バンク内の紙を使用頻度順に並べる: 商品一覧から各紙の使用頻度を見積もり（初期頻度の重み 4）、よく使う紙をバンクの浅い位置に置く。注文を処理するたびに実際の使用で頻度を更新する。
- 取り出すためにどかした紙を戻すとき、どかした紙と順序を保つべき残りの紙の列を、頻度を考慮した動的計画法で組み合わせる。制御窓の色を切り替えられるよう、バンクの先頭付近に反対色の紙を残す制約は維持する。

## パラメータ

- H=36、初期頻度の重み prior=4、アクセス費用の尺度 accessUnit=16（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra-03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（layered_cache_sorted.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 1.24 秒。
