# slimからの改善と構造模型の結論

マージ候補は **solutions/nogen-core-post5**。main.cpp: **487014 bytes**（`wc -c`）。独自上限520000 bytesまで32986 bytesの余裕がある。今回の改善は **−0.053824 ± 0.001499%**。0.3%には届かず、約3時間の作業区切りで報告する。SOTA超えは未達。

## 採用した変更

1. 所有者との距離を、256商品のAVX2ビット集合で0・1・2誤りまで厳密に求める。3以上なら従来の全探索へ戻す。近似値は目的関数に入れない。
2. 初期の列先頭を取っ手要求の多数色へ交換し、背景は既存の次注文期待費用が最小の順序から始める。内部紙番号を変えず出力番号を対応付けるので、候補の同点順を保つ。
3. 到達しないforcedG設計、そこでだけ使うEconomicDesign・anchor_rebuild、呼出しのない緊急設計を削除。段マーカー・目次・生きているログ、監査、プロファイラ、@paper/@ops、DesignStore v2を保持した。行結合やコメント一括削除はしていない。
4. 通常後処理を4候補から5候補へ増やす。中立書換えは2巡、窓300k+60k、列9.5M、山登り100k、再割当4+1を維持する。

所有者高速化の通常500件 `20261106-154708_nogen-owner-bits` は同時slimとstdoutが全件完全一致し、judge平均1.713940→1.684926秒。初期積層の模型 `20261106-160426_nogen-initial-model` は64保存設計・独立2048注文で0.002510±0.000282手/注文の改善、最初32注文で4.625±0.530手の改善だった。固定500×2の実装比較では多数色だけで約−0.042%、背景初期順も加えて約−0.045%。通常2000件の `20261106-161243_nogen-core-initial` 対slimでは−0.044561±0.001084%、1623/107/270。

削除前 `20261106-161243_nogen-initial-value` と削除後 `20261106-161243_nogen-core-initial` の通常500件はstdoutが完全一致した。assert行番号が変わるためオブジェクト同一性ではなく実出力で検証した。

後処理5候補は、固定比較 `20261106-162743_nogen-core-post5`、500設計×2注文列で基準core-initialに−0.010152±0.001611%、303/4/193。req_secは0.618428→0.652133秒。次の通常比較で確認した。

- G37は現在のslimとの通常500件で+0.012785±0.054944%、未確定。judgeは約0.114秒短縮。後処理強化はG37内で−0.019391±0.002724%だが、G36との優劣は未確定。所有者投影後300/1000試行の追加探索も有意差なし。
- 列9.5M→11Mは500件では改善側だったが、通常2000件 `20261106-162820_nogen-core-col110` は平均10372.22、core-initialより悪化側、judge1.743秒で時間比も1.1超。採らない。
- 現在の中立3巡の上積みは通常2000件で−0.004393±0.000540%。以前の古い基点での−0.094%を、そのまま現在の再配分効果とはみなせない。
- 出力同一の速度実験：filter-prefix（全1000出力一致）はreq約+0.0083秒、tail-wordhash（1000一致）は約+0.0039秒、control-cache（1000一致）は約+0.0011秒で不採用。matching-bucketsは通常500出力一致でも遅くなった。M=0固定も通常500出力一致でjudge約+0.0078秒となり、採用版に入れていない。

## 現在の差と次の検討

採用版のSOTAとの差（実@ops、2000件）はfix +0.07266、help +0.05251、fret +0.04496、lift +0.03681、hdig +0.02908。一方dig −0.12540、repair −0.05718、gen −0.03941。genは本系列では実商品が所有する背景紙の移動を指す。

今回、有望な大きな構造変更は確認できなかった。静的なペア・穴・背景距離の改善が、全商品の補助利用と終了状態を含めた費用へ移らないことが主な問題。原因候補は、背景の終了状態分布と補助紙選択の相関を、均一順序や独立被覆で近似している点である。正確な片向き背景距離だけでは解消しなかった。

背景ヘルパーを残して後処理だけ省く中間模型も検証した。[mid-rollout-model/REPORT.md](../nogen-mid-rollout-model/REPORT.md)、32設計・128候補で通常処理利得との相関0.277、選択後利得−0.010773±0.007969手/注文。約3.77倍速いが、2048注文/候補に約0.335秒かかり、正の選択利得も確認できない。次は同じ補助紙・列状態からの差分費用を測る模型などを較正し、独立注文で正の選択利得が出た場合だけオンライン設計へ組み込む。静的目的値が良い候補を増やすだけの再試行は優先しない。

capは今回も物理窓63固定。STATEの「cap窓は自由」とBRIEFの「例外は63、0–62は厳密」の適用範囲について確認を出しており、他の物理窓へ例外を移す変更は行っていない。trial_log.md、STATE.md、既存解法、共有scriptsは変更せず、コミットも行っていない。
