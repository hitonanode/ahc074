# 軽い計画を使わない版（ジャッジでの時間の測定用）

改良元: solutions/esw-tidy。

注文処理の軽い計画（倍率込みで 1.80 秒を過ぎた注文を軽く処理する保険、kFastAfter）を外し、どれだけ遅くなっても全注文を通常の計画で処理する。それ以外は esw-tidy と同じ。

- 目的: esw-tidy をジャッジに出すと、暫定 50 件の総和が as6-canon より悪く（529870 → 531759）、最大の実行時間は 1810 ms だった。手元では as6-canon より約 1.5% 良いので、ジャッジでは注文処理が手元の見積りより遅く、多くのケースで 1.80 秒の保険に入ったと考えられる。この版をジャッジに出すと、ケースごとの実行時間から、ジャッジでの注文処理の実際の時間が分かる（2 秒を超えれば TLE になる）。
- 手元の評価（`-DLOCAL_BENCH`）では、esw-tidy も軽い計画を使わないので、両者の動作は同じ（プリプロセス後のコードの差は、消した 2 行と定数 kFastAfter だけ）。
