# pool-climb

改良元: solutions/pool-value

紙の設計に、焼きなましの後の山登り（filler_climb）を足した。深い列の紙が浅い列の目標の穴埋め紙として使いやすくなるように、単位（対または単独の目標。専用紙 1 枚に当たる）の列を入れ替える。注文ごとの操作は pool-value と同じ。

## 変更点

- 穴埋め紙は深い列の上端付近の紙で、浅い列の目標 u のハンドルの穴（三角形の穴）を、u と色が合う範囲でまとめて覆う。どれだけ覆えるかは列の紙と u の模様の偶然の一致で決まり、焼きなましはこれを見ていない（焼きなまし後の値は無作為に並べたのと同じ程度）。
- そこで、焼きなましの後（1.10 秒）から 1.15 秒まで、次の入れ替えを山登りで試す。
  - 同じ種類（対どうし・単独どうし）で、両方のハンドルの色が同じ 2 つの単位の列を入れ替える（列の色の釣り合いと、モデルの掘りの費用は変わらない）。
  - 目的 = モデルの費用（ハンドルの穴の数 × 0.51）− 0.7 × Σ_u proxy(u)。
  - proxy(u) は、u の列より深い各列 c について、c の単位 y の紙を「u と色が合わない最も深いハンドルの次」の段に置いたときに覆える u の三角形の穴の数 g（h_c は除く）から max(0, g − 3) を作り、列 c の中で平均して足したもの。注文ごとの回帰で、proxy 1 単位は約 0.7 手に当たった。
- 入れ替えで値が変わるのは、2 つの単位の目標と、ほかの目標から見た列 a, b の和だけなので、ほかの目標は g を 4 回計算した差分で評価する（0.05 秒で約 10 万回）。

## パラメータと指標

- 環境変数 `CLIMB_TL`（既定 1.15）: 山登りを打ち切る時刻（プログラム開始からの秒）。`CLIMB_ITERS`（既定 0）: 正なら時刻でなく回数で打ち切る（実験用）。負なら山登りをしない。
- `CLIMB_W`（既定 0.7）: proxy の重み。`CLIMB_T`（既定 3）: proxy の閾値（g から引く数）。`CLIMB_T0`（既定 0）: 正なら焼きなまし風に悪化も受理する開始温度（実験用）。
- stderr の `climb_proxy_before` / `climb_proxy_after`: 山登りの前 / 後の proxy の 1 目標あたりの平均。`climb_accepted`: 受理した入れ替えの数。`climb_iters`: 試した回数。`climb_end_sec`: 山登りが終わった時刻。
