# chatgpt-match

改良元: `solutions/imp-combo`

窓の割り当てを評価する際の「費用の小さい順に70対を取る貪欲マッチング」を、
交互路・交互閉路による局所改善で補正する。安い1対を先に確保したために、
残りの対が高くなる組合せを、2対まで同時に入れ替えて解消する。

- 貪欲法で70対を確保できた候補だけを補正する。補正中は70対と商品を重複使用しない制約を守る。70対未満なら従来の不足ペナルティで評価する。
- 片端を未使用商品へ付け替える手、未使用2商品の対との交換、長さ4の交互路、4辺の閉路、
  長さ3の増加路と別の高価な対の削除を比較する。
- 1回の評価につき、最も費用を下げる変更を最大3回適用する。
- 改善済みの対を、その後の候補除外・窓移動候補の生成にも使う。
- 専用紙の初期化・焼きなましと注文処理は改良元と同じ。補正したmatchingは窓割り当て内の評価・候補生成だけに使い、`Design::initialize` には渡さない。初期化では改良元の別の費用係数による貪欲matchingを作り直す。時計には `CLOCK_SCALE` を適用する。

環境変数 `MATCH_REPAIR_PASSES` で最大反復数を変更できる。既定3、0は補正なしの比較用。
matching_evaluations はマッチング評価回数、matching_repairs は受理した補正回数、
matching_repair_gain は1評価あたりの目的値低下の平均。


## 評価の区別

通常の対話比較と、共通の注文列を使う `SIM_HARNESS` の比較は [評価環境の説明](../chatgpt-study/README.md) を参照。後者は補助紙表の初期化期限と注文処理の時間による軽量化を外した研究用実験であり、2 秒制約下の性能や合法性の独立検査とは別に扱う。
