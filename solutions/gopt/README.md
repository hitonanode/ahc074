# gopt

改良元: solutions/gsel

gsel で 4 候補から選んだ汎用窓・ブロック・Y_b を、選択の指標 greedy_pair_obj そのものの山登りでさらに改善してから、焼きなましに入る。

- 動機（trial_log の ceil-）: greedy_pair_obj（整合する対だけを候補に、ハンドル窓で違う窓の数が少ない順に貪欲にマッチングした 70 組の平均の違い）は、焼きなまし後の期待手数と相関がある。4 候補から選ぶだけでは指標は約 15.0 → 13.3 だが、山登りで直接下げると 12.6 前後まで下がり、焼きなましの回数を固定した模擬で期待手数が gsel よりさらに約 0.5% 下がった。
- climb_greedy: choose_blocks と同じ近傍（ブロックの窓とハンドル窓の交換、2 ブロックの窓の交換。変わったブロックは best_y で Y_b を選び直す）を 3000 回試し、greedy_pair_obj が増えず、choose_blocks の目的（整合する対の割合の対数和）の低下が開始時から kSlack = 0.5 以内なら受理する。
- greedy_pair_obj の高速化: 全 32640 組をハンドル窓での違いの数で数え上げソートして持ち（sort_pairs。ハンドル窓が変わったときだけ作り直す）、違いの少ない組から整合を判定しながら貪欲に取る。現在の値を超えることが確定したら打ち切る。
- 時間: G の段（4 候補 + 3000 回）は手元で約 0.25 秒で、その分焼きなましの時間が減る（焼きなましの打ち切り時刻は同じ）。
- 実験用: 環境変数 `GSEL_K`（候補の数、既定 4）、`GOPT_STEPS`（山登りの回数、既定 3000）、`GOPT_SLACK`（既定 0.5）。`-DSIM_HARNESS` でコンパイルすると `SIM_SEQS=n` で乱数の注文列 n 本を模擬して 1 注文の平均手数を出して終わる（ceil-probe と同じ）。
- stderr: `gsel_obj` / `gsel_pick`（gsel と同じ）、`gopt_obj`（山登り後の指標）、`gopt_acc`（受理した回数）、`gopt_blockobj_drop`（choose_blocks の目的の低下）、`gopt_end_sec`（G の段の終了時刻）。
