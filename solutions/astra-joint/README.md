# astra-joint

改良元: `solutions/astra-search4`

汎用窓の割り当てと、紙を共有する70商品対を同じ探索状態にする。従来は窓の候補を試すごとに近い全商品対を評価し、貪欲マッチングで70対を選び直していた。本方式は現在の70対だけを差分評価し、互換性を失った最大2対を未使用の商品も使う短い交代路で修復する。

- 窓の交換・比較組の変更・色反転は、現在の対が作る制約と費用だけを更新する。
- 対の端点の差し替え、2対の組み替えも独立した近傍として探索する。対の集合は固定しない。
- 定期的に全商品対を評価し、貪欲法と長さ3の増大路で作った別のマッチングも調べる。
- 最良状態の70対を後段の設計焼きなましの初期対として渡す。窓の変更後に古い貪欲法で対を捨て直すことはしない。

目的関数の辺費用1800/5/144、距離上限26、設計後半と注文処理、時間配分、CLOCK_SCALEは改良元と同じ。初期状態からこの共同探索だけを使い、旧割り当て探索によるウォームスタートはしない。

主なコンパイル定数は `JOINT_MAP_PERCENT`（窓近傍の割合、既定70）と `JOINT_REFRESH`（全辺を見直す試行間隔、既定2048）。`MAP_ITERS`/`GOPT_STEPS` は共同探索の試行数で、旧解法の1試行とは仕事量が異なる。固定回数実験に加えて、実時間を揃えた比較が必要。

stderrの `joint_window_trials`/`joint_window_accepts` は窓変更の試行・受理数、`joint_pair_trials`/`joint_pair_accepts` は対変更の試行・受理数、`joint_repairs` は壊れた対を修復して受理した窓変更数、`joint_refreshes` は全辺再評価数、`joint_matched` は返した対数。

## ガイド付き近傍

現在の70対について窓を1つ外した制約の推移閉包を求め、ハンドル窓との全交換方向と比較組の全方向から、壊す対が2以下の方向だけを列挙する。状態が変わるまでは結果を再利用する。対近傍は直近の全辺再評価で互換だった辺から80%、全近傍辺から20%を引く。局所の修復では足りない候補だけ全辺を見直し、ほかの対を通る交代路も許す。初期の対数が70未満の間も全辺修復を使う。`JOINT_GOOD_PERCENT`で互換辺候補の比率を変えられる。

## 保存している版

- `initial.cpp`: 最初の原型。窓の方向・商品対を無作為に選び、壊れた対の端点だけから修復する。全辺再構築は2048試行ごとだけ。
- `main.cpp`: 第2版。全方向の互換性ガイド、互換辺候補の再利用、局所修復が届かないときの全辺修復を加える。
- `joint-search.inc`: 第2版の割り当て探索部分。提出用の `main.cpp` 内には同じ内容が埋め込まれているため、コンパイル時にこのファイルを含める必要はない。

## 診断

`design_probe.cpp` は注文を処理せず、窓割り当てだけを実行する研究用プログラム。`curve.py` は探索回数別の代理目的値を比較し、`profile.py` は全辺再構築・ガイド・局所修復の時間内訳を測る。結果と再現手順は `EXPERIMENTS.md` に記録する。これらはコンテストスコアの対比較を代替しない。
