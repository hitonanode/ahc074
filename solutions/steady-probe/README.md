# steady-probe: 慣れた状態と、設計の模型・注文処理の評価の突き合わせ

改良元: なし（解法ではなく、as6-cap38p0 の出力の分析と模擬の道具）。

- state_stats.py: 注文の始めの重なりを、最初の注文と慣れた状態（注文 200 以降）で比べる。列の外にある紙の数、各列の一番上がハンドルで要求の多数派の色か、手の役割（持ち上げ・掘り・汎用紙・前の紙・列の外の紙・ほかの列）。
- column_shape.py: 列の中身を、設計の模型の仮定（上 2 枚に両方の色、対の紙が上）と比べる。
- mismatch_rate.py: ハンドルごとに、要求の少数派の割合 m と、注文の始めに D の穴に見える色の不一致の率を、設計の模型（前の色が残る: 2m(1−m)）と比べる。
- dig_check.py: 列の深さごとに、D を遮る紙の数と、持ち上げ前に動かした紙の数。
- regress.py: 注文ごとの手数を、D を遮る紙・注文の始めの不一致・穴の数・対かどうかで回帰する（numpy が要るので /home/sato/ahc074/.venv/bin/python で動かす）。
- compute.cpp, run_compute.py: as6-cap38p0 を、回数を固定した模擬（-DSIM_HARNESS、SIM_SEQS 本の乱数の注文列）で動かす。補助表の時間の打ち切りを外してあるので、設計の回数を増やしても補助紙が消えない。設計の回数を何倍にすると手数がどれだけ減るかを測る。

列の番号は、紙の一番深い不透明なハンドルで決める（対の紙は違う窓のハンドルにも穴があるので、不透明なハンドルの数では決まらない）。汎用紙は窓 63 が穴の紙、キャップは窓 63 だけが不透明な紙として見分ける。
