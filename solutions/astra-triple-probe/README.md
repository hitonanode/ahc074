# 比較器と 3 商品共有の構造診断

改良元: なし（提出用解法ではなく、入力の商品一覧だけを読む分析用プログラム）。

`probe.cpp` は 6〜8 枚の比較器を汎用窓へ割り当て、3 商品が 1 枚の紙を共有できる組を数える。
3 商品のうち一つでも色が異なる窓をすべて穴にし、各商品の要求が作る有向グラフが
3 個とも非巡回であることを要求する。単なる 3 商品間の各対の互換性では判定しない。
さらにハンドル窓に少なくとも 1 つ、3 商品が一致する窓があることを要求する。

比較組は全組を少なくとも 1 回使い、余った窓の比較組と色は固定 seed の乱数で決める。
入力の注文列は読まず、スコアや提出性能を測る道具ではない。

`TRIPLE_STEPS` を正の整数にすると、近い 2048 個の三つ組を使って窓割当を学習する。
各商品の制約で有向閉路に含まれる頂点数に滑らかな罰則を置き、重ならない三つ組を
優先する焼きなましを行う。汎用窓とハンドル窓の交換、極性反転、汎用窓同士の交換、
比較辺の付け替えを使う。全比較辺が少なくとも一つ残るよう制約する。
`TRIPLE_SUM_OBJECTIVE=1` は非重複性を無視する対照実験で、通常は指定しない。

コンパイル例: `g++ -std=c++23 -O2 probe.cpp -o probe`

使用例: `./probe 8 36 4 tools/in/0000.txt`

引数は比較紙数、汎用窓数、同じ入力で試す割り当て数、入力パス（複数可）。
出力は JSON Lines 形式。近い共有組は、64 窓全体での穴の和集合が 40 以下と定義する。
`greedy_disjoint` は穴の数が少ない順に取った重ならない 3 商品組の数で、
最適な集合詰め込みの解ではない。

汎用手数は、一様な開始順列を 128 個サンプルし、それぞれについて合法な最短手数を
求めた平均である。2 商品の専用紙だけで必要な紙数削減を満たす構成と、三つ組を先に
選んで残りを対で埋める構成の両方について、穴数と汎用手数を出力する。

`model.py` はこの JSON Lines を読み、同じ比較紙数・汎用窓数・窓割当の二つの構成を
連続変数の列配属模型で比較する。依存ライブラリは NumPy と SciPy。
順位優先 0.85、ハンドル穴係数 0.40 は基準解法と合わせるが、列人数を実数として
最適化し、色・個別ハンドル可否・フィラー・実際の注文列を省略する。実スコアでも
厳密な下界でもない。紙数削減が足りない構成は比較を拒否する。

`constrained.cpp` は保存済みの基準解法の初期設計から、二つの 2 商品紙を
3 商品紙と 1 商品紙へ置き換える診断を行う。残り 68 対、全商品の被覆、列位置、
ハンドルを保ち、6 枚の汎用紙の模様だけを変更する。602 種類の非定数三値印刷から
窓ごとの規則を選び、720 順列に対する表示不一致数を使って成立する構成を探す。
最終的な互換性と汎用手数は全 720 順列で厳密に検査する。
`baseline-design-0000.json` は注文列を含まない解析の出発点である。
`CONSTRAINED_FIVE=1` なら、既存の対と単体を三つ組にし、別の対を二つの単体へ
分ける 5 目標交換も候補へ加える。`CONSTRAINED_NEAR` の既定値 1 は表示が近い
印刷規則を優先し、0 は一様な規則選択の再現用。`CONSTRAINED_TEMP` の既定値は 2.0。
各候補の探索終了時までに全条件が成立しなければ、代理費用の改善例として採用しない。

実験結果、再現コマンド、模型の限界は `REPORT.md` に分離して記録する。
