# astra-03-02-pair-final

改良元: solutions/astra-03-01-handles-verified

## 改良元との差分

- 三角形の制御構造: バンク j の紙が自分の制御窓 j に加えて番号の小さい制御窓にも色を持ち、番号の大きい制御窓は穴にする。取り出す順序を保ったまま、1 枚で複数の制御窓を直せる。
- 主紙と制御用補助紙: 前面の主紙に加え、基底データ層より下に補助紙を 1 枚差し込み、そのデータ部分は基底層に隠したまま制御窓の色だけを使う。
- 設計の評価: 残った 0・1 の個数から基底層の修正手数を見積もる表 `F[z][o]` を使い、紙を足したときの期待修正手数の減少で選ぶ。
- 注文時に背景紙の位置と単独紙の移動を合わせて選び、取り出した紙の戻し位置も調整する。

## パラメータ

- H=24（データ窓 40）（main の実行引数 `H seed Q prior accessUnit cw` の既定値。seed=1 は設計中の乱数の初期値）。

## 移植について（全 astra-03-* 共通）

外部の agent（astra-03。この repo の文脈を共有しない）が作った検証用シミュレータ（商品と注文を内部の乱数で作り、設計・操作・検査を自前で行う）を、提出できる reactive 形式に機械的に移植したもの。アルゴリズムは元のまま。元のソースと報告は main checkout の other_agents/astra-03.md, astra-03.zip（pair_final.cpp）。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた（Clang でもビルドできるように）。
- 商品 A を標準入力から読む（文字 j を bit j に）。注文 a を標準入力から読み、`-1` か入力の終わりで終了する。
- 設計の直後に 192 枚の模様を出力する（内部では窓ごとに色を反転して正規化しているので、元の色に戻して出す）。初期の重ね順は内部の ord と同じ紙 0〜191。
- 注文ごとに、採用した操作列（内部の act の記録。仮実行を巻き戻した分は除く）を出力して flush する。
- 実行引数の既定値を報告時の設定（下記）にした。テスターは引数なしで起動する。最後の統計の 1 行（`H ... avg ... design_s ... total_s ... components ...`）は stdout ではなく stderr に出す。
- 内部の assert（操作する紙が見えていること、表示が目標に一致すること、1 注文 384 手以下）はそのまま有効。時間の打ち切りはなく、報告時の手元計測で全処理 約 0.81 秒。
