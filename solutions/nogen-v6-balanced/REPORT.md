# v6移植と時間予算の再配分（milestone 2）

## 方針と実装

ベースは `solutions/ng-product-v6-fast`。背景6商品の所有者を潜在変数として比較窓と同時に探索する設計を維持した。nogen-map9kから、背景ヘルパー計画を通常計画と共通の候補集合・後処理・計画キャッシュへ渡す処理、広い予備ヘルパー候補、安定radix sort、DesignStore v2、探索の時計上限と軽量注文を移植した。

単独ヘルパー3、ペア予備16、深さ3、実計画4。元v6の独立後処理と単独6・実計画6をそのまま高速化したものではなく、候補予算も再配分している。背景を主紙とする追加評価はV5_ALTERNATE=0。最終構成では編集済みの拡張候補にもキャッシュを使って排出処理まで行い、候補幅3・追加計画1とした。

窓63については承認済みの規約に戻し、異色の2所有者が共有する紙は白印刷を許す。窓0–62の実印刷は全所有者との色一致を検査し、窓63はキャップの形・色とペア規約を別に検査する。キャップ以外191枚には必ず実商品の所有者を持たせ、違反時はLOCAL_BENCHでassertする。

## 測定から決めた時間配分

大きな構造の追加より先に、保存設計500件×注文2列で移植版を評価した。旧v5で得た「ヘルパー後処理が時間の大半」というモデルをv6でも実測で確認し、浮いた時間を設計へ回した。元v6の要求処理を復元したreference版は、保存出力と500/500件でstdout全体が一致した。移植版の紙も元v6と500/500件一致した。比較条件と中間候補は [移植レポート](../nogen-v6-port/REPORT.md) に記載。

潜在所有者の窓探索300k+60k→450k+90kは、通常500件で−0.084±0.054%にとどまった。列探索2M→12Mとfiller climb 30k→100kは−0.414±0.045%改善した。穴費用のモデル改善は0.0308手、背景窓を増やした場合の背景費用改善は0.0040手。列へ時間を優先した。

最後に列11M・後処理幅3と列8M・幅4を比較した。幅4は500件でjudge 1.714658秒、同時SOTAの1.1044倍となり、幅3に対する有意な得点改善もなかったため打ち切り。列12M・既定後処理と列11M・強化後処理を2000件まで延長した。

最終予算は潜在所有者窓300,000反復＋60,000 climb、列11,000,000反復、filler climb100,000、再割当4回。全stageにscaled clockを使い、窓0.85秒、列1.15秒、climb1.20秒まで。注文は1.70秒から軽量処理に切り替える。LOCAL_BENCHでは注文の切り替えだけ無効にする。

## 監査と再現性

- 全2000件でWA 0、E 0、所有色違反0、無所有商品紙0、キャップ規約違反0、操作ラベル不整合0。
- 各ケースの非cap商品紙191枚を監査。窓63の異色所有者ペアは平均34.691枚（21–50枚）で、すべて許可された白印刷だった。
- 潜在所有者設計の構築成功は2000/2000。元v6同様、seed1029で所有者への射影後5窓を修復し、出力前監査は通過した。
- 全件で窓300,000＋climb60,000、列11,000,832、filler climb100,000を完了した。列の端数832は256反復ごとの既存停止検査によるもの。今回の比較に時計による探索量の差はなかった。
- `20261106-105141_nogen-v6-lightcheck`：最終保存設計seed0–49×2注文列、全1024注文を軽量処理に固定。100実行すべてWA/E/所有色違反/キャップ違反/ラベル不整合0。req_sec平均0.024451、最大0.030160秒。軽量処理の得点は全注文強制時+6.801±0.054%で、通常の評価得点とは分ける。
- 同時の `20261106-104736_nogen-v6-balanced` は、保存設計を再読込した通常注文のstdoutが最終runと50/50件一致。DesignStore v2は背景列・重複所有者を復元できた。
- g++ / clang++、LOCAL_BENCHあり・なしの4構成を C++23 -O2 -Wall -Wextra -Werror でビルド成功。Clangが指摘したv6由来ループの字下げだけ整形した。評価済みsrcと最終srcは空白以外一致し、処理・定数は変更していない。ビルドは共有flock下で行い、/tmpの検証バイナリは削除済み。
- 模型最大のseed465はhelper_end1.18712、req0.557997、end1.76419。模型では2.006974秒だが、LOCAL_BENCHは軽量化を無効にしている。提出版は1.70秒から軽量化する。実ジャッジでの最大時間を保証する測定ではない。

## 残る差と次のモデル

SOTAとの差は **0.119040操作/注文**。ラベル差（balanced−SOTA）はfix +0.202526、repair +0.179803、help +0.062428、hdig +0.042962、fret +0.023374、dig −0.122618、fill −0.142755、lift −0.049855、gen −0.049469。ラベルは操作の生成場所なので、共通後処理でfixがrepairへ変わった分も含み、各差をそのまま構造の損失と見なせない。

列費用2.819707、ハンドル穴費用4.150389、背景費用1.343424。元v6の2.822114 / 4.181556 / 1.344172と比べ、今回の設計利得は主にハンドル穴費用。要求の平均は単独主紙9.639158手、ペア主紙10.633013手、背景所有者10.781952手。ただし商品分類は設計により変わり、同一商品の対照比較ではない。

次は保存したv6設計を使い、実列費用・ハンドル費用によるマッチングと、穿孔後の再割当の模型利得を先に測る。背景窓の代理ペア費用と完成した列費用のずれを重点に置く。旧v5のcap探索模型には異色ペア禁止の影響があるため、その推定値を今回へ流用しない。キャップ窓・ペア・所有者・背景窓・列の一体設計、背景ヘルパーをjoint DP自体へ組み込む変更は今後の作業であり、この版では実装していない。
