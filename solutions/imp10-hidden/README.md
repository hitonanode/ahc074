# imp10-hidden

改良元: solutions/imp-lean

solutions/gpt6pro-10-01-filler-chain の「穴埋め紙は上から順に回収できれば残してよい」を移植した。設計は imp-lean のまま。

- fillers_reachable（注文の終わりの状態で、列の外の紙 = 穴埋め紙を次の注文で戻せるかの判定）: imp-lean は「持ち上げた紙を除いて、穴埋め紙がそれぞれ見えている」ことを求めていた。これを「見えている穴埋め紙を 1 枚ずつ除いていって全部除ける」に緩めた（穴埋め紙どうしが隠し合ってよい）。紙を除いてもほかの紙が隠れることはないので、毎回見えている紙（一番上のもの）を除けばよい。
- この判定は、計画の候補の選択（process、補助紙の計画）と後処理（post_optimize。編集した操作列の結果を canonicalize してから判定）の両方で使う。後処理で削れる手が増える。
- 穴埋め紙を列に返すところは、すべて見えている紙から返す（return_visible_fillers: リストの後ろから見て最初の見えている紙。隠れた紙がなければ imp-lean と同じ順）: run_plan の古い穴埋め紙を全部返す選択肢（fret_mode 1、ret_mode 3 の中も）、補助紙の計画の最初（try_helpers）、軽量処理と最後の手段の計画（PlanOpt{}）。run_joint の「選ばれなかった古い穴埋め紙のうち見えている紙を先に返す」も、見えている紙がなくなるまで繰り返す。
- refill_or_return（古い穴埋め紙を新しい穴埋めに使う・そのまま残す・戻す）は、重なりの上の紙から順に処理し、害のない紙は見えていなくても残してよい（10 と同じ）。
- 安全網: 軽量処理（1.80 秒から）と、どの計画も通らないときの最後の手段の計画は、見えない紙を動かさないかを確かめていなかった。隠れた穴埋め紙があると不正な出力（WA）になりうるので、可視性と 2K 手以内を確かめ、通らなければ、軽量処理は通常の探索に回し、最後の手段は何も動かさない（表示は誤るが出力は正しい）。

stderr: `unsafe_plans`（上の安全網で計画を捨てた回数。通常 0）。
