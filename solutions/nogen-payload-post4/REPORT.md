# 今回の統合と検証

改良元の系列はng-product-v6-fast → nogen-v6-balanced → nogen-perf-reuse。汎用紙は追加していない。cap以外の191枚すべてに商品所有者を持たせ、0–62窓の所有色一致と、63窓の承認済みcap規約を実際の印刷に対して検査する。

今回採用した主な変更:

- Feas等が使わない距離表を作らず、必要な距離表は番号置換で構築する。背景の距離順・正解状態を再利用する。
- 背景の1段先読みを通常計画と背景補助紙の同距離選択へ使う。単独補助紙は背景距離が同点でも取っ手の節約を評価する。
- 無効な代替主紙への仮想需要を除き、実際に注文処理が使う主紙だけで列の将来費用を作る。終了費用キャッシュ1024枠・所有者65536枠・後処理終了状態512枠を使う。
- 通常後処理の候補数と中立書換の巡数を増やし、列探索から時間を配分する。穿孔と穿孔後の再割当はperf-reuseから維持する。
- 背景に挟む補助紙の保持・被覆確率に比較窓の色一致を加え、実際のgen_harmと費用模型をそろえる。この修正だけの設計固定500件×2列は−0.022728 ± 0.002771%、313/1/186。

構造模型と途中の比較は [nogen-request-cache/REPORT.md](../nogen-request-cache/REPORT.md) にまとめた。個別の完全一致高速化を統合しても通常比較で速くならない例があったため、最終版は通常の個別正規化に戻した。

## 正しさ・時間制限

- 全2000ケースでWA・表示誤り・操作ラベル異常・所有色違反・cap規約違反・無所有紙が0。各ケース191枚の商品紙、256商品の補完証明を確認した。
- 窓探索300k＋climb60k、列探索9,500,672回、列climb100kを全件完走。保存設計2000件、評価時と提出用のmain.cppのハッシュ一致。
- g++/clang++の双方で、LOCAL_BENCH・CLOCK_SCALE=1.1あり/なしの4通りをC++23・O2・Wall・Wextra・Werrorでビルドした。生成物は/tmpで削除した。
- 提出版はscaled_sinceを通す時計で設計探索を打ち切り、注文処理は1.70秒から軽量化する。LOCAL_BENCHは軽量化を無効にするため、表の時間分布には軽量化の短縮を含めない。
- `20261106-142858_nogen-payload-transition` は最終col95保存設計500件×2列で、前半512注文を通常、後半512注文を軽量処理へ強制した。1000列のstderrとorder_scoresを検査し、各列light_requests=512、所有色・cap・表示・操作ラベルの違反とWAが0だった。先行する10M設計の `20261106-141955_nogen-payload-transition` も1000列で同じ検査を通った。

## 今後の構造変更

実列・取っ手費用を含むペア割当模型は、割り当てた商品だけの取り出し費用が良くても、他商品からの補助紙利用と定常状態が変わり、独立再生では悪化した。完成後の窓交換模型も、ペアを固定すると可行な候補がほぼ残らない。次は窓とペアを同時に動かし、全商品の補助紙価値を含めた模型を独立注文列で検証する。

背景補助紙を置く前に区間DPを走らせる小変更は、+0.000687 ± 0.000926手／注文と未確定で時間が増えた。補助紙集合と背景内の挿入位置を一体で選ぶ構造が必要。模型・棄却案・各部の固定設計比較は [今回の全体記録](../nogen-request-cache/REPORT.md) と、そのリンク先に残した。

旧ベストから0.3%以上改善し、時間条件内・監査済みとなったため、ここでマージの区切りとする。trial_log.md、STATE.md、既存解法、scriptsは変更せず、コミットも行っていない。
