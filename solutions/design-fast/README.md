# 窓の割り当てを同じ結果のまま速くする（design-fast）

改良元: solutions/climb4-fast

## 改良元からの差分

設計の段のうち、窓の割り当て（assign_windows と、そこから呼ぶ PosetSums・WindowRelations・WindowPairs・evaluate_move・各スクリーン・matching_cost）だけを、出力を変えずに速くした。設計の焼きなまし以降（filler climb、再割り当て、穴あけ、補助紙の表）と注文処理には手を入れていない（そちらは solutions/anneal-fast が別に速くしている）。

- **PosetSums の表を小さくした。** 6 枚の汎用紙の半順序ごとの平均手数の和（both_of）は、関係とその転置で同じ値になる。関係を 30 ビットに詰めた形（WindowRelations の形）の小さい方を鍵にすると鍵は 65012 個になり、これを変位ハッシュ（CHD: 鍵のバケットに置いた変位で値の位置が決まる）で引く。表は 32 KB と 256 KB で、鍵の比較も探索の繰り返しもない（climb4-fast は 64 ビットの鍵 2^18 個と値の配列 2 本で 3 MB、引くたびに 2 本の配列を読む）。表を作るときは、互いに転置の関係にある 2 つの類（双対）の片方だけを 720 通りに番号を付け替えて鍵を作り、値は 2 つの類の和にする（双対の表 kPosetDual はオフラインで計算して埋め込んだ）。値は同じ類の同じ和で、`-DPOSET_VERIFY` で 130023 個の関係すべてについて climb4-fast の表と一致することを確かめた。
- **関係のコストのキャッシュ（2 MB、3 分の 1 が外れていた）をやめた。** 閉包の計算はメモリを使わずに閉路の有無を決めるので、表を引くのは閉路のない関係だけになる。反転・交換のスクリーンは閉路の有無だけを見る。
- **閉路の証拠。** 組ごとに、その組の関係に含まれる 3 枚の閉路の弧の集合（証拠）を持つ。動かした後の関係が証拠を含めば閉路があるので、閉包を計算しない（関係が変わる組のうち約半分）。証拠はどんな閉路でもよいので、古くなっても判定は正しく、計算を省けるかどうかが変わるだけ。閉包を計算して閉路が見つかった組は、今の関係と新しい関係の両方に含まれる 3 枚の閉路を新しい証拠にする。
- **閉包の計算と表の参照を 2 段に分け、閉包は AVX2 で 4 組ずつ計算する。** 閉路の有無で分岐しないので並列に進む。4 組の閉包（WindowRelations::closure4）は、各ピボットで行の掛け算の代わりにバイトのマスクを使う同じ計算で、prepare_cross と make_transfer_options の閉包にも使う。
- **matching_cost。** 並べ替えの要素を「鍵 << 32 | 組の番号 << 16 | 2 つの注文の番号」の 64 ビットにした。並びは climb4-fast の安定な並べ替え（同じ鍵は組の順）と同じで、貪欲法は要素から注文を読み、分岐なしで進む。
- **swap_losses（prepare_windows の表）。** 窓 a を外すと弧を失う組の、外した後の閉包を計算しない（選ばれた組は閉路がないので、失った弧の上の紙の別の後続が下の紙に届くかを、今の閉包から調べればよい）。辺ごとの禁止の表（group_forbidden）は 4 組ずつ分岐なしで作る。
- **細かい変更。** 窓の番号の剰余を定数で割る（g = 38, 32, 28 のとき）、焼きなましの温度を使うときだけ計算する、窓の位置の表（order の中の探索の代わり）、k 番目の立っているビットを pdep で選ぶ、make_transfer_options の対象の組を分岐なしで集める。

どれも、乱数の列、候補の順、浮動小数点の計算は変えていない（選ぶ組と並びが同じになる計算だけを置き換えた）。stdout は climb4-fast とバイト単位で同じで、窓の割り当てが stderr に出す指標（search_* など）も同じ値になる。

## スイッチ

- `DESIGN_PROFILE`（ソースのマクロ。既定 0）: 1 以上で、窓の割り当ての各部（準備、提案、各スクリーン、評価、マッチング、受理など）の時間（rdtsc のサイクル数、`dprof_<部分>_mcyc`）と回数（`dprof_<部分>_calls`）を、窓の割り当ての終わりに stderr に出す。3 以上で、評価とマッチングの内訳と組の数（`dpc_*`: 関係が変わった組、証拠で省いた組、閉包を計算した組、閉路のない組、有効な組など）も出す。計測自体が時間を使うので、速さの比較には使わない。
- `POSET_VERIFY`（テスト用）: 窓の割り当ての始めに、PosetSums の新しい表を climb4-fast の表とすべての関係で比べ、結果（`poset_verify_*`）を stderr に出して終わる（入力は何でもよい）。
