# astra-search4

改良元: solutions/imp-combo

`assign_windows` の事前除外・停滞脱出・候補計算を変更する。目的関数、距離上限26、時間区切り0.50 / 0.61秒、他の段、CLOCK_SCALEは同じ。

- 選択中の70対のうち、互換でなくする対が**3対以上**の手を事前除外する（改良元は4対以上）。組移動の移動先を作るビット並列カウンタも、この条件に合わせる。
- 受理が途切れたときに観測済みの最小費用候補へ進むまでの試行数を、焼きなまし**1024**、最後の区間**2048**にする（改良元は2048 / 4096）。逆手禁止は4受理分、温度は0.05→0.00125のまま。
- 事前判定用の色のビット集合は、マッチングに残る商品対の位置を保ち、入れ替わった対だけ更新する。同じ比較器の組では元の禁止方向を共有し、窓の削除で最後の辺が消える対だけ閉包を再計算する。
- 組移動は先に全方向の損失数を数える。全方向が除外されたら途中終了し、残り1方向なら順位を計算しない。複数残る場合は、その方向だけ汎用層の費用増加を正確に計算して優先する。既に選別済みの組移動への重複した事前判定を省く。
- 近傍の除外結果と目的値を1本の世代表で管理する。通常の36/28窓では、乱数の剰余を同じ値になる定数除算で計算する。

追加のstderr指標:

- `screen_color_pairs`: 色のビット集合で追加・削除した商品対の延べ数。
- `screen_refreshes`: 現在のマッチングに合わせて事前判定用の表を更新した回数。
- `transfer_empty` / `transfer_single` / `transfer_many`: 移動先が0 / 1 / 複数となった組移動候補表の数。

計測の手順・結果・採否は [REPORT.md](REPORT.md) を参照。
