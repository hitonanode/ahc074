# chatgpt-rescue-learned

改良元: `solutions/chatgpt-rescue-layer`。

## 救済窓と色を、現在の入力に合わせる

6枚の比較紙と比較窓35個の割り当てを初期化した後、その割り当てを固定して救済紙の模様を探索する。
救済紙が色を持つ比較窓の数は8個のまま、色を持つ窓と穴の窓の交換、色を持つ窓の色反転を焼きなましで試す。
初期の支持窓・色は改良元と同じ。最良の模様を保持し、探索終了後に10080状態の操作グラフを構築する。

目的関数は、全64窓の Hamming 距離が26以下の商品対を静的費用順に並べ、共有可能な対から商品が重複しない72対を貪欲に選んだ平均費用。
1対の静的費用は `0.65 * 取っ手の相違数 + 0.28 * 汎用窓の相違数 + 0.04 * 全窓の相違数`。
72対に足りないときは不足1対につき100の罰を加える。共有可能な辺の総数だけでは、同じ商品を中心とした辺の増加を過大評価するため、matchingを目的にする。
この費用と貪欲matchingは設計用の近似であり、実際の操作数・最適matchingを求めているわけではない。

## 共有可能性は7枚の貪欲法で厳密に判定する

上側の救済紙の色を固定すると、有効なのは比較紙6枚と救済紙1枚の7枚だけ。
まだ覆っていない要求窓に対して、不透明な場所がすべて要求色と一致する紙を選び、その紙が覆う窓を要求から除く。
全要求を覆えれば表示可能。残る要求があるのに選べる紙がなければ不可能。

この存在判定は厳密である。有効な順序があれば、上の条件を満たす紙をその順序の先頭へ移しても、正しい色を先に覆うだけなので表示を壊さない。
逆に有効な順序のうち未被覆窓に触れる最初の紙は必ず選べる。したがって固定順で選んでも完全性を保つ。
救済紙の上側の色2通りを、それぞれ元の要求から試す。救済専用窓を要求する場合はその色に限定する。
商品対の双方の要求でこの判定を行う。操作手順は改良元と同じ10080状態グラフ上の逆BFSで求める。

## 設計時の汎用距離を厳密に測る実験オプション

既定の紙設計では、改良元と同じ `0.35 * log2(10080 / goal数)` による費用近似を用いる。
`RESCUE_EXACT_COST=1` を指定すると、互換性がある各商品対について逆BFS表を作り、比較紙6枚が両救済紙より上にある1440状態（720順列×救済色2通り）からの最短距離の平均を求め、商品の両方向を平均する。
この距離平均は指定した初期状態分布とcanonicalグラフ内で厳密だが、実際の注文中の状態分布の平均費用ではない。

このオプションは初期化時間とメモリを多く使う。初期化期限だけ1.12秒から1.50秒へ延ばし、焼きなまし1.28秒・登山1.34秒の期限は維持する。
期限を過ぎて初期化が終わった場合、焼きなましは最低限の0.005秒だけとなる。時間超過・初期化失敗を隠す切り替えは行わない。
既定値は0であり、通常版とは分けて評価する。

## パラメータと診断値

- 救済模様の探索は0.14倍率補正秒、最大400候補。温度は0.03から0.003まで下げる。
- `RESCUE_LEARN_STEPS`: 正なら時間の代わりに指定候補数だけ探索、負なら模様の探索を無効化、0または未指定は上の時間制限。
- `RESCUE_SUPPORT`、`RESCUE_Y`: 探索の初期値。未指定時は支持窓 `0x418c01120`、色 `0x365f993b3`。支持窓数は初期値のまま維持する。
- `RESCUE_EXACT_COST`: 上記の初期状態分布での距離平均を紙設計に使う実験用スイッチ。既定0。
- `rescue_learn_before`、`rescue_learn_after`: 探索前と最良の静的目的関数。実スコアではない。
- `rescue_learn_before_matching`、`rescue_learn_after_matching`: 選べた対の数。
- `rescue_learn_trials`、`rescue_learn_accepted`、`rescue_learn_checks`: 候補数、受理数、商品対の共有可能性の検査回数。
- `rescue_learn_end_sec`: 模様の探索終了時刻。
- `rescue_exact_cost`: 厳密距離の実験設定を使ったか。
- その他の診断・時間倍率・通常の紙設計と注文処理は改良元と同じ。

## 独立検査

`verify.cpp` は提出用 `main.cpp` を直接読み込む。5種類の支持窓について7枚貪欲法をbitsetの全状態判定と照合し、汎用層の手順を可視性込みで再生する。
実入力での照合も必要なら `-DGREEDY_VERIFY` でビルドすると、選んだ模様について距離26以下の全商品対で両判定の一致を確認する。検査処理の時間が加わるため評価用の通常ビルドとは分ける。

```sh
g++ -std=c++23 -O2 solutions/chatgpt-rescue-learned/verify.cpp -o /tmp/rescue-learned-verify
/tmp/rescue-learned-verify
```

評価結果は `trial_log.md` と[検証レポート](../../docs/chatgpt-multiroute-rescue-study.md)を参照。
