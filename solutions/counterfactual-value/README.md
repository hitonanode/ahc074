# 別の操作を選んだ後の費用を直接比べる

改良元: solutions/tight-thirty-eight。特徴量はsolutions/state-learning。

現方策が通常訪れる状態だけで学ぶと、列の深さの係数が安定しない。そこで同じ注文に対する別の合法な計画を2個まで保存し、元の計画と同じ将来注文で処理して、その後の費用差を測る。候補は現在の費用の最良から1.5手以内とし、後処理後に順序が異なるものを使う。

独立な8系列・各16注文先までの手数に、その終点の元の状態評価を加える。特徴差と費用差を回帰し、紙の設計と注文を変えた未使用入力で方策を比較する。学習の紙設計は保存窓割当から列共有2000万提案・山登り65000提案・再割当4回・補助穴設計。隠された実注文は読まず、時計はCLOCK_SCALE倍。main.cpp単独の方策は比較元と同じで、trace_valueは研究用の記録だけ。
