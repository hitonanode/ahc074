# mix-ap

改良元: solutions/mix-pt

焼きなましの費用にも、filler_climb の穴埋めの proxy（深い列の紙が浅い列の目標の穴埋め紙としてどれだけ使えるか）を入れた。注文ごとの操作と、焼きなまし後の山登りは mix-pt と同じ。

## 変更点

- filler_climb の proxy（持続の重み付きのもの）は、1 回の入れ替えごとに全目標を見るので、焼きなましには重すぎる。そこで (単位 x, 列 l) ごとに線形化した値 V[x][l] を作り、焼きなましの単位の移動・交換の費用に −0.5 × V を足す。
  - V[x][l] = x を列 l に置いたときの x の目標の proxy（ほかの単位は今の位置のまま）+ x の紙が列 l の穴埋め紙として浅い列の目標に与える proxy ÷ 列 l の大きさ（x を含む）。
  - V は焼きなましの進捗 50% から、4 回（進捗 50%, 62.5%, 75%, 87.5%）、そのときの割り当てから計算し直し、その間は固定する（持続の限界費用の重みと同じやり方）。1 回 約 7 ms。
  - 組み替え（対の相手の変更）とハンドルの入れ替えでは、V の変化を見ない。
- 狙いは、山登りの前から proxy の高い割り当てにしておくこと。

## パラメータと指標

- 環境変数 `AP_W`（既定 0.5）: V の重み（0 で mix-pt と同じ）。`AP_START`（既定 0.5）: V を入れ始める焼きなましの進捗。`AP_REFRESH`（既定 4）: V を計算し直す回数。proxy の閾値は filler_climb と同じ `CLIMB_T`（既定 3）。
- stderr の `ap_refreshes`: V を計算した回数。`ap_sec`: その計算にかかった時間の合計（秒）。
