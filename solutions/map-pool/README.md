# 窓の割り当ての手の評価を、鍵の小さい対の池に限る（map-pool、試作）

改良元: solutions/climb4-fast

## 改良元からの差分

- 窓の割り当て（assign_windows）の焼きなましと山登りで、提案した手の費用（71 組の貪欲マッチングの費用）を、全部の近い対ではなく「今の状態で鍵の小さい対の池」（`MAP_POOL` 組、既定 768。0 なら改良元と同じ）だけで計算する。
- 受理された手だけを全部の対で計算し直し、その厳密な費用を今の費用にする。池は受理のたびに、全部の対の並べ替えの結果から作り直す。
- 目的: 1 回の評価を安くして、同じ時間で窓の割り当ての反復を増やす。
  - 計測によると、反復 2 倍で設計 −0.154%、8 倍で gobj −0.115（約 −0.35% の見込み）。
- 注意: 使える（閉路のない）対は全部で約 160 組しかない。そのため、池は今使える対のほぼ全部になり、手によって新しく使えるようになる対は評価に入らない（近似）。
- stderr の指標:
  - `pool_evals`: 池での評価の回数。
  - `pool_rebuilds`: 池を作り直した回数。
  - `pool_exact_lower` / `pool_exact_higher`: 受理した手の厳密な費用が、池での費用より低かった / 高かった回数。
