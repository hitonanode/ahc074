# 比較制約の費用キャッシュの容量を調べる

改良元: solutions/tight-thirty-eight。

窓割当で使う比較制約の費用キャッシュを、2の18乗要素から16/14/20乗へ変え、24並列で同じ仕事の時間を測る。キーが一致した場合だけ保存値を返し、衝突時は正確に再計算するため、設計結果を変えない。

公開入力1632〜1695、64件で窓割当10万回・山登り25000回を各容量2回、順をずらして測定する。割当後の全バーコード・窓番号・比較組・色のハッシュ一致を検査する。研究ではREL_CACHE_RESEARCHで容量を切り替え、提出用main.cppの既定はまだ元の18。全時計にCLOCK_SCALEを掛ける。実注文は読まない。
