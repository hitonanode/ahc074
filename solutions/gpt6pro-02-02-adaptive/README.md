# gpt6pro-02-02-adaptive

改良元: solutions/gpt6pro-02-01-original

## 改良元との差分

- 窓の並べ替えと色の反転: 内部では窓ごとに多数派の色を 0 とみなし（反転）、偏りの強い 16 窓を内部の窓 0〜15 にする。出力時に元の窓・色へ戻す。
- 紙の配分: 内部の窓 0〜15 は固定色（白）の紙 1 枚ずつ（16 枚）、窓 16〜47 は 2 枚ずつ（64 枚）、窓 48〜63 は 7 枚ずつ（112 枚）。窓 0〜15 の黒は自前の紙では出せないので、共有紙で必ず覆う。全 256 商品について作り方（使う紙と差し込み位置）を設計時に保存・検証し、作れない商品が残れば改良元と同じ全窓 2 色の配分に作り直す（universal_fallback）。
- 学習の「挿入位置の境界」: 商品ごとに境界 c_t を持ち、境界の窓が固定紙の白で済む、または既に上の紙で正しい色が出せるようになったら境界を先へ進め、その手前の窓はもう後の紙に一致を要求しない。共有の条件がさらに緩くなる。
- アンカーの選び方: 次のアンカー窓を、まだ多くの商品で未確定（U_t に残っている）でない窓から選ぶ（学習結果をアンカーの割当に戻す）。
- 注文時: 幅 64 のビーム探索。紙を露出させる手数、使った後に残る色の修正、他の紙で不一致を隠して使う 2 枚組を、実際の費用で評価する。探索を打ち切っても、保存した作り方で必ず正しく表示できる。
- 時間: CPU 全体 1.80 秒、学習は最大 1.60 秒。

## パラメータ

- 固定窓 16、学習の試行（starts=128, probes=24, λ=6）、ビーム幅 64、CPU 上限 1.80 秒（学習 1.60 秒）。学習の乱数は入力の商品のハッシュで初期化する。
- stderr: `learn_cpu`、`design_cpu`（設計全体）、`total_cpu`、`active_papers`（前へ出ている紙の平均枚数）、`universal_fallback`（1 なら全窓 2 色の配分に作り直した）、`repairs`（学習後に作り方を修理した商品数）、`truncated`（時間切れで探索を省いた回数）。

## 移植について

出所: main checkout の other_agents/gpt6pro-02.md と gpt6pro-02-layered_barcode_adaptive_bundle.zip（layered_barcode_adaptive.cpp）。元から reactive 形式で、引数なしで提出用の設定が動く。未来の注文は読まない。変更は次だけ:

- `#include <bits/stdc++.h>` を個別の include に置き換えた。
- 最後に上記の統計を `名前 = 数値` の形で stderr に出すようにした。アルゴリズムは不変。自己テスト用コードは残してある。
- 報告された成績（独自生成ケース、公式 seed とは対応しない）: 内部検証 8 ケースで平均 13.845 手/注文（ケース別 13.744〜13.982）、別実装の reactive 検証器で 3 ケース平均 13.755 手、誤り 0、CPU 0.93〜1.04 秒/ケース。前へ出す紙は平均約 2.80 枚。
- 同じ zip の validate_adaptive_protocol.py は独自の検証器（解法ではない）。graph の zip にある baseline_matched_driver.cpp はこの版の自己テスト用の生成器だけを変えたもので、reactive の動作は同じ。
