# astranova-resident

改良元: なし。`solutions/imp-gla` の保存済み6枚比較器を使う、常駐補助紙の**核だけの研究プローブ**。提出用・対話用の解法ではない。

G窓すべてと予約したH窓 `h0` だけを不透明にした7枚目を、汎用6枚と一緒に常駐させる。通常主紙はすべて `h0` を覆い、同じ紙にする2商品は `h0` で同色でなければならない。収納用ハンドルは残り27列。常駐紙が商品を担当しなければ、185主紙で256商品を持つため71対が必要。常駐紙自身が1商品を担当する場合は、残255商品に70対が必要になる。

`probe.cpp` は保存済み設計のG窓と6枚の印刷を固定し、次を調べる。

- 6! / 7! の全順序を列挙し、実際の不透明マスクで移動元の可視性を検査した有向グラフを作る。
- 64窓のHamming距離が26以下の全商品対について、6枚・7枚の双方の表示可能性を照合する。
- 予約ハンドル28候補と、常駐紙のG模様（全白・全黒、商品番号0,128）を調べる。
- 6枚の厳密な一様始状態平均距離を使った同じ固定代理費用で、商品対を貪欲に選ぶ。まずこの費用で予約ハンドルを選び、その同じ商品対を6枚・7枚の合法グラフの逆向き多点BFSで比較する。任意の重み付き最適マッチングを解くものではない。
- 7枚全5040始状態の平均と、常駐紙を最下位に固定した720始状態の平均を分ける。後者は6枚と同じ初期順序へ1枚を足した比較で、6枚の経路をそのまま使えるため距離が増えないことも検査する。

7枚の核グラフは、主紙・修正紙をすべて収納へ戻し、先頭7枚が核だけになった状態を仮定する。通常紙が残ると予約ハンドルを隠すので、このグラフをそのまま使えない。比較には通常紙の全回収、27列化、主紙の持ち上げ、H修正、要求間の状態分布を含めない。補助紙の取り出し・挿入・回収という別料金も足さない。出力される距離差は**核の操作数だけ**であり、コンテスト得点ではない。

入力の公開された256商品だけを読み、末尾の未知の注文列は読まない。保存済み出力から読むのも先頭192枚の印刷だけ。入力は `astra-generated-v1`、比較器の出典は `astra-options/reference_manifest.json`。

## 再現

```sh
g++ -std=c++23 -O2 solutions/astranova-resident/probe.cpp -o /tmp/ahc074-resident-probe
/tmp/ahc074-resident-probe tools/in solutions/astra-options/reference-output 0 2 \
  solutions/astranova-resident/results.csv \
  solutions/astranova-resident/handles.csv
```

固定回数・全列挙の研究用プログラムで、時間打ち切りや `CLOCK_SCALE` は使用しない。結果と解釈は `RESEARCH.md` に記録する。
