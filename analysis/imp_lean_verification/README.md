## 結論

- `imp-lean` の `Comparator::plan` は、既に保持集合（poset/閉包）を用いた厳密な最短操作数の探索を実装している。
  独立BFSとの照合では、100個の実現可能DAG × 720開始順序 = 72,000状態の操作数が一致した。
- 汎用紙を6→7枚・8枚と増やすだけでは改善しない。追加した汎用紙の移動数の増加が、専用紙の移動数の減少を上回る。
- 補助紙探索の重複計算を削減した7枚版も、499ケースで原版より +0.997% ± 0.097% 悪化。
- 共有ペアの二方向の平均費用を評価する修正は +0.069% ± 0.102% で、有意な改善を確認できない。
- **提出用の `solutions/imp-lean/` は無変更・採用見送りが妥当。**

## 何を試したか

### 1. 二方向の平均費用 (`imp-dual-mean`)

原版は `gcost[a][b] = gcost[b][a] = mean_moves(A[a], A[a] ^ A[b])` とするため、
底の紙を直接動かせない制約では対称な値を見積もる近似になります。
評価を
`0.5 * (mean_moves(a,a^b) + mean_moves(b,a^b))` に変更しました。
結果は誤差範囲内で改善確認できず。

### 2. 汎用紙の増加 (`imp-poset-7-38`, `imp-poset-8-44`)

元の6枚向け `M! × M!` 距離表は8枚で巨大になるため、
実際の `Comparator::plan` によるサンプル開始順序からの最短操作数を設計評価に使用します。
7枚では56、8枚では64個の開始順序を使います。標本中の最短距離は厳密ですが、平均は標本近似です。

補助紙の挿入は、現在の汎用紙順序から、合法移動で距離2以内の近傍を探索します。
6枚版の全720状態事前列挙から探索方針が変わる点は、純粋な枚数パラメータ変更ではないことに注意。

### 3. 近傍BFSの事前計算 (`imp-poset-cached7-38`, `imp-poset-cached8-44`)

標準の汎用紙順序から距離2以内の近傍を事前に列挙し、
注文時には紙番号を写し替えて利用します。
合法移動は紙の名前ではなく並び順に依存するため、同型な近傍を使い回せます。

## 実行・判定条件

- 入力: リポジトリの `tools/in/0000.txt`〜`0499.txt`。以前の比較時に全入力をGit blob SHAで照合。
- 実行: `scripts/pahcer_run.py --compare`、各ケースの実行順を回転して9並列、時間制限を維持。
- ビルド: GCC 13.3 / `-std=c++23 -O2 -DCLOCK_SCALE=1.1`。
- 判定: Rustの公式テスターではなく、同ソースを移植したC++互換テスター。
  最終比較に用いた保存出力は独立した `replay.py` でも可視性・表示・手数を再計算。
- 3,224本の出力を再生し、採用したケースは表示誤り `E=0`。
- 比較用ログ欠損のため共通に除外: 497ケースの比較ではseed `145,348,377`、
  499ケースの比較ではseed `397`。64ケースの検証は別母集団。
- 対照群: 元と同じ6枚・36窓へ戻した比較版は、固定反復数の8ケースで
  原版とスコア・操作列が全て同じ。
